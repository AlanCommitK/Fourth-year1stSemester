# L10 输入输出

> [!info] 这一讲的骨架

## 1 第三个关键部件

课件开门见山：**计算机与嵌入式系统的 I/O 体系结构，就是它与外部世界的接口。**

到此为止这门课讲过两个重要模块——**处理器**和**内存**。**第三个关键部件是一组 I/O 模块**；**每个 I/O 模块一头接到系统总线，另一头控制一个或多个外围设备**。

这正好补齐了 [[L06 计算机互连#1.1 三个模块各自要什么线|L06 说的三类模块]]里最后那一类。

**一个 I/O 模块有两大功能**：

- **经系统总线或中央交换器，与处理器和内存打交道**；
- **经专门定制的数据链路，与一个或多个外围设备打交道**。

课件说这一讲要看的也正是这两侧：**内部 I/O 接口**（I/O 功能如何与处理器、内存配合完成）与**外部 I/O 接口**（I/O 模块与外部世界之间）。

## 2 外部设备

**外部设备**在外部环境与计算机之间提供交换数据的手段，**通过一条到 I/O 模块的链路挂上来**；**这条链路用来在 I/O 模块与外部设备之间交换控制、状态和数据**。连到 I/O 模块上的外部设备叫**外围设备**（peripheral device）。

### 2.1 三类外部设备

| 类别 | 适合做什么 | 课件给的例子 |
| --- | --- | --- |
| **人可读**（human readable） | 与**计算机用户**通信 | 视频显示终端（VDT）、打印机等 |
| **机器可读**（machine readable） | 与**设备**通信 | 磁盘与磁带系统、**传感器与执行器** |
| **通信**（communication） | 与**远端设备**通信 | 远程终端、另一台机器可读设备、另一台计算机 |

"传感器与执行器"这一条就是 [[L01 实时系统#2.1 输入输出在物理上长什么样|L01 那条采集—处理—输出回路]]的两端。

### 2.2 外部设备的框图：三组信号

课件用一张图说明一个外部设备的一般构造。**它与 I/O 模块之间的接口由控制、数据、状态三种信号构成**：

| 信号 | 方向 | 作用 |
| --- | --- | --- |
| **控制信号** | I/O 模块 → 设备 | **决定设备要执行什么功能** |
| **状态信号** | 设备 → I/O 模块 | **表明设备的状态** |
| **数据位** | 双向 | 要送往或来自 I/O 模块的**一组比特** |

**控制信号能让设备做四件事**（课件逐条列出）：

1. **把数据送给 I/O 模块**（INPUT 或 READ）；
2. **从 I/O 模块接收数据**（OUTPUT 或 WRITE）；
3. **报告状态**；
4. **执行某种该设备特有的控制功能**（例如定位磁盘磁头）。

**状态信号**的例子是 **READY / NOT-READY**，用来表明设备是否已经准备好传数据。

设备内部有三个部分：**控制逻辑**（接控制与状态信号）、**缓冲器**（接数据位）、**换能器**（transducer，把数据在电信号与该设备特有的物理形式之间互相转换）。

> [!note] 把 READY / NOT-READY 这一位记住，后面两节都绕着它转
> 第 6 节的程序控制 I/O，处理器做的全部事情就是**反复读这一位**；第 7 节的中断驱动 I/O，则是**数据一进到模块的数据寄存器，模块就主动发中断**，不再要处理器来问。
> 2023 卷 Q2(b) 里的 **FGI / FGO** 两个标志位，可以看作这个 READY 信号在一台具体机器上的样子。
> （把这三处串成一条线是我补的；课件只是在讲外部设备时顺带给了 READY / NOT-READY 这个例子。）

### 2.3 键盘与显示器

课件拿键盘/显示器当例子，讲的是**字符怎么编码**。

- **国际参考字母表**（International Reference Alphabet, IRA）；
- **交换的基本单位是字符**，每个字符对应一个码；
- **每个字符用唯一的 7 位二进制码表示**，所以**能表示 128 个不同的字符**；
- 字符分两类：**可打印的**（字母、数字、特殊字符）与**控制字符**（控制打印或显示，例如回车；另一些与通信规程有关）。

一次按键发生了什么：**用户按下一个键，产生一个电信号；键盘里的换能器解释它，翻译成对应 IRA 码的位模式；这个位模式被送到计算机里的 I/O 模块。** 输出方向反过来：**IRA 码字符从 I/O 模块送到外部设备，换能器解释这个码，送出相应的电信号，让输出设备显示那个字符或执行所要求的控制功能。**

## 3 I/O 模块本身

### 3.1 框图

课件给的通用框图分成两侧：

- **朝系统总线一侧**：数据线、地址线、控制线；内部有**数据寄存器**和**状态/控制寄存器**；
- **朝外部设备一侧**：若干套**外部设备接口逻辑**，每套引出数据、状态、控制三组线。

课件逐条说明：

- **送进送出模块的数据，缓冲在一个或多个数据寄存器里**；
- **可能还有一个或多个状态寄存器提供当前状态信息；状态寄存器也可以兼作控制寄存器，接收处理器送来的详细控制信息**；
- **模块内的逻辑通过一组控制线与处理器交互；处理器用控制线向 I/O 模块发命令**；其中**有些控制线是 I/O 模块自己用的**（例如仲裁和状态信号）；
- **模块必须能识别和产生它所控制的那些设备的地址**。**每个 I/O 模块有唯一的一个地址；如果它控制不止一个外部设备，就有唯一的一组地址**；
- **最后，I/O 模块含有针对它所控制的每个设备的专用接口逻辑**。

"状态寄存器兼作控制寄存器"这一条马上会在 [[#6.3 内存映射 I/O 与独立编址 I/O|§6.3]] 的例子里兑现：地址 517 既读状态也写命令。

### 3.2 I/O 模块的五大功能

这是一条标准的"列举并简述"答案：

| 功能 | 课件的说明 |
| --- | --- |
| **控制与定时**（control and timing） | **协调内部资源与外部设备之间的流量** |
| **与处理器通信**（processor communication） | **命令译码、数据、状态报告、地址识别** |
| **与设备通信**（device communication） | **命令、状态信息和数据** |
| **数据缓冲**（data buffering） | **做必要的缓冲，以平衡设备速度与内存速度** |
| **差错检测**（error detection） | **检出并报告传输错误** |

**"数据缓冲是为了平衡设备速度与内存速度"——这句话是整讲主线的另一种说法。**

## 4 四类 I/O 命令

**当一个 I/O 模块被处理器寻址时，它可能收到四类 I/O 命令**：

| 命令 | 作用 |
| --- | --- |
| **控制**（control） | **激活一个外设，并告诉它做什么** |
| **测试**（test） | **测试与 I/O 模块及其外设相关的各种状态条件** |
| **读**（read） | **让 I/O 模块从外设取一项数据，放进它的内部缓冲** |
| **写**（write） | **让 I/O 模块从数据总线取一项数据，随后把它发给外设** |

注意**读和写都分两段**：read 是"外设 → 模块缓冲"，处理器还要再来取一次；write 是"数据总线 → 模块"，模块再发给外设。**这个两段式正是 §3.2 那条"数据缓冲"功能的体现**（这层挂钩是我补的，课件只是分别列出四条命令和五项功能）。

## 5 三种 I/O 技术

![[L10 三种 IO 技术.png]]

### 5.1 课件的 2×2 定位表

**这一节直接对应 2023 卷 Q2(a)「列举并简要定义三种常用的 I/O 技术」[2+2+2=6 分]**，照课件原文答即可：

| | **不用中断** | **用中断** |
| --- | --- | --- |
| **I/O 与内存之间的传送要经过处理器** | **程序控制 I/O** | **中断驱动 I/O** |
| **I/O 与内存直接传送** | （空） | **直接内存访问 DMA** |

三者的定义：

- **程序控制 I/O**（programmed I/O）：**数据在处理器与 I/O 模块之间交换**；**处理器执行一段程序，直接控制这次 I/O 操作**；**处理器发出命令之后必须一直等到 I/O 操作完成**；**如果处理器比 I/O 模块快，这就是在浪费处理器时间**。
- **中断驱动 I/O**（interrupt-driven I/O）：**处理器发出一条 I/O 命令，继续执行别的指令，等 I/O 模块干完活之后由它来中断处理器**。
- **直接内存访问**（direct memory access, DMA）：**I/O 模块与主存直接交换数据，处理器不参与**。

> [!warning] 答这道题时最该写进去、也最容易漏的两句
> **程序控制 I/O** 的定义里，"处理器必须等到操作完成"和"如果处理器更快就是浪费"是**两个分开的采分点**，别合成一句。
> **DMA** 的定义里，关键词是 **"without processor involvement"**（处理器不参与）——只说"直接传送"不够，要点明处理器被绕开了。
> 另外那张表里空着的一格值得顺带一提：**不经过处理器、又不用中断**，等于数据直接进了内存却没人通知处理器，所以课件把它留空。（课件只留了空格没有解释，这句是我补的；严格说处理器仍可以主动去轮询 DMA 的状态寄存器，所以这一格更像是"不值得单列"而不是"不可能存在"。）

### 5.2 读一个数据块，三种做法各走几步

图里三栏对照着看，一眼能看出处理器时间花在哪：

- **(a) 程序控制**：发命令 → 读状态 → 没好就**回去再读状态**（死循环）→ 好了读一个字 → 写进内存 → 没搬完就**回到最上面、为下一个字重新发一条读命令**。**整块搬完之前处理器一步都离不开。** 图里两条回跳线的落点不同，别记混：Not ready 那条回到"读状态"，Done? = No 那条一直回到"发命令"。
- **(b) 中断驱动**：发命令 → **去干别的事** → 被中断 → 读状态 → 读一个字 → 写内存 → 没搬完就回到"发命令"那一步，再去干别的事、等下一次中断。**等待的那段时间还给了处理器，但每一个字仍然要经处理器的手。**
- **(c) DMA**：发"读整块"命令 → **去干别的事** → 整块搬完后被中断一次 → 读 DMA 状态 → 下一条指令。**处理器只在头尾各出面一次。**

**一句话记住三者的差别：处理器要出面几次。** 程序控制是"全程"，中断驱动是"每个字一次"，DMA 是"每块一次"。[[#7.7 真题现场：2022 卷 Q2(d) 处理器占用率三连问|§7.7]] 那道真题算的就是这个次数怎么换成百分比。

## 6 程序控制 I/O

### 6.1 I/O 指令与地址

**用程序控制 I/O 时，处理器从内存取到的那些 I/O 相关指令，与它发给 I/O 模块去执行的 I/O 命令之间，有紧密的对应关系。** **指令的形式取决于外部设备是怎么被寻址的。**

**每个通过 I/O 模块接入的 I/O 设备都有唯一的标识符或地址。** **处理器发出 I/O 命令时，命令里含有目标设备的地址**；因此**每个 I/O 模块都必须解释地址线，判断这条命令是不是给自己的**。

### 6.2 两种编址方式

| | **内存映射 I/O**（memory-mapped I/O） | **独立编址 I/O**（isolated I/O） |
| --- | --- | --- |
| 地址空间 | **设备和内存共用一个地址空间** | **分开的地址空间** |
| 总线上要什么 | **总线上只需要一根读线和一根写线** | **需要 I/O 选择线或内存选择线** |
| 指令 | **没有专门的 I/O 命令**；**可用的内存访问命令有一大把** | **有专门的 I/O 命令**；**指令集有限** |
| 看起来像什么 | **I/O 看上去就跟内存读写一样** | 另一套东西 |

这正是 [[L06 计算机互连#1.1 三个模块各自要什么线|L06 提过的那条设计选择]]在指令层面的样子，也是 [[Lab1 寄存器、定时器与中断#3.1 CRL 与 CRH：每个引脚 4 位|Lab 1 往 `GPIOB->CRL` 里写值]]之所以看起来像在改内存的原因——STM32 用的就是内存映射 I/O。

### 6.3 内存映射 I/O 与独立编址 I/O

![[L10 内存映射与独立编址.png]]

课件用同一件事——**从终端键盘读一个字节到处理器的累加器**——给出两段程序。

**内存映射那一侧**：**两个地址专供某个终端的键盘输入**，**地址 516 是数据寄存器，地址 517 是状态寄存器（它同时兼作接收处理器命令的控制寄存器）**。状态寄存器里 **1 = ready、0 = busy**，而**往它写 1 就启动一次读**。程序是：

```
200   Load AC               "1"     取立即数 1
201   Store AC              517     写状态寄存器 → 启动键盘读
202   Load AC               517     读回状态字节
203   Branch if Sign = 0    202     没好就跳回 202
204   Load AC               516     好了，读数据字节
```

**独立编址那一侧**：**I/O 端口只能由专门的 I/O 命令访问，这些命令会激活总线上的 I/O 命令线**。程序是：

```
200   Load I/O          5     启动键盘读
201   Test I/O          5     查是否完成
202   Branch Not Ready  201   没好就跳回 201
203   In                5     读数据字节
```

> [!warning] 这一页真正的考点不是两种编址的差别，而是它们的共同点
> **两段程序都有一条往回跳的分支**（203→202 和 202→201）。课件也点了这件事：**"注意处理器会一直循环，直到数据字节可用"。**
> 这就是**忙等**（busy waiting）：处理器在原地打转读状态位，什么别的事都干不了。它和 [[Lab1 寄存器、定时器与中断#4.4 为什么轮询不够，必须上中断|Lab 1 讲的轮询]]是同一件事。
> **换哪种编址方式都治不了这个毛病**——那要靠中断。
> （"忙等"是通用叫法，课件没有用这个词——这一页的原话只是 *"the processor loops until the data byte is available"*，图里标的是 1 = ready / 0 = busy；课件中确实出现过 poll，但在 [[#7.5 设备识别：四类技术|§7.5]]，指的是中断之后逐个问各模块，与这里不是一回事。答卷上写 polling 或 busy waiting 都可以。）

### 6.4 真题现场：2023 卷 Q2(b) 用五个寄存器做 I/O

> **题干**：某计算机系统含一个 I/O 模块，控制一台简单的键盘/打印机电传打字机。处理器中含有下列寄存器，直接连在系统总线上：
> `INPR`：输入寄存器，8 位 ｜ `OUTR`：输出寄存器，8 位 ｜ `FGI`：输入标志，1 位 ｜ `FGO`：输出标志，1 位 ｜ `IEN`：中断允许，1 位
> 键盘输入与打印输出都由该 I/O 模块控制。电传打字机能把一个字母数字符号编码成 8 位字，也能把 8 位字解码成一个字母数字符号。
> **(i) 说清楚处理器如何用上面列出的前四个寄存器与电传打字机完成 I/O。[4 分]**
> **(ii) 提出另一种能让上述功能更高效的做法。[4 分]**

（课件没有讲 `INPR` / `OUTR` / `FGI` / `FGO` 这套寄存器，下面这套握手流程是我按题干给出的寄存器含义、加上电传打字机接口的通行约定补的；能直接对上课件的只有[[#6 程序控制 I/O|§6]] 的轮询思想本身。）

**(i) 答案要点**——注意题干说的是**前四个**寄存器（不含 `IEN`），所以这一问要答的是**程序控制 I/O / 轮询**：

**输入方向（键盘 → 处理器）**

1. 用户按下一个键，电传打字机把这个字符编码成 8 位字；
2. **I/O 模块把这 8 位放进 `INPR`，并把 `FGI` 置 1**，表示"有一个新字符待取"；
3. **处理器反复读 `FGI` 这一位**（忙等），直到看见它是 1；
4. 处理器**把 `INPR` 的内容取走**（送进累加器），**然后把 `FGI` 清 0**；
5. **清 0 这一步同时是给 I/O 模块的信号**：`INPR` 空出来了，可以放下一个字符。

**输出方向（处理器 → 打印机）**

1. **处理器反复读 `FGO`**，直到看见它是 1——这表示打印机已经打完上一个字符、可以接收新的；
2. 处理器**把要打的字符写进 `OUTR`，然后把 `FGO` 清 0**；
3. I/O 模块把 `OUTR` 的字符送给电传打字机打印；
4. **打完之后，I/O 模块把 `FGO` 置 1**，循环回到第 1 步。

**要写进答案的三句话**（这是给分的地方，不要只描述流程）：

- **`FGI` 与 `FGO` 是握手标志**：**由 I/O 模块置 1、由处理器清 0**，一置一清构成一次完整的交接；
- **两个方向各有自己的数据寄存器和标志位，所以输入和输出互不干扰**；
- **处理器是靠不断测试标志位来推进的，也就是轮询**；在设备就绪之前，**处理器只能忙等，做不了别的事**。

**(ii) 答案**：**用上第五个寄存器 `IEN`，改成中断驱动 I/O。**

把 `IEN` 置 1 之后，**不再由处理器去查标志，而是由 I/O 模块在 `FGI` 或 `FGO` 置 1 时向处理器发出中断**。处理器**执行完当前指令后响应中断**，保存 PC 与 PSW（程序状态字），进入中断服务程序；服务程序判断是哪个标志引起的，做相应的一次传送，然后返回被打断的程序继续执行。

**好处**：**处理器不必再忙等**，等待设备的那段时间可以去跑别的程序；**I/O 速率不再受"处理器多久查一次"限制，而是设备一就绪就能得到服务**。

**可以再加一句拿满分**：如果要传的是**大批量数据**（不是电传打字机这种一次一个字符的场合），**更进一步的做法是 DMA**——让 I/O 模块与内存直接交换，处理器连每个字节都不用经手。

### 6.5 真题现场：2023 卷 Q2(d) 轮询次数

> **题干**：某系统由操作员通过键盘输入命令来控制。在 8 小时内输入的命令平均为 60 条。
> **(i) 在当前设计中，处理器每 100 ms 扫描一次键盘。8 小时内键盘会被检查多少次？[2 分]**
> **(ii) 作为一名嵌入式系统工程师，你认为 (i) 里用的办法对这个系统是最优的吗？是就说明理由；否就提出更好的做法。[3 分]**

**(i)**

$$
8\ \text{小时} = 8 \times 3600 = 28800\ \text{s}, \qquad
N = \frac{28800\ \text{s}}{0.1\ \text{s}} = \mathbf{288{,}000}\ \text{次}
$$

**(ii) 答：不是最优。** 要把"为什么不好"量化出来才拿得到分：

$$
\text{有效扫描的比例} = \frac{60}{288000} = \frac{1}{4800} \approx 0.021\%
$$

也就是说，**每 4800 次扫描里只有 1 次真的查到了命令，其余 99.98% 的扫描完全是空转**——纯粹浪费处理器时间和功耗。

**更好的做法：改成中断驱动 I/O。** 键盘在有按键时主动向处理器发中断，处理器平时完全不用管它。**代价对比一目了然：288,000 次扫描 → 60 次中断服务。**

> [!note] 这一问想听到的是"嵌入式工程师"的回答，所以值得再加一句权衡
> 轮询并非一无是处：**它的时延是确定的**（最坏 100 ms），**而且不需要中断控制器、代码更简单**——对硬实时系统，可预测性有时比平均效率更重要（[[L01 实时系统#5 硬实时、固实时、软实时|L01 那条线]]）。
> 但在这个场合，**人按键本来就是稀疏的随机事件，60 次 / 8 小时**，确定性没有任何价值，而浪费是 4800 倍——**所以这里中断明显更合适**。
> 把这层权衡写出来，比只答"用中断"更像工程师的答案。（这段权衡是我补的，课件没有讨论。）

## 7 中断驱动 I/O

### 7.1 它解决什么

**程序控制 I/O 的问题是：处理器要等很久，才等到 I/O 模块准备好接收或发送数据。**

**另一种办法叫中断驱动 I/O：处理器向模块发出一条 I/O 命令，然后去做别的有用的事。I/O 模块准备好与处理器交换数据时，再中断处理器请求服务；处理器执行这次数据传送，然后恢复原先的处理。**

**从 I/O 模块的角度看**（以输入为例）：

1. **I/O 模块从处理器收到一条 READ 命令**；
2. **模块随即从相连的外设把数据读进来**；
3. **数据一进到模块的数据寄存器，模块就通过一条控制线向处理器发出中断信号**；
4. **然后模块一直等，直到处理器来要这份数据**；
5. **处理器来要时，模块把数据放到数据总线上，接着就可以做下一次 I/O 操作了**。

**从处理器的角度看**：

1. **处理器发出 READ 命令，然后转去做别的事**（例如同时在跑好几个不同的程序）；
2. **在每一个指令周期的末尾，处理器检查有没有中断**；
3. 中断来了，**处理器保存当前程序的上下文**（例如程序计数器和各处理器寄存器）**，然后处理这次中断**；
4. 这里"处理中断"就是**从 I/O 模块读走那个字、存进内存**；
5. **然后恢复原先那个程序（或别的程序）的上下文，继续执行**。

> [!warning] 第 2 条是容易被略过的关键
> **检查中断的时刻是"每个指令周期的末尾"，不是任意时刻。** 这解释了两件事：
> 一是 [[#7.3 一次中断从头到尾九步|§7.3]] 第 2 步为什么是"先把当前指令执行完"；
> 二是[[#8.2 DMA 模块与"周期窃取"|§8.2]] 那张图里，为什么中断的断点只有一个、而 DMA 的断点有好几个。

### 7.2 这一节和 L05 的关系

[[L05 计算机部件#5 中断：为了不让 CPU 干等|L05 已经讲过中断是什么]]、四类中断、以及[[L05 计算机部件#6 有没有中断，CPU 的时间去向完全不同|有没有中断时 CPU 的时间去向]]。这一讲不重复那些，只补两样 L05 没讲的：**一次中断的完整九步**，和**多个设备时怎么认人、怎么排队**。

### 7.3 一次中断从头到尾九步

![[L10 中断处理的九步.png]]

**一次中断会在处理器硬件和软件两边各触发一串事件。** 课件把硬件那五步写得很细：

1. **设备向处理器发出一个中断信号**；
2. **处理器先把当前这条指令执行完，然后才响应中断**；
3. **处理器检测到中断，向发出中断的那个设备送一个应答信号**；**这个应答让设备可以撤掉它的中断信号**；
4. **处理器把 PSW 和 PC 压入控制栈**（control stack；课件下一页的图里管它叫系统栈，指的是同一个栈）；
5. **处理器根据这次中断装入新的 PC 值**——也就是中断处理程序的入口。

软件那一侧接着做四步：**6 保存进程状态的其余部分 → 7 处理这次中断 → 8 恢复进程状态信息 → 9 恢复旧的 PSW 与 PC**。

课件另有一页用内存与寄存器的变化把第 4–9 步画出来，要点是：**程序计数器和 PSW 被保存在系统栈上**；**中断处理完之后，保存的寄存器值从栈里取回、写回寄存器**；**最后一步是从栈里恢复 PSW 和程序计数器的值**。

> [!warning] 两条最容易丢分的细节
> **一、第 2 步不是"立刻响应"**，而是**先把当前指令执行完**。中断的检查点在指令周期的末尾。
> **二、第 4 步硬件压的只有 PSW 和 PC 两样**，**其余寄存器是第 6 步由软件保存的**。硬件只管最少的那一份，剩下的归中断处理程序——这也是 [[Lab1 寄存器、定时器与中断#4.4 为什么轮询不够，必须上中断|Lab 1 里 ISR 要尽量短]]的底层原因之一。

### 7.4 两个设计问题

**实现中断式 I/O 会冒出两个设计问题**：

- **既然 I/O 模块有好几个，处理器怎么知道是哪个设备发的中断？**
- **如果同时发生了多个中断，处理器怎么决定先处理哪一个？**

### 7.5 设备识别：四类技术

**常用的技术分四大类**：

| 技术 | 课件的说明 |
| --- | --- |
| **多条中断线**（multiple interrupt lines） | **在处理器与各 I/O 模块之间拉多条中断线**。**最直截了当的办法**；但**即使用了多条线，每条线上也很可能仍挂着多个 I/O 模块** |
| **软件轮询**（software poll） | **处理器检测到中断后，转去执行一个中断服务程序，这个程序的任务就是逐个轮询各 I/O 模块，确定是哪个模块引起的中断**。**很费时间** |
| **菊花链**（daisy chain，硬件轮询、向量式） | **中断应答线以菊花链方式串过各模块**。**向量**（vector）是 **I/O 模块的地址或其他唯一标识**。**向量中断**：**处理器把向量当作指针，直接找到对应的设备服务程序，不必先执行一个通用的中断服务程序** |
| **总线仲裁**（bus arbitration，向量式） | **I/O 模块必须先取得总线控制权，才能拉起中断请求线**。**处理器检测到中断后在中断应答线上回应，于是提出请求的那个模块把自己的向量放到数据线上** |

> [!note] 四种技术其实是按"谁来做识别"排的
> **多条中断线**：靠**线本身**——哪根线响就是哪一类设备，最省时间但最费引脚。
> **软件轮询**：靠**处理器跑一段程序去问**——最省硬件但最费时间。
> **菊花链与总线仲裁**：靠**设备自己报名**（把向量送上来）——这就是"向量中断"，兼顾了速度和引脚数，代价是设备要更聪明。
> 顺着这条线看，**优先级**问题（第二个设计问题）也同时被解决了：多条中断线按线定优先级，软件轮询按程序里问的先后顺序定，菊花链按在链上的物理位置定，总线仲裁按仲裁规则定。
> （这个归纳是我补的，课件只是平列四条。）

### 7.6 一个具体的中断控制器：82C59A

- **Intel 80386 只提供一条中断请求线（INTR）和一条中断应答线（INTA）**；
- 为了让它能应付多种设备和多种优先级结构，**通常给它外配一个中断仲裁器：82C59A**；
- **外部设备接到 82C59A 上，82C59A 再接到 80386**；
- **一片 82C59A 能管最多 8 个模块**；
- **需要管超过 8 个时，可以用级联方式，最多管到 64 个模块**。

$8 \times 8 = 64$：一片主片的 8 条输入各接一片从片，每片从片再管 8 个设备。

### 7.7 真题现场：2022 卷 Q2(d) 处理器占用率三连问

这是两份真题里**分值最高的一道小题（12 分）**，三问层层递进，正好对应 [[#5.2 读一个数据块，三种做法各走几步|§5.2]] 说的"处理器要出面几次"。

> **题干**：某系统对一个设备采用中断驱动 I/O，该设备**持续地以平均 8 KB/s 的速率传输数据**。

> [!warning] 开算之前先定 kB 的口径——这道题和 Cache 那道题用的是两套
> 本题取 **8 KB/s = 8000 字节/秒**（十进制 $10^3$）。
> **先排掉一个站不住的理由**：不能说"因为 $8000/16 = 500$ 是整数"——$8192/16 = 512$ 同样是整数，中断次数这一步根本分不开两种读法。真正分得开的是最后的百分比：取 8000 得到 **80%、11.4%、6.6%** 三个整洁的数，取 8192 则是 **81.92%、11.67%、6.76%**。
> 对照 [[L09 高速缓存#5.6 真题现场：2023 卷 Q2(c)|L09 那道 Cache 题]]：那里的 8 kB **必须**按 $2^{13}$ 读，否则位宽不是整数——那是硬约束；本题的"整洁"只是软线索，两者强度完全不同。
> **所以答卷上先写一句口径**（"take 8 KB/s = 8000 B/s"）再往下算。按 8192 算出的 81.92% / 11.67% / 6.76% 本身并没有算错，口径写明了就不至于被判错。（口径两可这件事课件与真题都没有交代，这段判断是我补的。）

**(i) 假设中断处理约需 100 μs（即跳进 ISR、执行它、再返回主程序的时间）。若设备每传一个字节就中断一次，这个 I/O 设备消耗了处理器时间的几分之几？[4 分]**

每秒中断次数 = 每秒字节数 = 8000 次。

$$
f_{1} = 8000\ \text{次/s} \times 100\ \mu\text{s} = 8000 \times 100 \times 10^{-6}\ \text{s} = 0.8 \Rightarrow \mathbf{80\%}
$$

**八成的处理器时间被一个 8 KB/s 的设备吃掉了。** 这个数字本身就是"为什么需要缓冲和 DMA"的答案。

**(ii) 现在假设设备有两个 16 字节的缓冲区，每当其中一个满了就中断处理器。中断处理自然更久，因为 ISR 要搬 16 个字节。执行 ISR 时，处理器搬每个字节约需 8 μs。这种情况下占处理器时间的几分之几？[4 分]**

中断频率降到每 16 字节一次：

$$
n_{2} = \frac{8000}{16} = 500\ \text{次/s}
$$

每次中断的开销 = **固定开销 + 搬 16 个字节**：

$$
t_{2} = 100 + 16 \times 8 = 100 + 128 = 228\ \mu\text{s}
$$

$$
f_{2} = 500 \times 228 \times 10^{-6} = 0.114 \Rightarrow \mathbf{11.4\%}
$$

**(iii) 现在假设处理器配有块传送 I/O 指令（如 Z8000 上那种），使得对应的 ISR 搬一个块里的每个字节只需 2 μs。这种情况下占几分之几？[4 分]**

中断频率不变，只有每字节的搬运时间从 8 μs 降到 2 μs：

$$
t_{3} = 100 + 16 \times 2 = 132\ \mu\text{s}, \qquad
f_{3} = 500 \times 132 \times 10^{-6} = 0.066 \Rightarrow \mathbf{6.6\%}
$$

**三问的结果串起来看**：

| | 中断频率 | 每次开销 | 占用率 | 省下来的来自哪 |
| --- | --- | --- | --- | --- |
| (i) 每字节中断 | 8000 次/s | 100 μs | **80%** | —— |
| (ii) 16 字节缓冲 | 500 次/s | 228 μs | **11.4%** | **把固定开销摊薄了 16 倍** |
| (iii) 再加块传送指令 | 500 次/s | 132 μs | **6.6%** | **把每字节的搬运时间从 8 μs 压到 2 μs** |

> [!warning] 这道题的四个坑
> **一、(ii) 里那 100 μs 还要不要加？** 要。题干说"中断处理更久，**因为** ISR 要搬 16 字节"——是在原来的 100 μs 之上**加**搬运时间，不是替换。
> **二、"两个 16 字节缓冲区"不会让中断频率翻倍。** 一个满了中断一次，所以是每 16 字节一次。第二个缓冲区的作用是**让设备在 ISR 搬第一个缓冲区时继续接收数据**（双缓冲），它保证不丢数据，但不改变中断频率。
> **三、三问比较的是"每次中断摊到多少字节"和"每字节多贵"两件不同的事。** (i)→(ii) 省的是**固定开销的摊销**，(ii)→(iii) 省的是**每字节的单价**。答题时点明这一点，比只给三个数字稳。
> **四、单位。** 100 μs = $10^{-4}$ s。整道题的量纲是 $(\text{次/s}) \times (\text{s/次}) = $ 无量纲的比例，算完应该是个 0 到 1 之间的数——不是的话必定哪里错了。

**顺手把这道题接到 DMA 上**：按这个趋势，如果换成 DMA，每搬一个 16 字节块处理器只在块的头尾各出面一次，占用率还会再降一个量级——这正是下一节的理由。

## 8 直接内存访问

### 8.1 前两种办法的两个固有缺陷

**程序控制 I/O 和中断驱动 I/O 都有两个与生俱来的缺点**：

1. **I/O 的传输速率，受限于处理器测试和服务一个设备的速度**；
2. **处理器被绑在 I/O 传输的管理上；每一次 I/O 传输都要执行若干条指令。**

**当要搬的数据量很大时，更高效的技术是直接内存访问（DMA）。**

注意这两条缺陷**中断驱动 I/O 并没有解决**——它只解决了"等待时处理器闲着"，没解决"每个字都要处理器经手"。§7.7 的 (iii) 已经把每字节压到 2 μs，但那 2 μs 仍然是处理器的时间。

### 8.2 DMA 模块与"周期窃取"

![[L10 DMA 的断点与周期窃取.png]]

- **DMA 在系统总线上多加一个模块，这个模块能够模仿处理器，甚至从处理器手里接管对系统的控制**；
- **它必须这么做，才能通过系统总线与内存之间搬数据**；
- 为此，**DMA 模块只能在处理器不需要总线时用总线，否则就必须强迫处理器暂时挂起**；
- **后一种技术更常用，叫周期窃取（cycle stealing），因为 DMA 模块实际上偷走了一个总线周期**。

课件用一张"指令周期里的断点"图把这件事说清楚：**一个指令周期被摊成取指令、译码指令、取操作数、执行指令、存结果、处理中断六个处理器周期**；**DMA 断点出现在各个处理器周期之间**（有好几个），而**中断断点只有一个，在指令执行完之后**。

> [!warning] 周期窃取不是中断，这是最容易混的一点
> **中断**：处理器**保存 PSW 和 PC、跳到中断处理程序、回来再恢复**——上下文切换是实打实的开销。
> **周期窃取**：处理器**什么都不保存、也不跳转**，只是**这一拍不用总线**，下一拍接着干。
> 所以单次周期窃取的开销远小于一次中断，这正是搬大块数据要用 DMA 的理由（小多少取决于具体机器，课件没有给数字，别在答卷上编倍数）。
> （"不保存上下文"这层对比课件没有明说，是我补的；课件给出的事实是断点位置不同、以及"偷走一个总线周期"。）

### 8.3 处理器交给 DMA 模块的四样信息

**处理器想读或写一块数据时，向 DMA 模块发一条命令，把下面这些信息送过去**：

| 信息 | 怎么送 |
| --- | --- |
| **是读还是写** | 用处理器与 DMA 模块之间的**读/写控制线** |
| **涉及的 I/O 设备的地址** | **经数据线**传过去 |
| **内存里的起始位置**（从哪读或往哪写） | **经数据线**传过去，**由 DMA 模块存进它的地址寄存器** |
| **要读或写的字数** | 同样**经数据线**传过去，**存进数据计数寄存器** |

所以 DMA 模块内部至少有三样东西：**数据计数寄存器、数据寄存器、地址寄存器**，外加**控制逻辑**。它对外的线是：数据线、地址线、"向 DMA 请求"、"DMA 的应答"、中断、读、写。

**注意一个容易答反的细节：设备地址、内存起始地址、字数这三样都是经数据线送的，只有"读还是写"走控制线。**

### 8.4 三种 DMA 配置

课件给了三种配置：

| 配置 | 结构 | 代价 |
| --- | --- | --- |
| **(a) 单总线、分离的 DMA** | 处理器、DMA、各 I/O 模块、内存**都挂在同一条系统总线上** | 每搬一个字要**占用两次总线周期**（I/O→DMA，DMA→内存） |
| **(b) 单总线、DMA 与 I/O 集成** | **DMA 模块与一个或多个 I/O 模块合为一体**，它们之间的通路不经系统总线 | 每个字只占**一次**总线周期 |
| **(c) I/O 总线** | **各 I/O 模块挂在一条独立的 I/O 总线上**，DMA 模块接在系统总线与 I/O 总线之间 | 同样每字一次系统总线周期，而且**DMA 模块上只需要一个 I/O 接口，扩展容易** |

（三种配置的"占几次总线周期"课件没有逐条写出，是我按图里的连接方式推的；课件给的是三张结构图和它们的名字。）

### 8.5 8237 与 Fly-By

**8237 DMA 芯片**在系统总线上的用法：**CPU 通过 HRQ（HOLD request）/ HLDA（HOLD acknowledge）与 8237 交接总线控制权**；**设备侧用 DREQ（DMA request）/ DACK（DMA acknowledge）**；控制总线上的四根命令线是 **IOR、IOW、MEMR、MEMW**。

**Fly-By（飞越式）DMA 控制器**：

- **数据不经过、也不存放在 DMA 芯片里**；
- 因此**只能在 I/O 端口与内存之间搬**，**不能在两个 I/O 端口之间、也不能在两个内存位置之间搬**；
- **经由寄存器可以做内存到内存的搬运**；
- **8237 含四个 DMA 通道**，**各自独立编程**，**任一时刻只有一个在工作**，**编号 0、1、2、3**。

fly-by 这个名字说的是数据"飞过"控制器而不在里面落地；具体到 8237 上的做法是：**一个总线周期里同时拉有效 IOR 与 MEMW，数据在数据总线上直接从 I/O 端口流进内存**，不在 DMA 芯片里停留。（这句解释是我补的，课件只给了"数据不经过、也不存放在 DMA 芯片里"这个结论和 IOR / IOW / MEMR / MEMW 四根命令线。）

### 8.6 DMA 之后：直接缓存访问

课件最后一页指出 DMA 也到了极限：

- **由于网络 I/O 的数据率急剧上升，DMA 已经无法按比例扩展以满足需求**；
- 需求**主要来自 10 Gbps 和 100 Gbps 以太网交换机的广泛部署**，它们要在数据库服务器等高性能系统之间搬运海量数据；
- **另一个来源是千兆级的 Wi-Fi**：**能跑 3.2 Gbps 和 6.76 Gbps 的 Wi-Fi 设备正变得普及**，给企业系统带来压力。

于是有了**直接缓存访问**（direct cache access, DCA）。课件只点到这个名字，没有展开。

## 9 一个具体的接口芯片：8255A

课件末尾用几页介绍 **Intel 8255A 可编程外设接口**，这部分在两份真题里从未出现，按"知道它是什么"的程度准备即可：

- 它有 **24 条 I/O 线**，分成 **A 口（8 位）、C 口上半（4 位）、C 口下半（4 位）、B 口（8 位）** 四组，由 **A 组控制**与 **B 组控制**两套逻辑管理；
- 对外是**双向数据总线 D7–D0**，加上 **RD、WR、A1、A0、Reset、CS** 等读写控制线；
- **当处理器把 A1 和 A0 都置 1 时，8255A 把数据总线上的 8 位值解释成一个控制字**；**当送来的控制字 D7 位为 1 时，这个控制字用来配置那 24 条 I/O 线的工作模式**；
- 课件给的应用例子是**用它接一个键盘/显示终端**：**键盘提供 8 位输入，其中 SHIFT 和 CONTROL 两位对处理器里运行的键盘处理程序有特殊含义**；C 口的几位用作 **Data ready / Acknowledge / Blanking / Clear line** 等握手信号，并引出**中断请求**。

> [!note] 课件把 A1/A0 写成了 "A1 and A2"
> 讲控制字那一页的原文是 *"When the processor sets both A1 and A2 to 1…"*，但同一讲的引脚图上**只有 A1 和 A0 两根地址线，没有 A2**。按 8255A 的实际规格，**选中控制寄存器的条件是 A1 = A0 = 1**。
> **这是课件的笔误**；本节按 A1/A0 写。（这个判断是我对照同一讲的引脚图做的，课程材料里没有更正说明。）

## 本讲速记

- **三个关键部件的第三个是 I/O 模块**：一头接系统总线、一头控制一个或多个外设。**I/O 模块的两大功能**：经系统总线与处理器和内存打交道；经定制数据链路与外设打交道。
- **外部设备三类**：**人可读**（VDT、打印机）、**机器可读**（磁盘磁带、**传感器与执行器**）、**通信**（远端终端、另一台计算机）。
- **外部设备与 I/O 模块之间三组信号**：**控制**（决定设备执行什么功能）、**状态**（表明设备状态，如 READY / NOT-READY）、**数据位**。控制信号能让设备做四件事：**送数据给模块（INPUT/READ）、从模块收数据（OUTPUT/WRITE）、报告状态、执行设备特有的控制功能**（如定位磁头）。设备内部：**控制逻辑 + 缓冲器 + 换能器**。
- **IRA**：交换的基本单位是**字符**，**每个字符一个唯一的 7 位码**，**共 128 个**；字符分**可打印**与**控制**两类。
- **I/O 模块的五大功能**：**控制与定时、与处理器通信、与设备通信、数据缓冲、差错检测**。其中**数据缓冲是为了平衡设备速度与内存速度**。**每个 I/O 模块有唯一地址；控制多个设备时有唯一的一组地址。**
- **四类 I/O 命令**：**控制**（激活外设并告诉它做什么）、**测试**（测状态条件）、**读**（外设 → 模块内部缓冲）、**写**（数据总线 → 模块 → 外设）。
- **三种 I/O 技术（2023 卷 Q2(a) 原题，6 分）**：
  **程序控制 I/O**——数据在处理器与 I/O 模块之间交换，处理器执行程序直接控制该操作，**发出命令后必须等到操作完成**；**处理器比 I/O 模块快时就是浪费**。
  **中断驱动 I/O**——处理器发出命令后继续执行别的指令，**由 I/O 模块干完活后中断它**。
  **DMA**——**I/O 模块与主存直接交换数据，处理器不参与**。
  2×2 定位表：横轴是用不用中断，纵轴是经不经过处理器；**"不经过处理器又不用中断"那一格是空的**。
- **处理器要出面几次**：程序控制 = 全程；中断驱动 = 每个字一次；DMA = 每块一次。
- **两种编址**：**内存映射 I/O**——设备与内存**共用一个地址空间**，**总线只需一根读线一根写线**，**没有专门 I/O 命令**，**可用的内存访问命令很多**。**独立编址 I/O**——**分开的地址空间**，**需要 I/O 或内存选择线**，**有专门的 I/O 命令但指令集有限**。
- **两段示例程序的共同点才是考点**：都有一条**往回跳**的分支，处理器**一直循环到数据可用**——这就是**忙等 / 轮询**；换编址方式治不了它。
- **2023 卷 Q2(b)（8 分）**：`INPR`/`OUTR` 各 8 位、`FGI`/`FGO`/`IEN` 各 1 位。**前四个寄存器 = 程序控制 I/O**：模块把字符放进 `INPR` 并置 `FGI`=1，处理器轮询 `FGI`，读走后清 0 通知模块可放下一个；输出方向处理器轮询 `FGO`=1，写 `OUTR` 并清 `FGO`=0，打完模块再置 1。**三个采分点**：标志位是握手（模块置 1、处理器清 0）；两个方向各有独立的数据寄存器与标志位；处理器靠轮询推进、设备就绪前只能忙等。**(ii) 用 `IEN` 改成中断驱动**，大批量场合进一步用 DMA。
- **2023 卷 Q2(d)（5 分）**：8 h = 28800 s，每 100 ms 一次 ⇒ **288,000 次**；有效比例 $60/288000 \approx 0.021\%$，**4800 次里才有 1 次有用**。**答"不是最优，改中断驱动"**，并补一句权衡：轮询的时延是确定的、代码简单，但本场合事件稀疏，确定性无价值而浪费 4800 倍。
- **中断九步**：硬件 **1 设备发中断 → 2 处理器把当前指令执行完 → 3 检测到中断并发应答（设备据此撤信号）→ 4 把 PSW 与 PC 压入控制栈 → 5 装入新 PC**；软件 **6 保存其余进程状态 → 7 处理中断 → 8 恢复进程状态 → 9 恢复旧 PSW 与 PC**。
  **两条易错**：**不是立刻响应，而是先执行完当前指令**（检查点在指令周期末尾）；**硬件只压 PSW 和 PC，其余寄存器由软件保存**。
- **两个设计问题**：**多个 I/O 模块时怎么知道是谁发的中断**；**多个中断同时发生时先处理哪个**。
- **设备识别四类**：**多条中断线**（最直截了当，但每条线上仍可能挂多个模块）；**软件轮询**（ISR 逐个问各模块，**很费时间**）；**菊花链**（中断应答线串过各模块，**向量 = 模块地址或唯一标识**，**向量中断让处理器直接找到设备服务程序，不必先跑通用 ISR**）；**总线仲裁**（模块**先取得总线控制权**才能拉中断请求线，处理器应答后模块**把向量放到数据线上**）。后两种都是向量式。
- **82C59A**：80386 只有**一条 INTR 和一条 INTA**；**一片 82C59A 管 8 个模块**，**级联最多管 64 个**（$8 \times 8$）。
- **2022 卷 Q2(d)（12 分，全卷最大的小题）**：设备 **8 KB/s = 8000 B/s**（取十进制。判据**不是** $8000/16=500$ 为整数——$8192/16=512$ 也是整数——而是取 8000 时三问答案才整洁：80% / 11.4% / 6.6%；按 8192 则是 81.92% / 11.67% / 6.76%。答卷上先把口径声明一句）。
  **(i) 每字节中断**：$8000 \times 100\ \mu s = \mathbf{80\%}$。
  **(ii) 16 字节缓冲、每字节搬 8 μs**：$500 \times (100 + 16\times8) = 500 \times 228\ \mu s = \mathbf{11.4\%}$。
  **(iii) 块传送指令、每字节 2 μs**：$500 \times (100 + 16\times2) = 500 \times 132\ \mu s = \mathbf{6.6\%}$。
  **四个坑**：(ii) 的 100 μs 要**加**不是换；**两个缓冲区不改变中断频率**（第二个是为了搬运期间不丢数据）；(i)→(ii) 省的是**固定开销的摊销**、(ii)→(iii) 省的是**每字节单价**；量纲算完应在 0 与 1 之间。
- **前两种办法的两个固有缺陷**：**I/O 速率受限于处理器测试与服务设备的速度**；**处理器被绑在传输管理上，每次传输都要执行若干条指令**。**数据量大时用 DMA。**
- **DMA**：在系统总线上多一个**能模仿处理器、甚至接管控制权**的模块。**只在处理器不需要总线时用，或强迫处理器暂时挂起**；**后者更常用，叫周期窃取**。**DMA 断点在各处理器周期之间（多个）；中断断点只有一个，在指令执行完之后。** **周期窃取不保存上下文、不跳转**，所以开销远小于中断。
- **处理器交给 DMA 的四样信息**：**读还是写**（走读/写控制线）、**I/O 设备地址**、**内存起始位置**（存入地址寄存器）、**字数**（存入数据计数寄存器）——**后三样都经数据线送**。
- **三种 DMA 配置**：**单总线分离式**、**单总线 DMA 与 I/O 集成**、**独立 I/O 总线**。
- **8237**：**HRQ/HLDA** 与 CPU 交接总线，**DREQ/DACK** 与设备握手，命令线 **IOR、IOW、MEMR、MEMW**；**四个通道，独立编程，任一时刻只有一个工作，编号 0–3**。**Fly-By**：**数据不经过也不存放在 DMA 芯片里**，**只能在 I/O 端口与内存之间搬**，**经寄存器可做内存到内存**。
- **DCA**：DMA 已跟不上网络 I/O 的数据率——**10 Gbps / 100 Gbps 以太网**与**千兆级 Wi-Fi**（3.2 Gbps、6.76 Gbps）是主要来源。
- **8255A**（从未考过，知道即可）：24 条 I/O 线分 A 口 8 位、C 口上下各 4 位、B 口 8 位；**A1 = A0 = 1 时数据总线上的值被当作控制字**（课件把 A0 误写成 A2）；**D7 = 1 的控制字用于配置这 24 条线的工作模式**。
