# L11 指令集的特征与功能（上）

> [!info] 这一讲的骨架
> 前十讲讲的是**机器怎么搭起来**——部件、总线、存储、I/O。从这一讲起换一个视角：**程序员怎么指挥这台机器**。
> 主线一句话：**指令集是硬件与程序员之间唯一的约定面。一条机器指令必须说清四件事——干什么、拿谁算、结果放哪、下一条在哪——而指令集设计的全部取舍，都发生在"一条指令里肯写几个地址"这个问题上。**
> **考情**：本讲属 **Q3 区**（指令集），和 [[L12 指令集的特征与功能（下）]]、[[L13 寻址方式与指令格式]]、L14 处理器结构与功能同属一题。课件末尾的三道 Sample Question 里，**第二问要求把一个算式分别用一、二、三地址指令写出来**——那是本讲唯一需要动笔算的考点，见[[#5 一条指令里放几个地址：本讲的考点\|§5]]。
> ⚠ 注意 **Sample Q2 给的算式是 C 加上 D 乘 E，比 §5.3 正文那条（A 减 B 的差再除以它）简单一截**，别把两者混成一道题；套路相同，但题目真考的时候很可能就是这种短式子。其余是概念题，按[[#本讲速记\|速记]]背即可。
> 课程总览见 [[00 课程信息与考情]]。对应课件 `L11_Instruction Set Characteristics and Function (Part1)--2026-27`，32 页（2026-27 新版）。

## 1 先把"机器指令"这个词落到实处

### 1.1 一条指令，拆开看就是一组控制位

课件开篇没有讲定义，而是直接给了一张数据通路图（第 6 页）。先看懂它，后面所有定义都会变得具体。

![[L11 机器指令就是一组控制位.png]]

图里这台极简机器有四个输入、三种运算电路、四个输出。要让它干一件事，只需要拨四组开关：

- **源一选哪个输入**（图里标 SRC1），四选一，所以需要 **2 位**；
- **源二选哪个输入**（SRC2），同样 2 位；
- **做哪种运算**（OP），加 / 减 / 乘三选一，2 位；
- **结果送到哪个输出**（DEST），四选一，2 位。

于是「把 In0 和 In3 相加、结果送到 Out2」这件事，对硬件来说就是 **`00 11 00 10` 这 8 个比特**；换成「把 In1 减去 In2、结果送到 Out3」，电路一根线都不用改，变的只是 **`01 10 01 11`**。

> [!tip] 这张图值得多看两眼
> 它把三件抽象的事一次说清了：
> 1. **指令不是"命令"，是控制位。** 处理器不"听懂"指令，它只是被这些比特拨到某个状态。
> 2. **操作码就是运算选择器的控制位**，**操作数字段就是源与目的选择器的控制位**。后面讲的"操作码字段""操作数字段"全是这个意思。
> 3. **能编出多少种指令，由字段宽度死死卡住。** 这里 OP 只有 2 位，所以这台机器最多只能有 4 种运算——不是设计者不想多给，是位不够。

### 1.2 指令集：唯一的约定面

有了上面的图，课件第 7 页那三句定义就不再空洞：

- 处理器的行为**完全由它执行的那些指令决定**，这些指令叫**机器指令**（machine instruction）或计算机指令。
- 一个处理器**能执行的全部不同指令的集合**，叫这个处理器的**指令集**（instruction set）。
- **每一条指令都必须自带处理器执行它所需的全部信息**——这句话就是下一节四个要素的来历。

为什么说它是"唯一的约定面"：硬件工程师可以随意改电路（流水线、超标量、多核，后面几讲全在讲这个），只要**同一串比特仍然产生同样的结果**，所有已有程序就照跑不误；反过来，程序员不需要知道芯片里有什么，只需要知道这串比特的含义。**指令集把两边解耦了**，这也是为什么它一旦定下来就极难改。

## 2 一条指令必须说清四件事

![[L11 一条指令要说清的四件事.png]]

### 2.1 四个要素

课件第 8–9 页给的四个**机器指令要素**（elements of a machine instruction）：

| 要素 | 英文 | 回答什么 | 实际写不写在指令里 |
| --- | --- | --- | --- |
| **操作码** | operation code, **opcode** | 执行哪个操作。这个操作由一个二进制码指定，这个码就叫操作码 | **总是写** |
| **源操作数引用** | source operand reference | 这个操作的**输入**是谁。可能有一个或多个 | **通常写** |
| **结果操作数引用** | result operand reference | 操作**产生的结果**放到哪 | **常被省掉** |
| **下一条指令引用** | next instruction reference | 这条执行完之后，**去哪取下一条** | **几乎总是省掉** |

后两个"省掉"不是偷工减料，而是**用约定代替字段**：

- **下一条指令**几乎总是"紧挨着的下一条"，所以不必每条都写——用**程序计数器**（PC）自动加一就够了（[[L05 计算机部件#3.2 四个寄存器，两对|L05 讲过 PC 这个寄存器]]）。只有**转移类指令**才需要显式给出下一条的地址，这也正是课件那张汇总表特意注明「**非转移指令**」的原因。
- **结果操作数**可以约定成"覆盖某一个源"，于是三个地址缩成两个。这一条正是[[#5 一条指令里放几个地址：本讲的考点|§5]] 的全部内容。

### 2.2 接回取指—执行循环

课件第 10 页又把 [[L05 计算机部件#4.4 把循环画成状态图|L05 那张指令周期状态图]]搬了出来，位置选得很好——因为**四个要素正好对应状态图里的四段**：

| 要素 | 对应状态图里的哪一段 |
| --- | --- |
| 下一条指令引用 | **指令地址计算 → 取指令**（`Instruction address calculation` → `Instruction fetch`） |
| 操作码 | **指令操作译码**（`Instruction operation decoding`） |
| 源操作数引用 | **操作数地址计算 → 取操作数**（可能要走多次，对应多个操作数） |
| 结果操作数引用 | **操作数地址计算 → 存操作数**（同样可能多次，对应多个结果） |

状态图里那两条标着 `Multiple operands` / `Multiple results` 的回环，和那条 `Return for string or vector data` 的回环，说的都是同一件事：**一条指令可能要访存好几次**。这是后面算执行时间时绕不开的。

### 2.3 操作数能从哪四个地方来

课件第 11–12 页。源操作数和结果操作数的**位置**只有四种可能：

| 位置 | 指令里要写什么 | 代价 |
| --- | --- | --- |
| **主存或虚存** | 必须给出**内存地址** | 地址长，字段占位多；还要一次访存 |
| **处理器寄存器** | 若有多个寄存器，每个有唯一的编号，指令里写**寄存器号** | 编号短（几位就够），且不访存，最快 |
| **立即数**（immediate） | **值本身就写在指令的某个字段里** | 不访存，但值的范围被字段宽度卡死 |
| **I/O 设备** | 必须指明是**哪个 I/O 模块、哪个设备** | 接 [[L10 输入输出#5.1 课件的 2×2 定位表\|L10 的两种编址方式]]：内存映射时这一类并入第一行 |

> [!note] 四个位置的顺序不是随便排的
> 从上到下，**离处理器越来越近**：主存要走总线，寄存器在片内，立即数干脆就在指令里。这解释了为什么寄存器数量是指令集设计的核心议题之一（见[[#6 设计一套指令集，要定哪五件事|§6]]）——**寄存器多一个，就多一个不必访存的操作数位置**，但指令里的寄存器号字段也要跟着变宽。

## 3 指令长什么样：从比特到助记符

同一条指令有两层外观，课件第 13–15 页讲的就是这两层。

### 3.1 比特层：字段宽度决定了这台机器的上限

**计算机内部，每条指令都是一串比特。** 课件给的简单格式是 16 位：

| 字段 | 宽度 | 这个宽度意味着什么 |
| --- | --- | --- |
| 操作码 | **4 位** | $2^4 = 16$，这台机器**最多只能有 16 种操作** |
| 操作数位置 | **6 位** | $2^6 = 64$，每个操作数**最多只能指向 64 个位置** |
| 操作数位置 | **6 位** | 同上 |

课件只说了"这是一个简单例子，多数指令集会用不止一种格式"，但上面这两行推论是本讲真正的分量所在：**字段宽度不是版式问题，它是硬约束**。想多要几种操作，就得从操作数字段里借位，于是能寻址的范围立刻缩水。**"用不止一种格式"正是为了绕开这个矛盾**——这件事要到 [[L13 寻址方式与指令格式]] 才展开。

### 3.2 符号层：助记符与符号化操作数

直接写比特没法干活，所以有了符号写法：

- **操作码用缩写表示，这种缩写叫助记符**（mnemonic）。课件列的常见几个：`ADD` 加、`SUB` 减、`MUL` 乘、`DIV` 除、`LOAD` 从内存取数、`STOR` 存数到内存。
- **操作数也用符号表示**，**每个符号操作数都有一个固定的二进制表示**，**由程序员指定每个符号操作数的位置**。

于是同一条指令有了两副面孔：程序员写 `ADD R, Y`，机器看到的是一串比特。**把前者翻译成后者的那个程序就是汇编器**；课件标题里的「Assembly Code vs Machine Code」指的就是这一层对应关系。

## 4 指令分四类

### 4.1 高级语言的一行，机器要几条

课件第 16 页的例子：高级语言写 `X = X + Y`，其中 X、Y 分别在内存的 **513** 和 **514** 号位置。机器要用**三条**指令完成：

1. 把 **513** 号位置的内容**装进一个寄存器**；
2. 把 **514** 号位置的内容**加到这个寄存器上**；
3. 把寄存器的内容**存回 513** 号位置。

课件的结论是：**一条高级语言语句需要三条机器指令。** 这件事 [[L05 计算机部件#4.3 一台假想机器，把循环跑一遍|L05 用一台假想机器跑过一遍]]，这里是同一个现象的第二次出现，可以互相印证。

值得单独记住的是课件第 17 页那组对照：

- **高级语言**用**变量**，以**简洁的代数形式**表达操作；
- **机器语言**只能表达**最基本的形式，即数据往返于寄存器的搬运**；
- 任何高级语言程序**必须被翻译成机器语言才能执行**；
- 因此**机器指令集必须足够完备，能表达高级语言里的任何一条语句**。

最后这一句是指令集设计的底线要求：**不是"够用就好"，而是"必须能表达一切"。**

### 4.2 四个类别

课件第 18 页把指令归成四类：

| 类别 | 英文 | 是什么 |
| --- | --- | --- |
| **数据处理** | data processing | **算术与逻辑指令** |
| **数据存储** | data storage | **数据在寄存器与内存位置之间的搬入搬出** |
| **数据传送** | data movement | **I/O 指令** |
| **控制** | control | **测试与转移指令** |

> [!warning] 这四类和 L05 那四类是同一套，但第二、三类的中文名极易记反
> [[L05 计算机部件#4.2 指令能做的事只有四类|L05 讲过同样的四类]]。这里要当心课件用词：**data storage 说的是"存储"，指内存与寄存器之间；data movement 说的是"传送"，指的是 I/O。**
> 按字面直觉很容易把 movement 理解成内存搬运——**记法是盯住英文后面那半句**：storage 配的是 register / memory，movement 配的是 I/O。

## 5 一条指令里放几个地址：本讲的考点

![[L11 一条指令里放几个地址.png]]

### 5.1 最多需要几个地址

课件第 19 页先问：**一条指令最多可能需要几个地址？** 推理是这样的：

- **算术与逻辑指令需要的操作数最多**，所以按它来算上限；
- 源操作数**最多两个**，于是要两个地址；
- **结果必须存起来**，于是要第三个地址，指向目的操作数；
- 执行完还要**取下一条指令**，于是还要它的地址。

所以理论上限是**四个**。但实际上**下一条指令的地址几乎总是隐含的，由程序计数器给出**，于是真正写进指令的是**一个、两个或三个**。

### 5.2 四种地址数的汇总

课件第 21 页那张表（标题是「非转移指令的指令地址用途汇总」）是本讲最该背下来的一页：

| 地址个数 | 写法 | 含义 | 谁被隐含了 |
| --- | --- | --- | --- |
| **3** | `OP A, B, C` | A 得到 B 与 C 运算的结果 | 只隐含了下一条指令 |
| **2** | `OP A, B` | A 得到 A 与 B 运算的结果 | **目的与一个源合并**，A 被覆盖 |
| **1** | `OP A` | 累加器得到累加器与 A 运算的结果 | **另一个源与目的都隐含成累加器** |
| **0** | `OP` | 栈顶得到次栈顶与栈顶运算的结果 | **两个源与目的全部隐含成栈** |

表下的符号约定也要记：**AC 是累加器**（accumulator），**T 是栈顶**（top of stack），**T − 1 是栈里的第二个元素**，**A、B、C 是内存或寄存器位置**。

> [!tip] 一句话串起这张表
> **从 3 到 0，每少写一个地址，就多一条"默认用哪儿"的约定。** 三地址什么都说明白；二地址约定"目的就是第一个源"；一地址约定"另一个源和目的都是累加器"；零地址约定"操作数就在栈顶那两个"。**省下的是指令长度，付出的是灵活性。**

### 5.3 同一个算式，三种写法

课件第 20 页用同一个算式给出三段程序。算式是：**A 减 B 的差，除以 C 加上 D 乘 E 的和**。

**三地址，4 条**：

```
SUB  Y, A, B      ; Y ← A − B
MPY  T, D, E      ; T ← D × E
ADD  T, T, C      ; T ← T + C
DIV  Y, Y, T      ; Y ← Y ÷ T
```

**二地址，6 条**。因为不能再写第三个地址，凡是"不想破坏源操作数"的地方都得先搬一次，于是多出两条 `MOVE`：

```
MOVE Y, A         ; Y ← A
SUB  Y, B         ; Y ← Y − B
MOVE T, D         ; T ← D
MPY  T, E         ; T ← T × E
ADD  T, C         ; T ← T + C
DIV  Y, T         ; Y ← Y ÷ T
```

**一地址，8 条**。只剩一个累加器 AC 可用，每算完一段都得腾地方：

```
LOAD D            ; AC ← D
MPY  E            ; AC ← AC × E
ADD  C            ; AC ← AC + C
STOR Y            ; Y  ← AC        ← 先把分母存起来
LOAD A            ; AC ← A
SUB  B            ; AC ← AC − B
DIV  Y            ; AC ← AC ÷ Y    ← 再把它当除数用
STOR Y            ; Y  ← AC
```

> [!warning] 一地址那段里有个容易看漏的细节
> **Y 被当成了临时变量用。** 第 4 条先把分母 $C + D\times E$ 存进 Y，第 7 条又把 Y 当除数读出来，最后一条才把真正的结果写回 Y。
> 考试里若让你自己写一地址程序，**"先算哪一半"不是随便选的**：必须先算**要当除数（或减数）的那一半**并存起来，因为累加器只有一个，后算的那一半必须留在 AC 里当被除数。顺序搞反就得多花两条指令来回倒。

### 5.4 取舍：字段省下来，条数还回去

把上面三段并排看，规律很清楚：**4 条 → 6 条 → 8 条**。

- **地址字段越多**：单条指令**越长**，但**同一件事需要的指令条数越少**，而且程序更直观。
- **地址字段越少**：单条指令**越短**，但**条数越多**，还会多出一堆纯搬运的 `MOVE` / `LOAD` / `STOR`。

两头都要占存储空间和总线带宽，所以**这是取舍，不是优劣**。真实机器通常**混着来**：常用操作给少地址的短格式，偶尔用的给多地址的长格式——这正是 [[L13 寻址方式与指令格式]] 要讲的"变长指令格式"。

> [!warning] 课件这一节缺了一页
> 第 19、20 页标的是「Number of Addresses (1 of 4)」「(2 of 4)」，**下一页直接跳到了「(4 of 4)」——(3 of 4) 那页不在这份 PDF 里**（2026-27 版核对过，确实没有）。
> 从编号推测，缺的那页多半是零地址（栈）写法的程序示例。**影响不大**：零地址的规则在 (4 of 4) 的汇总表里写着，上面那三段程序也够用了。但如果考到"用零地址指令写出这个算式"，课件里确实没有现成范例，需要自己按栈的规则推（先把操作数依次压栈，再用无地址的 `OP` 取栈顶两个）。

## 6 设计一套指令集，要定哪五件事

课件第 22–23 页。先是四句话说明**为什么这件事难**：

- 指令集的设计**影响计算机系统的方方面面，所以非常复杂**；
- 指令集**定义了处理器要完成的许多功能**，因而**对处理器的实现有重大影响**；
- 指令集是**程序员控制处理器的手段**；
- 因此**设计时必须考虑程序员的需求**。

然后给出五个**基本设计议题**（这一节同样缺页：第 22 页标 (1 of 3)、第 23 页标 (2 of 3)，而 **(3 of 3) 不在这份 PDF 里**，下一页直接是「操作数的类型」。五个议题本身在 (2 of 3) 已给全，不影响）：

| 议题 | 英文 | 要定什么 |
| --- | --- | --- |
| **操作集合** | operation repertoire | **提供多少条、哪些操作，单条操作该做到多复杂** |
| **数据类型** | data types | **操作作用在哪几种数据上**（正是[[#7 操作数的四种数据类型\|§7]] 的内容） |
| **指令格式** | instruction format | **指令多长（多少位）、放几个地址、各字段多宽** |
| **寄存器** | registers | **有多少个可被指令引用的寄存器，各自怎么用** |
| **寻址** | addressing | **用哪种或哪几种方式指定操作数的地址** |

> [!note] 这五条就是后面三讲的提纲
> 「操作集合」和「数据类型」是 [[L12 指令集的特征与功能（下）]] 的内容，「指令格式」和「寻址」是 [[L13 寻址方式与指令格式]] 的内容，「寄存器」要到 L14 处理器结构与功能。
> 其中**单条操作该做到多复杂**这一句是整条 RISC 与 CISC 之争的种子——它问的是：该给一条又长又全能的指令，还是给几条又短又简单的指令？

## 7 操作数的四种数据类型

课件第 24 页：**机器指令作用在数据上**，最重要的数据类别有四种——**地址**（addresses）、**数**（numbers）、**字符**（characters）、**逻辑数据**（logical data）。

地址在本讲不展开（它本质上是一种无符号整数，真正的内容在 [[L13 寻址方式与指令格式]]）。下面三种各说一节。

### 7.1 数：计算机里的数是"受限的"

**所有机器语言都包含数值数据类型。** 课件第 25 页强调了一个区别：**数学里的数和计算机里的数，最大的不同是后者受限**——

- **可表示的数值大小有上限**；
- **浮点数还额外受限于精度**。

这两句话 [[L02 数制#3.6 位宽陷阱：补码的值离不开位宽|L02 从位宽的角度]]和 [[L02 数制#4.2 浮点：把编码非均匀地重新分配|从编码分配的角度]]都已经讲透，这里只是在指令集的语境下重申一次。

计算机里常见的**三种数值数据**（课件第 26 页）：

| 类型 | 英文 | 在 L02 的出处 |
| --- | --- | --- |
| **二进制整数 / 二进制定点** | binary integer / binary fixed point | [[L02 数制#4.1 定点：编码均匀铺开\|定点]] |
| **二进制浮点** | binary floating point | [[L02 数制#4.3 IEEE-754 单精度：每个字段都能倒推出理由\|IEEE-754]] |
| **十进制** | decimal | 下一小节 |

### 7.2 十进制为什么还要单独留一套

这是本讲少有的、L02 没覆盖的新东西（课件第 27 页）：

- **对于比较简单的计算，把数直接以十进制存储和运算反而更合适**；
- 最常用的表示叫**压缩十进制**（packed decimal）；
- **每个十进制数字用一个 4 位码表示**：0 = `0000`、1 = `0001`、……、8 = `1000`、9 = `1001`；
- 例如 **246 的编码是 `0000 0010 0100 0110`**；
- **许多机器提供直接对压缩十进制做运算的算术指令**，这样可以**省掉转换的开销**。

> [!tip] 为什么"简单计算反而用十进制更划算"
> 想想一台收银机或一份财务报表：数据从十进制输入来，结果又要以十进制输出去，中间的加减次数却很少。
> 若用二进制：**转进来一次、转出去一次**，转换的代价可能比运算本身还大，而且 [[L02 数制#4.2 浮点：把编码非均匀地重新分配|十进制小数在二进制里往往不能精确表示]]（0.1 就是典型），会引入舍入误差——对钱来说这是不可接受的。
> 用压缩十进制则**一次都不用转**，每个数字占 4 位、刚好半个字节，存储也不算浪费。**判据是"运算次数 vs 转换次数"，不是"哪种更快"。**

> [!warning] 课件这页有一处笔误
> 原文把 0 的编码写成了 **`0 = 000`**，只有三位。按同页自己的规则（每个十进制数字用 **4 位**）以及后面 246 的例子，**应该是 `0000`**。
> 顺带解释一下那个例子：246 只有三个数字，本该是 `0010 0100 0110`（12 位）；课件写成 `0000 0010 0100 0110`（16 位），是**在前面补了一个 0 把长度凑成整字节**——这是压缩十进制的常规做法，不是写错。

### 7.3 字符：IRA 与 ASCII

课件第 28 页：

- **文本或字符串是一种常见的数据形式**；
- 但**字符形式的文本没法被数据处理与通信系统直接存储或传输，因为这些系统是为二进制数据设计的**——所以必须编码；
- 最常用的字符编码是**国际参考字母表**（International Reference Alphabet, **IRA**），**在美国称为 ASCII**；
- **这套编码里每个字符用一个唯一的 7 位模式表示，因此能表示 128 个不同的字符**。

[[L02 数制#5.1 ASCII：把结构编进编码里|L02 讲过 ASCII 的内部结构]]——数字的低四位就是它的值、大小写只差一个比特，这些性质在写字符处理程序时能省掉查表。这里只补一点：**IRA 和 ASCII 是同一套编码的两个名字**，考试里两个词都可能出现。

### 7.4 逻辑数据：把一个单元当成 n 个独立的位

课件第 29 页。平常**一个字（或字节、半字等可寻址单元）被当作一个整体看待**；但**有时把一个 n 位单元看成 n 个各自独立的 1 位数据项**更有用，每一项只取 0 或 1。这样看待的数据就叫**逻辑数据**。

这么看有**两个好处**：

1. **存储最省**。若要存一个布尔数组，每项只有真（1）与假（0）两种取值，**按位存比按字节或按字存省得多**——32 个布尔值挤进一个字，而不是占 32 个字节。
2. **有时就是要操作数据项里的某些位**。课件给的例子：**如果浮点运算是用软件实现的，就必须能在某些步骤里移动有效位**。

> [!note] 同一串比特，含义由解释规则给定
> 这一节其实是 [[L02 数制#3.7 位串的意义由解释规则给定|L02 那条结论]]在指令集层面的落点：**同样 32 个比特，可以是一个整数、一个浮点数、四个字符，也可以是 32 个布尔值。** 决定它是什么的不是比特本身，而是**你用哪条指令去处理它**。
> 所以指令集必须同时提供算术指令和**按位逻辑指令**（与、或、异或、移位），两套指令作用在同一块内存上，只是解释方式不同。

## 本讲速记

- **指令集是硬件与程序员之间唯一的约定面**：硬件怎么改都行，只要同一串比特产生同样结果，程序就照跑；程序员不必知道芯片里有什么。所以指令集一旦定下极难改。
- **一条机器指令实质上就是一组控制位**。课件那张四输入、三运算、四输出的数据通路图里，`SRC1 | SRC2 | OP | DEST` 各 2 位，合起来 8 位就是一条指令。**操作码即运算选择器的控制位，操作数字段即源与目的选择器的控制位。**
- **处理器的行为完全由它执行的指令决定**；**能执行的全部不同指令的集合叫指令集**；**每条指令必须自带执行所需的全部信息**。
- **一条指令的四个要素**：**操作码**（干哪件事，由一个二进制码指定）、**源操作数引用**（输入是谁，可能一个或多个）、**结果操作数引用**（结果放哪）、**下一条指令引用**（接着取哪一条）。**后两个常被省掉，用约定代替字段**——下一条由**程序计数器**给出，结果常约定覆盖某个源。
- **四要素正好对应指令周期状态图的四段**：取指、译码、取操作数、存操作数。状态图里的 `Multiple operands` / `Multiple results` / `Return for string or vector data` 三条回环说明**一条指令可能访存多次**。
- **操作数只可能在四个地方**：**主存或虚存**（要写地址）、**处理器寄存器**（多个寄存器时要写编号）、**立即数**（值直接写在指令的字段里）、**I/O 设备**（要指明哪个模块哪个设备）。顺序是离处理器越来越近。
- **比特层**：课件的简单格式是 **16 位 = 4 位操作码 + 6 位 + 6 位操作数**。**4 位 ⇒ 最多 16 种操作；6 位 ⇒ 最多指向 64 个位置。字段宽度是硬约束，不是版式问题。** 多数指令集用不止一种格式，就是为了绕开这个矛盾。
- **符号层**：**操作码的缩写叫助记符**（`ADD` `SUB` `MUL` `DIV` `LOAD` `STOR`）；**操作数也符号化，每个符号操作数有固定的二进制表示，位置由程序员指定**。
- **高级语言一行 ≠ 机器一条**：`X = X + Y`（X 在 513、Y 在 514）要三条——**取 513 进寄存器 → 把 514 加上去 → 存回 513**。机器语言只能表达**数据往返寄存器的搬运**，但**指令集必须完备到能表达高级语言的任何一条语句**。
- **指令分四类**：**数据处理**＝算术与逻辑；**数据存储**＝寄存器与内存之间的搬入搬出；**数据传送**＝ **I/O 指令**；**控制**＝测试与转移。⚠ 第二、三类的中文名极易记反，**盯英文后半句**：storage 配 register/memory，movement 配 I/O。
- **一条指令最多需要四个地址**（两个源、一个目的、一个下一条），但**下一条几乎总是隐含（由 PC 给出）**，所以实际是 1～3 个。
- **地址数汇总表**（非转移指令）：**3 个** `OP A, B, C` → A 得到 B 与 C 的结果；**2 个** `OP A, B` → A 得到 A 与 B 的结果（A 被覆盖）；**1 个** `OP A` → **AC** 得到 AC 与 A 的结果；**0 个** `OP` → **T** 得到 **(T−1)** 与 T 的结果。**AC = 累加器，T = 栈顶，T−1 = 栈里第二个元素，A/B/C = 内存或寄存器位置。**
- **从 3 到 0，每少写一个地址就多一条约定**。省下的是指令长度，付出的是灵活性。
- **同一个算式（A 减 B 的差，除以 C 加 D 乘 E 的和）**：**三地址 4 条、二地址 6 条、一地址 8 条**。二地址多出的是 `MOVE`（因为不能不破坏源）；一地址多出的是 `LOAD`/`STOR`（因为只有一个累加器）。
- **一地址那段的关键**：**Y 被当成临时变量**——先算分母存进 Y，再算分子留在 AC，最后 `DIV Y`。**必须先算要当除数的那一半**，顺序反了要多花指令。
- **取舍**：地址多 ⇒ 指令长、条数少、直观；地址少 ⇒ 指令短、条数多、多出纯搬运指令。**两头都占存储与带宽，是取舍不是优劣。**
- **指令集设计的五个议题**：**操作集合**（多少条、哪些、单条多复杂）、**数据类型**、**指令格式**（长度、地址个数、字段宽度）、**寄存器**（多少个、怎么用）、**寻址**（用哪几种方式给出操作数地址）。
- **四类数据**：**地址、数、字符、逻辑数据**。
- **数有三种**：**二进制整数（定点）、二进制浮点、十进制**。计算机里的数**受限**：**大小有上限**，**浮点还受精度限制**。
- **压缩十进制**：**每个十进制数字用 4 位**（0 = `0000` … 9 = `1001`），**246 编码为 `0000 0010 0100 0110`**（前面补 0 凑整字节）。**许多机器有直接对它运算的指令，省掉转换开销。** 适用判据是**运算次数少而转换次数多**的场合。⚠ 课件把 0 写成了三位的 `000`，是笔误。
- **字符**：最常用编码是 **IRA（国际参考字母表），在美国叫 ASCII**；**每字符一个唯一的 7 位模式，共 128 个字符**。文本必须编码，因为数据处理与通信系统是为二进制设计的。
- **逻辑数据**：把一个 n 位单元看成 **n 个独立的 1 位数据项**。两个好处——**存布尔数组时内存最省**；**有时就是要操作其中某些位**（课件例子：浮点运算若用软件实现，需要移动有效位）。
- **同一串比特是什么，由你用哪条指令处理它决定**，不由比特本身决定。
