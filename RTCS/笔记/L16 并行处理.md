# L16 并行处理

> [!info] 这一讲的骨架

## 1 并行处理器的四类组织

### 1.1 按指令流与数据流分四类

分类看的是两个维度（课件第 4–5 页）。**指令流**（instruction stream）是一个控制单元依次发出的指令序列，**数据流**（data stream）是这些指令处理的数据序列（这两句定义是我补的，课件直接用了这两个词）。两者各取"单个"或"多个"，就得到四类——这套分法通常叫 Flynn 分类（课件没有提这个名字）：

| 类别 | 全称 | 课件的定义 | 属于这一类的 |
| --- | --- | --- | --- |
| **SISD** | single instruction, single data stream | **单个处理器执行单个指令流，处理存放在单个存储器里的数据** | **单处理器**（uniprocessor） |
| **SIMD** | single instruction, multiple data stream | **一条机器指令控制许多处理单元同时执行** | **向量处理器与阵列处理器** |
| **MISD** | multiple instruction, single data stream | **一串数据被送给一组处理器，每个处理器执行不同的指令序列** | **没有商业实现** |
| **MIMD** | multiple instruction, multiple data stream | **一组处理器同时在不同的数据集上执行不同的指令序列** | **SMP、集群和 NUMA** |

SIMD 那一行的"许多处理单元同时执行"，意思是同一条指令同时作用在许多份数据上，每个处理单元处理其中一份；向量处理器一条指令处理一整组数据（一个向量），阵列处理器由许多处理单元排成阵列、在同一条指令下各算各的数据（这几句是我按定义解释的，课件没有展开）。MIMD 那一行的集群与 NUMA，见 [[#1.2 MIMD 再往下分：共享存储与分布式存储|MIMD 的两支]]。

### 1.2 MIMD 再往下分：共享存储与分布式存储

课件第 6 页的分类树（教材图 17.1）把 MIMD 再分两支：

- **共享存储**（shared memory），也叫**紧耦合**（tightly coupled）：下面有**对称多处理器**（symmetric multiprocessor, SMP）和**非一致存储访问**（nonuniform memory access, NUMA）。
- **分布式存储**（distributed memory），也叫**松耦合**（loosely coupled）：下面是**集群**（clusters）。

紧耦合、松耦合说的是处理器之间靠什么联系：紧耦合的处理器共用一个存储器，松耦合的各有各的存储器、要经网络交换数据（这句是我补的）。

课件对共享存储的说明是：**如果处理器共享一个公共存储器，每个处理器就访问存放在这个共享存储器里的程序和数据，处理器之间也通过这个存储器通信；这类系统最常见的形式就是 SMP。**

NUMA 与集群课件只给了名字。NUMA 的每个处理器都能访问整个主存，但访问主存不同区域所花的时间不一样——"非一致"指的就是访问时间（这句是我补的）；SMP 正相反，每个处理器访问主存的时间大致相同（见 [[#2.1 五个特征|SMP 的五个特征]]）。集群按 Stallings 第 11 版配套幻灯片上的定义，是一组互连起来、作为一个统一的计算资源一起工作的完整计算机；2022 卷 Q4(b) 那个"九机集群"说的就是它。

### 1.3 四种组织的框图

![[L16 四种组织的框图.png]]

课件第 7 页把四种组织画成框图（上图按课件重画）。图里的缩写：**CU** 控制单元（control unit），**IS** 指令流（instruction stream），**PU** 处理单元（processing unit），**DS** 数据流（data stream），**MU** 存储单元（memory unit），**LM** 本地存储器（local memory）。课件的结论是：**MIMD 有多个控制单元，每个控制单元把一条独立的指令流送给自己的 PU；MIMD 可以是共享存储的多处理器（multiprocessor），也可以是分布式存储的多计算机（multicomputer）。** 多计算机指一组各带自己存储器、彼此经网络通信的计算机（这句是我补的）。

图里能看出两个区别：SIMD（课件画的是分布式存储的 SIMD）只有一个 CU，所有 PU 收到的是同一条指令流，各自处理自己本地存储器里的数据；MIMD 有 n 个 CU，指令流也就有 n 条。两种 MIMD 的区别在存储器：共享存储时所有 PU 连着同一个存储器，分布式存储时每个 PU 只直接连自己的本地存储器，彼此之间要经互连网络交换数据。

### 1.4 真题现场：2023 卷 Q4(b) 四类并行处理器

> (b) There are four common categories in grouping systems with parallel processing capability. List any three of these categories. [3]

这道题和 Sample Question 第一问（"What are four different types of parallel processor systems"）几乎同题，只要求列出任意三类。

**答案**（题目要求任列三类）：

- **Single instruction, single data (SISD) stream**
- **Single instruction, multiple data (SIMD) stream**
- **Multiple instruction, single data (MISD) stream**
- **Multiple instruction, multiple data (MIMD) stream**

题目只要求"列出"。每类后面再加一句定义或例子（如 SISD 是单处理器、SIMD 有向量与阵列处理器、MISD 没有商业实现、MIMD 包括 SMP、集群与 NUMA），是理解用。

## 2 对称多处理器（SMP）

### 2.1 五个特征

课件第 8 页：SMP 是**一台独立的计算机**，具有以下特征——

1. **有两个或更多能力相当的同类处理器**；
2. **这些处理器共享同一个主存**，**通过总线或其他内部连接相连**，**每个处理器访问主存的时间大致相同**；
3. **所有处理器共享对 I/O 设备的访问**；
4. **所有处理器都能执行同样的功能**——**"对称"这个名字就是从这里来的**；
5. **整个系统由一个集成的操作系统控制**，**它提供处理器与它们的程序之间的交互**。

### 2.2 相比单处理器的四个潜在优点

课件第 9–10 页：SMP 组织相比单处理器组织，有几项潜在的优点——

- **性能**（performance）：**如果计算机要做的工作能组织成其中一些部分可以并行地做，有多个处理器的系统就比只有一个同类处理器的系统性能更高。**
- **可用性**（availability）：**一个处理器坏了不会让整台机器停下来，系统还能以降低了的性能继续工作。**
- **增量扩展**（incremental growth）：**用户可以加一个处理器来提升系统性能。**
- **按规模分档**（scaling）：**厂商可以按系统里配置的处理器个数，推出价格与性能各不相同的一系列产品。**

第 9 页在"性能"那一条旁边配了一张图，对比两种情形，图里每个进程的时间线分成运行（running）与阻塞（blocked）两种状态（见 [[L04 操作系统概述#9.1 五个状态|L04 的五个进程状态]]）：(a) 单处理器的多道程序设计（见 [[L04 操作系统概述#2 这层假象是被逼出来的|L04 的多道程序设计]]），三个进程轮流运行，任一时刻只有一个在跑，叫**交替**（interleaving）；(b) 两个处理器的多处理，两个进程可以同时运行，叫**交替加重叠**（interleaving and overlapping）。图里没在运行的时段一律画成阻塞，就绪、等处理器的时段也算在里面，没有单独画（这句是我补的）。

第 10 页还写了：**由操作系统负责把线程或进程调度到各个处理器上，并负责处理器之间的同步**（线程与进程的区别见 [[L04 操作系统概述#8.3 程序、进程、任务、线程|L04 的程序、进程、任务、线程]]）。同一页还有一张利弊表：

| 优点 | 缺点 |
| --- | --- |
| 能执行的进程更多 | 进程的执行调度更复杂 |
| 一个处理器出了问题，另一个处理器可以接着执行这个进程 | 所有处理器连着同一个存储器，会影响总线取数据 |
| 可以加处理器来增强系统 | 多处理器比单处理器贵 |

### 2.3 组织：每个处理器自成一体

课件第 11 页的框图：几个处理器、几个 I/O 模块和主存都挂在一个**互连网络**（interconnection network）上。要点是——

- **有两个或更多处理器**，**每个处理器都自成一体**，**有自己的控制单元、ALU、寄存器，通常还有一级或多级 Cache**；
- **每个处理器都能访问共享的主存和 I/O 设备**；
- **处理器之间可以通过存储器通信**（**把消息和状态信息留在公共的数据区里**），**也可以直接交换信号**；
- **存储器常常组织成能同时访问不同的存储块**。

### 2.4 最常见的做法：分时共享总线

课件第 12 页：**个人计算机、工作站和服务器最常见的组织是分时共享总线**（time-shared bus），**这是构建多处理器系统最简单的办法**。课件的图里，每个处理器带 L1、L2 两级 Cache，与主存、I/O 子系统一起挂在一条共享总线上。**总线由控制线、地址线和数据线组成**，**结构和接口与单处理器系统用的分时共享总线相同**（三组线见 [[L06 计算机互连#2.2 三组线|L06 的三组线]]）。

第 13 页列了这条总线**为方便 I/O 子系统与处理器之间的 DMA 传送**而提供的三项功能（这一页的标题写的是 "Direct Memory Access Attractive Features"，内容讲的是总线的功能；DMA 见 [[L10 输入输出#8 直接内存访问|L10 的直接内存访问]]）：

- **寻址**（addressing）：**必须能区分总线上的各个模块，以确定数据的来源和去向**；
- **仲裁**（arbitration）：**任何一个 I/O 模块都可以临时充当"主控方"**，**要有一套机制按某种优先级方案裁决对总线控制权的竞争请求**（仲裁方式见 [[L06 计算机互连#3 总线设计的五个维度|L06 的总线设计五维度]]）；
- **分时**（time-sharing）：**一个模块控制总线时，其他模块被锁在外面，必要时要暂停操作，直到拿到总线**。

第 14 页是总线组织的三个优点：

- **简单**：**每个处理器的寻址、仲裁和分时逻辑都和单处理器系统里一样**；
- **灵活**：**往总线上多挂处理器，一般就能很容易地扩展系统**；
- **可靠**：**总线本质上是无源的介质**，**挂在上面的任何一个设备坏了，都不应导致整个系统失效**。

第 15 页是它的缺点，**主要在性能**：**所有的访存都要经过这条公共总线**，**性能受总线周期时间的限制**。为了提高性能，**可以给每个处理器配一个 Cache，减少访问总线的次数**；**但这样一来，一个 Cache 里改了一个字，可能让另一个 Cache 里的同一个字失效**——**这就是缓存一致性问题**（cache coherence problem）。**为了防止它，必须让其他处理器知道发生了更新**；**这通常靠硬件解决，而不是靠操作系统**。[[L09 高速缓存#7.2 还有两个更麻烦的问题|L09 讲写策略时]]已经点过这个问题，解法见 [[#4 缓存一致性|缓存一致性]]一节。

## 3 多处理器操作系统的设计考虑

课件第 16 页先交代总的要求：

- **SMP 的操作系统管理处理器和其他资源，让用户觉得是一个操作系统在控制系统资源**；
- **可以同时有多个作业或进程处于活动状态，由操作系统负责调度它们的执行、分配资源**；
- **用户可以写使用多个进程、或在进程里使用多个线程的应用，不必管有一个还是多个处理器可用**；
- **多处理器操作系统必须提供多道程序系统的全部功能，再加上为适应多个处理器而增加的功能**。

第 17–19 页列了五个设计考虑：

| 考虑 | 课件的要求 |
| --- | --- |
| **同时并发的进程**（simultaneous concurrent processes） | **操作系统的例程必须可重入**（reentrant）：**允许多个处理器同时执行程序的同一部分**；**操作系统本身和各种管理结构必须管理得当，以免死锁或非法操作** |
| **调度**（scheduling） | **任何一个处理器都可能执行调度，所以要避免冲突**；**调度程序必须把就绪的进程分派给可用的处理器** |
| **同步**（synchronization） | **多个活动进程都可能访问共享的地址空间或 I/O 资源，必须注意提供有效的同步** |
| **存储管理**（memory management） | **除了处理单处理器机器上的全部问题，操作系统还要利用硬件提供的并行性来获得最好的性能** |
| **可靠性与容错**（reliability and fault tolerance） | **处理器出故障时，操作系统应当平稳降级**；**调度程序和操作系统的其他部分必须能识别出少了一个处理器，并相应地重新组织** |

"平稳降级"课件写作 agile degradation，Stallings 第 11 版配套幻灯片上写的是 graceful degradation，指坏掉一部分后整体还能以较低的性能继续工作，与 [[#2.2 相比单处理器的四个潜在优点|SMP 的可用性]]说的是同一件事（这句对照是我补的）。同步要防的是什么，[[Lab3 任务、内存与队列#4.1 为什么不能图省事用全局变量|Lab 3 讲的全局变量竞态]]是一个现成的例子：两个任务共用一个全局变量，一个写到一半被切走，另一个就会读到半新半旧的值。那是单处理器上被抢占造成的；多处理器上两个处理器能真正同时访问，不用切换也会出这种问题（这个例子和后半句是我补的）。

## 4 缓存一致性

### 4.1 问题从哪里来

课件第 20 页：**为了获得合理的性能，通常给每个处理器配一到两级 Cache。** **同一份数据可能同时在不同的 Cache 里各有副本，如果允许处理器随意更新自己的那份，就会出现不一致的存储视图。**

这一页的两张示意图画的就是这种情形：左图里 P1、P3、Pn 的 Cache 与主存都存着 X；右图里 P1 把自己那份改成了 X1，P3、Pn 的 Cache 和主存里还是旧的 X（两张图里 P2 的 Cache 都没有 X）。

第 21 页回顾了单处理器里的两种写策略（详见 [[L09 高速缓存#7.3 两种策略|L09 的写直达与写回]]）：**写回**（write back）——**写操作通常只做在 Cache 里，只有这一行被换出 Cache 时才更新主存**；**写直达**（write through）——**所有写操作在写 Cache 的同时也写主存，保证主存总是有效的**。课件的结论是：**写回策略显然会导致不一致。**

写直达也不能单独解决问题：它只保证主存是新的，别的 Cache 里那份副本照样是旧的。所以不管用哪种写策略，都需要 [[#4.2 软件办法|软件办法]]或 [[#4.3 硬件办法：目录协议与监听协议|硬件协议]]来维持一致（这两句是我补的）。

### 4.2 软件办法

课件第 22 页：软件办法**想避免额外的硬件电路和逻辑**，**靠编译器和操作系统来处理这个问题**。它的吸引力在于：**检测潜在问题的开销从运行时转移到了编译时，设计的复杂度从硬件转移到了软件**。具体做法——

- **基于编译器的一致性机制分析代码，找出哪些数据项缓存起来可能不安全，并做上标记**；
- **然后由操作系统或硬件阻止这些不可缓存的数据项被放进 Cache**——**这样做太保守**；
- **更高效的做法是分析代码，为共享变量找出可以安全缓存的时段**。

### 4.3 硬件办法：目录协议与监听协议

课件第 23 页：硬件办法**一般叫作缓存一致性协议**（cache coherence protocols），**分成两类：目录协议**（directory protocols）**和监听协议**（snoopy protocols）。这就是 Sample Question 第三问要的两种协议，做法分别见 [[#4.4 目录协议|目录协议]]与 [[#4.5 监听协议：写更新与写作废|监听协议]]。

### 4.4 目录协议

课件第 24–25 页：

- **由一个中央目录保存系统里每个存储块的状态信息**：**记录哪些 Cache 持有某个存储块的副本，以及每份副本的状态——共享**（shared）、**独占**（exclusive）**或无效**（invalid）。
- **读操作**：**处理器要读某个存储块时，先向目录发请求**；**目录检查这个块的状态，如果它处在共享状态，就批准读**。
- **写操作**：**处理器要写时，也先向目录发请求**；**如果这个块处在共享状态，目录就让其他所有副本作废，把这个块转为请求方独占的状态**。
- **缺点**：**目录是集中式的，可能带来额外的复杂性**。**优点**：**正因为是集中控制，协调可以更高效，竞争也更少**。

课件只写了块处在共享状态时的读与写两种情形。

### 4.5 监听协议：写更新与写作废

课件第 26 页：监听协议**把维护缓存一致性的责任分散给多处理器里的所有 Cache 控制器**——

- **一个 Cache 必须能认出自己持有的某一行与别的 Cache 共享**；
- **对共享的行做更新时，必须通过广播机制通知其他 Cache**；
- **每个 Cache 控制器都能监听**（snoop）**网络，观察这些广播通知并作出相应的反应**。

Stallings 第 11 版配套幻灯片上还有一句：**监听协议适合基于总线的多处理器，因为共享总线为广播和监听提供了简单的手段**（课件没写这一句）。

**探索过的基本做法有两种：写更新**（write update，**也叫写广播**，write broadcast）**和写作废**（write invalidate）；**有些系统把两者自适应地混合使用**。

**写更新**（课件第 27 页）：**可以有多个写者，也可以有多个读者**。**处理器要更新一个共享行时，把要更新的那个字分发给所有其他处理器，持有这一行的 Cache 就能照着更新**。

- 优点：**数据在所有 Cache 里同时得到快速更新**；**其他 Cache 的副本都被更新了，不必作废**。
- 缺点：**多个处理器同时广播写数据时，系统总线可能出现争用**。

**写作废**（课件第 28 页）：**可以有多个读者，但同一时刻只有一个写者**。**要写时，其他所有 Cache 里的这一行都被作废**；**写的那个处理器从此独占这一行，直到别的处理器要用它**。**这是商用多处理器系统里用得最广的做法，例如 x86 体系结构**。**它把每一行的状态标成修改**（Modified）、**独占**（Exclusive）、**共享**（Shared）**或无效**（Invalid）——**所以写作废协议也叫 MESI**。

![[L16 缓存一致性的问题与两种监听做法.png]]

上图把两种做法放在一起比。左栏是没有任何协议时的情形，按课件第 20 页的图简化成三台处理器、每台都有副本：P1 改了自己那份，别人手里的和主存里的都还是旧值。中栏是写更新，P1 把改动广播出去，持有这一行的 Cache 都改成 X1。右栏是写作废，P2、P3 的副本作废，P1 独占这一行。右栏的主存按 MESI 写回时的 M 态画成旧值；课件第 26 页的图里主存已经是 X1，相当于写的同时也写了主存。写作废只管别的 Cache 里的副本，主存是不是新的取决于写策略（这段对照是我补的）。

### 4.6 MESI：写作废协议给每一行标四种状态

课件第 29 页：**为了在 SMP 上保持 Cache 一致，数据 Cache 支持一种叫 MESI 的协议**。**数据 Cache 的每个标记带两个状态位**，两位正好表示四种状态——

- **修改**（Modified, M）：**这一行被改过，与主存里的不同，而且只在这个 Cache 里有**；
- **独占**（Exclusive, E）：**这一行与主存里的相同，而且不在任何别的 Cache 里**；
- **共享**（Shared, S）：**这一行与主存里的相同，别的 Cache 里也可能有**（第 29 页原文作"别的 Cache 里有"，这里按第 30 页的表写，见下面的提示）；
- **无效**（Invalid, I）：**这一行里没有有效数据**。

> [!warning] 共享态的定义，课件两页说法不一
> 第 29 页的文字把共享态写成 "is present in another cache"（别的 Cache 里有）；第 30 页的表在"别的 Cache 里有没有副本"一行给共享态填的是 "Maybe"（可能有）。
> 按表来理解：别的 Cache 把副本换出去时，换出一行没改过的副本不必通知别人，留下的这一份并不知道自己已是唯一一份，所以仍标着共享态、不会改成独占态（这个解释是我补的）。Stallings 第 11 版配套幻灯片上的定义也是 "may be present in another cache"（可能在别的 Cache 里有）。

课件第 30 页的表：

| | **M** 修改 | **E** 独占 | **S** 共享 | **I** 无效 |
| --- | --- | --- | --- | --- |
| 这一行有效吗 | 是 | 是 | 是 | 否 |
| 主存里那份 | 已过时 | 有效 | 有效 | — |
| 别的 Cache 里有副本吗 | 没有 | 没有 | 可能有 | 可能有 |
| 写这一行时 | 不上总线 | 不上总线 | 上总线，并更新本 Cache | 直接上总线 |

课件这一页的第一条说，要给出任意两个 Cache 里同一行允许处在的状态组合，页上只写了这一条：**一个块在某个 Cache 里标为 M 或 E 时，它在其他 Cache 里的副本都标为 I**。由四种状态的定义可以推出完整的组合（这是我推的）：一方是 M 或 E，另一方只能是 I；一方是 S，另一方是 S 或 I；一方是 I，另一方四种都可能。

> [!example]- 表里"写这一行时"那一栏为什么是这样（课件只给结论，这里按写作废的规则推）
> - **M、E 不上总线**：别的 Cache 里没有副本，写了也不用通知谁。E 态的行写过之后就与主存不同了，成为 M 态（这一步状态变化课件没讲）。
> - **S 要上总线**：别的 Cache 里可能有副本，按写作废的规则要先广播，让那些副本作废，再改本 Cache 里的这一行；改完后这一行成为 M 态（课件没讲）。
> - **I 直接上总线**：本 Cache 里这一行没有有效数据，写操作只能交给总线。

## 本讲速记

- **四类并行处理器（Sample Q1；2023 卷 Q4(b) 3 分，任列三类）**：**SISD**——单处理器执行单个指令流、处理单个存储器里的数据（单处理器）；**SIMD**——一条机器指令控制许多处理单元同时执行（向量处理器、阵列处理器）；**MISD**——一串数据送给一组处理器、各执行不同的指令序列（没有商业实现）；**MIMD**——一组处理器同时在不同数据集上执行不同指令序列（SMP、集群、NUMA）。
- **MIMD 两支**：**共享存储**（紧耦合）下有 SMP 与 NUMA，**分布式存储**（松耦合）下有集群；共享存储时处理器经共享存储器访问程序与数据、彼此通信，最常见的形式是 SMP。**MIMD 有多个 CU，各给自己的 PU 一条指令流**，可以是共享存储的多处理器，也可以是分布式存储的多计算机。
- **SMP 五个特征**：两个或更多能力相当的同类处理器；**共享主存**，经总线或内部连接相连，**访问主存时间大致相同**；**共享 I/O**；**都能执行同样的功能（所以叫对称）**；**由一个集成的操作系统控制**。
- **SMP 四个潜在优点**：**性能、可用性、增量扩展、按规模分档**；调度与同步由操作系统负责。
- **SMP 组织**：每个处理器自成一体（CU、ALU、寄存器，通常带 Cache），共享主存与 I/O；经存储器通信，也可直接交换信号。**最常见的是分时共享总线**（最简单），总线由控制、地址、数据线组成。
- **总线**：为 DMA 传送提供**寻址、仲裁、分时**三项功能；三个优点**简单、灵活、可靠**；主要缺点是**性能**——所有访存都走这条总线，受总线周期时间限制；加 Cache 减少总线访问，却带来**缓存一致性问题**，通常靠硬件解决。
- **多处理器操作系统五个设计考虑**：**同时并发的进程**（例程要可重入，防死锁与非法操作）、**调度**（任何处理器都可能调度，要防冲突）、**同步**、**存储管理**（利用硬件并行性）、**可靠性与容错**（处理器坏了要平稳降级，重新组织）。
- **缓存一致性问题**：同一份数据在几个 Cache 里各有副本，各自随意更新就会出现不一致；写回显然会不一致；写直达也只保证主存是新的（补充）。
- **软件办法**：靠编译器与操作系统，开销从运行时移到编译时、复杂度从硬件移到软件；标出不可安全缓存的数据（太保守），更好的是找出共享变量可以安全缓存的时段。
- **硬件办法（Sample Q3）**：**目录协议**——中央目录记录每个块被哪些 Cache 持有及状态（共享、独占、无效），读写都先问目录，写共享块时目录作废其他副本、转为独占；集中式带来复杂性，但协调更高效、竞争更少。**监听协议**——责任分散给各 Cache 控制器，更新共享行时广播，各控制器监听并反应；两种做法：**写更新**（多写者多读者，广播更新的字；快，但同时广播会争用总线）与**写作废**（多读者单写者，写时作废其他副本、自己独占；x86 等商用系统最常用，即 MESI）。
- **MESI（Sample Q2）**：每个标记两位状态。**M**——改过、与主存不同、只在本 Cache；**E**——与主存相同、不在别的 Cache；**S**——与主存相同、别的 Cache 里可能有；**I**——无有效数据。写 M、E 不上总线，写 S 上总线并更新本 Cache，写 I 直接上总线；一处是 M 或 E 时，其他 Cache 里都是 I。
