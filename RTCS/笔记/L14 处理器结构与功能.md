# L14 处理器结构与功能

> [!info] 这一讲的骨架
> [[L11 指令集的特征与功能（上）]]到 [[L13 寻址方式与指令格式]]三讲讲的都是指令这一侧：一条指令长什么样、要求机器做什么、操作数从哪里来。这一讲掉头看机器那一侧：**处理器必须做哪几件事、靠哪些寄存器干活、一条指令在里面走过哪几个周期，以及怎样让多条指令重叠着执行。**
> 主线一句话：**处理器要做五件事——取指令、解释指令、取数据、处理数据、写数据——做的过程中指令和数据都得有地方暂存，这就是寄存器；把一条指令的处理拆成几段、让几条指令同时处在不同的段上，就是流水线；流水线被迫停下的三种原因——抢同一个资源、访问同一个操作数起冲突、转移转错——就是三类冒险。**

## 1 处理器必须做的五件事

### 1.1 五件事

课件第 3–4 页先列出**处理器组织必须满足的要求**（the requirements placed on the processor），也就是处理器必须做的事：

| 要求 | 英文 | 做什么 |
| --- | --- | --- |
| **取指令** | fetch instruction | 从存储器（寄存器、Cache、主存）读入一条指令 |
| **解释指令** | interpret instruction | 对指令译码，确定要执行什么动作 |
| **取数据** | fetch data | 执行这条指令**可能**需要从存储器或 I/O 模块读数据 |
| **处理数据** | process data | 执行这条指令**可能**需要对数据做算术或逻辑运算 |
| **写数据** | write data | 执行的结果**可能**需要写进存储器或 I/O 模块 |

后三件都带着"可能"（may require）：要不要取数据、要不要运算、要不要写回，取决于是哪条指令。

这五件事不是新东西。[[L11 指令集的特征与功能（上）#2.2 接回取指—执行循环|L11 讲指令的四个要素时]]对照过指令周期状态图里的取指、译码、取操作数、存操作数四段；五件事与那张状态图走的是同一条线，只是把中间的"数据操作"也单列成了一件（这层对照是我做的）。

### 1.2 处理器里有什么

课件第 5 页的简化图里，处理器只有三样东西：**算术逻辑单元**（arithmetic and logic unit, ALU）、**寄存器**、**控制单元**（control unit），经**系统总线**——控制总线、数据总线、地址总线——与外界相连（三组总线各管什么，见 [[L06 计算机互连#2.3 三组线各自决定什么|L06 的三组总线]]）。

第 6 页把内部放大：ALU 里有**状态标志、移位器、求补器、算术与布尔逻辑**几个部件，经**内部 CPU 总线**（internal CPU bus）与寄存器相连；控制单元经**控制通路**（control paths）指挥 ALU 和寄存器。

把这三样东西和五件事对上（这层对应是我归纳的，课件没有并排写）：按第 5 页的简化图，取指令、取数据、写数据要和外界打交道，走系统总线；解释指令靠控制单元；处理数据靠 ALU。而指令和数据在执行期间都得有地方暂存，处理器还得记住下一条指令在哪——这些就是寄存器的活，也是下一节的内容。

### 1.3 真题现场：2023 卷 Q3(b) 处理器必须做的事

> In the processor organization, some main requirements are placed (the things that the processor must do). Mention four of these requirements. [4]

这道题改编自本讲 Sample Question 第一问（"What are the main requirements that need to be placed in processor organization?"）：课件列了五项，题目要其中四项。

**答案**：从下面五项里任选四项——**fetch instruction**（取指令）、**interpret instruction**（解释指令）、**fetch data**（取数据）、**process data**（处理数据）、**write data**（写数据）。题目的动词是 mention（提到），不是 explain；每项的含义见[[#1.1 五件事|上面那张表]]。

## 2 寄存器的组织

### 2.1 两种角色

课件第 7 页：处理器内部有一组寄存器，**在存储层次里是位于主存和 Cache 之上的一级存储**（存储层次见 [[L08 存储技术#2.2 解法不是选一种器件，而是用一个层次|L08 的存储层次]]）。这些寄存器扮演两种角色：

- **用户可见寄存器**（user-visible registers）：让机器语言或汇编语言的程序员**通过用好寄存器来尽量减少对主存的访问**。
- **控制与状态寄存器**（control and status registers）：供**控制单元控制处理器的操作**，也供**有特权的操作系统程序控制程序的执行**。

这正是 Sample Question 第二问的两个大类：[[#2.2 用户可见寄存器：四类|§2.2]] 与 [[#2.3 条件码的利与弊|§2.3]] 讲用户可见寄存器，[[#2.4 控制与状态寄存器：四个必不可少的|§2.4]] 与 [[#2.5 程序状态字|§2.5]] 讲控制与状态寄存器。

### 2.2 用户可见寄存器：四类

课件第 8–9 页：**用户可见寄存器，是处理器执行的机器语言能够引用的寄存器。** 它们分四类：

| 类别 | 英文 | 是什么 |
| --- | --- | --- |
| **通用寄存器** | general purpose registers | 程序员可以把它派给各种用途 |
| **数据寄存器** | data registers | **只能用来存数据，不能用来计算操作数地址** |
| **地址寄存器** | address registers | 本身可能有一定通用性，也可能专门服务于某种寻址方式；例子是**段指针、变址寄存器、栈指针** |
| **条件码** | condition codes，又叫标志 flags | **由处理器硬件作为运算结果而设置的位**；这类寄存器**至少有一部分对用户可见** |

地址寄存器那一格的三个例子都在 L13 见过：变址寄存器就是[[L13 寻址方式与指令格式#4.3 变址寻址|变址寻址]]里装位移的那个寄存器，栈指针就是[[L13 寻址方式与指令格式#3.2 七种逐个过|栈寻址]]里指向栈顶的那个寄存器。条件码则是 [[L12 指令集的特征与功能（下）#9.1 四个标志|L12 讲 ARM 的 N、Z、C、V]] 时用到的那几个标志。

### 2.3 条件码的利与弊

课件第 10 页单独列了条件码的优缺点：

| 优点 | 缺点 |
| --- | --- |
| 减少需要的 `COMPARE` 与 `TEST` 指令 | 给硬件和软件**都增加了复杂度** |
| 让 `BRANCH` 这类条件指令得以简化 | 需要额外的硬件连线 |
| 子程序调用时，可以和其他寄存器信息一起保存到栈上 | 在流水线实现里，条件码**需要专门的同步来避免冲突** |

前两条优点说的是同一件事：运算指令已经顺手把结果的正负、是否为零等记在条件码里，后面的条件指令直接读标志就能决定做不做，不必再专门执行一条比较指令。ARM 让每条指令都能带条件执行（见 [[L12 指令集的特征与功能（下）#9 ARM 条件码：让一条指令自己决定要不要执行|L12 的 ARM 条件码]]），就是把条件码用到了每一条指令上。最后一条缺点要等 [[#5 流水线冒险|§5 讲完冒险]]才看得清：流水线里几条指令同时在跑，条件码到底是哪一条设置的，必须对得上。这一段的解释都是我补的，课件只列了条目。

### 2.4 控制与状态寄存器：四个必不可少的

课件第 11 页：**有四个寄存器对指令执行必不可少**——

| 寄存器 | 全称 | 装什么 |
| --- | --- | --- |
| **PC** | program counter，程序计数器 | **下一条要取的指令的地址** |
| **IR** | instruction register，指令寄存器 | **最近取进来的那条指令** |
| **MAR** | memory address register，存储器地址寄存器 | **内存中某个位置的地址** |
| **MBR** | memory buffer register，存储器缓冲寄存器 | **要写进内存的一个字，或最近读出来的那个字** |

这四个在 L05 都出现过：MAR 与 MBR 见 [[L05 计算机部件#3.2 四个寄存器，两对|L05 的"四个寄存器，两对"]]，要点是**地址寄存器说"去哪"，缓冲寄存器说"带什么"**；PC 与 IR 见 [[L05 计算机部件#4.1 取指周期|L05 的取指周期]]。[[#3.2 取指、间接、中断三个周期的数据流|§3.2 三个周期的数据流]]里搬来搬去的，正是这四个。

### 2.5 程序状态字

课件第 12 页：**程序状态字**（program status word, PSW）是**装状态信息的一个或一组寄存器**，通常包含条件码加上其他状态信息。常见的字段：

- **符号**（sign）：上一次算术运算结果的符号位。
- **零**（zero）：结果为 0 时置位。
- **进位**（carry）：运算越过最高位产生了进位（加法）或借位（减法），就置位。
- **相等**（equal）：逻辑比较的结果为相等时置位。
- **溢出**（overflow）：表示发生了算术溢出。
- **中断允许/禁止**（interrupt enable/disable）：允许或禁止中断。
- **管态**（supervisor）：表示处理器在管态还是用户态下执行；**某些特权指令只能在管态下执行，某些内存区域只能在管态下访问**。

符号、零、进位、溢出四个字段，与 ARM 的 N、Z、C、V 一一对得上；中断允许位相当于 [[L10 输入输出#6.4 真题现场：2023 卷 Q2(b) 用五个寄存器做 I/O|L10 那道真题里的 IEN]]；管态位则是 [[L12 指令集的特征与功能（下）#7 转换、输入输出、系统控制|L12 讲的系统控制指令]]只能在特权状态下执行的硬件依据（这三处对应是我做的）。

### 2.6 三个实例：MC68000、8086、80386

课件第 13–15 页举了三种微处理器的寄存器组织：

- **MC68000**：把 32 位寄存器分成 **8 个数据寄存器**（D0–D7）和 **9 个地址寄存器**（图上画了九行，标着 A0–A6 和 A7′，第九行没有标号），另有程序计数器与状态寄存器。**数据寄存器主要用于数据操作，在寻址中也可当变址寄存器用**；寄存器的宽度允许做 **8、16、32 位**的数据操作，具体做哪种由操作码决定。
- **Intel 8086**：**14 个 16 位寄存器**，分四组——**通用寄存器**（AX 累加器、BX 基址、CX 计数、DX 数据，可按字节或按 16 位访问）、**专用寄存器：指针与变址**（SP 栈指针、BP 基址指针、SI 源变址、DI 目的变址）、**段寄存器**（CS 代码段、DS 数据段、SS 栈段、ES 附加段，同一时刻只允许四个段在工作）、**标志寄存器**（条件控制与程序状态）。图上标志寄存器和指令指针 IP 同列在"程序状态"一组，四组合计 4 + 4 + 4 + 2 = 14 个。
- **Intel 80386**（课件标题写作 Intel 80386 (P4)）：作为 8086 扩展的 32 位微处理器。**为了与早期机器上写的程序向上兼容，80386 把原来的寄存器组织原样嵌进新的组织里**；**受这个约束，32 位处理器的架构师在设计寄存器组织时灵活性有限**。

三个实例放在一起，能看出两件事（这是我归纳的）：MC68000 把"装数据"和"装地址"分成两组寄存器，对应 [[#2.2 用户可见寄存器：四类|§2.2]] 里数据寄存器与地址寄存器的区分，只是分得不彻底——它的数据寄存器在寻址时还能当变址寄存器用，而 §2.2 定义的数据寄存器不能用来计算操作数地址；80386 则说明**兼容性会反过来束缚寄存器设计**——新机器的寄存器长什么样，有一部分是被旧程序决定的。

## 3 指令周期，以及三个周期里的数据流

### 3.1 四个阶段

课件第 16 页用"To recall"开头，这是复习：一个**指令周期**（instruction cycle）包括——

- **取指**（fetch）：把下一条指令从内存读进处理器。
- **执行**（execute）：解释操作码，执行所指示的操作。
- **中断**（interrupt）：如果中断已允许、而且发生了中断，就保存当前进程的状态并服务这个中断。
- **间接**（indirect）：如果用了间接寻址，就需要额外的访存。

取指与执行是 [[L05 计算机部件#4 取指—执行：这个循环本身|L05 的取指—执行循环]]，中断插进循环的方式见 [[L05 计算机部件#5.3 中断是怎么插进循环的|L05 讲中断如何插进循环]]。第四个阶段是新加的：[[L13 寻址方式与指令格式#3.2 七种逐个过|L13 讲间接寻址]]时说过它要访存两次——先取出操作数的地址、再取操作数，**多出来的那一次访存，就是这里的间接周期**。

课件第 17 页的状态图，与 L05、L11 用过的那张（见 [[L05 计算机部件#4.4 把循环画成状态图|L05 的状态图]]、[[L11 指令集的特征与功能（上）#2.2 接回取指—执行循环|L11 的状态图]]）基本相同，只是在"取操作数"和"存操作数"两个状态上各多了一个标着 Indirection 的自环——间接寻址多出来的访存，就画在这两个自环上。

### 3.2 取指、间接、中断三个周期的数据流

课件第 18–20 页分别画了三个周期里数据怎么流动。下面按同一种布局重画在一起，便于对比：

![[L14 三个周期的数据流.png]]

**取指周期**（fetch cycle）：PC 里存着下一条指令的地址，这个地址先送进 MAR，再放上地址总线；控制单元经控制总线发出读请求，内存把那个字放上数据总线，读进 MBR，再转进 IR；同时控制单元让 PC 加一，为下一次取指做准备。

**间接周期**（indirect cycle）：取指完成后，控制单元检查 IR 里的指令有没有用间接寻址。如果有，就把 MBR 里那条指令的地址字段送进 MAR，再发出读请求；内存送回来的，是**操作数的地址**，又落进 MBR。

**中断周期**（interrupt cycle）：PC 的当前值必须先保存起来，处理器才能在中断处理完之后接着原来的程序做下去。于是 PC 的内容先转进 MBR，准备写进内存；控制单元把专门留作保存用的那个内存位置的地址（例如栈指针所指的位置）送进 MAR，发出写请求；最后控制单元把中断服务程序的入口地址装进 PC，**于是下一个指令周期一开始，取进来的就是中断服务程序的第一条指令**。

> [!note] 课件这三页只有图
> 课件第 18–20 页没有文字说明，只有带红色编号的箭头。上面三段的走向与先后按箭头写；每一步搬的是什么、控制单元中间做了什么判断、为什么要这样搬，是我补的。课件的编号比上面的步骤细：寄存器与总线之间、总线与内存之间的每一段箭头都单独编了号。

## 4 指令流水线

### 4.1 装配线的想法，以及两段流水

课件第 21 页：**指令流水线**（instruction pipelining）类似于工厂里的装配线——处在不同阶段的产品可以同时加工。在流水线里，**新的输入从一端被接收，而先前接收的输入还没从另一端出来**。要把这个想法用到指令执行上，先得承认**一条指令的处理可以分成若干阶段**。

最简单的分法是两段：**取指令**与**执行指令**。课件第 22 页的理由是：**执行一条指令的过程中，有些时候并不访问主存**；这段时间可以拿来**取下一条指令并先缓冲起来，与当前指令的执行并行进行**。这叫**指令预取**（instruction prefetch），也叫**取指重叠**（fetch overlap）。

同一页的展开图 (b) 在两段上各画了一个 Wait 自环，从执行段到取指段画了一条 New address 回箭头，取指段下方还有一条 Discard 箭头。课件没有配文字，按图与标签读（这一段是我按图补的）：两段耗时不等时，快的那一段要等慢的那一段；执行段遇到转移时，把新的目标地址送回取指段，已经预取进来的那条指令只能丢弃。[[#4.4 什么会拖慢流水线|§4.4]] 的头两个限制因素，在这张两段图里就已经出现了。

### 4.2 六段流水

**要想进一步提速，流水线必须有更多的段。** 课件第 23–24 页把指令处理分成六段（Sample Question 第四问）：

| 段 | 英文 | 做什么 |
| --- | --- | --- |
| **FI** 取指令 | fetch instruction | 把预计的下一条指令读进缓冲区 |
| **DI** 译码 | decode instruction | 确定操作码与操作数说明符 |
| **CO** 算操作数 | calculate operands | 计算每个源操作数的有效地址；可能涉及位移、寄存器间接、间接或其他形式的地址计算 |
| **FO** 取操作数 | fetch operands | 从内存取每个操作数；**在寄存器里的操作数不必取** |
| **EI** 执行 | execute instruction | 执行所指示的操作，若有结果，存进指定的目的操作数位置 |
| **WO** 写操作数 | write operand | 把结果存进内存 |

CO 段算的"有效地址"，就是 [[L13 寻址方式与指令格式#2 先把四个记号定下来|L13 的 EA]]——位移、寄存器间接、间接这几个名字都来自 L13 的七种寻址方式。

### 4.3 时序图：54 个时间单位压到 14 个

![[L14 六段流水线与转移的代价.png]]

课件第 25 页的时序图（timing diagram）：为了说明问题，**假设六段耗时相等**。在这个假设下，**六段流水线能把 9 条指令的执行时间从 54 个时间单位缩短到 14 个**（上图 (a)）。

两个数都能从时序图里直接数出来：不用流水线时，每条指令要依次走完 6 段，9 条共 $9 \times 6 = 54$ 个时间单位；用了流水线，第一条仍要走满 6 段，在第 6 个时间单位完成，此后每个时间单位完成一条，剩下 8 条再花 8 个时间单位，共 $6 + 8 = 14$ 个。

> [!example]- 推广成一般式（课件只给了 54 与 14 两个数，下面是我按时序图推的）
> 设流水线有 $k$ 段、每段耗时 $\tau$，要执行 $n$ 条指令，中间没有转移、也没有冒险：
>
> $$
> T_{\text{不流水}} = n k \tau, \qquad T_{\text{流水}} = \big(k + (n - 1)\big)\tau, \qquad S = \frac{T_{\text{不流水}}}{T_{\text{流水}}} = \frac{nk}{k + n - 1}
> $$
>
> 代入 $k = 6$、$n = 9$：$S = 54 / 14 \approx 3.86$。当 $n$ 很大时，$S$ 趋近于 $k$——**段数是理想加速比的上限**。这个上限在现实中到不了：$n$ 总是有限的，还有下一小节那几条因素。

### 4.4 什么会拖慢流水线

课件第 26 页列了三个限制性能提升的因素：

- **各段不等长**：六段耗时若不相等，各段之间就会出现等待（课件说"与前面讨论两段流水时一样"，指的就是 [[#4.1 装配线的想法，以及两段流水|§4.1]] 那张展开图里的两个 Wait 自环）。
- **条件转移指令**：它可能让好几次取指作废。
- **中断**：一种同样不可预测的事件。

条件转移的代价在课件第 27 页画得很清楚（上图 (b)）：**设第 3 条指令是一条转向第 15 条的条件转移。在这条指令执行之前，没有办法知道下一条该是哪条**，流水线只好按顺序继续取第 4、5、6、7 条。到第 7 个时间单位 I3 执行完，才发现要转；这时 I4 到 I7 已经进了流水线，只能清掉（flush）。课件把这段损失标作**转移代价**（branch penalty）。第 28 页换了一种画法说同一件事：**第 7 个时间单位，I3 处在执行段并执行了转向 I15 的转移，I4 到 I7 被清出流水线，所以第 8 个时间单位流水线里只剩 I3 和 I15 两条**。

> [!warning] 课件第 27 页的正文与它自己的图对不上
> 课件正文写"No instructions complete during time units 8 through 12"。但同一页的图上，**I3 的 WO 段就在第 8 个时间单位**——I3 在第 8 个完成；第 28 页也说第 8 个时间单位 I3 还在流水线里。I15 在第 8 个进入、第 13 个完成。所以**真正没有指令完成的是第 9 到 12 个时间单位，共 4 个**，上图 (b) 的红框就是这 4 个。课件这张图顶部标着 Branch Penalty 的双箭头，也正好横跨第 9–12 格。

这 4 个时间单位为什么是 4：转移在第 5 段（EI）才见分晓，它后面已经跟进来 4 条指令，全部作废；推广开来，流水线照顺序往下取指时，一条转移若确实要转，被作废的指令数等于"转移在第几段确定"减一（这一条是我按图推的）。

第 29 页用一张流程图给出了处理转移与中断所需的逻辑：CO 段之后先判断是不是无条件转移，是就更新 PC、清空流水线；WO 段之后再判断有没有转移或中断，有就同样更新 PC、清空流水线（流程图的走法是我按图写的）。这张图把转移放在 WO 之后才判断，与第 27 页时序图里 EI 段一执行完就转的口径不完全一致；上面的 4 个时间单位按的是第 27 页的时序图。

这一页还指出，会冒出两段流水时没有的问题——**CO 段可能依赖某个寄存器的内容，而这个寄存器可能正被流水线里一条更早的指令修改**，类似的寄存器与内存冲突也可能出现。这正是下一节冒险要讲的。

## 5 流水线冒险

### 5.1 三类冒险

课件第 30 页：**流水线冒险**（pipeline hazard）指**流水线或其中一部分因为条件不允许继续执行而必须停顿**（stall）；这种停顿也叫**流水线气泡**（pipeline bubble）。冒险分三类：

![[L14 流水线的三类冒险.png]]

- **资源冒险**（resource hazard）：**两条或更多条已在流水线里的指令需要同一个资源**，结果是在流水线的某一部分，这些指令**只能串行而不能并行执行**。资源冒险有时也叫**结构冒险**（structural hazard）。
- **数据冒险**（data hazard）：**对一个操作数位置的访问发生冲突**。一般地说，就是程序里先后执行的两条指令，访问同一个内存或寄存器操作数。**如果没有专门的硬件和专门的避免算法，数据冒险会让流水线用得不充分**。
- **控制冒险**（control hazard），也叫**转移冒险**（branch hazard）：**流水线在转移预测上做了错误的决定，于是把随后必须作废的指令取进了流水线**。[[#4.4 什么会拖慢流水线|§4.4]] 讲的那次转移，付出的就是一次控制冒险的代价。

### 5.2 三种数据冒险

课件第 33–34 页把数据冒险再分三种（Sample Question 第五问）：

| 名称 | 又叫 | 两条指令在做什么 | 什么时候出冒险 |
| --- | --- | --- | --- |
| **写后读**（read after write, RAW） | **真相关**（true dependency） | 前一条修改某个寄存器或内存位置，后一条读这个位置 | **读在写完成之前就发生了** |
| **读后写**（write after read, WAR） | **反相关**（antidependency） | 前一条读某个位置，后一条写这个位置 | **写在读发生之前就完成了** |
| **写后写**（write after write, WAW） | **输出相关**（output dependency） | 两条指令都写同一个位置 | **两次写的实际顺序与预定顺序相反** |

三个名字都按发生的先后来读：写后读，就是前一条写、后一条读；读后写，就是前一条读、后一条写；写后写，就是两条都写。上图下半部分各配了一对例子（写后读、读后写两对是我配的，课件第 33–34 页没有代码；写后写那一对取自 2023 卷；都是三地址写法，第一个寄存器是目的），例如写后读：`ADD R1, R2, R3` 写 R1，紧接着 `SUB R4, R1, R5` 读 R1，后一条如果抢在前一条写完之前读，读到的就是 R1 的旧值。

2023 卷 Q3(c)(i) 给的两条代码 `ADD R1, R2, R3` 与 `SUB R1, R4, R5`，就是图里写后写那一对。题目问它对并行施加了什么根本限制、(ii) 问怎样改写来消除，放在指令级并行的语境里，完整解答在 [[L15 指令级并行]]。

### 5.3 两个课件示例：资源冒险与数据冒险各卡几拍

课件第 31、32 页各用时序图举了一个例子。注意两页用的都是**五段**流水线（FI、DI、FO、EI、WO），没有 CO 段，与 [[#4.2 六段流水|§4.2]] 的六段不同；横轴是时钟周期（clock cycle），下面简称"拍"。

**资源冒险的例子**（第 31 页）：理想情况下四条指令每拍错开一段。图 (b) 的标题是"I1 的源操作数在内存里"：第 3 拍时 I1 在 FO 段要读内存取操作数，而 I3 的 FI 段也要读内存取指令，两者抢同一个内存（前提是内存一拍只能服务一次访问，且不考虑 Cache），于是 **I3 在第 3 拍只能空等（Idle），推迟一拍才开始取指**，I4 跟着推迟一拍（抢内存这个原因是我按图读出来的，课件只给了图）。

**数据冒险的例子**（第 32 页）：`ADD EAX, EBX` 之后是 `SUB ECX, EAX`。这是 x86 的二地址写法，目的在前（规则见 [[L11 指令集的特征与功能（上）#5.2 四种地址数的汇总|L11 的地址数汇总]]），所以 ADD 做的是 EAX ← EAX + EBX，SUB 做的是 ECX ← ECX − EAX。SUB 要读 ADD 写的 EAX，是一次写后读。ADD 在第 5 拍的 WO 段才把结果写进 EAX，**SUB 只好在第 4、5 两拍空等，第 6 拍才取操作数**；后面的 I3、I4 也跟着推迟两拍（这段因果同样是我按图读出来的）。

### 5.4 处理条件转移的五种办法

课件第 35–36 页列了五种对付条件转移的办法（Sample Question 第三问）：

- **多路流**（multiple streams）：**复制流水线的前几段**，让流水线把转移两边的指令都取进来，形成两路指令流。
- **预取转移目标**（prefetch branch target）：**一认出是条件转移，就把转移目标也预取进来**，不管最后转还是不转。
- **循环缓冲**（loop buffer）：由流水线取指段维护的**一块小而极快的存储器**，**按顺序存着最近取过的 n 条指令**。若要转移，硬件先查转移目标在不在缓冲里；在的话，下一条就直接从缓冲里取。
- **延迟转移**（delayed branch）：**自动重排程序里的指令，让转移指令出现得比实际需要的位置更晚**，以改善流水线性能。
- **转移预测**（branch prediction）：用各种技术**预测转移会不会发生**。

五种办法都是在对付[[#5.1 三类冒险|控制冒险]]：前三种想办法让转移后需要的指令提前就位，后两种分别从程序编排和猜测入手（这句归纳是我加的）。

## 6 x86 的两类事件：中断与异常

课件第 37 页：x86 把打断正常执行的事件分成两类——

- **中断**（interrupts），信号来自硬件：
  - **可屏蔽中断**（maskable interrupts）：CPU 可以控制、也可能忽略；例如键盘输入、磁盘 I/O 请求。
  - **不可屏蔽中断**（nonmaskable interrupts, NMI）：总是按高优先级处理，CPU 不能忽略或禁止；例如硬件故障、电源问题。
- **异常**（exceptions），信号来自软件：
  - **处理器检测到的异常**（processor-detected exceptions）：CPU 在正常运行中检测到的错误，对系统稳定很关键；例如除以零、无效操作码。
  - **编程异常**（programmed exceptions）：本身就是会产生异常的指令；例如显式的系统调用，像 x86 汇编里的 `INT`。

和 [[L05 计算机部件#5.2 四类中断|L05 的四类中断]]对照着看（对应关系是我归纳的）：L05 的 I/O 中断与定时器中断都来自硬件，落在这里的可屏蔽中断；硬件故障落在不可屏蔽中断，程序中断（溢出、除以零、非法指令）落在处理器检测到的异常。区别在于分类的角度：L05 按"谁产生的"分，x86 这里先按硬件还是软件分，再按能不能屏蔽、是不是有意为之细分。

## 本讲速记

- **处理器必须做的五件事（Sample Q1；2023 卷 Q3(b) 由它改编，要列四项）**：**取指令**（fetch instruction）、**解释指令**（interpret instruction）、**取数据**（fetch data）、**处理数据**（process data）、**写数据**（write data）。后三件都是"可能需要"，视指令而定。
- **处理器的三个部件**：**ALU、寄存器、控制单元**，经**系统总线**（控制、数据、地址）连到外界；ALU 里有**状态标志、移位器、求补器、算术与布尔逻辑**，经**内部 CPU 总线**与寄存器相连。
- **寄存器的两种角色（Sample Q2）**：**用户可见寄存器**——让程序员用好寄存器、减少访存；**控制与状态寄存器**——供控制单元控制处理器操作、供特权的操作系统程序控制程序执行。寄存器在存储层次里**位于主存和 Cache 之上**。
- **用户可见寄存器四类**：**通用**（可派各种用途）、**数据**（只存数据，**不能用来算操作数地址**）、**地址**（可通用或专用于某种寻址方式；**段指针、变址寄存器、栈指针**）、**条件码**（又叫标志，**由硬件作为运算结果设置**，至少部分对用户可见）。
- **条件码**：优点——**减少 COMPARE 与 TEST 指令**、**简化 BRANCH 这类条件指令**、**子程序调用时可随其他寄存器一起存到栈上**；缺点——**增加硬件与软件的复杂度**、**需要额外硬件连线**、**流水线里需要专门同步以免冲突**。
- **四个必不可少的控制与状态寄存器**：**PC**（下一条要取的指令的地址）、**IR**（最近取进来的指令）、**MAR**（内存某位置的地址）、**MBR**（要写进内存的字，或最近读出的字）。
- **PSW**：装状态信息的寄存器，通常是条件码加其他状态。字段：**符号、零、进位、相等、溢出、中断允许/禁止、管态**；**管态下才能执行某些特权指令、访问某些内存区域**。
- **三个实例**：**MC68000**——32 位，**8 个数据寄存器 + 9 个地址寄存器**，数据寄存器也可当变址用，支持 8/16/32 位操作；**8086**——**14 个 16 位寄存器**，分**通用、指针与变址、段、标志**四组（段寄存器同一时刻只允许四个段）；**80386**——8086 的 32 位扩展，**为向上兼容保留了原寄存器组织，因而设计灵活性有限**。
- **指令周期四阶段**：**取指、执行、中断**（已允许且发生时，保存进程状态并服务中断）、**间接**（用了间接寻址时额外访存）。状态图在取操作数、存操作数上的 Indirection 自环就是间接周期。
- **取指周期**：PC → MAR → 地址总线；控制单元发读；内存 → 数据总线 → MBR → IR；PC 加一。**间接周期**：MBR 里的地址字段 → MAR；读；操作数的地址回到 MBR。**中断周期**：PC → MBR；控制单元把保存位置的地址（如栈指针）→ MAR；写；控制单元把中断服务程序的入口地址 → PC。
- **流水线的想法**：像装配线，**新输入从一端进来时，先前的输入还没从另一端出去**。**两段流水**（取指、执行）利用执行期间不访存的空当**预取下一条**，叫**指令预取 / 取指重叠**。
- **六段流水（Sample Q4）**：**FI 取指令、DI 译码、CO 算操作数（有效地址）、FO 取操作数（寄存器里的不必取）、EI 执行、WO 写操作数**。
- **54 → 14**：六段等长时，9 条指令不流水要 $9 \times 6 = 54$ 个时间单位，流水只要 $6 + (9 - 1) = 14$ 个。一般式 $T = (k + n - 1)\tau$，加速比 $nk / (k + n - 1)$，上限是段数 $k$（理解用）。
- **限制流水线性能的三个因素**：**各段不等长、条件转移、中断**。
- **条件转移的代价**：I3 转向 I15，第 7 个时间单位执行完才知道，**I4–I7 被清掉**，**第 9–12 个时间单位没有指令完成**。⚠ 课件第 27 页正文写成"8 through 12"，与它自己的图矛盾（I3 在第 8 个完成）。
- **流水线冒险**：流水线或其一部分**因条件不允许继续执行而停顿**，这种停顿叫**气泡**。三类：**资源冒险**（又叫结构冒险，两条已在流水线里的指令要同一个资源，只能串行）、**数据冒险**（访问同一个操作数位置冲突，不加专门硬件就会让流水线用不满）、**控制冒险**（又叫转移冒险，转移预测错了，取进来的指令要作废）。
- **三种数据冒险（Sample Q5）**：**写后读 RAW＝真相关**（前写后读，读在写完成前发生）；**读后写 WAR＝反相关**（前读后写，写在读之前完成）；**写后写 WAW＝输出相关**（两条都写，写的顺序颠倒）。名字按发生的先后读。
- **两个课件示例**（都是五段流水，无 CO）：资源冒险——I1 的源操作数在内存，第 3 拍 I1 的 FO 与 I3 的 FI 抢内存，**I3 空等一拍**；数据冒险——`ADD EAX, EBX` 后接 `SUB ECX, EAX`，写后读，**SUB 空等两拍**。
- **处理条件转移的五种办法（Sample Q3）**：**多路流**（复制流水线前几段，两路都取）、**预取转移目标**（认出条件转移就预取目标）、**循环缓冲**（取指段维护的小而极快的存储器，存最近 n 条指令，目标在里面就直接取）、**延迟转移**（自动重排指令，让转移出现得更晚）、**转移预测**（预测转不转）。
- **x86 的两类事件**：**中断**（来自硬件）——**可屏蔽**（可控制、可忽略，如键盘、磁盘 I/O）与**不可屏蔽 NMI**（总是高优先级，不能忽略或禁止，如硬件故障、电源问题）；**异常**（来自软件）——**处理器检测到的**（如除以零、无效操作码）与**编程异常**（如系统调用 `INT`）。
