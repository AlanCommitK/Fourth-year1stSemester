## 1 GPU 和 CPU 差在哪里

### 1.1 GPU 是什么

课件第 3 页：

- **图形处理器**（graphics processor unit, GPU）**专门为快速的三维图形渲染和视频处理而优化**。
- **今天几乎所有工作站、笔记本、平板和手机里都有 GPU。**
- **最小的 GPU 在平板、手机这类嵌入式系统里，只有个位数的核**；**它们通常和几个普通的核，也就是中央处理器**（central processing unit, CPU）**做在一起**。

### 1.2 结构上的基本区别

课件第 4 页的图把两者并排：CPU 的芯片上一大块是控制逻辑（Control），一大块是 Cache，运算单元（ALU）只有 4 个；GPU 的芯片上几乎全是排成阵列的小运算核，控制和 Cache 只占每行开头的一小格；两者下面都是 DRAM（按图读出）。

- **CPU：控制逻辑和 Cache 占了芯片的大部分**；**它被调校成尽可能快地执行顺序代码**。
- **GPU：用大规模并行的 SIMD 结构，主要做数学运算**（SIMD 见 [[L16 并行处理#1.1 按指令流与数据流分四类|L16 的 SIMD]]）；**不需要 CPU 控制逻辑里那些复杂的功能**——**乱序执行**（见 [[L15 指令级并行#4.3 三种策略，同一个例子|L15 的乱序发射]]）、**转移预测**（见 [[L15 指令级并行#6 转移预测|L15 的转移预测]]）、**处理数据冒险**（见 [[L14 处理器结构与功能#5.2 三种数据冒险|L14 的数据冒险]]）等；**也不需要大量的 Cache**。

[[L17 多核计算机#4.1 什么是异构多核|L17 第 20 页的配图]]说的是同一件事：CPU 为串行任务优化，画成几个大核；GPU 为并行任务优化，画成大量小核。

### 1.3 GPU 架构走过的三个阶段

课件第 5 页：

- **第一阶段（1980 年代初到 1990 年代末）：GPU 由固定的、不可编程的专用处理级组成。**
- **第二阶段（大约 2000 年代初到中期）：把第一阶段那条固定的专用硬件流水线一步步改造成完全可编程的处理器。**
- **第三阶段：NVIDIA 在 2006 年引入的最终改造，配上它新的通用 GPU 编程语言 CUDA**；**这一阶段，GPU/GPGPU 架构成为一个出色而便宜的、高度并行的 SIMD 协处理器**。

通用 GPU（general-purpose GPU, GPGPU）指不只做图形、也拿来做一般计算的 GPU，本讲标题里的"通用"就是这个意思（这句解释是我补的）。

## 2 CUDA：怎样给 GPU 写程序

### 2.1 CUDA 是什么

课件第 6 页：

- **CUDA**（Compute Unified Device Architecture，统一计算设备架构）**是 NVIDIA 创建的并行计算平台和编程模型，由 NVIDIA 生产的 GPU 实现。**
- **CUDA C 是一种基于 C/C++ 的语言。**
- **一个 CUDA 程序分成三部分：在主机**（host，即 CPU）**上运行的代码；在设备**（device，即 GPU）**上运行的代码；在主机与设备之间传数据的代码。**
- **在 GPU 上运行的数据并行代码叫核函数**（kernel），**而线程**（thread）**是这个核函数的一个实例**。
- **核函数里通常很少甚至没有分支语句：核函数里的分支会让 GPU 硬件里的线程串行执行。** 原因见 [[#4.3 流多处理器，以及块怎样在 SM 上执行|warp 一节]]。

### 2.2 与顺序编程有什么不同

第 26 页第一问"CUDA 是什么，和顺序编程有什么不同"，课件没有单独一页回答。按第 6–7 页与第 24 页能整理出三点（这一段是我整理的）：

- **谁来执行**：顺序程序由一个线程把循环一遍遍做完；CUDA 把能并行的那部分写成核函数，一次启动成千上万个线程，每个线程处理一份数据。
- **代码分在两处**：主机代码在 CPU 上跑，核函数在 GPU 上跑，两边的数据要显式地拷来拷去（第 6 页的三部分）。
- **适合的代码不同**：核函数里通常很少甚至没有分支，有分支的地方线程会被串行执行；顺序程序没有这个讲究。

以附录里的向量加法为例：顺序写法是 `for (i = 0; i < n; i++) c[i] = a[i] + b[i];`，一个线程做 n 次加法；CUDA 写法是启动 n 个线程，第 `tid` 个线程只做 `c[tid] = a[tid] + b[tid]` 这一次加法（顺序写法是我写的，CUDA 写法见 [[#7 附录：向量加法的 CUDA 程序|附录的向量加法程序]]）。

### 2.3 线程、块、网格

课件第 7 页：

- **核函数被调用时，由程序员决定启动多少个线程。**
- **启动的线程总数通常是几千个，这样才能把 GPU 的处理器核**（也叫 CUDA 核，CUDA cores）**用满，并得到尽可能大的加速比。**
- **线程被均匀地打包成块**（block，也叫线程块，thread block），**一次核函数启动里的全部块叫一个网格**（grid）。

第 7 页的图画的是一个 3 × 2 个块的网格，每个块按 (x, y) 编号；把块 (1, 1) 放大，里面是 4 × 3 个线程，同样按 (x, y) 编号。

GPU 上执行线程的硬件单位叫**流多处理器**（streaming multiprocessor, SM），第 9 页的表里写作 CUDA 多处理器（CUDA multiprocessor），是同一个东西；第 9 页把这几个名词与硬件对上：

| CUDA 名词 | 定义 | 对应的 GPU 硬件 |
| --- | --- | --- |
| **核函数**（kernel） | **以函数形式写成、要在 GPU 上运行的并行代码** | 没有对应 |
| **线程**（thread） | **核函数在 GPU 上的一个实例** | **GPU/CUDA 处理器核** |
| **块**（block） | **分配给某一个 SM 的一组线程** | **CUDA 多处理器（SM）** |
| **网格**（grid） | **整个 GPU** | **GPU** |

同一页的一句：**一个块只分配给几个 SM 中的一个**。SM 的内部见 [[#4.3 流多处理器，以及块怎样在 SM 上执行|流多处理器]]。

## 3 线程在哪里：编号与线性地址

这几页的题目里，"网格大小"（grid size）指整个网格在 X、Y 两个方向上各有多少个线程；"X、Y 方向的块数"是网格在两个方向上各分成多少块（这是按课件的算法读出的）。附录代码（第 28–29 页）注释里的 Grid size 却指块数 `NUM_BLOCKS`，两处同名不同义（这是按两处的算法读出的）。

### 3.1 每个块里有几个线程

课件第 8 页的例子：

> (a) Consider a CUDA Kernel has a grid size of 1024×2048. The number of blocks in X and Y dimension are 16 and 32 respectively.
> i. What will be the number of threads in each block, both in X and Y dimension.

每个块在一个方向上的线程数 = 该方向的线程总数 ÷ 该方向的块数：

- X 方向：$1024 / 16 = 64$；
- Y 方向：$2048 / 32 = 64$（课件解答的第二行写成了"X dimension"，算的是 Y 方向）。

### 3.2 线程的全局位置与线性地址

课件第 18–19 页的例子：

> (a) Consider a CUDA Kernel has a grid size of 2048×2048. The number of blocks in X and Y dimension are 64 and 32 respectively.
> i. What will be the number of threads in each block, both in X and Y dimension.
> ii. What will be the address of the data in memory for a thread (11, 12) that is placed in block (15, 13). Assuming the 2D data array is stored in linear memory using row-major order.

第 19 页的解答分三步：

1. **每块的线程数**：X 方向 $2048 / 64 = 32$，Y 方向 $2048 / 32 = 64$（第 19 页红字的第二行写成了"Number of blocks"，算的是线程数）。
2. **全局位置** = 块号 × 每块在该方向的线程数 + 线程在块内的编号。直觉是：X 方向上块 15 前面有 15 个整块，先数过 $15 \times 32 = 480$ 个线程，再加上块内的编号 11（这一句是我补的）。
   - X：$15 \times 32 + 11 = 491$；
   - Y：$13 \times 64 + 12 = 844$；
   - 这个线程在整个网格里的位置是 (491, 844)。
3. **线性地址**：第 18 页的图写着每个线程对应同号的数据元素（Maps to corresponding data elements），所以要找的是全局位置 (491, 844) 那个元素。二维数组按**行优先**（row-major order）存进一维存储，地址 = Y 方向的全局位置 × X 方向的线程总数 + X 方向的全局位置 $= 844 \times 2048 + 491 = 1{,}729{,}003$。

行优先的意思，第 18 页用一个 3 × 3 的线程网格画了出来：Y 相同的一行存在一起，第 0 行的 (0,0)、(1,0)、(2,0) 占下标 0–2，第 1 行占 3–5，第 2 行占 6–8，所以下标 = y × 3 + x。把 3 换成 X 方向的线程总数 2048，就是第 3 步的式子。这里算出的"地址"是元素的下标；每个元素占 k 个字节时，字节偏移是下标 × k（这半句是我补的）。

### 3.3 课件留的练习

课件第 17 页的题，课件没有给答案：

> (a) Consider a CUDA Kernel has a grid size of 2048×2048. The number of blocks in X and Y dimension are 32 and 16 respectively.
> i. What will be the number of threads in each block, both in X and Y dimension.
> ii. What will be the address of the data in memory for a thread (23, 45) that is placed in block (1, 12). Assuming the 2D data array is stored in linear memory using row-major order.

按第 19 页的三步（答案是我算的）：

1. 每块的线程数：X 方向 $2048 / 32 = 64$，Y 方向 $2048 / 16 = 128$。
2. 全局位置：X $= 1 \times 64 + 23 = 87$，Y $= 12 \times 128 + 45 = 1581$。
3. 线性地址 $= 1581 \times 2048 + 87 = 3{,}237{,}975$。

> [!note] 课件例子里的块偏大
> 第 8 页每块 64 × 64 = 4096 个线程，第 19 页每块 32 × 64 = 2048 个，第 17 页每块 64 × 128 = 8192 个。按 CUDA 的规定，从 Fermi 这一代起（计算能力 2.x；计算能力即 compute capability，是 NVIDIA 给各代 GPU 标的硬件版本号），一个块最多 1024 个线程，所以这几个块在真实的 GPU 上开不出来；第 13 页也说块的大小要小于每块允许的最大线程数。三道题只是练编号与地址的算法，算法本身不受影响（这一段是我补的）。

## 4 Fermi：一块 GPU 里面有什么

### 4.1 几代架构，以及 Fermi 的规模

课件第 10 页：**NVIDIA 的 GPU 技术经历了好几代：Tesla、Fermi、Kepler、Maxwell**；**每一代的微架构与前一代相比只有小到中等的差别**。**Fermi GPU 一共有 16 个 SM，每个 SM 32 个 CUDA 核，共 512 个 CUDA 核。**

### 4.2 芯片布局

课件第 11 页的 Fermi 芯片布局（按图与标注读出）：

- **16 个 SM**，上下各 8 个；
- **L2 Cache 在芯片中央**，夹在上下两排 SM 之间；
- 两侧是 DRAM 接口：**6 个 DRAM I/O 接口，每个 64 位，合起来是 384 位的存储接口**；
- **PCIe 连接 GPU 与 CPU**（图上的主机接口，Host interface；PCIe 见 [[L07 通信与互连#4.2 PCIe：换成点对点之后|L07 的 PCIe]]）；
- **GigaThread 调度器负责把线程块分给各个 SM 的 warp 调度器**（warp 是 32 个线程一组、一起被调度的单位，见 [[#4.3 流多处理器，以及块怎样在 SM 上执行|下一节]]）。

### 4.3 流多处理器，以及块怎样在 SM 上执行

课件第 12 页列出一个 SM 里的部件（图里还有指令 Cache、互连网络和 uniform cache，按图读出）：

- **32 个 GPU 处理器核**（CUDA 核）；
- **warp 调度器与分派单元**（warp scheduler and dispatch unit，图里各 2 个；分派单元把调度器选中的指令发给执行部件，这半句是我补的）；
- **存取单元**（load/store unit，图里 16 个）；
- **寄存器堆**（register file，32k × 32 位）；
- **特殊功能单元**（special function unit, SFU，图里 4 个）；
- **共享存储/L1 Cache**（shared memory/L1 cache，64 kB）。

第 13 页的**双 warp 调度器**（dual warp scheduler；warp 一般译作线程束）：

- **芯片上的 GigaThread 全局调度单元把线程块分给各个 SM；**
- **双 warp 调度器再把它正在处理的每个线程块切成若干个 warp，每个 warp 32 个线程；**
- **程序员设定的线程块大小，应该大于一个 SM 里 CUDA 核的总数，但小于每块允许的最大线程数。**

把第 9、11、13 页和第 14–16 页合起来，就是第 26 页"块怎样在 SM 上执行"的答案（这一段是我整理的）：GigaThread 先把各个块分给各个 SM，一个块整个分给一个 SM，不跨 SM；SM 的双 warp 调度器把块切成 32 个线程一组的 warp；每个 warp 的 32 个线程执行同一条指令，由分派单元送到 CUDA 核上，要算地址的送到存取单元、要算超越函数的送到 SFU（这三个去处是按第 12 页的框图读出的）。warp 就是这样一组 32 个、一起被调度的线程。

第 6 页说核函数里的分支会让线程串行执行，原因就在 warp：一个 warp 的 32 个线程同时只执行同一条指令，分支两边的线程只能分批轮流执行（这一句是我补的）。

### 4.4 CUDA 核、SFU 与存取单元

**CUDA 核**，课件第 14 页（图里一个 CUDA 核由分派端口、操作数收集器、FP 单元、INT 单元和结果队列组成）：

- **Fermi 架构里每个 SM 有 32 个 CUDA 核；**
- **每个核有一条整数（INT）流水线和一条浮点（FP）流水线，一个时钟周期里只能用其中一条；**
- **INT 单元能做 32 位、64 位和扩展精度的整数运算与逻辑/按位运算；**
- **FP 单元能做单精度浮点运算，双精度浮点运算要用两个 CUDA 核；**
- **所以双精度浮点运算的时间是单精度的两倍。**

**特殊功能单元**，课件第 15 页：

- **SFU 在一个时钟周期内完成超越函数运算，如余弦、正弦、倒数和平方根；**
- **一个 SM 只有 4 个 SFU，而一个 warp 里是 32 个执行同一条指令的线程，所以一个要用 SFU 的 warp 要 8 个时钟周期才能做完**（$32 / 4 = 8$）。

**存取单元**，课件第 16 页：

- **SM 的 16 个存取单元，每个在一个时钟周期里为一个线程算出源地址和目的地址；**
- **这些地址指向线程要读写的 Cache 或 DRAM。**

照 SFU 的算法，一个 warp 的 32 个线程算地址要 $32 / 16 = 2$ 个时钟周期（这一句是我按第 15 页的算法推的）。

## 5 GPU 的存储

### 5.1 寄存器、共享存储与 L1 Cache

课件第 20 页：

- **每个 SM 有自己专用的（片上）寄存器组和共享存储/L1 Cache；**
- **每个 SM 有 32k 个 32 位寄存器；按 CUDA 计算能力 2.x 的规定，每个线程最多分到 64 个 32 位寄存器**（受每个 SM 最多同时活动的 warp 数和寄存器总数限制）。

第 22 页的图把 Fermi 的存储层次画了出来（按图读出）：

- 一个 SM 里：**128 kB 的寄存器堆**（32k × 32 位正好是 128 kB，这一句是我算的）；32 个核共用一块 64 kB 的存储，**分成 x kB 的共享存储和 (64 − x) kB 的 L1 数据 Cache**；另有 **64 kB 的 L1 指令 Cache**；
- 16 个 SM 共用一块 **768 kB 的 L2 Cache**，L2 下面是 DRAM。

### 5.2 六种存储的比较

课件第 21 页的表：

| 存储 | 相对访问时间 | 读写 | 谁能访问 | 存活多久 |
| --- | --- | --- | --- | --- |
| **寄存器**（registers） | 最快，片上 | 读写 | 单个线程 | 线程 |
| **共享存储**（shared memory） | 快，片上 | 读写 | 块里的所有线程 | 块 |
| **局部存储**（local memory） | 比共享存储和寄存器慢 100 到 150 倍，片外 | 读写 | 单个线程 | 线程 |
| **全局存储**（global memory） | 比共享存储和寄存器慢 100 到 150 倍，片外 | 读写 | 所有线程和主机 | 整个应用 |
| **常量存储**（constant memory） | 比共享存储和寄存器慢 100 到 150 倍，片外 | 只读 | 所有线程和主机 | 整个应用 |
| **纹理存储**（texture memory） | 比共享存储和寄存器慢 100 到 150 倍，片外 | 只读 | 所有线程和主机 | 整个应用 |

### 5.3 同一个 SM 里的线程只能经共享存储协作

课件第 23 页：

- **在 GPU 架构里，分到一个 CUDA 核上的每个线程都有自己的一组寄存器，一个线程不能访问另一个线程的寄存器，即使两者在同一个 SM 里也不行；**
- **同一个 SM 里的线程要互相协作（共享数据），唯一的办法是经过共享存储；**
- **通常的做法是由程序员只让 SM 里的某些线程去写共享存储的特定位置。**

第 21 页的表里共享存储的作用范围是一个块，所以不同块的线程要交换数据，只能经过全局存储（这一句是我按第 21 页推的）。

这一页的图（按图读出）：网格里的每个块有自己的共享存储，块里每个线程有自己的寄存器；全局存储和常量存储在所有块之外，主机（Host）也能访问它们。

## 6 什么时候把 GPU 当协处理器用

课件第 24 页：

- **程序里有高度可并行的部分，这部分能复制成几千个轻量级线程，同时处理大量数据。**
- **轻量级线程**（lightweight thread）**指一段相对小、可大规模并行、没有或几乎没有分支的代码的一个实例。**

GPU 只加速能并行的那一部分，剩下的串行部分仍在 CPU 上跑，整体能快多少还是由 [[L17 多核计算机#2.1 定律|Amdahl 定律]]决定（这一句是我补的）。

## 7 附录：向量加法的 CUDA 程序

课件第 27–29 页是一个向量加法程序的几段代码（图片）。下面按执行顺序排开，括号里注明各步属于 [[#2.1 CUDA 是什么|第 6 页的三部分]]里的哪一部分（归类是我做的）：

1. **在主机和设备上分配存储**（第 27 页；主机代码）：向量长度 `n = 1 << 16`，即 65536 个元素；`bytes = sizeof(int) * n`；主机上用 `malloc` 给 `h_a`、`h_b`、`h_c` 分配，设备上用 `cudaMalloc` 给 `d_a`、`d_b`、`d_c` 分配。
2. **把数据从主机拷到设备**（第 28 页；传数据的代码）：`cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);`，`d_b` 同样。
3. **定每块的线程数和块数**（第 29 页；主机代码）：每块 `NUM_THREADS = 256` 个线程，块数 `NUM_BLOCKS = (int)ceil(n / NUM_THREADS)`，65536 / 256 = 256 个块。
4. **核函数**（第 29 页；设备代码。`__global__` 表示这个函数在 GPU 上运行、由主机调用；注释是我译的，省掉了文件开头的 `#include` 几行）：

   ```c
   __global__ void vectorAdd(int* a, int* b, int* c, int n) {
       int tid = (blockIdx.x * blockDim.x) + threadIdx.x;  // 全局线程号
       if (tid < n) {                                     // 越界保护
           c[tid] = a[tid] + b[tid];                      // 每个线程加一个元素
       }
   }
   ```

5. **像调用 C 函数一样启动核函数，并给出块数和每块线程数**（第 29 页；主机代码）：`vectorAdd<<<NUM_BLOCKS, NUM_THREADS>>>(d_a, d_b, d_c, n);`
6. **把结果从设备拷回主机**（第 28 页；传数据的代码）：`cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);`

核函数里的 `tid = blockIdx.x * blockDim.x + threadIdx.x` 就是 [[#3.2 线程的全局位置与线性地址|全局位置的算法]]"块号 × 每块线程数 + 块内编号"的一维版本：`blockIdx.x` 是块号，`blockDim.x` 是每块的线程数，`threadIdx.x` 是线程在块内的编号（三个变量名的意思是我按代码解释的）。`if (tid < n)` 是因为块数一般向上取整，最后一个块里可能有多出来的线程，它们的 `tid` 超出数组，不能去读写（这一句是我补的）。

> [!warning] `ceil(n / NUM_THREADS)` 在 n 除不尽时会少开一个块
> 误：以为 `(int)ceil(n / NUM_THREADS)` 总是向上取整。
> 正：`n` 和 `NUM_THREADS` 都是整数，`n / NUM_THREADS` 先按整数除法截断，`ceil` 拿到的已经是整数，起不了作用；n 除不尽 256 时会少开一个块，最后几个元素没人算。课件里 65536 正好是 256 的倍数，所以没出问题。常见的写法是 `(n + NUM_THREADS - 1) / NUM_THREADS`（这一段是我补的）。

## 本讲速记

- **GPU**：为快速三维图形渲染与视频处理优化；嵌入式里的小 GPU 只有个位数的核，常和几个 CPU 核做在一起。
- **CPU 与 GPU 的区别**：CPU 的芯片大部分是控制逻辑和 Cache，调校成尽快执行顺序代码；GPU 用大规模并行的 SIMD 结构做数学运算，不需要乱序执行、转移预测、处理数据冒险这些复杂控制，也不需要大量 Cache。
- **三个阶段**：固定、不可编程的专用处理级（1980 年代初到 1990 年代末）→ 改造成完全可编程的处理器（2000 年代初到中期）→ NVIDIA 2006 年推出 CUDA，GPU 成为高度并行的 SIMD 协处理器。
- **CUDA**：NVIDIA 的并行计算平台和编程模型；CUDA C 基于 C/C++；程序分主机代码、设备代码、主机与设备之间传数据的代码三部分；在 GPU 上运行的数据并行代码叫**核函数**，**线程**是核函数的一个实例；核函数里通常很少甚至没有分支，分支会让线程串行执行。
- **线程、块、网格**：程序员决定启动多少线程（通常几千个）；线程打包成**块**，一次启动的全部块是一个**网格**；线程对应 CUDA 核，块对应 SM，网格对应整个 GPU；**一个块只分给一个 SM**。
- **编号与地址（第 8、17–19 页）**：每块的线程数 = 该方向线程总数 ÷ 该方向块数；全局位置 = 块号 × 每块线程数 + 块内编号；行优先的线性地址 = Y × X 方向线程总数 + X。第 19 页的例子：(491, 844)，地址 **1,729,003**；第 17 页的练习：每块 64 × 128，(87, 1581)，地址 **3,237,975**（我算的）。
- **Fermi**：16 个 SM × 32 个 CUDA 核 = 512 个；L2 在芯片中央；6 个 64 位 DRAM 接口共 384 位；PCIe 连 CPU；GigaThread 把块分给各 SM 的 warp 调度器。
- **SM**（流多处理器）：32 个 CUDA 核、warp 调度器与分派单元各 2 个、16 个存取单元、32k × 32 位寄存器堆、4 个 SFU、64 kB 共享存储/L1 Cache。**warp 是 32 个线程一组、一起被调度的单位**；GigaThread 把块分给各 SM，**SM 的双 warp 调度器把块切成 warp**；块的大小应大于一个 SM 的 CUDA 核数、小于每块允许的最大线程数。
- **CUDA 核**：一条 INT 流水线、一条 FP 流水线，每个时钟周期只用一条；双精度要两个核、时间翻倍。**SFU**：一个周期算一次正弦、余弦、倒数、平方根，4 个 SFU 做完一个 warp 要 **8 个周期**。**存取单元**：16 个，每个每周期给一个线程算一次源、目的地址。
- **存储**：寄存器每线程私有、最快；共享存储片上、块内共享；局部、全局、常量、纹理存储在片外，比寄存器和共享存储慢 100 到 150 倍；全局、常量、纹理存储所有线程和主机都能访问，常量与纹理只读。每个 SM 一块 64 kB，分成共享存储和 L1 数据 Cache；16 个 SM 共用 768 kB L2。**同一个 SM 里的线程只能经共享存储协作。**
- **何时用 GPU 当协处理器**：程序里有能复制成几千个轻量级线程、同时处理大量数据的高度可并行部分；轻量级线程是一段小的、可大规模并行、几乎没有分支的代码的一个实例。
