# L17 多核计算机

> [!info] 这一讲的骨架
> [[L16 并行处理#2 对称多处理器（SMP）|L16 的对称多处理器]]是几个处理器共享一个主存；这一讲把几个处理器核做进同一块芯片，也就是多核。
> 主线一句话：**流水线、超标量、同时多线程一步步挖指令级并行，但单核越做越复杂，性能只按复杂度的平方根增长，于是改成在一块芯片上放多个核；多核能快多少由 Amdahl 定律决定，程序里不能并行的那一部分定下了加速比的上限；多核芯片按各级 Cache 由谁独占、由谁共享分成几种组织；还可以把 CPU、GPU 这些不同种类的核（以及 FPGA）做在同一块芯片上，叫异构多核。**

## 1 为什么走到多核

### 1.1 多核是什么

课件第 3 页：**多核处理器**（multicore processor），**也叫片上多处理器**（chip multiprocessor），**把两个或更多处理器单元——叫作核**（core）**——集成在同一块硅片上**，这块硅片叫**管芯**（die）。

- **每个核通常具备一个独立处理器的全部部件**：**寄存器、ALU、流水线硬件、控制单元，外加 L1 指令 Cache 与 L1 数据 Cache**。
- **除了这些核，现代多核芯片还集成了 L2 Cache，而且越来越多地集成 L3 Cache**（多级 Cache 见 [[L09 高速缓存#9.1 为什么要做多级|L09 的多级 Cache]]）。
- **集成度最高的多核处理器叫片上系统**（systems on chip, SoC），**连存储控制器和外设控制器也做在芯片上**。

### 1.2 三步变化：流水线、超标量、同时多线程

课件第 4 页：**处理器设计在组织上的变化，主要都是为了利用指令级并行（ILP），让每个时钟周期做更多的事**（指令级并行见 [[L15 指令级并行#3.1 指令级并行与机器并行|L15 的指令级并行]]）。这些变化**依次是**：

1. **流水线**（pipelining），见 [[L14 处理器结构与功能#4 指令流水线|L14 的指令流水线]]；
2. **超标量**（superscalar），见 [[L15 指令级并行#1 超标量：同一时刻发射几条指令|L15 的超标量]]；
3. **同时多线程**（simultaneous multithreading, SMT）：**多个线程可以共用流水线的资源**。线程是轻量级进程：一个进程里可以有多个线程，它们共享同一份系统资源（见 [[L04 操作系统概述#8.3 程序、进程、任务、线程|L04 的进程与线程]]）。

第 4 页的标题是 Alternative Chip Organizations（几种可选的芯片组织），右侧三张框图画的是超标量、同时多线程、多核三种芯片组织，流水线没有单独画：

- **超标量**：一个程序计数器、一套单线程的寄存器堆，取指单元与几个执行单元共用一组发射逻辑，下面是 L1 指令 Cache、L1 数据 Cache 和 L2 Cache；
- **同时多线程**：取指单元、执行单元和 Cache 都与超标量相同，但有 **n 个程序计数器和 n 套寄存器**，每个线程一套，几个线程的指令一起送进同一组执行单元；
- **多核**：n 个核并排，**每个核本身可以是超标量或同时多线程的**，各带 L1 指令与数据 Cache，再共用一块 L2 Cache。

多核不属于上面那三步变化。为什么从挖指令级并行转向多核，是下面 [[#1.3 单核做大不划算：功耗、Pollack 规则|单核做大不划算]]这一节的内容。

### 1.3 单核做大不划算：功耗、Pollack 规则

课件第 5 页的标题是 Power and Memory Consideration（功耗与存储方面的考虑）：

- **高效地利用晶体管，是处理器设计的一个关键挑战。**
- **Pollack 规则**（Pollack's rule）：**性能的提升与复杂度提升的平方根成正比**。**例如，把一个核的逻辑（复杂度）加倍，性能只提升 40%**：复杂度变为 2 倍时，性能变为原来的 $\sqrt{2} \approx 1.41$ 倍，即提升约 41%，课件取整说 40%（这句换算是我补的）。
- **超标量与同时多线程在进一步提升性能上遇到了限制。**
- **多核的办法：用多个核可以得到接近线性的性能提升，但前提是软件为并行处理做过优化。**

这一页配的图是逻辑电路与存储器的功率密度（单位面积的功耗）随特征尺寸（feature size，工艺能做出的最小线宽）缩小而上升的曲线，纵轴是对数刻度：特征尺寸从 0.25 μm 缩到 0.10 μm，逻辑电路从约 28 W/cm² 升到约 94 W/cm²，存储器从约 3 W/cm² 升到约 17 W/cm²，存储器始终比逻辑低五到十倍（数值按图读出）。课件没有写这张图要说明什么。按图能读出两点：功率密度随工艺缩小一路上升，在一个核里堆更多高速逻辑，单位面积的发热会越来越难压住；同样大的芯片面积做成存储器（如 Cache），功耗要低得多（这两句是我补的推论）。

## 2 Amdahl 定律：多核能快多少

### 2.1 定律

课件第 6 页先给出**加速比**（speedup）的定义：

$$
\text{加速比} = \frac{\text{程序在单个处理器上的执行时间}}{\text{程序在 } N \text{ 个并行处理器上的执行时间}}
$$

然后是 **Amdahl 定律**（Amdahl's law）：设 $f$ 是系统或程序中**能并行的比例**，$1 - f$ 是**仍然只能串行的比例**，那么用 $N$ 个处理器**能得到的最大加速比**是

$$
\text{加速比} = \frac{1}{(1 - f) + \dfrac{f}{N}}
$$

式子的来历（课件只给了结论，推导是我补的）：把单处理器上的执行时间记作 1，其中 $1 - f$ 只能串行，$f$ 能分给 $N$ 个处理器。串行那一段用多少个处理器都还是 $1 - f$；能并行的那一段被 $N$ 个处理器均分，缩成 $f / N$。新的执行时间就是 $(1 - f) + f / N$，用 1 除以它，就是 Amdahl 定律的式子。"最大"两个字的意思是：这里假设并行那一段能被完美均分、而且没有任何额外开销。

从式子能直接读出两点：

- $N$ 越大，$f / N$ 越小，但分母永远不会小于 $1 - f$，所以**加速比的上限是** $1 / (1 - f)$，加多少处理器都超不过它；
- 上限只由 $f$ 决定。$f = 0.9$ 时上限是 10，$f = 0.6$ 时只有 2.5。

### 2.2 课件的第一个例子：8 个处理器

课件第 7 页：**如果代码里只有 10% 是固有串行的，在 8 个处理器的多核系统上运行，性能能提升多少？** 于是 $f = 0.9$，$N = 8$：

$$
\text{加速比} = \frac{1}{0.1 + \dfrac{0.9}{8}} = \frac{1}{0.2125} \approx 4.71
$$

课件写作 4.70；精确值是 $80/17 \approx 4.7059$，保留两位小数应为 4.71（4.70 像是截断所致，这是推断）。8 个处理器只快了不到 5 倍，因为那 10% 的串行部分在 8 核上占掉了将近一半的时间（$0.1 / 0.2125 \approx 47\%$，这个比例是我算的）：

![[L17 Amdahl 定律的时间条.png]]

第 10 页的图画的是串行部分分别占 0%、2%、5%、10% 时加速比随处理器个数的变化：0% 是一条斜率为 1 的直线，8 个处理器时正好是 8；串行部分越大，曲线越早弯下来，10% 那条在 8 个处理器时约为 4.7。

### 2.3 课件的第二个例子：5 台计算机的集群

课件第 8–9 页是一道集群上的题。集群是一组互连起来、作为一个计算资源一起工作的完整计算机（见 [[L16 并行处理#1.2 MIMD 再往下分：共享存储与分布式存储|L16 里集群的定义]]）。题干：

> **Problem:** An application program is executed on a 5-computer cluster. A benchmark program took time T on this cluster. Further, it was found that 40% of T was the time in which the application was running simultaneously on all five computers. For the remaining time, the application had to run on a single computer.
> Calculate the effective speedup under the afore-mentioned condition as compared to executing the program on a single computer.（第 8 页）
> Calculate the percentage of code that has been parallelized（第 9 页）

这道题给的是**集群上**的时间分配：总时间 $T$ 里，$0.4T$ 是 5 台同时在跑，$0.6T$ 只有 1 台在跑。两页的图把 5 台计算机画成 5 行：第一行先跑 $0.6T$ 的串行任务，再跑 $0.4T$ 的并行任务；其余 4 行前 $0.6T$ 空着，后 $0.4T$ 跑并行任务。课件的解法是把这些活全部挪到一台计算机上，看它要跑多久：

- **有效加速比**（第 8 页）：原来另外 4 台做的并行任务都挪到这一台上，多花 $4 \times 0.4T = 1.6T$；单机总时间 $(1 + 1.6)T = 2.6T$，**加速比 2.6**。
- **并行化代码的比例**（第 9 页）：并行代码在单机上要跑 $5 \times 0.4T = 2T$，串行代码 $0.6T$，**并行化的比例是 $2 / 2.6 \approx 76.9\%$**。第 9 页的算式把 $T$ 写成了 $X$，是同一个量。

用 Amdahl 定律复核（这一步是我补的）：$f = 2/2.6 = 10/13$，

$$
\frac{1}{\left(1 - \dfrac{10}{13}\right) + \dfrac{10/13}{5}} = \frac{1}{3/13 + 2/13} = \frac{13}{5} = 2.6
$$

这个例子与下面的 [[#2.4 真题现场：2022 卷 Q4(b) 九机集群|2022 卷 Q4(b)]] 几乎同题：题干是同一套说法，只是台数和百分比不同（课件 5 台、40%，真卷 9 台、25%）；真卷 (i) 把加速比和并行化比例合成一问，另有 (ii) 改用 17 台，课件没有这一问。

### 2.4 真题现场：2022 卷 Q4(b) 九机集群

> (b) An application program is executed on a nine-computer cluster. A benchmark program took time T on this cluster. Further, it was found that 25% of T was the time in which the application was running simultaneously on all nine computers. For the remaining time, the application had to run on a single computer.
> (i) Calculate the effective speedup under the aforementioned condition as compared to executing the program on a single computer. Also, calculate the percentage of code that has been parallelized (programmed or compiled so as to use the cluster mode) in the preceding program. [6]
> (ii) Suppose that we are able to effectively use 17 computers rather than 9 computers on the parallelized portion of the code. Calculate the effective speedup that is achieved. [2]

和 [[#2.3 课件的第二个例子：5 台计算机的集群|课件的集群例子]]一样，题目给的是**集群上**的时间分配，要先换算回单机：Amdahl 定律里的 $f$ 是按单机执行时间算的比例。

**(i) 答案**：

1. 集群上：$0.25T$ 是 9 台同时在跑，$0.75T$ 只有 1 台在跑。
2. 换到单机上：那 $0.25T$ 里 9 台各干了 $0.25T$ 的活，换成一台单机全干，用时 $9 \times 0.25T = 2.25T$（假设 9 台都在干有用的活、没有额外开销）；只有 1 台在跑的那 $0.75T$ 不变。单机总时间 $= 2.25T + 0.75T = 3T$。
3. 有效加速比 $= \dfrac{3T}{T} = 3$。
4. 并行化代码的比例，按单机执行时间算：$f = \dfrac{2.25T}{3T} = 0.75$，即 **75%**。
5. 用 Amdahl 定律复核：$\dfrac{1}{(1 - 0.75) + 0.75 / 9} = \dfrac{1}{1/3} = 3$。

**(ii) 答案**：并行部分改用 17 台，$f = 0.75$ 不变：

$$
\text{加速比} = \frac{1}{(1 - 0.75) + \dfrac{0.75}{17}} = \frac{1}{5/17} = \frac{17}{5} = 3.4
$$

台数几乎翻倍，加速比只从 3 涨到 3.4：串行部分占单机时间的 $1 - f = 0.75T / 3T = 0.25$，上限是 $1 / (1 - 0.75) = 4$。

> [!warning] 25% 不是 f，也不是串行比例
> 题目里的 25% 是**集群上**那段并行时间占集群总时间 $T$ 的比例。Amdahl 定律里的 $f$ 是能并行的部分占**单机**执行时间的比例。直接拿 $f = 0.25$ 去算，得到 $1 / (0.75 + 0.25/9) \approx 1.29$，是错的；正确的 $f$ 是 0.75。
> 把 25% 当成串行比例（$1 - f = 0.25$），这道题碰巧也能算出 3 和 3.4，因为 9 台时单机上的串行比例恰好也是 0.25。换一组数就对不上了：课件那道 5 台、40% 的例子，把 40% 当成串行比例，算得 $1 / (0.4 + 0.6/5) \approx 1.92$，课件的答案是 2.6（这一段是我补的）。

### 2.5 真题现场：2023 卷 Q4(c) 六台处理器

> (c) You are working on a computation that can be divided into two parts: a parallelizable portion and a sequential portion. The parallelizable portion accounts for 60% of the original execution time, and the remaining 40% is sequential and cannot be parallelized. You currently have 6 parallel processors to speed up the computation.
> (i) Calculate the theoretical speedup you can achieve with the current setup of 6 parallel processors. [2]
> (ii) How many additional processors would you need to add to achieve a 50% increase in speedup compared to the current setup (with 6 parallel processors)? [2]

这道题的 60% 是按"原来的执行时间"给的，就是 $f$：$f = 0.6$，$1 - f = 0.4$。

**(i) 答案**：

$$
\text{加速比} = \frac{1}{0.4 + \dfrac{0.6}{6}} = \frac{1}{0.5} = 2
$$

**(ii) 答案**：比现在提高 50%，目标加速比是 $2 \times 1.5 = 3$。要 $\dfrac{1}{0.4 + 0.6/N} = 3$，就得 $0.4 + 0.6/N = 1/3$，即 $0.6/N = 1/3 - 2/5 = -1/15$，$N = -9$——没有正数解。换个角度：加速比的上限是 $1/0.4 = 2.5$，目标 3 比上限还高。**所以加多少处理器都做不到**；就算处理器无穷多，加速比也只能逼近 2.5，提高的幅度只能逼近 25%，达不到。

这样读，这一问没有一个"加几台"的数字答案，结论由 [[#2.1 定律|Amdahl 定律的上限]]决定：串行部分占 40%，加速比就封顶在 2.5。

> [!note] (ii) 的另一种读法
> 如果把 (ii) 的 speedup 理解成**并行那一段**的提速：6 台时这一段快了 6 倍，提高 50% 是 9 倍，也就是用 9 台、再加 3 台。这样算，整体加速比是 $1 / (0.4 + 0.6/9) = 15/7 \approx 2.14$，只比现在高约 7%。(i) 问的是整体加速比，(ii) 用的是同一个词 speedup，按同一个意思读，结论是做不到；手上的两份真卷都没有附答案，出题人想要哪一种读法核实不了（这一段是我补的）。

### 2.6 开销让曲线先升后降

课件第 11 页：**软件通常还会有开销，来自在多个处理器之间通信和分配工作，以及维护缓存一致性**（缓存一致性见 [[L16 并行处理#4 缓存一致性|L16 的缓存一致性]]）。**这些开销让性能曲线先升到一个峰值，然后因为使用多个处理器的开销（例如协调与操作系统管理）越来越重而开始下降。**

这一页的图里，四条曲线标着 5%、10%、15%、20%（课件没有说明这几个百分比指什么），都在 5 个处理器左右到顶，峰值约 1.9 到 2.3，之后随处理器增多而下降（按图读出）。Amdahl 定律的式子里没有这一项，所以它给出的是不计开销时的上限。

## 3 能用好多核的应用，以及多核的组织

### 3.1 哪些应用能用好多核

课件第 12 页接着第 11 页的 [[#2.6 开销让曲线先升后降|开销]]说：**软件工程师一直在解决这个问题，已经有大量应用能有效地利用多核系统**（**重点就在减小串行部分的比例**）：

- **数据库管理系统**；
- **多线程的原生应用**（**线程级并行**，thread-level parallelism）；
- **多进程应用**（**进程级并行**，process-level parallelism）；
- **Java 应用**；
- **多实例应用**（**应用级并行**，application-level parallelism）。

后四类课件只列了名字，这几句解释是我按名字补的：原生应用指直接编译成本机机器码运行的程序，多线程的原生应用在一个进程里开多个线程并行；多进程应用由多个进程并行；Java 语言本身支持多线程，运行 Java 程序的 Java 虚拟机也是多线程的；多实例应用是同一个应用同时跑几份。

这一页的图是四种数据库负载在多处理器硬件上的扩展性（Scaling of Database Workloads on Multiple-Processor Hardware）：横轴是 CPU 个数，纵轴是扩展倍数；到 64 个 CPU 时，四条曲线约在 52 到 62 之间（完美扩展是 64），最高的 Oracle DSS 4-way join 约 62，最低的 Oracle ad hoc insurance OLTP 约 52（按图读出）。

### 3.3 四种 Cache 组织

课件第 14–17 页按 Cache 的分配，给了四种一般组织，各配一个实例：

## 4 异构多核

### 4.1 什么是异构多核

课件第 20 页：**异构多核**（heterogeneous multicore）**指一块处理器芯片上有不止一种核**。

- **最突出的趋势，是在同一块芯片上同时使用 CPU 和图形处理器**（graphics processing unit, GPU）；**不过这种混合会带来协调与正确性方面的问题**。
- **GPU 的特点是能支持数以千计的并行执行线程**（课件原文作 "execution trends"，应为 threads）。
- **所以 GPU 很适合处理大量向量与矩阵数据的应用。**

这一页右侧的配图把两者并排：CPU 为串行任务优化（Optimized for Serial Tasks），画的是四个大核；GPU 为并行任务优化（Optimized for Parallel Tasks），画的是大量小核。

GPU 本身的结构是 [[L18 通用图形处理器]]的内容。

### 4.2 异构芯片里有什么，以及 HSA

课件第 21 页的图（标题 Heterogenous Multicore Chip Elements，异构多核芯片的组成；旧版这页标着教材图 18.7，新版没有标）：几个 CPU 核和几个 GPU 核各带 Cache，通过一个**片上互连网络**连在一起；网络上还挂着一块**现场可编程门阵列**（field-programmable gate array, FPGA，一种硬件电路可以重新配置的芯片，见 [[#4.3 FPGA：硬件可编程|FPGA 一节]]）、几块**末级 Cache**（last-level cache）和两个 **DRAM 控制器**。

课件第 22 页的**异构系统架构**（Heterogeneous System Architecture, HSA）有这几个关键特点：

- **整个虚拟存储空间对 CPU 和 GPU 都可见**；
- **虚拟存储系统按需把页调入物理主存**；
- **一致的存储策略保证 CPU 与 GPU 的 Cache 看到的数据都是最新的**；
- **统一的编程接口**，让用户在依靠 CPU 执行的程序里也能用上 GPU 的并行能力。**总的目标是让程序员写出的应用能同时：发挥 CPU 的串行能力、发挥 GPU 的并行处理能力、发挥 FPGA 的专用设计能力，并在操作系统与硬件层面高效协调。** **这仍是一个正在研究与发展的领域。**

第 23–28 页是几个实例和一张示意图：NVIDIA 的 CPU–GPU 芯片（第 23 页）、德州仪器的 CPU–DSP 芯片（第 24 页）、一张 CPU–GPU–FPGA 的示意图（第 25 页）、AMD Xilinx 的 Zynq 与 Versal 系列 SoC（第 26–28 页）。有成段文字的只有第 24 页。

第 24 页的德州仪器芯片（DSP 在这里指数字信号处理器，digital signal processor）：

- **4 个 ARM Cortex-A15 CPU 核：做通用处理，共用一块 4 MB 的 L2 Cache**；
- **8 个 C66x DSP 核：加速数学密集的信号处理，每个核有独占的 L1 Cache 和 1 MB 可配置的 L2 Cache/SRAM**；
- **6 MB 的共享存储**（课件记作 MSM）：**所有 CPU 核、DSP 核和系统里的其他部件都能访问**；
- **应用：高端成像、视频监控、工业自动化与检测。**

**这一页的要点：CPU 处理通用任务，DSP 高效地完成数字信号上的密集数学运算。**

第 25 页是一张示意图：软件可编程（Software Programmability）加硬件可编程（Hardware Programmability），箭头指向系统性能、灵活性、可扩展性三项（按图读出）。其余几页以框图和产品介绍为主。

### 4.3 FPGA：硬件可编程

课件第 29–33 页讲 FPGA 的硬件可编程（hardware programmability）。

**FPGA 是一种集成电路，它提供**：

- **实现任何可综合逻辑的灵活性**（可综合逻辑指能用综合工具从硬件描述自动转换成电路的逻辑，这句解释是我补的）；
- **在逻辑之间实现任意互连的灵活性**；
- **给 FPGA 的引脚指定任意工作方式、并支持大量 I/O 标准的灵活性**。

**适合用 FPGA 的场合**：

- **需要数字系统的原型、概念验证或培训时**；
- **需要专用的数字系统芯片，但数量少、或时间紧时**；
- **要用硬件资源与系统性能来报告研究结果时**。

它的结构，第 30 页两条：**基于可配置逻辑块**（configurable logic block, CLB）**矩阵的半导体器件**，**逻辑块之间经可编程的互连相连**。下面三样是逻辑块里外的主要部件。

**查找表**（look-up table, LUT），第 31 页：**6 输入查找表相当于一块 64 × 1 的存储器**；**6 个输入信号选中 64 个存储值中的一个，这个存储值就是输出**；**一个 6 输入查找表能实现任意一个 6 输入逻辑函数，或两个各自的 5 输入函数**（两个函数共用同一组输入）。图上标着存进去的就是真值表（Truth table stored in memory），地址来自 A6–A1；之所以是 64 个值，是因为 6 个输入共有 $2^6 = 64$ 种取值，每种取值对应真值表的一行（这半句是我补的）。

这一页下面那张图画的是它的内部（按图读出）：6 输入查找表由两块存储器构成，各有 A1–A5 五根地址线（即 32 个单元）和一根输出。A1–A5 同时接到两块存储器的地址线上，A6 接在输出端一个二选一多路选择器的选择端：A6 决定 O6 输出哪一块读出的位，合起来就是一个 6 输入函数。下面那块的输出还单独引出为 O5；把 A6 固定、让选择器一直选上面那块，O6 与 O5 各出一块的结果，就是两个 5 输入函数，它们共用 A1–A5 这一组输入（怎样当两个 5 输入函数用，是我按图推的）。

同一页右边是一个**片**（slice）：

- **一个片里有多个查找表**（图里画了 4 个）；
- **F7AMUX、F7BMUX 把查找表的输出合起来，实现更宽的函数**（如 7 输入的逻辑函数）；
- **可选的寄存器（D、Q、CLK）能把输出存下来，于是可以做时序逻辑**；
- **一个片有两路输出，各带一个多路选择器和一个可选的寄存器**。

**DSP 块**（DSP 在这里指数字信号处理，digital signal processing），第 32 页：

- **专门做快速数字信号处理的硬件**；
- **完成乘累加**（multiply–accumulate, MAC）：**把几个值相乘，再把结果加起来**；
- **预加器**（pre-adder）**可以在乘法之前先把输入值相加**；
- **用于数字滤波器、图像处理、无线通信等应用**。

这一页的图（按图读出）：上面是一个系数对称的滤波器（$h(0) = h(4)$、$h(1) = h(3)$），系数相同的两个输入先相加、再乘一次系数，每对省一次乘法，5 个系数只做 3 次乘法（这句是我按图算的）。三支箭头都从中间那一路（$h(1) = h(3)$）引出：它的预加、乘法，和把乘积并入求和链的那次加法，分别指到下面 DSP 块里的预加器、乘法器和后面的加法器上。

**BRAM**（block RAM，块存储器），第 33 页：**FPGA 里专用的存储块，用来高速存数据**（图里每块举例为 36 Kb），**可以配成三种**：

- **单端口 RAM：只有一个访问端口，读或写；一次只能做一个操作；配置最简单。**
- **简单双端口 RAM：一个端口写、一个端口读；读和写可以同时进行；适合做缓冲**（例如生产者写、消费者读）。
- **真双端口 RAM：两个独立的端口，都能同时读或写；配置最灵活。**

端口上的信号：**地址**（ADDR）指定访问哪个单元，**数据输入**（DI）是要写进去的数据，**数据输出**（DO）是读出来的数据，**写使能**（WE）控制能不能写，**时钟**（CLK）让存储器的操作同步。同一页还有一张简化的 FPGA 架构图：逻辑单元、BRAM、DSP 块排在中间，两边是 I/O 块，彼此经可编程互连（布线）相连。

## 本讲速记

- **多核处理器**（片上多处理器）：两个或更多核集成在同一块硅片（管芯）上；每个核有寄存器、ALU、流水线硬件、控制单元和 L1 指令、数据 Cache；芯片上还有 L2，越来越多还有 L3；集成度最高的叫 **SoC**，连存储控制器与外设控制器也在芯片上。
- **增加指令级并行的三步**：**流水线 → 超标量 → 同时多线程**（多个线程共用流水线资源；每个线程一个程序计数器、一套寄存器）。多核不在这三步里；多核的每个核可以是超标量或同时多线程的。
- **为什么走到多核**：高效利用晶体管是关键挑战；**Pollack 规则——性能提升与复杂度提升的平方根成正比，逻辑加倍性能只提升 40%**（$\sqrt{2} \approx 1.41$ 倍）；超标量与同时多线程再往上提升有限；多核能接近线性提升，**前提是软件为并行做过优化**。
- **加速比** = 单处理器上的执行时间 ÷ N 个处理器上的执行时间。**Amdahl 定律（Sample Q1）**：加速比 = 1 / ((1 − f) + f/N)，f 是能并行的比例；**上限 1/(1 − f)**，由串行部分决定。课件第一个例子：f = 0.9、N = 8，约 4.71（课件写 4.70）。
- **课件的集群例子（第 8–9 页，与 2022 卷 Q4(b) 几乎同题）**：5 台、40% 的时间 5 台同时在跑 → 单机时间 = 5 × 0.4T + 0.6T = 2.6T，**加速比 2.6**，**并行化比例 2/2.6 ≈ 76.9%**。
- **2022 卷 Q4(b)（8 分）**：25% 是集群时间的比例，先换回单机：单机时间 = 9 × 0.25T + 0.75T = 3T，**加速比 3，并行化比例 f = 2.25T/3T = 75%**；改用 17 台：1/((1 − 0.75) + 0.75/17) = **3.4**。
- **2023 卷 Q4(c)（4 分）**：f = 0.6、N = 6，加速比 1/(0.4 + 0.1) = **2**；要提高 50% 即达到 3，但上限是 1/0.4 = **2.5**，**加多少处理器都做不到**；若把 speedup 读成并行那一段的提速，是再加 3 台（[[#2.5 真题现场：2023 卷 Q4(c) 六台处理器|两种读法]]）。
- **开销**：通信、分配工作、缓存一致性带来的开销，让加速比曲线先升后降。
- **能用好多核的应用**：数据库管理系统、多线程原生应用（线程级并行）、多进程应用（进程级并行）、Java 应用、多实例应用（应用级并行）；关键是减小串行部分。
- **多核组织的五个变量**：核的个数、Cache 的级数、Cache 怎样共享、是否用同时多线程、核的类型。**四种 Cache 组织（Sample Q2 多核系统的存储怎样组织）**：独占 L1（ARM11 MPCore）、独占 L2（AMD Opteron）、共享 L2（Intel Core Duo）、共享 L3（Xeon E5-2600）。
- **异构多核**：一块芯片上不止一种核，最突出的是 CPU + GPU，会带来协调与正确性问题；GPU 支持数以千计的并行线程，适合大量向量与矩阵数据。**HSA**：虚拟存储空间对 CPU、GPU 都可见；按需调页；一致的存储策略；统一编程接口，同时发挥 CPU 的串行能力、GPU 的并行能力、FPGA 的专用设计能力。**德州仪器的 CPU–DSP 芯片**：4 个 CPU 核共用 4 MB L2，8 个 DSP 核各有 L1 和 1 MB L2/SRAM，6 MB 共享存储所有 CPU 核、DSP 核和其他部件都能访问；CPU 管通用任务，DSP 管密集的数学运算。
- **FPGA**：可实现任意可综合逻辑、任意互连、引脚任意工作方式；适合原型、概念验证或培训，少量或急需的专用数字系统，用硬件资源与性能报告研究结果；由 CLB 矩阵和可编程互连组成。**LUT**：6 输入查找表相当于 64 × 1 存储器，输入选中一个存储值作输出，能实现任意 6 输入函数或两个 5 输入函数（共用同一组输入）；**片**里有多个 LUT、F7 多路选择器（拼 7 输入函数）和可选寄存器（做时序逻辑）；**DSP 块**做乘累加，预加器在乘法前先相加；**BRAM** 有单端口、简单双端口（一写一读、可同时）、真双端口（两口都能读写）三种。
- **CPU、GPU、FPGA 的比较（Sample Q3）**：CPU——标量、顺序处理，适合复杂算法与决策，受存储带宽限制，流水线与 I/O 固定，为串行任务优化；FPGA——可适配硬件，灵活的并行计算、快速本地存储、定制 I/O，适合延迟敏感负载、不规则数据结构、传感器融合；向量处理器（第 18 页举例 DSP、GPU；第 19 页这一栏没有写 GPU）——领域专用的并行、高计算效率，适合信号、视频与图像处理，I/O 与存储带宽固定；GPU 为并行任务优化，能跑数以千计的线程。
