Lecture 02 — Computer Number System

数制

上一讲说系统的输入要"按 8 位分辨率离散化"，这一讲回答那串 0 和 1 到底怎么表达一个数。三段递进：任意进制的记数原理 → 负数怎么放进定长位串 → 大小悬殊的实数怎么放进定长位串。

考情这一讲是全课最值钱的一讲

IEEE-754 单精度转换在 2022-2023 与 2023-2024 两份主卷里都出现了，都是 8 分，且步骤固定、答案唯一。两年的题干都要求写出全部计算与步骤才给满分。下面 §4.4 有可以自己出题练手的转换器。

1为什么是二进制

真实世界是模拟的：除量子层面外，物理量都是连续的。连续量有个麻烦——很难被忠实地复制，每复制一次就掺进一次噪声。离散量则容易量化、容易无损复制。

数字与模拟交界处的根本限制

无法在有限时间内把无限精度映射到有限个离散值上。所以任何模数转换都必然是"截断"，问题只是截在哪、留多少位。这条限制是本讲后面所有取舍的根源——包括浮点数为什么要这么设计。

类别计算机用二进制表示的东西
数整数、负整数、实数、浮点数，如 1、−2、1.23、1.23 × 104
字符A、B、0、1、a、b、c
指令Move、Add、Subtract、OR、AND
逻辑值真、假

注意最后两行：指令本身也是数。这一点在 L11 到 L13 讲指令集时会反复用到——处理器眼里没有"代码"和"数据"之分，只有位串和"当前该怎么解释它"。

2基数系统

定义基数 radix / base

定义了一套用来表示数的符号。配套的基数点（radix point）是决定每一位数值权重的参考点。

进制符号集基数点叫法
十进制0–9，共 10 个符号小数点 decimal point
二进制0、1，共 2 个符号二进制点 binary point
十六进制0–9、A–F，共 16 个符号十六进制点

一个数的值，是各位的符号值乘以位权再求和：

value = ∑ di × B i(1)

其中 d 是该位的符号，B 是基数，i 是该位相对基数点的位置。一句话概括就是数字 × 基数的位置次方。

2.1十六进制存在的唯一理由

16 = 24，所以一位十六进制数恰好对应四位二进制数，二者一一对应。有了这层对应，二进制与十六进制的互转就退化成查表，不需要任何算术。

做法是从基数点向两边各自四位一组，两端不足四位就补零：

0011 1010 0101 0110 . 1110 0010 1111 1000
  3    A    5    6  .   E    2    F    8
易错补零的方向不能反

整数部分向左补零、小数部分向右补零——分组必须以基数点为基准对齐。若把上例整数部分写成 11 1010 0101 0110 再按左起四位一组分，结果就错了。这条只在"基数是 2 的整数次幂"的关系下成立，十进制与二进制之间没有这种捷径。

勘误课件那句"7 位只能变成 2 位十进制"只对一个例子成立

课件 p7、p8 在 10110102 = 90 旁写着「7 bits binary number could turn into ONLY a 2 digit decimal number」。这对 90 成立，但作为一般命题不成立——11111112 = 127 就是三位十进制数。n 位二进制能表示到 2n−1，位数换算比例是 n·log102 ≈ 0.30n，不成整数比，不能拿位数直接比较不同进制数的大小。

课件例 1：一串 32 位二进制转成十六进制与十进制

00000000000000000000000000110111 表示的十六进制数与十进制数是多少？

四位一组：0011 0111 → 十六进制 37（前面 24 个 0 不写）。十进制：25+24+22+21+20 = 32+16+4+2+1 = 55。

3有符号整数

3.1同一串位有两种解释

10100111 这 8 个位本身不带任何含义，是"按什么规则读"决定了它代表哪个数。当作无符号数读是 167；当作有符号数读会得到一个负数，具体是几取决于用哪一套有符号规则——下面两小节各给一套，讲完后在 §3.3 末尾做对照。

允许两种解释是有用的：计数、年龄这类数据永远不会为负，把符号位省下来当数值位用，能让同样的位宽表示更大的范围。

3.2原码：直觉的做法，但不好用

要在只有 0 和 1 的位串里同时表达正负，最直接的想法是把符号和幅值（绝对值）分开处理：留最高位当符号（0 正 1 负），其余位存幅值。这叫原码（sign and magnitude）。它有两个实打实的麻烦：

  • 零有两种表示。8 位下 00000000 是 +0，10000000 是 −0，同一个数占两个编码，比较相等时还得特判。
  • 加法器不能直接用。算 a + b 时硬件必须先看两个符号是否相同：相同才是真加，不同则要比较幅值大小、决定谁减谁、再定结果的符号。一个本该只有加法的电路，被迫长出比较器和减法器。

3.3补码：把减法变成加法

补码（two's complement）是绝大多数计算机实际采用的表示法。从正数的表示得到对应负数的表示，只需两步：按位取反，然后加一。

+28 = 0001 1100
      1110 0011   ← 按位取反
      1110 0100   ← 加一，这就是 -28

验算 28 + (-28)：
  0001 1100
+ 1110 0100
-----------
1 0000 0000   ← 第 9 位溢出丢弃，8 位结果是 0，✓

补码转换器

看"取反加一"每一步的位串，并验证 x + (−x) 在定长寄存器里确实回到 0。

推导为什么"取反加一"能行

设位宽为 N，x 是正数。按位取反相当于用全 1 减去它，而全 1 这个数就是 2N−1，逐位相减不会产生借位：

x̄ = (2N − 1) − x(2)
x̄ + 1 = 2N − x(3)

也就是说，机器用 2N − x 这个位串来代表 −x。于是计算 a − x 时，机器实际算的是

a + (2N − x) = (a − x) + 2N(4)

而 2N 恰好是第 N+1 位上的 1，在 N 位的寄存器里自动被丢弃，剩下的正是 a − x。这就是补码的全部价值：减法不需要专门的电路，一个加法器就够了，而且零只有一种表示。

补码范围两端不对称：负数比正数多一个。原因是补码里零只占一个编码，而 §3.2 的原码要占两个（+0 和 −0），省下来的那个编码被分给了最负的那个数。所以 8 位补码有 −128，却没有 +128。

3.5位宽陷阱

易错先扩位宽，再取补码——顺序反了结果完全错

求 −25 的 8 位补码。25 = 110012，只有 5 位。

错：11001 → 00110 → 00111 → 扩到 8 位 00000111 = +7   ✗
对：11001 → 00011001 → 11100110 → 11100111 = -25       ✓

扩展位宽时的补位规则是：正数补前导 0，负数补前导 1。这个操作叫符号扩展（sign extension），它保证扩展前后代表的是同一个数。

3.6C 语言里的两种声明

int 声明有符号数、采用补码；unsigned int 把 32 位整个当作无符号整数，最高位是数值的一部分，不是符号位。

职责划分

硬件的算术一律按补码做，它只提供进位、溢出这类标志位供上层参考；把结果解释成有符号还是无符号，是程序员的事。同一条加法指令、同一串结果位，声明成 int 还是 unsigned int 会读出完全不同的值。

4浮点数

4.1定长位串装不下所有实数

先补一个到这里为止一直没定义的词：定点数（fixed-point number）指小数点的位置由格式写死、不随数值变化的表示法。§3 讲的整数就是定点数的特例——小数点钉死在最右端。

计算机内存有限，总得在某处截断。于是真正的问题变成三个：①需要多少精度？②精度需要在哪里？③整数位和小数位各分几位？课件用三个人的需求把它们具体化：

谁需求
修公路的工程师路宽是 10 米还是 10.0001 米无所谓，他的测量本来也没那么准
设计芯片的人0.0001 米是巨大的差别，但他永远不会碰到大于 0.1 米的距离
物理学家要在同一个式子里同时用光速（约 3×108）和牛顿引力常数（约 6.67×10−11）

前两人合起来回答了①和②：格式必须在差异极大的量级上都提供精度，但他们各自需要的只是相对精度——工程师不在乎米下面第四位，芯片设计师不在乎米上面第一位。物理学家回答了③：固定的整数位与小数位分配没法同时容纳两个相差 18 个数量级的数，所以小数点的位置本身必须能浮动。这就是浮点。

4.2浮点数由两部分组成

  • 尾数（significand，也叫 mantissa）装数字本身，它的正负决定整个数的正负；
  • 阶码（exponent）说明小数点相对尾数开头的位置。阶码为负表示数很小、接近零。

这个格式恰好对上了上面三条：①能表示量级差异极大的数，上限由阶码位数决定；②在所有量级上提供相同的相对精度，精度由尾数位数决定；③允许跨量级计算——一个很大的数乘一个很小的数时，两者的有效数字都保留在结果的尾数里，不会因为对齐小数点而被挤掉。

4.3IEEE-754 单精度

32 位切成三段。下面这条位带是活的——在 §4.4 的转换器里换个数，它会跟着变：

  • 第 31 位是符号位 S，与定点数一样，0 正 1 负；
  • 第 30 到 23 位是 8 位阶码，采用偏置 127（bias-127）的整数格式，即把真实的阶加上 127 再存；
  • 第 22 到 0 位是 23 位尾数，只存小数部分。因为规格化（normalization，把数写成小数点左边恰好一位非零数字的形式）之后，二进制下小数点左边永远是 1，这个 1 不必存储，白送一位精度。
value = (−1)S × 1.f × 2 E−127(5)

式 (5) 里 E 是存进去的那个 8 位无符号数，f 是 23 位尾数所表示的小数。两个"127"容易混：编码时加 127，解码时减 127。可表示的量值范围是

1.175 × 10−38 (2−126) < |x| < 3.4 × 1038 (≈ 2 × 2127)(6)

阶码的下界是 −126 而不是 −127，是因为 E 的两个端点编码被留作特殊用途、没有分给普通的规格化数：E=0 用来编码 ±0 与次正规数（subnormal，比最小规格化数还小的那一小段），E=255 用来编码 ±∞ 与 NaN（not a number，装 0/0、∞−∞ 这类没有数值答案的结果）。

阶码为什么用偏置而不用补码

用偏置存阶码，可以让两个同号浮点数的位串直接当无符号整数比大小，结果与数值大小一致。若阶码用补码，负阶的最高位是 1，位串比较的顺序就会和数值顺序反过来，比较指令得先拆字段。偏置把这件事变成了一次整数比较。

4.4转换五步法

这是必考题的固定流程。下面的转换器会把每一步都算给你看——先自己动笔做一遍，再输进去对答案。

IEEE-754 单精度转换器

输入十进制，实时给出五步过程、32 位位串、十六进制，以及回代验算。

五步是哪五步
  1. 定符号位——正数 0，负数 1。
  2. 整数与小数分别转二进制——整数用除 2 取余，小数用乘 2 取整：每次乘 2，取走整数位，余下的继续乘。
  3. 规格化成 1.f × 2e，记下小数点移动的位数 e。
  4. 算阶码 E = e + 127，写成 8 位二进制。
  5. 拼尾数——取 f，右边补零补满 23 位，然后按 S / E / F 顺序拼接。
易错第 2 步不一定会终止

乘 2 取整对 0.1、0.2 这类十进制小数永远停不下来——0.110 在二进制里是无限循环。这正是 §4.1 那句"总得在某处截断"落到具体动作上的时刻：真实做法是取到尾数位数用完（单精度 23 位）为止再舍入，误差就是浮点数不精确的来源。上面的转换器点「0.1 不终止」可以直接看到这个现象——回代验算那一行不会正好等于 0.1。

考点两道真题的原话

2022-2023 Q1(b)：Represent the number +33.8125 in IEEE-754 single precision standard floating point.「Show complete work (calculation and steps) to receive full marks.」［8 分］

2023-2024 Q1(b)(ii)：Represent the floating number −121.3125 in IEEE-754 single precision standard floating point.「Show all the calculations and steps to receive full marks.」［8 分］
两年措辞不同，要求一致：五步都要写在卷面上，只给最终位串拿不到满分。

课件的另一条路：−88 直接对读，以及拿它当验算手段

课件 p34、p35 演示 −88 时没走乘 2 取整，而是直接认出 88 = 1.375 × 26，再把十进制小数 0.375 对读成二进制 .011，于是 −88 = −1.0112 × 26。

这条路只在小数部分恰好是 0.5、0.25、0.125 这类"二进制友好"的值时才好用，但它更适合反过来当验算：把算出的 1.f 读成十进制、乘上 2e，看是否回到原数。上例 1.0112 = 1.375，1.375 × 64 = 88，对得上。转换器最后一行做的就是这件事。

4.6定点与浮点的取舍

优点缺点
浮点动态范围大（由阶码决定），分辨率由尾数决定硬件实现算术复杂，因而慢
定点直接用处理器的常规整数运算实现，因而快范围与分辨率都受限
这条取舍对本课程特别重要

实时系统看重的是最坏情况下的时间有界，而浮点运算的耗时既长又不易预测。所以许多嵌入式实时系统宁可用定点算法，也不引入浮点单元——这与 L01 讲的可预测性优先于平均性能是同一条取向。

5.2C 语言里的字符与字符串

字符串是变长的。变长带来一个问题：怎么知道它到哪结束？C 的答案是用值为 0 的字节（ASCII 的 NUL，写作 '\0'）作为结束标记。所以 Cope 实际占 5 个字节。

C 里的字符串就是一个 char 数组，课件给的 strcpy 正是靠这个结束符控制循环：

void strcpy (char x[], char y[]) {
  int i = 0;
  while ((x[i] = y[i]) != '\0')   /* 先复制，再用复制的值判断是不是结束符 */
    i = i + 1;
}

赋值表达式 x[i] = y[i] 的值就是被赋的那个字符，所以这一行同时完成了复制和判断，读到 '\0' 时循环结束，而这个 '\0' 本身已经被复制过去了。

字符常量（character constant）要和标识符（identifier，即变量、函数这类实体的名字）区分开：x 是一个标识符，'x' 是一个字符常量，它的值就是字符 x 的 ASCII 码。

5.3键盘扫描码

键盘送给主机的不是 ASCII 码，而是扫描码（scancode）——它标识的是哪个物理按键，而不是哪个字符。按下和松开同一个键会发出不同的码，主机端的驱动再根据当前的键盘布局和 Shift、Ctrl 等修饰键的状态，把扫描码映射成字符。

这层间接换来了什么

换一套键盘布局（比如美式换成德式）只要改软件设置、不用换硬件——同一个物理键发出的扫描码没变，变的只是驱动那张映射表。课件展示的是典型的 PC 101 键盘扫描码表，不需要记具体数值，记住这层映射关系即可。

5.4格雷码

格雷码（Gray code，也叫反射二进制码 reflected binary code、单位距离码 unit distance code）是一种相邻两个值只相差一个二进制位的编码方式。由 Frank Gray 在 1953 年提出，如今是数字通信与数据存储中做错误检测与修复的常用工具。

下表中红色标出的是相对上一行发生翻转的位——普通二进制那列经常一次翻好几位，格雷码那列永远只翻一位：

十进制普通二进制格雷码
g = b ⊕ (b >> 1)(8)

它的价值来自"只差一位"这条性质。普通二进制里 3 → 4 是 011 → 100，三位同时翻转；在真实电路里三位不可能严格同时改变，中间会短暂出现 111、001 之类的假值。若这时正好去采样（比如读一个旋转编码器的角度），读到的就是一个完全错误的位置。换成格雷码，3 → 4 是 010 → 110，只有最高位翻转，中间态不存在，假值也就无从产生。

课件另外列了平衡格雷码、N 元格雷码、二维格雷码、顺序格雷码四种变体。本课程只用上表这种二进制反射格雷码，其余知道存在即可，不展开。

本讲速记

  • 位权展开 value = ∑ di × Bi；十六进制存在的理由是 16 = 24，一位对四位，互转即查表。
  • 分组转换以基数点为基准：整数部分向左补零，小数部分向右补零。
  • 位数换算比例约 0.30n，不能拿位数直接比不同进制数的大小。
  • 原码符号与幅值分开，缺陷是两个零、加法器要先比大小。
  • 补码取反加一。本质是用 2N−x 代表 −x，多出的 2N 在 N 位寄存器里自动溢出丢弃，于是减法变成加法，零也只有一种表示。
  • 范围：无符号 0 ~ 2N−1；补码 −2N−1 ~ 2N−1−1，负数比正数多一个。
  • 位宽陷阱：先做符号扩展补到目标位宽，再取反加一；正数补前导 0，负数补前导 1。
  • 硬件一律按补码运算，解释成有符号还是无符号是程序员的责任。
  • IEEE-754 单精度 = 1 + 8 + 23，阶码偏置 127，尾数只存小数部分、整数位的 1 隐含。解码式 (−1)S × 1.f × 2E−127。双精度 = 1 + 11 + 52，偏置 1023。
  • 转换五步：定符号 → 整数与小数分别转二进制（小数用乘 2 取整）→ 规格化 → 阶码加偏置 → 拼尾数补零。真题要求写出全部步骤才给满分。验算手段：把 1.f 读成十进制乘 2e，看是否回到原数。
  • 浮点动态范围大但硬件慢，定点快但范围与分辨率受限；实时系统常因可预测性而选定点。
  • ASCII 锚点：'0'=0x30，'A'=0x41，'a'=0x61，大小写差 0x20；C 字符串以 '\0' 结尾，Cope 占 5 字节。
  • 键盘发的是扫描码（标识物理按键），字符由驱动按布局映射得到。
  • 格雷码 g = b ⊕ (b >> 1)，相邻值只差一位，用来消除多位同时翻转时的中间假值。
