# L09 高速缓存

> [!info] 这一讲的骨架
> [[L08 存储技术]]留下的问题是：Cache 的行**远少于**主存的块（$C \ll M$），那么**一个块该放进哪一行、怎么知道它在不在、满了换谁出去、改了之后主存怎么办**。这一讲就是这四个问题的答案。
> 主线一句话：**Cache 的全部设计，都是在"查得快"和"放得灵活"之间选一个点。** 全相联最灵活但要同时比对每一行；直接映射查得最快但一个块只能去一个地方；组相联是两头之间那条可调的线——而**关联度 $k$ 就是这条线上的刻度**。
> **考情：这是 Q2 区分值最重的一讲，而且已核实出过原题。** 2023 卷 Q2(c)「二路组相联 Cache，行 16 字节、总容量 8 kB，主存 64 MB 按字节编址，求主存地址的划分」[6 分]，考的正是 [[#5 映射方式：一个块能放进哪些行|第 5 节]]那套位宽计算；[[#5.6 真题现场：2023 卷 Q2(c)|§5.6]] 把它完整算了一遍。**复习时间要优先压在第 5、6、7 节。**
> 课程总览见 [[00 课程信息与考情]]。对应课件 `L09_Cache-Memory_2024-2025`，41 页。

## 1 Cache 是什么，以及它凭什么管用

**高速缓存**（cache memory）是一种计算机存储器，**充当中央处理器（CPU）与主存（RAM）之间的缓冲**。它**存放被频繁访问的数据和指令**，让处理器能高速取到它们，从而**显著提升整个系统的速度与性能**。

结构上就是 [[L08 存储技术#3.1 为什么要有 Cache|L08 讲过的那张图]]：

- **单级**：一块相对大而慢的主存，配一块更小更快的 Cache；**CPU ↔ Cache 按字传输，Cache ↔ 主存按块传输**。
- **多级**：**L2 比 L1 慢、通常也更大；L3 比 L2 慢、通常也更大**。

课件专门用一页强调它的重要性：人们常把计算机的性能归给处理器速度或内存大小，但 **Cache 决定的是这些部件能多高效地配合**——它**减少 CPU 访问主存的时间**，于是取数更快、整体性能大幅改善。

### 1.1 它为什么管用：引用局部性

课件给的原理只有一句，但这一句是整讲的地基：

> **Cache 背后的原理是引用局部性**（locality of reference）：**如果一个数据被访问过一次，它在不久的将来很可能再次被访问。**

把这句话和 [[L08 存储技术#2.2 解法不是选一种器件，而是用一个层次|L08 层次那四条]]里的第 4 条对上：之所以"处理器访问下层的频率会下降"，正是因为局部性让绝大多数访问都停在上层。**没有局部性，整个存储层次就不成立。**

> [!note] 局部性其实有两种，课件只明说了一种
> 课件说的"访问过一次、不久会再访问"是**时间局部性**（temporal locality）。
> 还有一种叫**空间局部性**（spatial locality）：**访问了一个位置，它附近的位置也很可能很快被访问**（数组遍历、顺序取指都是这样）。
> 为什么要补这一条：[[#8 行大小|第 8 节]]讲"为什么一次要连同相邻的字一起搬进来"，靠的正是空间局部性；只讲时间局部性解释不了那一节。
> （课件全篇没有出现 spatial / temporal 这两个词，这段是我补的。）

## 2 命中、未命中，以及一次读操作的全过程

### 2.1 两个基本词

- CPU 要取数据时，**先查 Cache**。若要的数据在 Cache 里，叫一次**命中**（cache hit）——CPU 直接从 Cache 快速取走，**绕开了慢的主存**。
- 若不在，叫一次**未命中**（cache miss）——CPU 必须去访问主存取数据，**随后把取回的数据放进 Cache**，以便将来再用。
- "**哪些数据留在 Cache、哪些丢掉**"由**缓存策略**（cache policy）决定。后面第 6、7 节讲的替换算法与写策略，就是这个策略的两个具体部分。

### 2.2 一次读操作走完整个流程

![[L09 Cache 读操作流程.png]]

课件的流程图（Figure 4.5）说的是三句话：

1. 处理器产生要读的那个字的**读地址 RA**；
2. **若这个字在 Cache 里**，直接把它交给处理器；
3. **否则**，把**包含这个字的那个块**装入 Cache，再把字交给处理器。

注意第 3 步装进去的是**整个块**，不是单独那个字——这正是空间局部性在起作用。

### 2.3 命中与未命中时，系统总线上发生什么

这一页容易被跳过，但它把 Cache 和 [[L06 计算机互连#2.1 根本性质|L06 的系统总线]]连了起来：

- **命中时**：**地址缓冲与数据缓冲都被禁用**，通信**只发生在处理器与 Cache 之间**，**系统总线上没有任何流量**。
- **未命中时**：目标地址被**送上系统总线**，数据**经数据缓冲返回**，并**同时送给 Cache 和处理器**。

"命中时总线上没有流量"这件事的价值，在[[#9.1 为什么要做多级|第 9 节]]会再出现一次：总线空出来了，就可以去支持别的传输。

## 4 Cache 地址：用虚拟地址还是物理地址

### 4.1 先说虚拟内存

**几乎所有非嵌入式处理器、以及许多嵌入式处理器都支持虚拟内存**（virtual memory）。

它是一种设施，**允许程序从逻辑的角度去寻址内存，不必管物理上实际有多少主存**。用了它之后，**机器指令的地址字段里装的是虚拟地址**；而对主存的读写，由一个硬件部件——**内存管理单元**（memory management unit, MMU）——**把每个虚拟地址翻译成主存里的物理地址**。

### 4.2 两种放法

| | **逻辑 Cache**（logical cache，又叫虚拟 Cache） | **物理 Cache**（physical cache） |
| --- | --- | --- |
| 用什么地址存数据 | **虚拟地址** | **主存的物理地址** |
| 处理器怎么访问它 | **直接访问，不经过 MMU** | 要先过 MMU |
| 好处 | **访问速度更快**——Cache 可以在 MMU 做完地址翻译之前就作出响应 | （课件未展开） |

课件只给了逻辑 Cache 的这一条明显优势，没有讲它的代价。

> [!note] 逻辑 Cache 的代价，课件没讲，但理解上缺不得
> 虚拟地址是**每个进程自己的**：两个进程的同一个虚拟地址，指向的往往是不同的物理位置。所以每次切换进程，逻辑 Cache 里的内容就可能全部失效，通常要清空（flush）。
> 物理 Cache 没有这个问题，因为物理地址在全系统是唯一的。
> **一句话：逻辑 Cache 省掉了翻译的时间，代价是切换进程时要付出代价。**（这段是我补的。）

## 5 映射方式：一个块能放进哪些行

### 5.1 为什么必须有映射

课件的开场句就是 [[L08 存储技术#3.2 Cache/主存结构|L08 结尾留的那个口子]]：

> **因为 Cache 的行数比主存的块数少，所以需要一个算法，把主存的块映射到 Cache 的行上。**

能用的技术有三种。下面这张图把三种放在一起，**地址怎么切，完全由"一个块能去哪些行"决定**：

![[L09 三种映射方式.png]]

三个例子用的是课件共用的同一套配置：**16 MB 主存（按字节编址）、16 K 行 Cache、每行 4 字节**。于是 $s + w = 24$、$w = 2$、$s = 22$。

### 5.2 直接映射（direct）

- **最简单的技术**；
- **把主存的每个块映射到唯一一条可能的 Cache 行上**。

地址切成三段：**标记 Tag ｜ 行号 Line ｜ 字内偏移 Word**，在例子里是 **8 ｜ 14 ｜ 2** 位。

比对逻辑因此很省：**拿行号字段直接定位到那一行，只比对这一行的标记**，匹配就是命中，不匹配就是未命中。

代价是**冲突**：两个映射到同一行的块如果轮流被用，就会反复把对方挤出去，即使 Cache 里还有大量空行。

### 5.3 全相联（associative）

- **允许每个主存块装进 Cache 的任何一行**；
- **Cache 控制逻辑把内存地址单纯看成「标记 + 字内偏移」两个字段**；
- **要判断一个块在不在 Cache 里，控制逻辑必须同时检查每一行的标记是否匹配**。

地址切成两段：**标记 Tag ｜ 字内偏移 Word**，在例子里是 **22 ｜ 2** 位——**没有行号字段**，因为块不固定去哪一行。

代价就写在定义里：**"同时检查每一行"意味着每一行都要配一套比较电路**，行一多就贵得离谱。这也是 [[L08 存储技术#1.4 四种访问方式|L08 说的"相联访问"]]在这里的落地——按内容找，不按地址找。

### 5.4 组相联（set associative）

- **一种折中，既体现直接映射与全相联各自的长处，又减轻它们的短处**；
- **Cache 由若干个组构成，每个组含若干行**；
- **一个给定的块，可以映射到某个给定组里的任何一行**；
- 例如**每组 2 行**，就叫**二路组相联**（2-way associative mapping）——**一个给定的块可以在唯一一个组里的 2 行中的某一行**。

地址切成三段：**标记 Tag ｜ 组号 Set ｜ 字内偏移 Word**，在例子里是 **9 ｜ 13 ｜ 2** 位。

![[L09 组相联的两种看法.png]]

课件专门用一页讲**同一个组相联 Cache 的两种等价实现方式**，这页值得看懂：

- 对组相联来说，**每个字映射到某个特定组里的所有 Cache 行**，于是主存块 $B_0$ 映射到组 0，依此类推。
- 因此组相联 Cache **可以物理实现成 $v$ 个全相联 Cache**（每个 $k$ 行）；
- **也可以实现成 $k$ 个直接映射的 Cache**（每个 $v$ 行），**其中每一个直接映射 Cache 叫做一条「路」（way）**。

"路"这个词就是这么来的：**$k$ 路 = 并排放着 $k$ 个直接映射的 Cache，一个块在每条路上各有一个候选位置。**

两头的极端值得单独记：**$k = 1$ 就是直接映射**（每组一行）；**$k =$ 总行数、$v = 1$ 就是全相联**（整个 Cache 只有一个组）。所以三种映射其实是同一个参数 $k$ 的三个取值。

### 5.5 三张 Summary 合成一张表

课件给了三页 Summary，字段几乎一样，合起来看最省力。符号：$s+w$ 是地址总位数，$w$ 是字内偏移位数，$r$ 是直接映射的行号位数，$d$ 是组相联的组号位数，$k$ 是每组行数。

| | **直接映射** | **全相联** | **组相联** |
| --- | --- | --- | --- |
| 地址长度 | $(s+w)$ 位 | $(s+w)$ 位 | $(s+w)$ 位 |
| 可寻址单位数 | $2^{s+w}$ 个字或字节 | $2^{s+w}$ | $2^{s+w}$ |
| 块大小 = 行大小 | $2^{w}$ 个字或字节 | $2^{w}$ | $2^{w}$ |
| 主存的块数 | $2^{s+w} / 2^{w} = 2^{s}$ | $2^{s}$ | $2^{s}$ |
| 每组行数 | （相当于 1） | （相当于全部） | $k$ |
| 组数 | —— | —— | $v = 2^{d}$ |
| Cache 行数 | $m = 2^{r}$ | **不定**（undetermined） | $m = kv = k \times 2^{d}$ |
| Cache 大小 | —— | —— | $k \times 2^{d+w}$ 个字或字节 |
| **标记位数** | $(s-r)$ 位 | $s$ 位 | $(s-d)$ 位 |

> [!warning] "全相联的 Cache 行数 = 不定"不是出题人漏了，它是有含义的
> 直接映射的行数由**地址里的行号字段**定死：$r$ 位行号 ⇒ 恰好 $2^{r}$ 行。组相联同理，$d$ 位组号 ⇒ $2^{d}$ 组。
> 全相联的地址里**根本没有行号或组号字段**，所以**行数不受地址格式约束**——想做多少行就多少行，是一个自由的设计参数。课件写 "undetermined"，说的就是"**由地址格式推不出来**"，不是"不知道"。

### 5.6 真题现场：2023 卷 Q2(c)

> **题干**：A two-way set-associative cache has lines of **16 bytes** and a total size of **8 kB**. The **64-MB** main memory is **byte addressable**. Calculate and show the configuration of designed main memory addresses. **[6 分]**

这题就是上表的反向使用。四步，每步只用一个已知量：

**① 由行大小定 $w$。** 行 16 字节，按字节编址，所以一行里有 16 个可寻址单位：

$$
2^{w} = 16 \Rightarrow w = 4\ \text{位}
$$

**② 由容量和关联度定组数，再定 $d$。**

$$
\text{总行数} = \frac{8\ \mathrm{kB}}{16\ \mathrm{B}} = \frac{8192}{16} = 512\ \text{行}, \qquad
v = \frac{512}{k} = \frac{512}{2} = 256\ \text{组} = 2^{8} \Rightarrow d = 8\ \text{位}
$$

**③ 由主存容量定地址总位数，再定 $s$。** 64 MB 按字节编址：

$$
2^{s+w} = 64\ \mathrm{MiB} = 2^{26} \Rightarrow s + w = 26\ \text{位}, \qquad s = 26 - 4 = 22
$$

**④ 标记位数 $= s - d$。**

$$
\text{Tag} = s - d = 22 - 8 = 14\ \text{位}
$$

**答案——主存地址的划分：**

| 字段 | 标记 Tag | 组号 Set | 字内偏移 Word |
| --- | --- | --- | --- |
| 位数 | **14** | **8** | **4** |

**自查**：$14 + 8 + 4 = 26$ 位，与 64 MB 按字节编址吻合 ✓。再用表里的"Cache 大小"式子反算一遍：$k \times 2^{d+w} = 2 \times 2^{12} = 8192$ 字节 $= 8\ \mathrm{kB}$ ✓。

> [!example]- 换成另外两种映射，同一组数据会变成什么
> **直接映射**（同样 512 行、行 16 字节、主存 64 MB 按字节编址）：
> $w = 4$；行数 $512 = 2^{9} \Rightarrow r = 9$；$s = 22$；$\text{Tag} = s - r = 22 - 9 = 13$ 位。划分是 **13 ｜ 9 ｜ 4**，合计 26 位 ✓。
> **全相联**：$w = 4$；没有行号字段；$\text{Tag} = s = 22$ 位。划分是 **22 ｜ 4**，合计 26 位 ✓。
> 对照着看就能记住那条规律：**关联度越高，组号/行号字段越短，标记字段越长。** 极端情况下全相联的标记最长（$s$ 位），直接映射的最短（$s - r$ 位）。

> [!warning] 这类题最常见的三个翻车点
> **一、把"行数"当成"组数"。** 二路时组数是行数的一半；$d$ 要用**组数**取对数，不是行数。
> **二、忘了看按什么编址。** 题干说 "byte addressable" 时 $2^{s+w}$ 数的才是字节；若改成"按 32 位字寻址"，同样 64 MB 只有 $2^{24}$ 个字，地址总位数就是 24 不是 26。这是 [[L08 存储技术#1.3 传输单位，以及与它纠缠的两个概念|L08 那条「地址位数与可寻址单位数」的关系]]的同一个坑。
> **三、算完不验算。** 三段位数相加必须等于地址总位数；再用 $k \times 2^{d+w}$ 反算容量，两道校验花不了十秒，却能挡住大部分计算错误。

### 5.7 牺牲 Cache

课件单独给了一页**牺牲 Cache**（victim cache）：

- 最初被提出，是为了**减少直接映射 Cache 的冲突失效，同时不影响它快速访问的优点**；
- 它是一个**全相联的 Cache**；
- **典型大小是 4 到 16 行**；
- **位置在直接映射的 L1 Cache 与下一级存储之间**。

这页其实是整讲的一个缩影：**直接映射快但会冲突，全相联不冲突但贵；那就用一个很小的全相联 Cache 专门接住被挤出去的那几个块。** 小到只有 4–16 行，比较电路就便宜得起了。

### 5.8 关联度和容量，哪个更值得加

![[L09 行大小与关联度的折中.png]]

课件给了一张"关联度随 Cache 大小变化"的命中率曲线图，并把读图结论写成三句：

- **直接映射与二路组相联之间的性能差别是显著的，一直到至少 64 kB 的 Cache 都还明显**；
- **在 4 kB 处，二路与四路之间的差别，远小于"把 Cache 从 4 kB 加到 8 kB"带来的差别**；
- **超过约 32 kB 之后，继续加大 Cache 不再带来明显的性能提升**。

课件由此给出的判断是：**Cache 的复杂度与关联度成正比上升**，所以在这个例子里，**与其从二路加到四路，不如把 Cache 加到 8 kB 甚至 16 kB**。

**记法：从"直接"迈到"二路"那一步最值；再往上加关联度，性价比迅速下降。**

## 6 替换算法：满了换谁出去

**Cache 装满之后，再要装入一个新块，就必须替换掉一个已有的块。** 两个前提先说清楚：

- **对直接映射，任何一个块都只有唯一一条可能的行，没有选择余地**——所以**直接映射根本不需要替换算法**；
- **全相联和组相联才需要替换算法**；
- **为了达到足够的速度，算法必须用硬件实现**。

课件列了四种：

| 算法 | 课件的说法 |
| --- | --- |
| **最近最少使用 LRU**（least recently used） | **最有效**。替换掉**组里在 Cache 中待得最久、且期间没有被引用过**的那个块。**因为实现简单，LRU 是最常用的替换算法** |
| **先进先出 FIFO**（first in first out） | 替换掉**组里在 Cache 中待得最久**的那个块。**容易用轮转或环形缓冲技术实现** |
| **最不经常使用 LFU**（least frequently used） | 替换掉**组里被引用次数最少**的那个块。**可以给每一行配一个计数器来实现** |
| **随机**（random） | 课件只列了名字 |

> [!warning] LRU 和 FIFO 的定义只差半句话，极易混
> **FIFO**：待得最久的出局——**只看进来的时间**。
> **LRU**：待得最久**而且期间没被引用过**的出局——**看的是最后一次被用的时间**。
> 一个块如果一直在被用，FIFO 照样会把它换出去，LRU 不会。**这半句"with no reference to it"就是两者的全部区别。**

## 7 写策略：改了之后主存怎么办

### 7.1 替换一个块之前要先问一句

**当 Cache 里的某个块要被替换掉时，有两种情况：**

- **如果这个旧块没有被改动过**，那就可以**直接用新块覆盖它，不必先写回去**；
- **如果这一行里至少有一个字被写过**，那就**必须先把这一行写回到它对应的那个内存块，然后才能装入新块**，否则主存就是旧的。

### 7.2 还有两个更麻烦的问题

课件点了两个：

- **可能不止一个设备能访问主存**（比如 [[L06 计算机互连#1.2 互连结构必须支持的五种传送|L06 说的 DMA]]，I/O 模块可以绕过处理器直接读写主存）；
- **更复杂的问题出现在多处理器**：多个处理器挂在同一条总线上、**各有各的本地 Cache**，**如果一个字在某个 Cache 里被改了，它就有可能让别的 Cache 里的那个字作废**。

第二条正是 [[L07 通信与互连#3.4 上面三层各做什么|L07 说的缓存一致性协议]]要解决的问题——那里是从互连的角度看，这里是从 Cache 的角度看，说的是同一件事。

### 7.3 两种策略

| | **写直达**（write through） | **写回**（write back） |
| --- | --- | --- |
| 做法 | **最简单的技术**：**所有写操作在写 Cache 的同时也写主存** | **更新只做在 Cache 里** |
| 好处 | 主存始终是最新的 | **把对主存的写降到最少** |
| 坏处 | **产生大量内存流量，可能形成瓶颈** | **主存的某些部分是无效的**，因此 **I/O 模块的访问只能经由 Cache 进行**；这**使得电路复杂，而且同样可能成为瓶颈** |

> [!note] 两者都"可能成为瓶颈"，但瓶颈在不同的地方
> 写直达的瓶颈在**总线与主存**：每一次写都要走一趟主存。
> 写回的瓶颈在**Cache 本身**：既然主存可能是旧的，所有想访问主存的设备（I/O 模块）就都得先问 Cache，于是 Cache 成了全系统的必经之路，而且判断"这一行脏没脏"的电路也更复杂。
> （课件给了两条"瓶颈"的结论但没说清各自在哪，这段是我补的。）

## 8 行大小

**当一个数据块被取回放进 Cache 时，取回的不只是想要的那个字，还有若干相邻的字。** 于是行大小本身成了一个要调的参数：

- **随着块变大，命中率一开始会上升，因为局部性原理**——**块越大，被搬进 Cache 的有用数据就越多**；
- **但块再继续变大，命中率会开始下降**：因为**"新取回来的信息被用到"的概率，开始低于"那些为了腾位置而被替换掉的信息被再次用到"的概率**。

课件给了两条具体效应来解释这个转折：

1. **块越大，一个 Cache 里装得下的块数就越少**；
2. **块越大，新增的每个字离被请求的那个字就越远**（因而用上的可能性越低）。

这两条正好对应上面补的[[#1.1 它为什么管用：引用局部性|空间局部性]]：空间局部性是有作用半径的，超出半径再多搬就是浪费。

## 9 Cache 的数目

### 9.1 为什么要做多级

**随着逻辑密度提高，把 Cache 做到和处理器同一块芯片上已经成为可能。** 这种**片上 Cache**（on-chip cache）**减少处理器的外部总线活动，加快执行时间、提升整体系统性能**。课件给了三条具体的好处：

- **当要的指令或数据在片上 Cache 里找到时，总线访问被完全省掉**；
- **片上 Cache 的访问，会比"零等待态的总线周期"还要明显地快**；
- **这段时间里总线是空闲的，可以去支持别的传输**。

第三条和 [[#2.3 命中与未命中时，系统总线上发生什么|§2.3]] 说的"命中时系统总线上没有流量"是同一件事的两种说法。第二条里的"零等待态总线周期"就是 [[L06 计算机互连#3 总线设计的五个维度|L06 等待态]]的那个概念——**即使总线快到一拍都不用等，也还是比片上访问慢。**

**两级 Cache** 的命名：**内部的那级叫 L1，外部的那级叫 L2**。要注意两点：

- **用 L2 能省多少，取决于 L1 和 L2 两者的命中率**；
- **多级 Cache 会让所有的 Cache 设计问题都变复杂**，包括大小、替换算法和写策略。

### 9.2 L2 要多大才有用

课件给了一张"总命中率随 L2 大小变化"的图（L1 分别为 8 kB 与 16 kB 两条曲线），读图结论是：

- **在 L2 至少达到 L1 的两倍大小之前，L2 对总命中数几乎没有影响**；
- **L1 为 8 kB 时，曲线最陡的那一段出现在 L2 = 16 kB**；
- **L1 为 16 kB 时，最陡的那一段出现在 L2 = 32 kB**；
- **在那个点之前，L2 对总的 Cache 性能几乎没有、甚至完全没有影响**。

课件自己给了理由，这句要记住：**如果 L2 的行大小和容量都和 L1 一样，它装的内容就会和 L1 的差不多一模一样**——于是 L1 没命中的，L2 多半也没有，L2 等于白加。

**记法：L2 的价值来自"它装得下 L1 装不下的东西"，所以至少要大一倍才开始有意义。**

### 9.3 统一 Cache 与分离 Cache

**趋势是：L1 用分离 Cache，更高的层级用统一 Cache。**

**分离 Cache**（split cache）已经很常见：

- **一块专门放指令，一块专门放数据**；
- **两者在同一层级，通常是两个 L1 Cache**。

| | **分离 Cache 的好处** | **统一 Cache 的好处** |
| --- | --- | --- |
| 课件的说法 | **消除取指/译码部件与执行部件之间对 Cache 的争用**；**这在流水线里很重要** | **命中率更高**——它**自动平衡指令取用与数据取用的负载**；而且**只需要设计和实现一个 Cache** |

> [!note] 为什么分离 Cache 对流水线重要
> 流水线会让"取下一条指令"和"执行当前指令时访存"**在同一拍里同时发生**。如果指令和数据共用一个 Cache，这两件事就要抢同一个端口，必须有一方等——这种等待叫**结构冒险**。
> 分成两块之后，取指走指令 Cache、访存走数据 Cache，互不相干，这一拍就不用停。
> 这是 L15 指令级并行的内容，这里只需知道**分离 Cache 的收益主要兑现在流水线上**。（课件只说了"important in pipelining"，理由是我补的。）

## 本讲速记

- **Cache** 是 CPU 与主存之间的**缓冲**，存放被频繁访问的数据与指令。**CPU ↔ Cache 按字传，Cache ↔ 主存按块传**；多级时 **L2 比 L1 慢且通常更大，L3 比 L2 慢且通常更大**。
- **原理是引用局部性**：**一个数据被访问过一次，不久很可能再被访问**。（课件只明说了这条时间局部性；"访问了一个位置、附近也很可能被访问"的**空间局部性**是我补的，第 8 节靠它。）
- **命中**：数据在 Cache 里，绕开主存；**地址与数据缓冲被禁用，系统总线上没有流量**。**未命中**：去主存取，地址上系统总线，数据**经数据缓冲同时送给 Cache 和处理器**，并把**整个块**装进 Cache。
- **读操作四步**：收到读地址 RA → 判断含 RA 的块在不在 Cache → 在就取字给 CPU；不在就访问主存取块 → 分配一行 → 装入 → 给 CPU。
- **七组设计要素**：Cache 地址（逻辑/物理）、Cache 大小、映射函数（直接/全相联/组相联）、替换算法（LRU/FIFO/LFU/随机）、写策略（写直达/写回）、行大小、Cache 数目（单级或两级；统一或分离）。
- **虚拟内存**让程序**从逻辑角度寻址、不管物理上有多少主存**；指令地址字段里是**虚拟地址**，由 **MMU** 翻译成物理地址。**逻辑（虚拟）Cache 用虚拟地址存、处理器不经 MMU 直接访问，因而更快**——它能在 MMU 翻译完成之前就响应；**物理 Cache 用物理地址存**。
- **映射的三种**：**直接**——每块只能进唯一一行，最简单；**全相联**——每块可进任何一行，地址只有 Tag + Word，**必须同时检查每一行的标记**；**组相联**——Cache 分若干组、每组若干行，**块先定组、组内任选**，是前两者的折中。
- **组相联的两种等价看法**：$v$ 个全相联小 Cache（每个 $k$ 行），或 $k$ 个直接映射 Cache（每个 $v$ 行）——**后者里每一个直接映射 Cache 叫一条「路」（way）**。**$k=1$ 即直接映射，$v=1$ 即全相联。**
- **三种映射的位宽公式**（$s+w$ 为地址总位数，$w$ 为字内偏移位数）：块大小 = 行大小 $= 2^{w}$；主存块数 $= 2^{s}$。
  **直接**：行数 $m = 2^{r}$，**标记 $= s-r$**。
  **全相联**：行数**不定**（地址里没有行号字段，推不出来），**标记 $= s$**。
  **组相联**：组数 $v = 2^{d}$，行数 $m = kv = k\cdot 2^{d}$，Cache 大小 $= k \cdot 2^{d+w}$，**标记 $= s-d$**。
- **位宽计算四步法**（2023 卷 Q2(c) 原题）：① 行大小 $\to w$；② Cache 容量 ÷ 行大小 = 行数，行数 ÷ $k$ = 组数 $\to d$；③ 主存容量 $\to s+w$，减去 $w$ 得 $s$；④ 标记 $= s-d$。**验算：三段相加 = 地址总位数；再用 $k\cdot 2^{d+w}$ 反算容量。**
  该题答案：**Tag 14 ｜ Set 8 ｜ Word 4，共 26 位**。
- **三个翻车点**：把行数当组数；没看清按字节还是按字编址；算完不验算。
- **牺牲 Cache**：为**减少直接映射的冲突失效且不损害其快速访问**而提出；它是**全相联**的，**典型 4 到 16 行**，**位于直接映射的 L1 与下一级存储之间**。
- **关联度读图三结论**：直接 vs 二路**到至少 64 kB 都差别显著**；**4 kB 处二路 vs 四路的差别，远小于把 Cache 从 4 kB 加到 8 kB**；**超过约 32 kB 再加容量不再有明显提升**。结论句：**复杂度与关联度成正比，所以与其加关联度不如加容量。**
- **替换算法**：**直接映射没有选择余地，不需要替换算法**；相联与组相联才需要；**必须用硬件实现**。**LRU** 换掉"待得最久**且期间没被引用过**"的，**最有效、也因实现简单而最常用**；**FIFO** 换掉"待得最久"的，**用轮转/环形缓冲实现**；**LFU** 换掉"被引用次数最少"的，**给每行配计数器**；还有**随机**。**LRU 与 FIFO 的全部区别就在"没被引用过"这半句。**
- **替换前要看脏不脏**：**没改过就直接覆盖；至少被写过一次就必须先写回主存**。两个麻烦：**不止一个设备能访问主存**；**多处理器各有本地 Cache，一处改动可能让别处作废**（即缓存一致性问题）。
- **写直达**：写 Cache 的同时也写主存，**最简单**，但**产生大量内存流量、可能成为瓶颈**。**写回**：只改 Cache，**把写主存降到最少**，但**主存部分无效，I/O 模块只能经 Cache 访问**，**电路复杂且同样可能成为瓶颈**。
- **行大小**：取回时连相邻的字一起取。**先因局部性而命中率上升**；**块再大则下降**——"新取回的被用到"的概率低于"被挤掉的被再用到"的概率。两条效应：**块越大 Cache 里装得下的块数越少**；**新增的字离请求的字越远**。
- **多级 Cache**：**片上 Cache 减少外部总线活动**；命中时**总线访问被完全省掉**，**比零等待态的总线周期还明显地快**，而且**总线空出来可以支持别的传输**。**L1 在内、L2 在外**；省多少**取决于两者的命中率**；多级会**让大小、替换算法、写策略所有问题都复杂化**。
- **L2 的大小**：**在 L2 至少是 L1 两倍之前几乎没有影响**；L1 = 8 kB 时最陡处在 L2 = 16 kB，L1 = 16 kB 时在 L2 = 32 kB。理由：**L2 若与 L1 同样的行大小和容量，内容会和 L1 差不多一样。**
- **统一与分离**：**趋势是 L1 分离、更高层级统一**。**分离**= 指令一块、数据一块，同层级、通常是两个 L1；好处是**消除取指/译码部件与执行部件对 Cache 的争用，这在流水线里很重要**。**统一**的好处是**命中率更高（自动平衡指令与数据取用的负载）**，且**只需设计实现一个 Cache**。
