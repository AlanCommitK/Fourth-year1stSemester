# L06 计算机互连

> [!info] 这一讲的骨架
> [[L05 计算机部件]]把一台机器拆成了三类模块——处理器、内存、I/O。这一讲回答下一个问题：**它们之间靠什么连起来？**
> 答案是**总线**，而总线的全部特点都来自一句话：**它是一条共享的传输介质。** 共享带来两个后果——所有人都听得见（所以需要地址线），同时说话会乱码（所以必须先抢到使用权）。整讲就是这两个后果展开成的设计：三组线、两步协议、五个设计维度，以及为什么一条总线不够、要分成三层。
> 考试上这一讲落在 Q2「硬件接口与 I/O」，而且是**已核实出过原题**的一讲：2022 卷 Q2(b)「解释 ARM Cortex-M 系列为什么存在多条总线」[4 分] 问的就是第 4 节；同卷 Q2(c) 的写时序计算 [3+2+2=7 分] 落在第 3 节的"同步 / 异步"上，第 3 节末尾把这道题完整算了一遍。地址线宽度与最大内存容量的换算不单独出题，但它是 Cache 地址划分题（2023 卷 Q2(c)）的第一步。
> 课程总览见 [[00 课程信息与考情]]。对应课件 `L06_Computer-Interconnection_2024-2025`，18 页。

## 1 要连的是什么，为什么要连

一台计算机由三种基本类型的部件或模块构成：**处理器、内存、I/O**。这些模块彼此通信，**所以必须有连接它们的通路**。把各个模块连起来的那些通路的总和，叫**互连结构**（interconnection structure）。

关键的一句在后面：**这个结构怎么设计，取决于模块之间必须进行哪些交换。** 所以先看每个模块要进出什么。

### 1.1 三个模块各自要什么线

**内存模块**：由 $N$ 个等长的**字**组成，每个字有一个唯一的数字地址（$0, 1, \dots, N-1$）。一个字可以被读出，也可以被写入。于是它需要：

- **读 / 写控制信号**——说明这次操作的性质；
- **地址**——说明操作的位置；
- **数据**——进来或出去的那个字。

**I/O 模块**：**从计算机系统内部看，I/O 在功能上和内存很像**——同样是读和写两种操作。差别在三处：

- 一个 I/O 模块可以控制**多个外部设备**，每个对外接口叫一个**端口**（port），各有唯一地址（$0, 1, \dots, M-1$）；
- 除了面向内部的数据通路，还有**面向外部设备的数据通路**；
- 它**可能具备向处理器发中断信号的能力**（课件原文是 *may be able to*，不是必然）——这一条内存没有。

**CPU 模块**：读入指令和数据，处理完写出数据；**用控制信号控制整个系统的运作**；并且**接收中断信号**。

> [!note] "I/O 在功能上和内存很像"是一条贯穿后面的伏笔
> 课件说到"从内部看 I/O 在功能上与内存相似，都是读和写两种操作"就停了，下面这段是补充背景。
> 既然两者从内部看都是"给个地址、读或写"，那么把 I/O 端口直接编进内存的地址空间就是一种可行的**设计选择**，叫**内存映射 I/O**（memory-mapped I/O）。注意这是"可行"而非"必然"：并存的另一条路是**独立编址 I/O**（isolated I/O，又称 port-mapped I/O），给 I/O 单独一套地址空间，用专门的 IN/OUT 指令访问。
> [[Lab1 寄存器、定时器与中断#3.1 CRL 与 CRH：每个引脚 4 位|Lab 1 往 `GPIOB->CRL` 里写值]]走的是前一条路：写的是一个被映射成内存地址的 I/O 寄存器——代码里看着像在改内存，实际改的是引脚配置。

### 1.2 互连结构必须支持的五种传送

| 方向 | 含义 |
| --- | --- |
| **内存 → 处理器** | 处理器从内存读一条指令或一个数据单元 |
| **处理器 → 内存** | 处理器往内存写一个数据单元 |
| **I/O → 处理器** | 处理器经 I/O 模块从外设读数据 |
| **处理器 → I/O** | 处理器把数据送给外设 |
| **I/O ↔ 内存** | **I/O 模块不经过处理器，直接和内存交换数据**——用的是**直接内存访问**（direct memory access, DMA） |

前四种都要处理器亲自搬运，第五种不用。**DMA 这一条是后面 L10 讲三种 I/O 技术时的终点**，这里先记住它的定义：数据绕过了 CPU。

## 2 总线：共享带来的一切

### 2.1 根本性质

**总线**（bus）是连接两个或更多设备的通信通路，**关键特征是它是一条共享的传输介质**（shared transmission medium）。

由此直接推出两条：

- **任何一个设备发出的信号，挂在总线上的所有其他设备都能收到**；
- **如果两个设备在同一段时间里同时发送，它们的信号会叠在一起、变成乱码。**

总线通常由**多条通信线路**组成，每条线都能传送代表二进制 1 和 0 的信号。一串比特可以在单条线上依次传过去；**用几条线就能让几个比特同时传（并行）**。

一台计算机里有**若干条不同的总线**，在系统层次结构的不同层级之间提供通路。其中连接主要部件（处理器、内存、I/O）的那条叫**系统总线**（system bus）；最常见的互连结构就建立在一条或多条系统总线之上。

### 2.2 三组线

![[L06 总线的三组线.png]]

一条系统总线可能有 **50 到 100 根线**，每根线都被赋予特定的含义或功能。不管哪种总线互连，这些线都能分成三组——**数据线、地址线、控制线**。

图里还画出了上一节那两条性质带来的直接后果：**因为所有人都听得见，才需要地址线指明"这次是给谁的"；因为同时发会乱码，才必须先取得总线使用权。**

于是总线的操作是这样的：

- 一个模块**要把数据发给另一个模块**，必须做两件事：**（1）取得总线的使用权；（2）通过总线把数据传出去。**
- 一个模块**要向另一个模块要数据**，必须：**（1）取得总线的使用权；（2）通过相应的控制线和地址线把请求发过去**，然后**等着对方把数据送回来**。

**"先取得使用权"这一步就是仲裁**（arbitration），第 3 节会讲它的两种做法。

### 2.3 三组线各自决定什么

**数据总线**（data bus）：为数据在各模块之间移动提供通路。可能由 **32、64、128 或更多条**独立的线构成。

- 线的条数叫**数据总线的宽度**（width）；
- **宽度决定了一次能传送多少位**；
- **数据总线的宽度是决定系统整体性能的一个关键因素。**

**地址总线**（address bus）：用来指明数据总线上那份数据的**来源或去向**。处理器要从内存读一个字时，就把那个字的地址放到地址线上。

- **宽度决定了系统可能的最大内存容量**；
- 它**也用来寻址 I/O 端口**；
- 分工是：**高位用来在总线上选中某一个模块，低位用来在那个模块内部选中某个内存位置或 I/O 端口。**

**控制总线**（control bus）：用来**控制数据线和地址线的访问与使用**。因为数据线和地址线被所有部件共享，**必须有办法管住谁在用**。

- 控制信号在各模块之间传送的是**命令和时序**两类信息；
- **时序信号指明数据和地址信息什么时候是有效的**；
- **命令信号规定要执行什么操作**。

> [!warning] 宽度 → 能力，是 Q2 最常见的小问
> 地址总线宽度 $n$ 位 ⇒ 最多寻址 $2^n$ 个单元。32 位地址线能寻址 $2^{32} = 4$ Gi 个单元；若每个单元是一个字节，就是 4 GiB。
> 这和 [[L05 计算机部件#4.3 一台假想机器，把循环跑一遍|L05 那台假想机器"12 位地址 → 4K 字"]]是同一个算法，只是位数不同。
> 别把两条总线的作用搞反：**地址宽度决定能寻址多少，数据宽度决定一次搬多少。**

### 2.4 物理上它长什么样

系统总线就是**一组并行的电导体**。这些导体是附着在卡或印制电路板上的**金属线**，**总线横贯所有部件，部件在线上"搭"上去**（tap into）。

课件讲到这里为止，没有继续说"设备搭多了会怎样"。但这是第 4 节分层的前提，所以先把原因补上——按 Stallings，挂接的设备一多，性能下降有两条原因：

- **设备越多，总线越长，传播延迟越大**；而协调总线使用权（也就是上一节说的仲裁）所需的时间，正由这个延迟决定。
- **各设备的总传输需求逼近总线带宽**，总线本身成为瓶颈。

（板级上还有第三层、更物理的原因：每多一个挂接点就多一份电容负载和一段残桩，信号边沿变缓、建立时间变长。这和 [[L03 性能#2.2 频率为什么不能想开多高就开多高|L03 说的"周期必须长到让最慢的那条路也稳定下来"]]是同一回事，只是从片内换到了板级。答题时主答上面两条，这一条作补充。）

## 3 总线设计的五个维度

课件把总线设计的选择归成五项，**但只给了项目名和选项名，一行解释都没有**（课件第 15 页）。下表第三列是补充的说明，不是课件原文：

| 维度 | 可选项 | 区别在哪 |
| --- | --- | --- |
| **类型**（type） | **专用**（dedicated） / **复用**（multiplexed） | 专用有两层含义：**功能专用**——地址和数据各占各的线；**物理专用**——一条总线固定服务于某一组物理部件（如一条 I/O 总线专连所有 I/O 模块）。复用是同一组线**分时**承担多种用途，典型做法是先传地址、再传数据：好处是线少、省面积和成本，代价是**每个模块内部电路更复杂**（要把地址锁存下来），而且共享同一组线的事件无法并行发生 |
| **总线宽度**（bus width） | **地址** / **数据** | 见 [[#2.3 三组线各自决定什么\|§2.3]]：地址宽度决定寻址范围，数据宽度决定一次搬多少 |
| **时序**（timing） | **同步**（synchronous） / **异步**（asynchronous） | 同步靠公共时钟划分事件，所有动作踩在固定的拍子上；异步靠**握手**，一方发信号、另一方应答，快慢设备可以各走各的节奏 |
| **仲裁方式**（method of arbitration） | **集中式**（centralized） / **分布式**（distributed） | 集中式由一个专门的仲裁器决定谁用总线；分布式由各模块按约定好的规则自行决出 |
| **数据传送类型**（data transfer type） | **读、写、读—改—写、读后写、块传送** | 前两个是基本操作。**读—改—写**对同一地址先读后写，地址只在开头广播一次，整套操作**通常**不可分割，目的是在多道程序环境下保护共享的内存资源。**读后写**先写、紧接着从同一地址把**刚写进去的那个值**读回来，用于校验写有没有成功——不是读出旧值，旧值在写的那一刻就没了。**块传送**一次给出地址，连续搬多个字 |

> [!warning] 这张表里有两项和实验同名，但都不能直接等同
> **读—改—写**的动作形状和 [[Lab1 寄存器、定时器与中断#3.3 ODR 与 IDR：写和读|Lab 1 改寄存器时那套"读出、改位、写回"]]一样，但层次不同：总线这一层的读—改—写由硬件保证（通常）不可分割；而 Lab 1 里 C 代码的 `REG |= mask` 编译出来是 LDR、ORR、STR **三条独立指令、三次独立的总线访问**，**中断完全可以插在中间**，它不是原子操作。把两者混为一谈是嵌入式里的典型踩坑点。
> **同步与异步**和 [[Lab2 串行通信与PWM#1.2 核心难题：接收方怎么知道"现在"|Lab 2 那条分界线]]同名——UART 是异步、SPI 与 I2C 是同步。但两处的"异步"做法并不相同：**总线的异步靠握手线逐次应答**（一方发信号、另一方回应，才进行下一步）；**UART 的异步没有应答**，靠起始位对齐加双方事先约定好的波特率，发完一个字节就发下一个。两处共同的只有"有没有一条公共时钟线"这一层。

关于**时序**：课件只给了"同步 / 异步"两个名字，**等待态（wait state）这个概念本讲课件并没有涉及**，但真题考过，所以在这里补齐。等待态落在同步总线上：慢设备跟不上固定的拍子时，用**额外的整个时钟周期**把一次传输拉长。

> [!example]- 真题现场：2022 卷 Q2(c) 写时序与等待态 [3+2+2=7 分]
> 题干：某微处理器的内存写时序由厂商规定为——Write 信号的宽度等于 $T - 50$，其中 $T$ 是以 ns 为单位的时钟周期。
>
> **(i) 若总线时钟频率为 5 MHz，Write 信号应有多宽？[3 分]**
> $T = 1/f = 1/(5 \times 10^{6})\ \text{s} = 200\ \text{ns}$，于是 Write 宽度 $= T - 50 = 150\ \text{ns}$。
>
> **(ii) 手册说数据在 Write 信号下降沿之后还会保持有效 20 ns。送给内存的有效数据总时长是多少？[2 分]**
> $150 + 20 = 170\ \text{ns}$。这 20 ns 是**加在后面**的，不包含在 Write 宽度里。
>
> **(iii) 若内存要求有效数据至少呈现 190 ns，应插入几个等待态？[2 分]**
> 现有 170 ns，差 $190 - 170 = 20\ \text{ns}$。但一个等待态加的是**一整个时钟周期**，也就是 200 ns，不是刚好 20 ns——所以 **1 个等待态**就够，加完共 370 ns。
>
> 这道题真正的得分点就在最后一句：**等待态的粒度是整个时钟周期，不能按差额去凑。** 先算"现有多少"，再算"差多少"，最后用 $\lceil \text{差额} / T \rceil$ 取整。

## 4 为什么一条总线不够：传统总线层次

### 4.1 问题

把所有东西挂到同一条总线上，会撞上三堵墙——前两条就是 [[#2.4 物理上它长什么样|§2.4]] 补的那两条原因：

- **设备越多，总线越长，传播延迟越大**，仲裁所需的时间跟着变长；
- **总传输需求逼近总线带宽**，总线成为瓶颈；
- **快设备被慢设备拖住**——一条总线只有一套节奏，必须照顾到最慢的那个。

这三条正是 2022 卷 Q2(b)「解释 ARM Cortex-M 系列为什么存在多条总线」[4 分] 的答案骨架。

### 4.2 答案：按速度分层

![[L06 传统总线层次.png]]

课件给的传统架构分三层。表里会出现 **Cache**（高速缓存）——它在前面几讲只作为影响性能的一个因子被提到过（[[L03 性能#3.4 五个因子，四个系统属性|L03 §3.4]]），这里先给一句够用的定义：**夹在处理器与主存之间的一块小而快的存储，存放最近用过的数据**；细节留到讲存储层次那一讲（L09）。

| 层 | 连接的是 | 为什么单独一层 |
| --- | --- | --- |
| **局部总线**（local bus） | 处理器 — Cache | 最快、线最短，只连最亲近的几个；局部 I/O 控制器也挂在这里 |
| **系统总线**（system bus） | 主存 — Cache | 主存要跟上处理器的节奏，但不必跟着外设走 |
| **扩展总线**（expansion bus） | 各种 I/O 模块 — 主存 | 设备多、速度杂，网络、SCSI、调制解调器、串口全关在这一层 |

两层之间靠**扩展总线接口**（expansion bus interface）打通。课件只在图里画了这个方框，没有一个字说明它做什么；按 Stallings，它在系统总线与扩展总线之间**缓冲**数据传输，**把 I/O 流量与"存储器—处理器"流量隔开**——于是慢设备的节奏不会传染给上面两层。

> [!warning] 课件里"系统总线"有两种口径，别混用
> [[#2.1 根本性质|§2.1]] 的说法（课件第 8 页）：系统总线是**连接处理器、内存、I/O 这些主要部件**的那条总线。
> 这里三层架构的说法（课件第 13 页）：系统总线**特指主存与 Cache 之间**那一层——I/O 已经被挪到扩展总线上了。
> 这是课件自身的口径冲突，不是笔记写错。答题时按题干上下文选一种，不要在同一句里同时用两种。

一句话记法：**分层的全部目的，是让每一层只按自己那一档速度跑。**

## 本讲速记

- 一台计算机三类模块：**处理器、内存、I/O**；连接它们的通路总和叫**互连结构**，**怎么设计取决于模块之间要做哪些交换**。
- 内存模块：$N$ 个等长的字，地址 $0..N-1$，靠**读/写控制信号**定性质、靠**地址**定位置。
- I/O 模块：**内部看和内存很像**（也是读与写），但多三样——**多个端口**各有地址（$0..M-1$）、**面向外设的数据通路**、**能发中断**。
- CPU 模块：读指令与数据、写出数据、**用控制信号控制全局**、**接收中断**。
- **五种传送**：内存→处理器、处理器→内存、I/O→处理器、处理器→I/O，以及 **I/O ↔ 内存（DMA，绕过处理器）**。
- 总线的根本性质是**共享传输介质**，由此有两条后果：**所有设备都收得到**（所以要地址线）、**同时发会乱码**（所以要先取得使用权）。
- 系统总线 **50–100 根线**，分三组：**数据线 / 地址线 / 控制线**。
- 一次传输：**发数据** = 取得使用权 → 发出去；**要数据** = 取得使用权 → 经控制线与地址线发请求 → 等对方送回。
- **数据总线宽度**决定一次传几位，是**整体性能的关键因素**；**地址总线宽度**决定**最大内存容量**，**高位选模块、低位选模块内的位置或端口**；**控制总线**传**命令**（做什么）与**时序**（数据和地址什么时候有效）。
- 物理上总线是**一组并行金属导体**，横贯所有部件，部件"搭"在上面。**设备搭多了性能下降有两条标准原因**（课件没讲，Stallings 给的）：**总线变长、传播延迟变大**，仲裁时间随之变长；**总传输需求逼近总线带宽**，总线成为瓶颈。再加上"一条总线只有一套节奏，快设备被慢的拖住"，就是 2022 卷 Q2(b) 的答案。
- **五个设计维度**：类型（专用/复用）、宽度（地址/数据）、时序（同步/异步）、仲裁（集中式/分布式）、传送类型（读/写/读—改—写/读后写/块）。易错点三个：**专用含"功能专用"与"物理专用"两层**；**读后写是"写完再把刚写进去的值读回来校验"**，不是读旧值；**读—改—写只是"通常"不可分割**，而且它与 C 代码里的 `REG |= mask` 不是一回事（后者不原子）。
- **等待态不在本讲课件里，但 2022 卷 Q2(c) 考了**：粒度是**一整个时钟周期**，按差额凑是错的，要 $\lceil \text{差额}/T \rceil$ 取整。
- **三层总线**：局部总线（处理器—Cache）、系统总线（主存—Cache）、扩展总线（I/O 模块—主存），用**扩展总线接口**衔接。**分层是为了让每层按自己那档速度跑，慢设备不拖住快设备。**
