# L19 CPU 调度（上）

> [!info] 这一讲的骨架

## 1 调度器与两种调度方式

### 1.1 CPU 调度器

课件第 3 页：

- **CPU 调度**（CPU scheduling）**是多道程序操作系统的基础。** 多道程序设计就是一个程序等 I/O 时让 CPU 去运行另一个，见 [[L04 操作系统概述#2 这层假象是被逼出来的|L04 的多道程序设计]]。
- **CPU 调度器**（CPU scheduler）**也叫短期调度器**（short-term scheduler），**负责从就绪的进程里挑选、决定下一个在 CPU 上运行的进程。** 叫"短期"，是因为它决定的是接下来马上由谁运行，每隔很短一段时间就要做一次（这一句是我补的）。
- **CPU 调度主要分两类：抢占式和非抢占式。**

### 1.2 非抢占式与抢占式

**非抢占式调度**（non-preemptive scheduling），课件第 4 页：

- **也叫协作式调度**（cooperative scheduling）：**进程一直运行，直到它自愿让出 CPU，要么是执行完了，要么是进入等待状态（比如做 I/O）。**
- **调度器不会强行打断正在运行的进程。**
- **只有当前运行的进程决定释放 CPU，CPU 的控制权才从一个进程交到另一个进程手里。**
- **它比抢占式调度容易实现。**

**抢占式调度**（preemptive scheduling），课件第 5 页：

- **操作系统可以强行打断正在执行的进程，按调度算法把 CPU 交给另一个进程。**
- **调度器可以按预先定好的时间片打断进程、换另一个进程运行（即分时），也可以按优先级这样做。**
- **它的响应性和公平性更好，因为没有哪个进程能长时间独占 CPU。**
- **抢占式调度可能比非抢占式更难实现，因为要处理同步和上下文切换。**

第 5 页用到的几个词（这几条是我补的）：

- **时间片**（time slice）：每次分给一个进程连续运行的一小段时间。分时见 [[L04 操作系统概述#2 这层假象是被逼出来的|L04 的分时系统]]。
- **上下文切换**：把当前进程的寄存器等执行现场存起来，再装入另一个进程的现场，可能要几千个 CPU 周期，见 [[L04 操作系统概述#8.6 上下文切换要花多少钱|L04 的上下文切换]]。
- **同步**：几个进程或任务共用一份数据时，一个进程改到一半被切走，别的进程就会读到改了一半的数据。Lab 3 的第一种竞态就是这种情形，见 [[Lab3 任务、内存与队列#4.1 为什么不能图省事用全局变量|Lab3 的竞态]]。
- **按优先级抢占的实例**：Lab 3 里的 FreeRTOS 默认按优先级抢占，更高优先级的任务一变成就绪，调度器立刻停下当前任务去运行它，见 [[Lab3 任务、内存与队列#2.2 抢占|Lab3 的抢占]]。

第 4 页右下角还有一张装饰性的小状态图，箭头与 [[#3.2 任务与它的三个状态|第 8 页的状态图]]对不上（画了就绪到等待，没有等待回到就绪），状态转换以第 8 页为准（按图读出）。

### 1.3 Sample Question 第一问：非抢占式调度的优缺点

课件第 27 页第一问：

> Q1: What is pre-emptive scheduling and non-preemptive scheduling? Briefly describe the pros and cons of the latter.

两者是什么，就是 [[#1.2 非抢占式与抢占式|两种调度的定义]]。非抢占式的优缺点课件没有单独列出，下面两条是我按第 4、5 页整理的：

- **优点**：实现简单（第 4 页）。进程只在自己让出 CPU 的地方被换下，不会在任意一条指令处被打断：切换次数少，上下文切换的开销小，要处理的同步问题也少（第 5 页说抢占式难在同步和上下文切换，这两样在非抢占式下都少得多）。
- **缺点**：一个进程可以长时间独占 CPU，别的进程哪怕很急、很短，也只能等它让出 CPU，响应性和公平性差，响应时间没有保证（第 5 页说抢占式的好处是没有哪个进程能长时间独占 CPU，反过来就是非抢占式的短处）。后面 [[#4.1 先来先服务（FCFS）|先来先服务]]的例子里，短进程排在长进程后面干等的护航效应，就是这种情形。

## 2 调度看什么

### 2.1 五个指标

课件第 6 页：

- **CPU 利用率**（CPU utilization）：**让 CPU 尽可能忙。** 它的定义与算法见 [[L01 实时系统#8 CPU 利用率|L01 的 CPU 利用率]]。
- **吞吐量**（throughput）：**单位时间里执行完的进程数。**
- **周转时间**（turnaround time）：**进程从到达到完成所用的总时间。**
- **等待时间**（waiting time）：**进程在就绪队列**（ready queue）**里等着拿到 CPU 的时间总和。**
- **响应时间**（response time）：**从提交请求到产生第一个响应所用的时间，不是到输出为止。**

第 6 页右边的图把它们分成两组：**CPU 利用率和吞吐量要最大化；周转时间、等待时间和响应时间要最小化。**

这里的响应时间按调度的口径，算到第一个响应为止；[[L01 实时系统#3 响应时间|L01 的响应时间]]是实时系统的口径，从一组输入呈现算到所有相关输出都可用。两处同名，口径不同（这一段是我补的）。

### 2.2 周转时间与等待时间怎么算

调度题的表里，每个进程给两个数：**到达时间**（arrival time）$A$，即进程进入就绪队列的时刻；**执行时间**（burst time）$B$，即进程这一次要在 CPU 上运行多久。排出运行的先后之后，每个进程有一个**完成时间**（completion time）$C$（这几个释义和记号是我补的）。课件第 27 页的提示给了两个式子：

$$
\text{周转时间} = C - A, \qquad C = S + B
$$

$S$ 是进程开始运行的时刻（start time）。第二个式子只对运行中没被打断过的进程成立，非抢占式调度下每个进程都是这样；被抢占过的进程，$C$ 是它最后一段运行结束的时刻（这一句是我补的）。

等待时间课件没有给式子。进程从到达到完成，不是在 CPU 上运行，就是在就绪队列里等（本讲的例子里进程都不做 I/O），所以（这一段是我补的）：

$$
\text{等待时间} = (C - A) - B
$$

非抢占式调度下，它就等于 $S - A$。算响应时间时，把"第一个响应"近似成进程第一次拿到 CPU，响应时间就是那个时刻减去 $A$。平均周转时间和平均等待时间，是把每个进程的值加起来再除以进程数（这一段是我补的）。

## 3 调度谁：进程、线程与任务状态

### 3.1 进程与线程

课件第 7 页：

- **进程**（process）**是操作系统里执行的基本单位；它代表一个正在执行的独立程序，有自己的内存空间、资源和系统状态。**
- **线程**（thread）**是进程内部一个轻量级的执行单位。**
- **同一进程里的线程能访问同一片内存空间，所以它们之间通信、共享数据比进程之间容易。**
- **线程可以并发运行，让一个进程内部也能多任务。**

第 7 页的图（按图读出）：操作系统里有三个进程，进程 1 里有 A、B、C 三个线程，进程 2 里有一个线程 A，进程 3 里有 A、B 两个线程。程序、进程、任务、线程四个词的分工见 [[L04 操作系统概述#8.3 程序、进程、任务、线程|L04 的四个词]]。

### 3.2 任务与它的三个状态

课件第 8 页：

- **在进程和线程这一级怎样调度处理器，取决于程序的复杂程度和硬件结构（比如核的数目）。**
- **"任务"（task）可以指系统要管理、要执行的一个工作单位，比如一个线程或一个进程。任务可以处于三种状态：就绪**（ready）、**运行**（running）、**阻塞**（blocked）**，阻塞也叫等待**（waiting）。

第 8 页的"任务"比 L04 说得宽：[[L04 操作系统概述#8.3 程序、进程、任务、线程|L04 的词表]]把任务当作进程的同义词，[[Lab3 任务、内存与队列#1.2 任务是什么|Lab 3 里 FreeRTOS 的任务]]相当于线程，第 8 页说两者都可以叫任务（这一句是我补的）。

第 8 页的状态图（按图与标注读出）：

| 从 | 到 | 图上的标注 |
| --- | --- | --- |
| 开始 | 就绪 | 任务被创建 |
| 就绪 | 运行 | 分派（DISPATCH）：优先级最高的任务被选中执行 |
| 运行 | 就绪 | 抢占（PREEMP）：任务不再是优先级最高的 |
| 运行 | 阻塞 | 等待（WAIT）：任务请求的资源不可用，被阻塞 |
| 阻塞 | 就绪 | 任务解除阻塞，但不是优先级最高的 |
| 阻塞 | 运行 | 任务解除阻塞，而且优先级最高 |
| 运行 | 终止 | 退出（EXIT）：任务结束 |

> [!note] 第 8 页的状态图与 L04 的五状态模型
> 第 8 页的开始、终止画在红色虚线框外，框里是课件列的三个状态（按图读出）。对到 [[L04 操作系统概述#9.2 六种转换，各自由什么触发|L04 的六种转换]]上：开始对应新建，终止对应退出；分派对应 Dispatch，抢占对应 Time out 里被抢占的那一种，等待对应 Event Wait，解除阻塞后回到就绪对应 Event Occurs。阻塞直接到运行这条边，L04 里没有。
> 第 8 页是按优先级抢占的实时操作系统的画法：解除阻塞的任务若优先级最高，直接进入运行，不经过就绪，原来在运行的任务同时沿抢占那条边回到就绪；不是最高的，才回到就绪排队。L04 是通用操作系统的画法，事件发生后一律回到就绪，再由调度器挑。在按优先级抢占的系统里，两种画法的结果一样：优先级最高的任务一解除阻塞就上 CPU。FreeRTOS 的实现走的是 L04 那条路：延时到期或队列来了数据，任务先进就绪列表，调度器随即切换过去，见 [[Lab3 任务、内存与队列#2.2 抢占|Lab3 的抢占]]（这一段是我补的）。

### 3.3 分派程序

课件第 9 页：

- **分派程序**（dispatcher）**把 CPU 的控制权交给短期调度器选中的进程，也就是做上下文切换。**
- **分派延迟**（dispatch latency）：**分派程序停下一个进程、让另一个进程开始运行所用的时间。**

第 9 页的图（按图读出）：时间轴上依次是任务 1、任务 2、任务 3、任务 1。任务 1 运行到暂停时，它的上下文被保存；任务 2、任务 3 各自从开始运行到暂停；任务 1 再次上 CPU 时，上下文被恢复，从上次停下的地方继续。

调度器决定下一个运行谁，分派程序负责把 CPU 换过去；分派延迟就是每次切换要付出的时间，[[L04 操作系统概述#8.6 上下文切换要花多少钱|L04 说的上下文切换开销]]就算在这里面（这一句是我补的）。

## 4 六种调度算法

课件第 10 页列出六种常用的调度算法：**先来先服务（FCFS）、最短作业优先（SJF）、最短剩余时间优先（SRTF）、优先级调度（PB）、轮转（RR）、多级队列（MLQ）。** 第 24–25 页又讲了多级反馈队列（MLFQ）。

课件的例子用**甘特图**（Gantt chart）表示调度的结果：横轴是时间，一段一段写着这段时间在 CPU 上运行的进程，段与段之间标着起止时刻（按图读出）。下面把甘特图写成"P1（0–24）→ P2（24–27）"这样的序列，括号里是这一段的起止时刻（这种写法是我用的）。

### 4.1 先来先服务（FCFS）

**先来先服务**（first-come, first-served, FCFS）按到达的先后运行进程，先到的先运行，一直运行到完（这句定义是我补的，课件第 11–12 页只给了例子）。

课件第 11 页的例子：执行时间 P1 24、P2 3、P3 3，**按 P1、P2、P3 的先后到达**；课件注明三个进程都算在时刻 0 到达（assumed all processes are arrived on time 0），先后只决定排队的次序。

- 甘特图：P1（0–24）→ P2（24–27）→ P3（27–30）。
- **等待时间 P1 = 0，P2 = 24，P3 = 27；平均等待时间 $(0 + 24 + 27)/3 = 17$。**

第 12 页把到达的先后换成 **P2、P3、P1**：

- 甘特图：P2（0–3）→ P3（3–6）→ P1（6–30）。
- **等待时间 P1 = 6，P2 = 0，P3 = 3；平均等待时间 $(6 + 0 + 3)/3 = 3$，比前一种好得多。**
- **护航效应**（convoy effect）：**短进程排在长进程后面。**

第一种先后里，P2、P3 各只要 3 个单位，却要跟在 24 个单位的 P1 后面等，平均等待时间就被拉到了 17（这一句是我补的）。

### 4.2 最短作业优先（SJF）

课件第 13 页：

- **最短作业优先**（shortest-job-first, SJF）**按每个进程的 CPU 执行时间来调度，挑执行时间最短的进程运行。** 作业（job）在这里与进程同义（这一句是我补的）。
- **SJF 是最优的：对一组给定的进程，它给出最小的平均等待时间。**
- **难处在于不知道下一次 CPU 请求有多长。** 实际系统只能按进程过去几次的执行时间去估计（这一句是我补的）。

课件第 14 页的例子：四个进程都在时刻 0 到达，执行时间 P1 6、P2 8、P3 7、P4 3。

- 甘特图：P4（0–3）→ P1（3–9）→ P3（9–16）→ P2（16–24）。
- **平均等待时间 $(3 + 16 + 9 + 0)/4 = 7$。**

第 10 页把 SJF 和 SRTF 列成两种算法，所以本课说的 SJF 指非抢占式的那种（按第 10 页读出）。课件这几页的例子与 Silberschatz 等人的《Operating System Concepts》相同，那本书里 SJF 抢占、非抢占两种都包括，抢占式的另称 SRTF；2023 卷的题干写明了 Non-Preemptive（这一句是我补的）。

"SJF 最优"这句话的前提是这组进程同时到达，第 14 页的例子正是这样（这一句是我补的）。到达时间不同时的情形，见 [[#5.2 同一组数据换成 SRTF|2023 卷那组数据换成 SRTF]]。

### 4.3 最短剩余时间优先（SRTF）

课件第 15 页：

- **最短剩余时间优先**（shortest-remaining-time-first, SRTF）**把处理器分给离完成最近的作业。**
- **它属于抢占式调度。**
- **问题是饥饿**（starvation）：**一个进程不断被优先级更高的进程抢占，被无限期地推迟。比如执行时间长的进程，一直被执行时间更短的进程抢占，可能永远没有机会执行完。**

在 SRTF 里，剩余时间短就相当于优先级高（这一句是按第 15 页的说法读出的）。

课件第 16 页的例子，**这次加上了各不相同的到达时间和抢占**：

| 进程 | 到达时间 | 执行时间 |
| --- | --- | --- |
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

- 甘特图：P1（0–1）→ P2（1–5）→ P4（5–10）→ P1（10–17）→ P3（17–26）。课件把它叫作 Preemptive SJF Gantt Chart，SRTF 就是抢占式的 SJF（按第 16 页读出）。
- **平均等待时间 $[(10-1)+(1-1)+(17-2)+(5-3)]/4 = 26/4 = 6.5$ msec**（课件的式子里 $5-3$ 前少了一个左括号）。

每有一个进程到达或运行完，就把就绪进程的剩余时间比一次（这一段是我补的）：

1. 时刻 1，P2 到达，执行时间 4 短于 P1 剩下的 7，P2 抢占 P1；
2. 时刻 2，P3 到达，9 不比 P2 剩下的 3 短；时刻 3，P4 到达，5 不比 P2 剩下的 2 短；P2 一直运行到 5；
3. 时刻 5，剩余时间 P1 7、P3 9、P4 5，P4 运行到 10；
4. 时刻 10，P1 的 7 短于 P3 的 9，P1 运行到 17，最后 P3 运行到 26。

课件式子里 P1 那一项是 $10 - 1$：P1 在 0–1 运行过，从 1 等到 10。按 [[#2.2 周转时间与等待时间怎么算|等待时间的式子]]算，P1 是 $(17 - 0) - 8 = 9$，结果相同（这一段是我补的）。

### 4.4 优先级调度（PB）

**优先级调度**（priority-based scheduling, PB），课件第 17 页：

- **每个进程关联一个优先级数（整数）。**
- **CPU 分给优先级最高的进程，数越小，优先级越高。**
- **分非抢占式和抢占式两种。**
- **问题是饥饿：优先级低的进程可能永远得不到执行。**
- **解决办法是老化**（aging）：**随着时间推移，提高进程的优先级。**

课件第 18 页的例子：五个进程都在时刻 0 到达。

| 进程 | 执行时间 | 优先级 |
| --- | --- | --- |
| P1 | 10 | 3 |
| P2 | 1 | 1 |
| P3 | 2 | 4 |
| P4 | 1 | 5 |
| P5 | 5 | 2 |

- 甘特图：P2（0–1）→ P5（1–6）→ P1（6–16）→ P3（16–18）→ P4（18–19）。
- **平均等待时间 8.2 msec。** 课件没写分项：P1 6、P2 0、P3 16、P4 18、P5 1，合计 41，$41/5 = 8.2$（分项是我算的）。

SJF 可以看成优先级调度的一个特例：优先级按执行时间定，越短越高（这一句是我补的）。

### 4.5 轮转（RR）

**轮转**（round robin, RR），课件第 19 页：

- **每个进程每次得到一小段 CPU 时间，叫时间片**（time quantum，即第 5 页的 time slice，记作 $q$），**通常 10–100 毫秒；时间片用完，进程被抢占，排到就绪队列的末尾。**
- **就绪队列里有 $n$ 个进程、时间片为 $q$ 时，每个进程得到 $1/n$ 的 CPU 时间。**
- **定时器每个时间片中断一次，调度下一个进程。**
- **性能：$q$ 很大时就成了 FIFO；$q$ 很小时，上下文切换太多，开销太高。**

FIFO（first in, first out，先进先出）在这里就是先来先服务：$q$ 不短于每个进程的执行时间时，每个进程在第一个时间片里就运行完，轮转就退化成按到达的先后运行（这一句是我补的）。

课件第 20 页的例子，$q = 4$，三个进程的执行时间 P1 24、P2 3、P3 3，与 [[#4.1 先来先服务（FCFS）|先来先服务的例子]]是同一组数（课件没写到达时间，按甘特图当作都在时刻 0 到达、按 P1、P2、P3 排队）：

- 甘特图：P1（0–4）→ P2（4–7）→ P3（7–10）→ P1（10–14）→ P1（14–18）→ P1（18–22）→ P1（22–26）→ P1（26–30）。
- **通常平均周转时间比 SJF 长，但响应时间更好。**
- **$q$ 应当比上下文切换的时间大得多；$q$ 通常是 10–100 ms。**

P2、P3 的执行时间 3 小于 $q = 4$，在第一个时间片里就运行完，只占了 3 个单位；之后只剩 P1，它每用完一个时间片就排回队尾，队里只有它自己，于是接着运行（这一句是我补的）。

课件没有算这个例子的时间，按 [[#2.2 周转时间与等待时间怎么算|周转时间与等待时间的式子]]（这一段是我算的）：

| 指标 | P1 | P2 | P3 | 平均 |
| --- | --- | --- | --- | --- |
| 周转时间 | 30 | 7 | 10 | $47/3 \approx 15.67$ |
| 等待时间 | 6 | 4 | 7 | $17/3 \approx 5.67$ |
| 第一次拿到 CPU | 0 | 4 | 7 | $11/3 \approx 3.67$ |

同一组进程用 SJF，甘特图是 P2（0–3）→ P3（3–6）→ P1（6–30）（P2、P3 一样长，按排队的先后 P2 在前），平均周转时间 $(3 + 6 + 30)/3 = 13$，比轮转的 15.67 短，与课件"通常比 SJF 长"一致（这一句是我算的）。

课件说轮转的响应时间"通常"更好，原因有两条（这一段是我补的）。一是有上限：$n$ 个进程轮流时，每个进程最多等 $(n - 1)q$ 就能轮到一次（不计切换开销；这个例子 $n = 3$、$q = 4$，上限是 8，P3 在时刻 7 拿到 CPU）。二是不用事先知道执行时间，而 [[#4.2 最短作业优先（SJF）|SJF 的难处]]正在这里。在 [[#4.1 先来先服务（FCFS）|先来先服务的第一种先后]]里，P2、P3 要等到 24 和 27 才第一次拿到 CPU，轮转里是 4 和 7。不过这组数据里三个进程同时到达，SJF 下第一次拿到 CPU 的时刻是 P1 6、P2 0、P3 3，平均 3，比轮转的 $11/3 \approx 3.67$ 还短，只有 P1 比轮转晚。

### 4.6 多级队列（MLQ）

课件第 21 页：

- **多级队列**（multilevel queue, MLQ）**用多个优先级不同的队列来调度进程。**
- **进程按预先定好的标准（比如进程的优先级或类型）分到某一个队列。**
- **每个队列用自己的调度算法（比如轮转、先来先服务）。**
- **某个队列用什么算法是固定的，不随进程的表现而变。**
- **比如三级的 MLQ 可以有高、中、低三个优先级的队列，优先级高的进程先调度。**

课件第 22–23 页的例子：队列 1 的优先级高于队列 2；**队列 1 用轮转，时间片为 2；队列 2 用先来先服务。**

| 进程 | 到达时间 | 执行时间 | 队列 |
| --- | --- | --- | --- |
| P1 | 0 | 4 | 1 |
| P2 | 0 | 3 | 1 |
| P3 | 0 | 8 | 2 |
| P4 | 10 | 5 | 1 |

- 甘特图：P1（0–2）→ P2（2–4）→ P1（4–6）→ P2（6–7）→ P3（7–10）→ P4（10–15）→ P3（15–20）。
- 课件的解说：**① 开始时两个队列里都有进程（原文 have been processed，按上下文应是两个队列开始时都有进程），队列 1 优先级更高，所以它的 P1、P2 先按轮转运行，7 个单位后运行完；② 这时队列 1 里没有进程，队列 2 的 P3 开始运行，但 P3 运行时 P4 进入队列 1，打断了 P3，之后 P3 再拿到 CPU，运行到完。**

两处要读清楚（这一段是我补的）：

- 队列 2 的先来先服务只管队列 2 内部的先后；队列之间按优先级抢占，所以 P4 一到，P3 就被打断，哪怕先来先服务本身不抢占。
- P4 的时间片是 2，却从 10 连续运行到 15：它每用完一个时间片就排回队列 1 的队尾，而队列 1 里只有它自己。

这个例子的周转时间 P1 6、P2 7、P3 20、P4 5，平均 9.5；等待时间 P1 2、P2 4、P3 12、P4 0，平均 4.5（这一句是我算的）。

### 4.7 多级反馈队列（MLFQ）

课件第 24 页：

- **和多级队列一样，多级反馈队列**（multilevel feedback queue, MLFQ）**也有多个队列，每个队列的优先级不同。**
- **不同的是，MLFQ 按进程的表现动态调整它的优先级。**
- **一个多级反馈队列调度器由这几个参数决定：队列的个数；每个队列的调度算法；决定何时把进程升级的方法；决定何时把进程降级的方法；决定进程需要服务时进入哪个队列的方法。**
- **例子：进程一开始放在优先级高的队列里；一个进程用完了时间片还没运行完，它的优先级就逐步降低。**

课件第 25 页的例子：

- **三个队列：Q1 用轮转，时间片 8 毫秒；Q2 用轮转，时间片 16 毫秒；Q3 用先来先服务。**
- **新作业进入 Q1，按轮转调度；它拿到 CPU 时得到 8 毫秒，8 毫秒内没运行完，就移到 Q2。**
- **在 Q2 里它再按轮转调度，又得到 16 毫秒；还没运行完，就被抢占，移到按先来先服务调度的 Q3。**

第 25 页右边的图（按图读出）：三个队列从上到下排开，最上面是时间片 8 的，中间是时间片 16 的，最下面是先来先服务；没运行完的进程沿右边那条线绕下去，从左端排进下一级的队尾；每个队列右边还伸出一个没有文字的箭头，应是在这一级运行完离开（这一点是我推断的）。

和多级队列比，差别在进程能不能换队列：MLQ 里进程一直待在分到的队列，MLFQ 按进程用 CPU 的表现升降。短作业在 Q1 的 8 毫秒里就运行完，很快得到响应；执行时间长的作业逐级沉到下面。升级的办法可以用 [[#4.4 优先级调度（PB）|优先级调度的老化]]：在低优先级队列里等得太久的进程，被移到高一级的队列，防止饥饿（这一段是我补的）。

## 5 真题现场：2023 卷 Q4(d) 非抢占式 SJF

> (d) Consider a set of processes arriving at a computer system with the following burst time requirements. Assume that Non-Preemptive Shortest-Job-First (SJF) scheduling is used.
>
> | Process | Arrival Time | Burst Time |
> | --- | --- | --- |
> | P1 | 0 | 6 |
> | P2 | 1 | 4 |
> | P3 | 2 | 8 |
> | P4 | 3 | 3 |
>
> (i) Calculate the completion order of these processes by providing a Gantt chart to illustrate the execution sequence. [8]
> (ii) Calculate the average turnaround time for all processes. [2]
> (iii) Calculate the average waiting time for all processes. [2]

### 5.1 解答

非抢占式 SJF 的规则：只在 CPU 空出来的时刻做选择，从已经到达的进程里挑执行时间最短的；选中的进程一直运行到完（这条规则是我按 [[#4.2 最短作业优先（SJF）|SJF]] 与 [[#1.2 非抢占式与抢占式|非抢占式]]的定义合起来写的）。

**(i) 答案**（这道题的答案都是我算的）：

1. 时刻 0：只有 P1 到达，P1 运行 0–6。
2. 时刻 6：P1 运行完，P2（4）、P3（8）、P4（3）都已到达，挑最短的 P4，运行 6–9。
3. 时刻 9：剩下 P2（4）、P3（8），P2 运行 9–13。
4. 时刻 13：P3 运行 13–21。

甘特图是 P1（0–6）→ P4（6–9）→ P2（9–13）→ P3（13–21），完成的先后是 **P1 → P4 → P2 → P3**。下图的 (a) 是这道题的答案；(b) 是 [[#5.2 同一组数据换成 SRTF|换成 SRTF]] 之后的对照，推算在 5.2：

![[L19 非抢占式 SJF 与 SRTF 的甘特图.png]]

**(ii)、(iii) 答案**，按 [[#2.2 周转时间与等待时间怎么算|周转时间与等待时间的式子]]：

| 进程 | 到达 $A$ | 执行 $B$ | 开始 $S$ | 完成 $C$ | 周转 $C - A$ | 等待 $C - A - B$ |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | 0 | 6 | 0 | 6 | 6 | 0 |
| P2 | 1 | 4 | 9 | 13 | 12 | 8 |
| P3 | 2 | 8 | 13 | 21 | 19 | 11 |
| P4 | 3 | 3 | 6 | 9 | 6 | 3 |

- 平均周转时间 $= (6 + 12 + 19 + 6)/4 = 43/4 = 10.75$；
- 平均等待时间 $= (0 + 8 + 11 + 3)/4 = 22/4 = 5.5$。

验算：非抢占式下等待时间等于 $S - A$，四个进程是 0、8、11、3，与表里一致（这一句是我补的）。

> [!warning] 两个常见的错
> 误：把四个进程按执行时间从短到长排成 P4、P2、P1、P3。
> 正：调度只能在已经到达的进程里挑。时刻 0 只有 P1 到了，P4 要到时刻 3 才来，所以先运行的是 P1。
> 误：时刻 1 P2 到达，它的 4 比 P1 剩下的 5 短，就让 P2 抢占 P1。
> 正：那是 SRTF 的做法。非抢占式一旦让 P1 上了 CPU，就让它运行到完（这一段是我补的）。

### 5.2 同一组数据换成 SRTF

题目考的是非抢占式。把同一组数据换成 [[#4.3 最短剩余时间优先（SRTF）|SRTF]]，能看清抢占带来的不同（下面的推算和表是我算的）：

1. 时刻 1，P2 到达，4 短于 P1 剩下的 5，P2 抢占 P1；
2. 时刻 2，P3 到达，8 不比 P2 剩下的 3 短；时刻 3，P4 到达，3 不比 P2 剩下的 2 短；P2 一直运行到 5；
3. 时刻 5，剩余时间 P1 5、P3 8、P4 3，P4 运行 5–8；
4. 时刻 8，P1 的 5 短于 P3 的 8，P1 运行 8–13，最后 P3 运行 13–21。

甘特图是 P1（0–1）→ P2（1–5）→ P4（5–8）→ P1（8–13）→ P3（13–21），即 [[#5.1 解答|5.1 那张甘特图]]的 (b)。

| 进程 | 完成 $C$ | 周转 $C - A$ | 等待 $C - A - B$ |
| --- | --- | --- | --- |
| P1 | 13 | 13 | 7 |
| P2 | 5 | 4 | 0 |
| P3 | 21 | 19 | 11 |
| P4 | 8 | 5 | 2 |

平均周转时间 $41/4 = 10.25$，平均等待时间 $20/4 = 5$，都比非抢占式的 10.75 和 5.5 小：两个短进程 P2、P4 不用再等 P1 运行完。代价是 P1 被切成了两段，多了一次 [[L04 操作系统概述#8.6 上下文切换要花多少钱|上下文切换]]。

这说明 [[#4.2 最短作业优先（SJF）|"SJF 最优"]]那句话为什么要加上"同时到达"这个前提：到达时间不同时，允许抢占能做得更好。这组数据里，不抢占的排法中平均等待时间最小的就是 SJF 的 5.5（我穷举验算过）；允许抢占后，SRTF 降到 5。不计切换开销时，SRTF 给出的平均等待时间在所有排法里最小（这一段是我补的）。

## 本讲速记

- **CPU 调度器**（短期调度器）从就绪的进程里挑下一个运行的；**分派程序**把 CPU 交给它，即做上下文切换，所用的时间叫**分派延迟**。
- **非抢占式**（协作式）：进程运行到执行完或进入等待（如 I/O）才自愿让出 CPU，调度器不强行打断，实现简单。**抢占式**：操作系统可以按时间片或优先级强行打断，响应性和公平性好，没有进程能长时间独占 CPU；因为要处理同步和上下文切换，实现往往更难。
- **非抢占式的优缺点**（Sample Q1，我整理的）：优点是实现简单、切换少开销小、同步问题少；缺点是一个进程能长时间独占 CPU，急的、短的进程只能等，响应时间没有保证。
- **五个指标**：CPU 利用率、吞吐量要大；周转时间（从到达到完成）、等待时间（在就绪队列里等的总时间）、响应时间（从提交到第一个响应）要小。
- **式子**：周转时间 $= C - A$，$C = S + B$（第 27 页的提示；后一个只对运行中没被打断的进程成立，这个限定是我加的）；等待时间 $= C - A - B$（我补的），非抢占式下就是 $S - A$。
- **进程**有自己的内存空间、资源和系统状态；**线程**是进程里的轻量执行单位，同一进程的线程共用内存，通信更容易。**任务**有就绪、运行、阻塞三种状态；第 8 页的图里，解除阻塞的任务若优先级最高，直接进入运行、不经过就绪。
- **FCFS**：按到达的先后；P1、P2、P3（24、3、3）的先后平均等待 17，换成 P2、P3、P1 只有 3；**护航效应**是短进程排在长进程后面。
- **SJF**：挑执行时间最短的；进程同时到达时平均等待时间最小；难处是不知道下一次 CPU 请求有多长。第 14 页的例子平均等待 7。
- **SRTF**（抢占式 SJF）：挑剩余时间最短的，有进程到达就重新比较；会**饥饿**。第 16 页的例子平均等待 6.5。
- **优先级调度**：数越小优先级越高，有抢占与非抢占两种；会**饥饿**，用**老化**解决。第 18 页的例子平均等待 8.2。
- **轮转**：每次最多运行一个时间片 $q$（通常 10–100 ms），用完排到队尾；$q$ 大退化成 FIFO，$q$ 小切换开销大，$q$ 要比上下文切换的时间大得多；通常平均周转时间比 SJF 长，响应时间更好。
- **多级队列**：进程固定在分到的队列，各队列的算法固定，队列之间按优先级，高的抢占低的。**多级反馈队列**：进程按表现在队列之间升降，用完时间片没运行完就降一级（第 25 页：8 ms → 16 ms → FCFS）。
- **2023 卷 Q4(d)**：P1（0–6）→ P4（6–9）→ P2（9–13）→ P3（13–21）；平均周转时间 **10.75**，平均等待时间 **5.5**。时刻 0 只有 P1 到了；非抢占式选中就运行到完。
