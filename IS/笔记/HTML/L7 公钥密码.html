Lecture 7 — Public-Key Cryptography

公钥密码

两个素不相识的人，能不能在全世界都看得见的信道上建立保密通信，并且证明"这句话是我说的"？

主线这一讲在做什么

到上一讲为止的密码都是对称密码（symmetric cryptography：加密和解密用同一把密钥，L3 的 DES（data encryption standard，数据加密标准）、L4 的 AES（advanced encryption standard，高级加密标准）都是），它们有一个绕不开的前提：通信双方事先已经共享了一把密钥。这一讲回答 L6 对称密码的安全使用 结尾课后作业 4 留下的问题：两个素不相识的人，能不能在全世界都看得见的信道上建立保密通信，并且证明"这句话是我说的"？

答案是公钥密码：每个人一对数学上相连的钥匙，一把公开、一把自己留着。主线是一条因果链：

  1. 对称密码解决不了两件事——密钥分发、无法抵赖的签名 → 需要"一把公开、一把私有"的钥匙对；
  2. 钥匙对靠陷门单向函数（trapdoor one-way function：人人能正着算，只有握有"陷门"这条秘密的人能倒着算）造出来；它有两种用法：用对方的公钥加密是保密，用自己的私钥加密是证明出处；
  3. 要在纸上算它，先备一套小数模运算工具：取模、平方-乘（square-and-multiply）求模幂、扩展欧几里得算法（extended Euclidean algorithm）求模逆、欧拉函数（Euler's totient function）、欧拉定理（Euler's theorem），各自的含义在第 4 节逐个讲；
  4. RSA（以三位发明者 Rivest、Shamir、Adleman 命名）：靠"大数分解难"实现钥匙对——手算密钥生成、加密、解密，看清它为什么解得回来、为什么安全、裸用会出什么事；
  5. Diffie–Hellman：靠"离散对数（discrete logarithm：已知乘方的结果，反求指数）难"在公开信道上约定一个共同的秘密；它不认证任何人，所以挡不住中间人（man-in-the-middle：截下双方的消息、换成自己的再转发的攻击者）；
  6. 真实系统：公钥只用来传钥匙、证明身份，数据交给 AES；椭圆曲线密码（elliptic curve cryptography，ECC）用更短的钥匙做同样的事。

1对称密码解决不了的两件事

课件第 5 页把公钥密码的动机归结为两个问题，二者都是对称密码在结构上就做不到的。

1.1密钥分发：建安全信道之前先得有安全信道

密钥分发（key distribution）：让通信双方拿到同一把密钥。课件原话："Two parties who want to communicate securely must already share a key. Delivering that key requires a secure channel — which is the thing we were trying to build."

安全信道（secure channel）指窃听者读不到、也改不了的通道。对称密码要建立这样一条信道，前提却是先有一条这样的信道把密钥送过去——这是循环论证。L2 讲对称密码的模型时就指出，密钥要靠安全信道事先送达，而有了安全信道又何必加密——这就是密钥分发问题，当时放下了；一次一密把它放大成"密钥和消息一样长"（L2 8.4）；L6 对称密码的安全使用的密钥层级（key hierarchy：用上层密钥加密保护下层密钥，最顶上是主密钥）把问题往上推了一层，但最顶上那把密钥仍然得靠某种方式送到双方手里，问题没有消失。

规模也是问题（课件外）：N 个人两两之间都要能保密通信，就要 N(N − 1)/2 把不同的密钥，1000 人就是约 50 万把。

1.2签名：共享密钥分不清是谁写的

L6 对称密码的安全使用讲过 MAC（message authentication code，消息认证码：发送方用共享密钥给消息算出一个短标签，接收方用同一把密钥重算，对得上就说明消息没被改过、而且出自持钥人）。它提供两样东西：

  • 完整性（integrity）：消息在路上没被改过；
  • 真实性（authenticity，L6 叫数据源认证）：消息确实来自持有这把密钥的人。

它提供不了第三样：不可否认性（non-repudiation：发送方事后无法抵赖自己发过这条消息）。真实性和不可否认性都在 L1 4.2 定义过；L1 的不可否认性是"发送方和接收方事后都不能否认发过或收过"，这里用到的是其中"发送方不能抵赖"那一半。原因只有一句：密钥双方都有。Bob 收到一条带正确标签的消息，他能确定不是外人写的；但如果双方闹上法庭，Bob 说"这是 Alice 发的"，Alice 说"是 Bob 自己用同一把钥匙造的"，第三方无从判断。课件原话："A shared secret can never settle a dispute between the two people sharing it."

所以数字签名（digital signature：只有签名者能产生、任何人都能验证的一段数据）需要一样只有发送方一个人拥有的东西——对称密码给不出来。

1.31976 年的转折

1976 年 Whitfield Diffie 和 Martin Hellman 发表论文 "New Directions in Cryptography"。课件说，四千年来保密通信一直默认"必须事先送达一个共享秘密"，这个假设在这一篇论文里终结了。一年后，Rivest、Shamir、Adleman 发明了 RSA（1977 年完成，1978 年正式发表）。

勘误课件第 5 页的史实说反了一半

课件原话："Diffie and Hellman set out to solve both, and did not know how to build either. They published the requirements and challenged the world to meet them — and two years later Rivest, Shamir and Adleman did."

误：1976 年的论文两个问题都没解决。

正：1976 年的论文给出了 Diffie–Hellman 密钥交换，第一个问题（密钥分发）当场就解决了；他们没给出的是一个能用的公钥加密与签名方案，只提出了概念和要求，这一半由 RSA 补上。课件自己在第 2 页（"That assumption ended in one paper"）和第 20 页（Diffie–Hellman "is also the answer to last week's take-home task"）都承认了这一点，与第 5 页矛盾。

"two years later" 按 RSA 正式发表（1978）算是对的，按发明（1977）算是一年后；课件第 13 页写的就是 "1977"。

补充公开史之外（背景，不考）

英国政府通信总部（Government Communications Headquarters，GCHQ）内部更早就有了同样的想法：James Ellis 1970 年提出"非秘密加密"的概念，Clifford Cocks 1973 年给出了等价于 RSA 的方案，Malcolm Williamson 1974 年给出了等价于 Diffie–Hellman 的方案，1997 年才解密公开。课件"四千年"的说法按公开学术史成立。

2公钥的思想：一对钥匙

课件第 4 页的一句话概括："Two keys instead of one. Publish one of them. Everything follows from that."

2.1公钥公开，私钥永不离手

公钥密码（public-key cryptography，也叫非对称密码 asymmetric cryptography：加密和解密用两把不同的钥匙）让每个人生成一个钥匙对（key pair）：

公钥（public key）私钥（private key）
谁有公开发布：放在网站、目录或证书里，任何人都可以拿，包括攻击者只有主人自己知道，从不在网络上传送
怎样得到和私钥作为一对，由主人同时生成（RSA 见 5.1，DH 见 6.2）只知道公钥，在计算上推不出私钥
用来做什么给主人加密；验证主人的签名解密发给主人的消息；以主人的身份签名

（"证书"是把公钥和主人身份绑在一起的文件，L8 数字签名、证书与 PKI的内容。）

两把钥匙的关系，课件一句话："What one key does, only the other can undo."——一把钥匙做的事，只有另一把能撤销。

整个体系只靠一句话撑着，课件叫它 "The key requirement"：

"It must be computationally infeasible to determine the private key given only the public key. Everything rests on that one sentence."

计算上不可行（computationally infeasible）：理论上算得出来，但已知最好的方法也要花远超信息有效期的时间。这和 L2 的计算安全是同一种思路：不是"不可能"，而是代价远超值得付出的程度。

2.2单向函数与陷门

钥匙对靠什么造出来？靠一类特殊的函数。

单向函数（one-way function）：正着算容易，倒着算在计算上不可行。课件的两个例子：

  • 两个大素数（prime：只有 1 和自身两个因数的数）相乘很容易；从乘积分解回两个素数很难（大数分解，factoring）。
  • 一个数的若干次方对一个素数取模很容易；从结果反求指数很难（离散对数，discrete logarithm，第 6 节讲）。

单向函数对公钥加密还不够：公钥加密要求"任何人都能加密"（正向容易），同时"主人自己能解密"（主人能倒着算）。所以需要陷门单向函数（trapdoor one-way function）：对所有人都是单向的，唯独掌握一条额外信息——陷门（trapdoor）——的人能轻松倒着算。陷门就是私钥。

勘误课件把两种函数混为一谈

课件第 6 页的标题是 "a one-way function with a trapdoor"，随后举的两个例子都当作陷门函数。

误：素数相乘、模幂都是"带陷门的单向函数"。

正：在 DH 使用的设定下（公开的大素数模），离散对数没有已知的陷门——没有哪条可以交给主人保管的额外信息能让他从结果轻松反求指数。Diffie–Hellman 根本不需要陷门，它靠的是指数运算的交换律（6.2）。素数相乘同样只是单向函数本身。RSA 真正的陷门函数是"把消息做一个公开次数的乘方再取模"，陷门是私钥（等价地，是模数的两个素因子），见 5.5。教材第 9.1 节把这两个概念分开定义。

考试被问"公钥密码靠什么"，答"陷门单向函数：公开方向容易，没有陷门（私钥）就无法逆转"即可。

2.3公钥密码不是什么

课件第 6 页底部专门有一框 "Note what it is NOT"："Public-key cryptography is not more secure than symmetric cryptography, and it does not replace it. It solves different problems, and it is far slower."

教材第 9.1 节把这归纳为三个常见误解：

  1. 误：公钥密码比对称密码更安全。 安全性取决于密钥长度和破解所需的计算量，与"对称还是公钥"无关。
  2. 误：公钥密码让对称密码过时了。 公钥运算比对称慢得多（课件说约一千倍，这是经验量级，随硬件与密钥长度变化很大），实际系统只用它处理几百字节，数据全交给 AES（7.1）。
  3. 误：有了公钥密码，密钥分发就轻而易举了。 公钥虽然可以公开，但"这把公钥真是 Bob 的吗"仍要解决，否则就会遭到中间人攻击（6.5）。课件没有列这一条，但第 22、25 页讲的正是它。

3两种用法

记号：E(K, X) 表示用钥匙 K 对 X 做加密运算，D(K, Y) 表示用 K 对 Y 做解密运算；PUa、PRa 是 Alice 的公钥、私钥，PUb、PRb 是 Bob 的。

3.1机密性模式：用接收方的公钥加密

课件第 7 页左栏："Alice encrypts with BOB'S PUBLIC key. Bob decrypts with BOB'S PRIVATE key."

课件只有这两句文字，教材 Fig. 9.1(a) 把它画成了图，模拟卷 Q2(d) 的参考答案用的就是那张图。按课件的角色重画如下：

从左上角读起：

  1. 公钥环（public-key ring）：每个用户都收集着别人的公钥，像一串钥匙。Alice 要给 Bob 发保密消息，就从自己的公钥环里取出 Bob 的公钥 PUb。
  2. 明文 X 和 PUb 一起进入加密算法（例如 RSA），得到密文 Y = E(PUb, X)。
  3. Y 在公开信道上传给 Bob。窃听者看得到 Y，也看得到所有公钥，唯一缺的是 Bob 的私钥。
  4. Bob 用自己的私钥 PRb 运行解密算法，恢复明文 X = D(PRb, Y)。

为什么成立，课件原话："Anyone can encrypt to Bob, because his public key is published. Only Bob can read it, because only he holds the matching private key."

代价："Gives: confidentiality. Bob has no idea who sent it."——这里得到的是机密性（confidentiality：只有授权的人能读），但 Bob 的公钥人人都有，谁都可能是发件人，所以没有任何认证。

考场上这道题怎么答、图怎么画，在讲完 RSA 之后的 5.7 汇总，那里还给了一张英文标注的考场版图。

  • 为什么能证明出处："Only Alice could have produced it, because only she holds her private key."
  • 为什么人人能验证："Everyone can check it, because her public key is published."
  • 代价："Gives: authenticity and non-repudiation. No secrecy at all."——Alice 的公钥是公开的，谁都能解开，内容毫无保密性可言。

这就是第 1.2 节要的签名：不可否认性来自"私钥只有一个人有"，这是共享密钥给不了的。

易错"用私钥加密 = 签名"只是 RSA 上的简化说法

课件（和教材 Fig. 9.1(b)）把签名说成"用私钥加密"，第 6 页还说"一把钥匙做的事，只有另一把能撤销"。

误：任何公钥算法都能"用私钥加密"，签名就是对消息做私钥加密。

正：这只在 RSA 上成立，因为 RSA 的加密和解密是同一种运算（5.2）。DSA（digital signature algorithm，美国标准数字签名算法）及其椭圆曲线版本 ECDSA（elliptic curve DSA）这类签名算法的私钥根本不能用来"加密"，Diffie–Hellman 的钥匙对也没有"撤销"这回事。即使是 RSA，实际签名也不是直接对消息运算，而是先对消息求哈希（hash：把任意长的消息压成固定长度摘要的函数）、加填充，再用私钥运算，填充方案如 PKCS#1 v1.5（公钥密码标准 PKCS 第 1 号里较早的确定性签名填充，public-key cryptography standards，5.1 还会提到这份标准）或 RSA-PSS（PSS 是 probabilistic signature scheme，概率签名方案）。签名的细节是 L8 数字签名、证书与 PKI 的内容。

按课件和教材的说法答题不会扣分。

3.3一条规则判定所有情形

课件把两种模式压成一条规则（"The rule that decides every case"）：

"If you want only ONE person to be able to read it, use THEIR public key — because only they hold the matching private one. If you want EVERYONE to be able to verify that it came from you, use YOUR private key — because only you hold it."

课件第 27 页的说法更短："The public key is for talking TO someone. The private key is for proving you ARE someone."

判断时先问"我要的是保密还是证明出处"，再看"这件事只有谁做得到"：

目标用谁的哪把钥匙理由
只让某一个人能读接收方的公钥加密只有接收方有配对的私钥
让所有人能验证出自我我自己的私钥加密（签名）只有我有这把私钥

两者合用（课件 "And both together"）：Alice 先用自己的私钥签名，再用 Bob 的公钥把结果加密；Bob 先用自己的私钥解密，再用 Alice 的公钥验签。

Z = E(PUb, E(PRa, X)),  X = D(PUa, D(PRb, Z))

四次钥匙运算，消息同时具备机密性、真实性和不可否认性。外层用 Bob 的公钥，所以只有 Bob 能剥开；内层用 Alice 的私钥，所以剥开后能确认出自 Alice。课件说这是下一讲 L8 数字签名、证书与 PKI 的起点。

课堂活动 1 解答：哪把钥匙做哪件事

题目：对每种情形说出用哪把钥匙，四个候选：Alice 的公钥、Alice 的私钥、Bob 的公钥、Bob 的私钥。

题情形答案理由

3Alice 要让所有人确认一份公开声明出自她Alice 的私钥要人人能验证出自我，用我的私钥

4手算工具箱：模运算

课件第 9 页说要用到的数学只有三样："arithmetic on a clock face, one counting function, and one theorem"——取模运算、欧拉函数、欧拉定理。要在考场上真正算出来，还得补两样课件只点了名的技能：平方-乘的具体格式，和求模逆的扩展欧几里得算法。本节把这五样讲到能直接套用。

4.1取模，以及随时可以取模

a mod n 是 a 除以 n 的余数，取值在 0 到 n − 1 之间。RSA 的一切运算都在这 n 个数里进行，超出范围就"绕回来"，像钟面一样。

式子理由
17 mod 5 = 217 = 3 × 5 + 2
23 mod 12 = 11钟面上的 23 点是 11 点
−3 mod 7 = 4加 7 直到变成非负：−3 + 7 = 4

同余（congruence）：a ≡ b (mod n) 读作"a 与 b 模 n 同余"，意思是两者除以 n 的余数相同，等价于 n 整除 a − b。例如 81 ≡ 1 (mod 40)。两种写法的分工：mod 写在算式里当运算（"取余数"），≡  (mod n) 写在两个数之间当关系。

易错负数取模

数学上的 a mod n 永远落在 0 ～ n − 1：−3 mod 7 = 4，不是 −3。C、Java 的 % 对负数会给出 −3，那是编程语言的约定。扩展欧几里得算出负的逆元时也要这样加 n 化正（4.3）。

手算能进行下去全靠两条规则：

(a × b) mod n = ((a mod n) × (b mod n)) mod n
(a + b) mod n = ((a mod n) + (b mod n)) mod n

为什么成立：把 a、b 写成 a = k1n + ra、b = k2n + rb，则 ab = n(k1k2n + k1rb + k2ra) + rarb，前一项是 n 的倍数，取余时整个消失，余数只由 rarb 决定。加法同理。

用法就是课件那句："You may reduce at every step — which is what keeps the numbers small." 每做一次乘法就立刻取模，参与运算的数永远小于 n，乘积永远小于 n2。

考场上怎么取模（不依赖计算器的存储功能）：每一步写成"乘积 → 商 → 余数"三栏，商是乘积除以 n 的整数部分，余数 = 乘积 − 商 × n。普通计算器上就是"乘积 ÷ n，读整数部分"；不用计算器就先估商，再修正。例：5808 mod 187，先估 187 × 30 = 5610，5808 − 5610 = 198，比 187 大，再减一次得 11，所以商 31、余数 11。最后检查余数在 0 ～ n − 1 之间。

一个可选的省力技巧：余数接近 n 时改用负数代表。例如模 187 时 154 ≡ −33，算 88 × 154 可以改算 88 × (−33) = −2904；2904 = 15 × 187 + 99，所以 −2904 ≡ −99 ≡ 88。与直接算 13552 = 72 × 187 + 88 结果一样，但乘积小了很多。

4.2模幂：平方-乘

模幂（modular exponentiation）：计算 be mod n。RSA 的加密、解密和 Diffie–Hellman 的每一步都是它。

直接算行不通：课件第 15 页的例子里 887 有 14 位、1123 有 24 位，真实 RSA 的指数有 2048 位，连写下来都不可能。办法是课件第 10 页的平方-乘（square-and-multiply）：只做"平方"和"乘底数"两种乘法，每做一次就取模。课件的最小例子 74 mod 11："do not calculate 2401 first"——72 = 49 ≡ 5，52 = 25 ≡ 3，所以 74 mod 11 = 3。

指数不是 2 的幂时，有两种等价的格式。两种都要会：课件第 16 页的提示 "write d in binary first" 指的是第二种；第一种每一项都能单独复核，更不容易出错。下面都用课件第 15 页的加密 887 mod 187 演示。

格式一：逐次平方表。

  1. 把底数反复平方、每次取模，列出 b1, b2, b4, b8, …，列到不超过指数的最大的 2 的幂为止；
  2. 把指数拆成 2 的幂之和（就是写成二进制）：7 = 4 + 2 + 1；
  3. 把对应的几项连乘，每乘一次取模。依据是 b4+2+1 = b4 · b2 · b1。
项计算商余数
881——88
88288 × 88 = 7744417744 − 7667 = 77
88477 × 77 = 5929315929 − 5797 = 132
881+288 × 77 = 6776366776 − 6732 = 44
881+2+444 × 132 = 5808315808 − 5797 = 11

结果 887 mod 187 = 11，与课件一致。

格式二：从左到右二进制法。

  1. 把指数写成二进制：7 = 1112；
  2. 从 r = 1 开始，从最高位往最低位逐位读：每读一位先把 r 平方；如果这一位是 1，再乘一次底数。每步都取模。
读到的位平方是 1 则乘 88当前值 r
112 = 11 × 88 = 8888
1882 = 7744 ≡ 7777 × 88 = 6776 ≡ 4444
1442 = 1936 ≡ 6666 × 88 = 5808 ≡ 1111

为什么这样做对：从左往右读二进制，每多读一位，已读部分代表的数就"乘 2，再加上这一位"。例如 23 = 101112 的已读部分依次是 1 → 102 = 2 → 1012 = 5 → 10112 = 11 → 101112 = 23。指数乘 2 对应把当前结果平方，指数加 1 对应再乘一次底数，所以 r 始终等于"底数的已读部分次方"。

两种格式的取舍：格式一的平方链和连乘分开，每一项都能单独复核，适合考场；格式二不用存一张表，是课件提示的做法，也是真实实现的做法。指数是 k 位二进制时，两种格式都最多做约 2k 次模乘，所以 2048 位的指数也只要几千次乘法——这就是课件说"how real implementations exponentiate numbers thousands of bits long"的原因。（课件外：实际 RSA 常取 e = 65537 = 216 + 1，二进制只有两个 1，加密只要 16 次平方加 1 次乘法。）

易错平方-乘的四个常见错
  • 忘了取模：一步不取，后面的数就失控，手算必错。
  • 二进制写错：先把指数的二进制写出来、再反过来加一遍核对（27 = 110112 = 16 + 8 + 2 + 1）。
  • 格式一里把指数相乘：b4 · b2 = b6，指数相加；只有平方那一列才是指数翻倍。
  • 格式二里顺序颠倒：每一位都是先平方、后（视该位）乘底数；最高位那个 1 也照样"先平方再乘"，只是 12 = 1 看不出来。

自查办法：两种格式各算一遍；模数是素数时还可以用费马小定理先把指数约小（4.5）；平方链里一旦出现 1，此后的平方全是 1。

平方-乘计算器：两种格式同时排出来

填底数、指数、模数，页面按上面两种格式逐行写出「乘积 → 商 → 余数」，可以拿来对自己的手算。

课堂活动 2(e)：35 mod 7

格式一：31 = 3，32 = 9 ≡ 2，34 = 22 = 4；5 = 4 + 1，所以 4 × 3 = 12 ≡ 5。

格式二：5 = 1012。读 1：1 · 3 = 3；读 0：32 = 9 ≡ 2；读 1：22 = 4，4 × 3 = 12 ≡ 5。

核对：243 = 34 × 7 + 5。题面提示 "Do not compute 243 first if you can avoid it"，这里 243 只用来核对。

4.3模逆与扩展欧几里得

模逆（modular inverse）：a 模 n 的逆元是满足 a × b ≡ 1 (mod n) 的数 b，记作 a−1 mod n。它扮演"除以 a"的角色——模运算里没有直接的除法，要除以 a 就乘它的逆元。课件的例子：3 × 27 = 81 = 2 × 40 + 1，所以 3−1 mod 40 = 27。

RSA 生成私钥那一步就是求一个模逆（5.1）。

什么时候存在。 最大公因数（greatest common divisor，gcd）是两个数共有的最大因数；gcd 为 1 叫两数互素（coprime）。结论：

a−1 mod n 存在 ⟺ gcd(a, n) = 1

必要性：若 a 与 n 有公因数 g > 1，则 ab − kn 对任何整数 b, k 都是 g 的倍数，不可能等于 1，所以找不到 b 使 ab ≡ 1。充分性由下面的扩展欧几里得算法给出：它在 gcd 为 1 时直接把 b 构造出来。

方法一：试算。 课件说小数可以试。高效的试法是利用"ab = 1 + kn"：

b = 1 + kna,  k = 1, 2, 3, … 直到整除为止

因为 b < n，所以 1 + kn = ab < an，k 一定小于 a，最多试 a − 1 次。例：

  • 7−1 mod 160：k = 1，161/7 = 23，整除，所以是 23。
  • 3−1 mod 40：k = 1，41/3 不整除；k = 2，81/3 = 27，所以是 27。
  • 13−1 mod 60：1 + 60k 依次为 61、121、181、241、301、361、421、481，到 k = 8 才有 481 = 13 × 37，所以是 37。

RSA 里求逆的数是公开指数 e，考试题的 e 一般很小（3、7、13），这个试法几步就出结果。

方法二：扩展欧几里得算法（extended Euclidean algorithm）。a 稍大、试算太慢时用它，它也是程序里的标准做法。

先看普通的欧几里得算法（Euclidean algorithm，辗转相除法）：用大数除以小数取余数，再用小数除以余数，反复进行，最后一个非零余数就是 gcd。依据是 gcd(n, a) = gcd(a, n mod a)。

扩展版在辗转相除的同时，多记一列 t，保证每一行都满足

ri ≡ ti · a (mod n)(A)

做法：

  1. 第一行写 r = n, t = 0；第二行写 r = a, t = 1。这两行显然满足 (A)：n ≡ 0 · a，a ≡ 1 · a。
  2. 往下每一行：用上上行的 r 除以上一行的 r，取商的整数部分（下文就叫"商"，不另用字母，免得和 RSA、DH 里的素数 q 混淆）；新的 r = 上上行 r − 商 × 上一行 r（就是余数），新的 t = 上上行 t − 商 × 上一行 t。
  3. 当 r = 1 时，这一行的 t 就是 a−1（若为负，加 n）。若 r 先变成 0、最后的非零余数不是 1，说明 gcd ≠ 1，逆元不存在。

为什么第 2 步保持 (A)：新行的 r 和 t 用的是同一组"上上行减商倍上一行"，两行都满足 (A)，相减后仍满足。所以走到 r = 1 时有 1 ≡ t · a，t 正是逆元。

例：13−1 mod 60（课后任务 1 要用）。

r商t检查 (A)

再看课件第 14 页的 7−1 mod 160，两步就到：160 = 22 × 7 + 6，t = 0 − 22 × 1 = −22；7 = 1 × 6 + 1，t = 1 − 1 × (−22) = 23。所以 d = 23，验算 7 × 23 = 161 = 160 + 1。

另一种常见写法：先辗转相除，再回代

教材和很多参考书用"回代"：先把辗转相除写完，再从倒数第二个等式往回代入，把 1 表示成 s · n + t · a 的形式（这个等式叫裴蜀等式，Bézout's identity）。以 7−1 mod 160 为例：

  1. 辗转相除：160 = 22 × 7 + 6；7 = 1 × 6 + 1。
  2. 回代：1 = 7 − 1 × 6 = 7 − (160 − 22 × 7) = 23 × 7 − 1 × 160。
  3. 两边模 160：1 ≡ 23 × 7，所以 7−1 ≡ 23。

结果和上面的表格法完全相同。回代步数一多就容易抄错系数，考场上推荐表格法：每行只依赖上两行，可以逐行检查 (A)。

易错求逆的两个常见错
  • 模数用错：RSA 求私钥时是 e−1 mod φ(n)，模的是 φ(n)，不是 n。（φ 见下一小节。）
  • 负数不化正：表格最后的 t 常是负数，要加上模数。最后一定用 a × b mod n = 1 验一次。

4.4欧拉函数 φ(n)

欧拉函数（Euler's totient function）φ(n)：1 到 n − 1 中与 n 互素的整数个数。

  • φ(11) = 10：11 是素数，1 到 10 全都与它互素。
  • φ(15) = 8：与 15 互素的是 1, 2, 4, 7, 8, 11, 13, 14，3 和 5 的倍数被去掉了。

一般地，素数 p 满足 φ(p) = p − 1。

RSA 只需要一种情形：n 是两个不同素数 p、q 的乘积，

φ(n) = (p − 1)(q − 1)

计数理由：在 1 到 pq 这 pq 个数里，与 pq 不互素的数一定是 p 的倍数或 q 的倍数（因为 pq 的因数只有 1、p、q、pq）。p 的倍数有 p, 2p, …, qp 共 q 个；q 的倍数有 p 个；pq 本身被数了两次。所以不互素的有 p + q − 1 个，

φ(pq) = pq − (p + q − 1) = pq − p − q + 1 = (p − 1)(q − 1)

（这里数到了 pq 本身，但 pq 与自己不互素，不影响个数，和定义里"小于 n"一致。）

课件的例子：n = 17 × 11 = 187，φ(187) = 16 × 10 = 160；不互素的数有 17 + 11 − 1 = 27 个，187 − 27 = 160。

课件强调的一点："Anyone who knows p and q can compute φ(n) instantly. Anyone who knows only n must factor it first — and that is the whole security of RSA." 反过来也成立：知道 φ(n) 就能分解 n，见 5.5。

补充定义的措辞

课件写 "share no common factor with n"，严格说是"除 1 以外没有公因数"，即 gcd(k, n) = 1（任何两个数都有公因数 1）。另外约定 φ(1) = 1，这时"小于 n"的写法不适用。对 RSA 没有影响。

4.5欧拉定理

欧拉定理（Euler's theorem）：

aφ(n) ≡ 1 (mod n)  前提：gcd(a, n) = 1

前提不能丢：a 必须与 n 互素。课件原文也写了 "for any a sharing no factor with n"，下一节会看到，课件自己的 RSA 例题恰好违反了它。

n 是素数 p 时，φ(p) = p − 1，定理变成费马小定理（Fermat's little theorem）：p 不整除 a 时，ap−1 ≡ 1 (mod p)。

课件的验证：710 mod 11 = 1，而 φ(11) = 10。用格式一手算：72 ≡ 5，74 ≡ 3，78 ≡ 9，710 = 78 · 72 ≡ 9 × 5 = 45 ≡ 1。

它在本讲有两个用处：

  1. 保证 RSA 解得回来：若 ed = 1 + kφ(n)，则 Med = M · (Mφ(n))k ≡ M。课件说的就是这个，5.3 展开。
  2. 约小指数，用来验算：gcd(a, n) = 1 时，指数可以先对 φ(n) 取模，ax ≡ axmodφ(n)。模数是素数 q 时就是对 q − 1 取模。例：590 mod 23，90 = 4 × 22 + 2，所以等于 52 mod 23 = 2。Diffie–Hellman 验算时会用到（6.3）。
欧拉定理为什么成立（选读，课件说不要求证明）

设与 n 互素的 φ(n) 个余数是 x1, …, xφ(n)。把它们每个都乘上 a（a 与 n 互素）再取模：

  • 结果仍与 n 互素（两个都与 n 互素的数相乘，仍与 n 互素）；
  • 两两不同：若 axi ≡ axj，两边乘 a−1（存在，因为 gcd(a, n) = 1）得 xi ≡ xj。

所以 ax1, …, axφ(n) 只是原来那组数换了个顺序，两组的乘积相同：aφ(n)∏xi ≡ ∏xi。每个 xi 都可逆，两边消去 ∏xi，得 aφ(n) ≡ 1。

证明里"乘 a−1"这一步正是前提 gcd(a, n) = 1 发挥作用的地方。

RSA 以三位发明者 Rivest、Shamir、Adleman 的姓氏首字母命名，课件第 13 页称它 "Still the most widely deployed public-key algorithm in the world"。它把第 2.2 节的陷门单向函数落成了具体算式：加密是 e 次方取模，解密是 d 次方取模，陷门是 d。

误：生成密钥后 p、q 就没用了，可以扔掉。

5.2加密与解密

加密：C = Me mod n  用接收方的公钥 {e, n}
解密：M = Cd mod n  用接收方的私钥 {d, n}

M 是表示成整数的明文，C 是密文。要求 0 ≤ M < n：运算全在模 n 下进行，M 和 M + n 加密出的是同一个密文，解密只能还原出小于 n 的那个。更长的消息要切成块，课件提醒这就回到了 L6 对称密码的安全使用 的工作模式（mode of operation：规定怎样把一个只能处理定长分组的算法反复用在任意长度的数据上）问题。

5.3为什么解得回来

课件第 15 页的"一行证明"：

(Me)d = Med = M1+kφ(n) = M × (Mφ(n))k ≡ M × 1k ≡ M (mod n)

逐步看：

  1. (Me)d = Med：解密就是对密文再做 d 次方。
  2. ed = 1 + kφ(n)：第 5 步取 d = e−1 mod φ(n)，意思就是 ed 除以 φ(n) 余 1，k 是某个正整数。例题里 7 × 23 = 161 = 1 + 1 × 160，k = 1。
  3. M1+kφ(n) = M · (Mφ(n))k：指数相加拆成乘积。
  4. Mφ(n) ≡ 1：欧拉定理。
  5. 所以 Med ≡ M。
勘误课件的"一行证明"漏了一种情形，而且课件自己的例题就落在这种情形里

课件原话："Euler's theorem gives M^φ(n) ≡ 1. That is the whole proof."

误：这一行证明对所有明文 M 都成立。

正：第 4 步用欧拉定理，前提是 gcd(M, n) = 1。例题的 M = 88 = 8 × 11 与 n = 187 = 17 × 11 有公因数 11，欧拉定理不适用：实际算出 88160 mod 187 = 154 ≠ 1。可 88 仍然正确解回了——结论对，证明不全。对所有 0 ≤ M < n 都成立的证明要对 p、q 分开讨论，再合起来，见下面。

顺带一个缺陷：这个例题的密文 C = 11 恰好就是素因子 q，任何人算一下 gcd(11, 187) = 11 就把 n 分解了。课堂演示无妨，真实系统里这类明文出现的概率可以忽略（见下）。

完整证明。 目标：对任意 0 ≤ M < n，Med ≡ M (mod n)。思路是先证模 p 成立、再证模 q 成立，最后合成模 n。

① 模 p 成立。 由 ed = 1 + k(p − 1)(q − 1)，分两种情况：

  • p 不整除 M：费马小定理给出 Mp−1 ≡ 1 (mod p)，于是 Med = M · (Mp−1)k(q−1) ≡ M · 1 = M (mod p)。
  • p 整除 M：两边都是 p 的倍数，Med ≡ 0 ≡ M (mod p)。

两种情况都得到 Med ≡ M (mod p)。

② 模 q 成立。 把 ① 中的 p、q 互换，同样得到 Med ≡ M (mod q)。

③ 合成。 ① 说 p 整除 Med − M，② 说 q 整除 Med − M；p、q 是不同的素数，所以它们的乘积 n 也整除 Med − M，即 Med ≡ M (mod n)。证毕。

第 ③ 步就是中国剩余定理（Chinese remainder theorem，CRT）的最简单形式：p、q 互素时，一个数模 p 的余数和模 q 的余数一旦确定，它模 pq 的余数就唯一确定。

用例题看清楚欧拉定理失效在哪、完整证明又怎样补上：

  • 88 mod 17 = 3，88 mod 11 = 0。
  • 88160 mod 187 = 154，而 154 mod 17 = 1、154 mod 11 = 0：模 17 那一半符合费马小定理（17 不整除 88），模 11 那一半是 0 而不是 1（11 整除 88）。欧拉定理"得 1"的结论只在模 17 的那一半成立。
  • 88161：模 17 时 88161 ≡ 3161 = (316)10 · 3 ≡ 3（费马小定理，161 = 10 × 16 + 1）；模 11 时是 0。0 ～ 186 里模 17 余 3、模 11 余 0 的数只有 88，所以 88161 ≡ 88 (mod 187)。

这种"坏"明文有多少：与 n 不互素的 M 恰有 n − φ(n) = p + q − 1 个，例题里是 27 个（占 187 个的约 14%）；真实的 2048 位 n 里占比约为 2−1023，随机碰上的可能性可以忽略。而且真碰上了，算 gcd(M, n) 就分解了 n，问题出在"碰上"本身，不在解密。

课件第 3 页说不会让证明。如果被问"为什么 RSA 解密能还原明文"，写出上面那行式子，注明"ed ≡ 1 (mod φ(n))，且 gcd(M, n) = 1 时由欧拉定理；一般情形对 p、q 分别用费马小定理，再由中国剩余定理合成"即可。

5.5安全性建立在大数分解上

课件第 17 页："Multiplying two 1024-bit primes takes microseconds. Recovering them from the 2048-bit product has never been done and no efficient method is known."（课件外：公开的最大分解纪录是 2020 年分解的 RSA-250，一个 829 位的公开挑战数。）

为什么分解 n 就破了 RSA：分解出 p、q → 算出 φ(n) = (p − 1)(q − 1) → 用扩展欧几里得算出 d = e−1 mod φ(n)，和合法主人走的是同一条路。

反过来，知道 φ(n) 就等于分解了 n，这是第 5.1 节第 3 步要求 φ(n) 保密的原因。推导：

φ(n) = (p − 1)(q − 1) = pq − (p + q) + 1 = n − (p + q) + 1 ⇒ p + q = n − φ(n) + 1

知道了 p + q 和 pq = n，p、q 就是一元二次方程 x2 − (p + q)x + n = 0 的两个根。例：n = 187，φ = 160，p + q = 28，方程 x2 − 28x + 187 = 0，判别式 282 − 4 × 187 = 36，x = (28 ± 6)/2 = 17 或 11。（课件外：知道 d 也能高效地分解 n，所以 p, q、φ(n)、d 三者知道任何一个都等价于破解。）

这也就是 2.2 说的陷门：x ↦ xe mod n 人人能算，没有 d（或 p、q）就无法倒回去。

课件用红字提醒："Note carefully: nobody has PROVED that factoring is hard. RSA is computationally secure in exactly the sense of Lecture 2 — unbroken, not unbreakable." 即 L2 的计算安全：至今没人破，不等于证明了破不了。（课件外：破 RSA 是否一定要先分解 n，也没有证明。）

密钥长度（课件第 17 页）：

  • 1024 位：已不再被认为足够；
  • 2048 位：目前常用的最低要求；
  • 3072 位或更长：用于长期保护。

课件："a 128-bit symmetric key is roughly as strong as a 3072-bit RSA key. Public-key algorithms need far longer keys for the same security." 对称密钥只能穷举，每多一位难度翻倍；RSA 的模数有比穷举快得多的分解算法可用，所以要长得多才达到同样的强度。完整对照表见 7.2。课件第 27 页的总结："Its security is the size of the numbers, not the structure of the algorithm."

5.6教科书 RSA 的三个问题

教科书 RSA（textbook RSA）：直接按 C = Me mod n 加密、不做任何额外处理的 RSA，就是上面学的版本。课件第 17 页列了它的三个问题和修复办法：

问题怎么回事修复
确定性同一明文在同一公钥下永远得到同一密文随机化填充（padding：加密前给消息混入新鲜随机数据再编码，如 OAEP，optimal asymmetric encryption padding，最优非对称加密填充）："Never encrypt a raw message with RSA."
慢同样的数据量约比 AES 慢一千倍混合加密：RSA 只保护一把新生成的 AES 密钥，数据用 AES（7.1）
侧信道（side channel：从实现的耗时、功耗等物理表现里偷信息）求幂的耗时随私钥 d 的各位变化，测时间能推出 d常数时间实现与盲化："Never write your own."

问题一：确定性。 这正是课后任务 2（"the one that matters"）。

题目："Alice sends Bob one of only four possible instructions, encrypted with textbook RSA using Bob's public key. Explain how an eavesdropper reads the message without factoring anything. Which Lecture 5 failure is this?"

答：教科书 RSA 是确定性（deterministic）的，同一个 M 在同一把公钥下永远加密成同一个 C。Bob 的公钥是公开的，窃听者把四条可能的指令各自用它加密一遍，得到四个密文，再和截获的密文比对，相同的那条就是明文。全程不需要分解 n，也不需要 d。

数值演示：用课件的公钥 {7, 187}，设四条指令编码为 2、3、4、5，

27 ≡ 128, 37 ≡ 130, 47 ≡ 115, 57 ≡ 146 (mod 187)

截获 C = 130，立刻知道指令是 3。

可能报文攻击：把每个候选都用公钥加密一遍

默认就是上面的四条指令（编码 2、3、4、5）和公钥 {7, 187}。改候选、改截获的密文都行。

这是 L6 对称密码的安全使用 里 ECB 模式（electronic codebook，电子密码本：每个分组用同一把密钥独立加密）的同一个病：相同明文 → 相同密文。课件原话 "That is the ECB problem from Lecture 5, in a different algorithm"。明文空间越小，这一招越致命。教材把这类攻击叫可能报文攻击（probable-message attack）。

修复：OAEP（optimal asymmetric encryption padding，最优非对称加密填充：加密前把消息和一串新鲜的随机数混合编码，再做 RSA 运算），同一条消息每次加密的结果都不同，窃听者的"逐条试加密再比对"就失效了。

教科书 RSA 的另外两个毛病（课件外，选读）
  • 小指数、小明文：公钥 {3, 55} 下加密 M = 3，M3 = 27 < 55，根本没有发生取模，C = 27；攻击者对 27 开立方就得到 3。
  • 可乘性（malleability）：同一公钥下 C(2) = 8，C(3) = 27，8 × 27 mod 55 = 51 = C(6)。不知道明文，也能把两个密文相乘，造出"明文乘积"的合法密文，原因是 (M1M2)e = Me1Me2。

OAEP 同时消除这两个问题：填充后的明文是一个随机的大数，既不会小到不取模，乘起来也不再是合法的填充格式。

问题二：慢。 2048 位的模幂很贵。修复办法"混合加密"放到 7.1 讲，那里还要纠正课件 "This is what TLS does" 的过时说法。TLS（transport layer security，传输层安全协议）是 HTTPS（HTTP over TLS，加密的网页访问）底下负责加密的那一层协议，L9 实用安全协议 会讲。

问题三：侧信道。 平方-乘里"这一位是 1 就多乘一次"，所以求幂的耗时取决于 d 有多少个 1、分布在哪里；攻击者测量大量解密的耗时，就能逐位推出 d。这是 L3 讲过的计时攻击（timing attack），课件说 "the attack we met in Lecture 3"。修复：

  • 常数时间实现（constant-time：运行时间与密钥、数据都无关），例如每一位都做一次乘法、把不需要的结果丢掉（丢弃本身也要用不带分支的选择来实现，否则分支和缓存仍会泄露；常见的做法叫 Montgomery 阶梯）；
  • 盲化（blinding）：解密前先选一个随机数 r，把密文换成 C′ = C · re mod n 再解密，得到 M · r，最后乘 r−1 还原。真正参与求幂的是攻击者不知道的 C′，耗时和他选的密文对不上。

课件的建议是 "Never write your own"：密码学代码用现成的、经过审查的库。

规范答法（按本笔记的角色 Alice → Bob，补上 RSA 实例和安全前提）：

答法考场作答（可直接照写）

Public-key decryption takes the ciphertext and the receiver's private key — the key that matches the public key used for encryption — and produces the original plaintext.

Essential steps (Alice sends a confidential message to Bob):

  1. Key generation. Each user generates a pair of mathematically related keys, a public key and a private key. It must be computationally infeasible to derive the private key from the public key.
  2. Publication. Each user places the public key in a public register or other accessible file and keeps the companion private key secret. Each user maintains a collection of public keys obtained from others (a public-key ring).
  3. Encryption. To send a confidential message X to Bob, Alice takes Bob's public key PUb from her ring and computes Y = E(PUb, X). With RSA, PUb = {e, n} and Y = Xe mod n.
  4. Decryption. Bob decrypts with his own private key: X = D(PRb, Y). With RSA, PRb = {d, n} and X = Yd mod n, which recovers X because ed ≡ 1 (mod φ(n)). No other recipient can decrypt, because only Bob knows PRb; it must also be computationally infeasible to recover X from PUb and Y.

考场版图不带编号；①–⑤ 是 3.1 那张图上标出得分点用的，考场上不画红圈。画图要点（五个得分点一个都不能少）：① 发送方的公钥环，并标出从中取出的是接收方的公钥；② 接收方的私钥，标明只有接收方持有；③ 加密算法框（写 e.g., RSA）；④ 中间的传输箭头，标 "Transmitted ciphertext" 和 Y = E(PUb, X)；⑤ 解密算法之后的明文输出，标 X = D(PRb, Y)。两侧用大括号标出发送方、接收方。

6Diffie–Hellman 密钥交换

课件第 18 页的定位："Not encryption at all. A way for two strangers to agree on a number that nobody watching can compute."

6.1在公开信道上约定一个秘密

课件第 2 页讲评上一讲的课后题（L6 对称密码的安全使用 结尾的课后作业 4，可以回去对照自己当时的答案）：两个陌生人能否在公开信道上约定一个秘密？

直觉说不能："Everything Alice sends, the attacker sees. Everything Bob sends, the attacker sees. The attacker has exactly the same information as Bob does." 课件说大多数人都得出了"不可能"的结论，"That is a reasonable conclusion, and it is wrong."

漏掉的那一点："Bob and the attacker do NOT have the same information. Bob has one extra thing: a secret number he chose himself and never sent." 只要消息构造得让 Bob 的秘密能和 Alice 发来的东西结合、而攻击者又无法从线路上的内容反推出任何一方的秘密，Alice 和 Bob 就会得到同一个值，攻击者得不到。

Diffie–Hellman（以两位作者命名，下文简称 DH）就是这样一个密钥协商（key agreement）协议：双方各出一个秘密，共同算出同一个数，没有一方生成后传给另一方。课件第 19 页强调："It encrypts nothing. At the end, both parties hold the same number and an eavesdropper who saw every message does not."

课件的调色类比（原图只有文字）：

  1. Alice 和 Bob 公开约定一种起始颜色，所有人包括攻击者都看得到；
  2. 两人各自秘密选一种颜色，与公共颜色混合，然后公开交换混合后的颜料；
  3. 各自把自己的秘密颜色加进收到的混合颜料里，两人手里都得到同样的三色混合；
  4. 攻击者有公共颜色和两份双色混合，但把混合颜料分离回原来的成分很难。

对应到数学上："Mixing is raising a number to a power modulo a prime. Separating a mixture is recovering the exponent — the discrete logarithm problem." 加颜料的先后不影响最终颜色，对应的是指数运算的交换律，下一小节的关键。

6.2协议只有四行

事先公开约定两个数：一个大素数 q，以及 q 的一个本原根（primitive root）α。本原根的意思是：α1, α2, …, αq−1 模 q 恰好把 1, 2, …, q − 1 每个数各取到一次。这保证公开值 Y 可能是 1 ～ q − 1 中的任何一个，秘密指数有 q − 1 种可能，不会因为 α 的各次方只落在一小部分数里而变少。（课件外：实际系统还要求 q − 1 有大素因子，否则 Y 会泄露 X 的一部分信息。例如本讲的 q = 23，q − 1 = 22 = 2 × 11，算 Y11 mod 23 是 1 还是 22 就知道 X 的奇偶：811 ≡ 1 对应 XA = 6 为偶数，1911 ≡ 22 对应 XB = 15 为奇数。所以实际用 q = 2p′ + 1 这类"安全素数"，p′ 也是大素数。）

谁做什么算什么发送
Alice秘密选 XA < qYA = αXA mod qYA 发给 Bob
Bob秘密选 XB < qYB = αXB mod qYB 发给 Alice
Alice收到 YBK = YXAB mod q—

为什么两边算出的 K 相同：

YXAB = (αXB)XA = αXAXB = (αXA)XB = YXBA (mod q)

中间一步只用到指数法则 (αx)y = αxy = (αy)x；每一步都在模 q 下成立，因为乘法可以随时取模。课件："Alice and Bob apply their secrets in opposite orders and arrive at the same value. That commutativity is the entire trick."

课件第 20 页的另一句重点："XA and XB never cross the wire. That is the whole point, and it is what the attacker cannot obtain."

补充K 不直接当 AES 密钥（课件前后口径不一）

课件第 20 页说 K "is then used as a symmetric key — for AES"；第 25 页又说共享秘密要先 "expanded into the keys actually used"。以第 25 页为准：K 是 1 ～ q − 1 里的一个数，它的二进制位并不均匀随机，实际系统先把它送进密钥派生函数（key derivation function，KDF：把一个共享秘密压缩、扩展成若干把均匀随机的密钥；L6 讲密钥层级时见过），再拿派生出的密钥给 AES 用，见 7.1。

6.4窃听者要解什么：离散对数

离散对数问题（discrete logarithm problem，DLP）：已知素数 q、底数 α 和 Y = αX mod q，求指数 X。"对数"是因为它是求幂的逆运算，"离散"是因为一切都在整数模 q 下进行，没有连续函数可以利用。

在 q = 23 这样的小数上，逐个列出 5k mod 23 就破了：

k123456789101112131415
5k mod 235210420817161192218211319

查到 8 在 k = 6、19 在 k = 15，XA、XB 都暴露了。安全性完全来自 q 的大小：课件说对 2048 位的素数 "nobody knows how"——列表要列约 22048 项，已知的更好算法也远不实用。

DH 用到的单向函数是"X ↦ αX mod q"：正着算是 平方-乘，倒着算是离散对数。它没有陷门，DH 也不需要陷门（2.2）。

补充严格说攻击者要解的是另一个问题

课件第 19 页："To compute the shared secret they need XA or XB"。攻击者真正的目标是从 αXA 和 αXB 算出 αXAXB，这叫计算 Diffie–Hellman 问题（computational Diffie–Hellman problem，CDH）。解出离散对数足以解决它，但"必须先求出 XA 或 XB"并没有被证明，二者在一般情况下是否等价仍是开放问题。考试按课件和教材答"窃听者必须解离散对数问题"即可。

6.5中间人攻击

中间人攻击（man-in-the-middle attack，MITM）：攻击者坐在通信双方之间，截下每一条消息，换成自己的再转发，双方都以为在直接对话。它是主动攻击（active attack：攻击者不只是旁听，还修改、伪造或替换消息，L1 5.2 讲过）的典型。缩写 MITM 和 L3 的中间相遇攻击（meet-in-the-middle，攻击双重 DES）相同，两者毫无关系，不要混。课件第 22 页："Unauthenticated Diffie–Hellman is defeated completely by an attacker who can intercept and replace messages."

6.6修复：认证交换的值

课件第 22 页底部："The fix is to authenticate the exchange — sign the exchanged values with a private key, and verify with a public key you can trust."

即：Alice 用自己的私钥对 YA 签名（认证模式）一并发出，Bob 用 Alice 的公钥验签；Bob 对 YB 同样处理。Darth 换掉 YA 后造不出 Alice 对 YD 的签名，替换立刻被发现。课后任务 3 问"能防住它的那一件事"，答的就是这个。

但这又引出新问题，课件原话："Which raises the question: how do you know whose public key it is?" 如果 Darth 能让 Bob 相信"Darth 的公钥就是 Alice 的公钥"，签名也挡不住他。L1 讲网络安全模型时预告过同一件事：Diffie–Hellman 能让两个陌生人在公开信道上协商出共享秘密，做不到的是确认对方到底是谁（L1 8.1）。这个问题由证书和 PKI（public key infrastructure，公钥基础设施：由可信机构签发证书、把公钥和身份绑定起来的一整套体系）解决，见 L8 数字签名、证书与 PKI。

7真实系统里的公钥密码

课件第 23 页："Where public-key cryptography actually sits in a real system — and why it is never used alone."

7.1混合加密：公钥管钥匙，对称管数据

课件第 25 页的标题就是结论："Nobody encrypts data with a public key."——公钥运算约比对称慢一千倍，没有真实系统用它加密大量数据。混合加密（hybrid encryption）分三步：

  1. 约定或传送一把密钥：用 DH 约定一个共享秘密，或者用 RSA 加密一把新生成的随机密钥发给对方。不论哪种，只做一次公钥运算。
  2. 派生对称密钥：把共享秘密送进密钥派生函数，扩展成实际使用的几把密钥——每个方向一把加密密钥，外加认证用的密钥。
  3. 用 AES 加密一切：全部流量用 AES 的认证加密（authenticated encryption：一步同时完成加密和完整性认证）模式加密，例如 GCM（Galois/counter mode，伽罗瓦/计数器模式，L6 对称密码的安全使用 的内容），快，而且有硬件加速（L4 讲的 AES-NI，处理器里的 AES 专用指令）。

课件说每次打开 HTTPS 连接发生的就是这件事："An elliptic-curve Diffie–Hellman exchange, authenticated by a signature, producing a shared secret that becomes an AES-GCM key. Public-key cryptography is used once, for a few hundred bytes. Everything after that is symmetric." 这里说的是 TLS，椭圆曲线上的 Diffie–Hellman 见下一小节。

分工（课件 "The division of labour"）："Public-key cryptography solves key distribution and identity. Symmetric cryptography does the actual work. Neither replaces the other."

勘误课件第 17 页说的 TLS 做法已经过时

课件第 17 页在"RSA 慢"的修复里写："Use RSA to protect a freshly generated AES key, then use AES for the data. This is what TLS does."

误：今天的 TLS 用 RSA 加密会话密钥。

正：那是 TLS 1.2 及更早版本的做法之一（严格说 RSA 加密的是预主密钥 pre-master secret，会话密钥再由它派生，见 L9 实用安全协议）。TLS 1.3（2018 年，RFC 8446）删除了 RSA 密钥传输和静态 DH，基于公钥的密钥交换只剩每次连接临时生成的（椭圆曲线上的）Diffie–Hellman，RSA 只用来签名认证。（另有会话恢复用的预共享密钥模式 PSK，pre-shared key，与本讲无关。）课件第 25 页的 HTTPS 描述本身就是 TLS 1.3 的做法，和第 17 页不一致。

删掉它的原因（课件外）：用 RSA 传会话密钥时，服务器的 RSA 私钥一旦日后泄露，攻击者就能解开此前录下的所有会话；每次连接临时生成、用完即弃的 DH 秘密没有这个问题，这叫前向保密（forward secrecy）。

考场上写"混合加密：公钥运算只用来传送或协商对称密钥"不会错；要举 TLS 的例子，写"TLS 1.3：临时（椭圆曲线）Diffie–Hellman 协商 + 签名认证 + AES-GCM"。

课件留了一个悬而未决的地方（"The unresolved piece"）："'authenticated by a signature' is doing a great deal of work in that sentence — and it assumes you already know whose public key you hold." 和 6.6 是同一个问题，交给 L8 数字签名、证书与 PKI。

7.2椭圆曲线：同样的思想，更短的密钥

椭圆曲线密码（elliptic curve cryptography，ECC）：课件第 24 页，"Same ideas, different arithmetic. Instead of exponentiating numbers modulo a prime, ECC adds points on a curve. The structure of the problem is identical; the difficulty per bit is far higher." 对应的难题叫椭圆曲线离散对数问题（elliptic curve discrete logarithm problem，ECDLP）；在曲线上做的 DH 叫 ECDH（elliptic-curve Diffie–Hellman）。TLS 1.3 每次连接临时生成一对 ECDH 钥匙、用完即弃，这种用法记作 ECDHE（末尾的 E 是 ephemeral，临时），HTTPS 用的就是它。

7.3量子计算

课件第 24 页的提醒："A sufficiently large quantum computer would break RSA, Diffie–Hellman and elliptic curves alike — all three rest on problems a quantum algorithm solves efficiently. Symmetric ciphers like AES are far less affected."

  • 打破三者的是 Shor 算法（1994）：在足够大的量子计算机上，能在多项式时间（运算量随密钥位数按多项式增长，例如位数的三次方，对比穷举的 2k 就算"高效"）内完成大数分解和离散对数（包括椭圆曲线上的）。
  • 对称密码只受 Grover 算法影响：穷举的工作量从 2k 降到约 2k/2，把密钥长度加倍就能补回来，所以长期保护用 AES-256。
  • "data that must stay secret for decades is a live concern today"：攻击者现在就可以录下加密流量，等量子计算机造出来再解密（"先收集、后解密"，harvest now, decrypt later）。所以需要现在就换成后量子（post-quantum）算法——在量子计算机面前仍然安全的公钥算法。（课件外：主流浏览器和内容分发网络（content delivery network，CDN：替网站就近分发内容的服务器网络）的 TLS 1.3 已默认采用 X25519 椭圆曲线 DH 与后量子算法 ML-KEM-768 的混合密钥交换，两者都被攻破才会泄密。）
补充后量子标准已经发布

课件说 "post-quantum algorithms are being standardised now"。NIST 已于 2024 年 8 月发布首批三项后量子标准：FIPS 203（ML-KEM，密钥封装 key encapsulation mechanism：用公钥把一把随机对称密钥"封"给对方）、FIPS 204（ML-DSA，签名）、FIPS 205（SLH-DSA，签名），后续标准仍在进行。说"正在标准化"不算错，只是首批已经落地。

7.4这把公钥真是银行的吗

课后任务 4："Alice receives a public key claiming to belong to her bank. How can she tell whether it really does? Write down every mechanism you can think of, and the weakness of each." 课件说这题没有标准答案，用来引出下一讲。可以想到的机制：

机制弱点
带外（out-of-band：走另一条独立的渠道）核对：打电话、去柜台、对照纸质信件上的公钥指纹（fingerprint：公钥的哈希摘要，短到可以念出来核对）麻烦、难以大规模使用；带外渠道本身也可能被冒充
由可信第三方（证书颁发机构 certificate authority，CA）签发证书要信任 CA；CA 可能被攻破或误签；证书吊销（revocation：证书到期前宣布作废，L8 讲）检查不可靠
把银行公钥预装在 App 里（公钥固定，pinning）换钥困难；首次安装本身必须可信
首次使用即信任（TOFU，trust on first use；远程登录协议 SSH 的做法）第一次连接如果已被中间人攻击，就会一直信任错误的公钥
信任网（web of trust：熟人之间互相签名担保；邮件加密软件 PGP 的做法）信任传递不可靠，覆盖面小
从官网下载网站或域名解析被劫持时没用；访问官网本身就需要认证，循环了

每一种都把问题变成了"信任另一样东西"。PKI 是目前规模化的答案，见 L8 数字签名、证书与 PKI。

8六条结论

课件第 27 页的总结：

  1. 公钥密码用两把数学上相连的钥匙：公钥发布，私钥从不离开主人。（2.1）
  2. 公钥用来"对某人说话"，私钥用来"证明你是某人"。（3.3）
  3. RSA 依赖大数分解的困难；它的安全来自数的大小，不来自算法结构。（5.5）
  4. Diffie–Hellman 在公开信道上约定一个共享秘密，不加密任何东西；双方从不同方向算出同一个值。（6.2）
  5. 不经认证的 Diffie–Hellman 会被中间人完全攻破——它不认证任何人。（6.5）
  6. 公钥密码慢，从不用于大量数据；它负责分发密钥，真正干活的是对称密码。（7.1）

本讲速记

  • 对称密码解决不了：密钥分发（要先有安全信道才能送密钥，循环）；不可否认的签名（MAC 的密钥双方都有，只给完整性和真实性）。1976 年 Diffie–Hellman 论文解决了密钥分发并提出公钥概念（课件第 5 页说"两个都没解决"是错的），RSA（1977/78）给出加密与签名。
  • 钥匙对：公钥公开，用来给主人加密、验证主人签名；私钥只有主人有，用来解密、签名。核心要求：只知公钥，在计算上推不出私钥。
  • 单向函数：正算易、逆算难。陷门单向函数：有陷门（私钥）的人能逆算。RSA 是陷门函数（陷门 d）；离散对数没有陷门，DH 不需要陷门。
  • 三个误解：公钥不比对称更安全；不取代对称（慢约千倍）；也没让密钥分发变简单（还要确认公钥归属）。
  • 机密性模式：用接收方的公钥加密，接收方用自己的私钥解密，Y = E(PUb, X)，X = D(PRb, Y)；保密，但不知道谁发的。认证模式：用自己的私钥加密，任何人用发送方公钥解密；证明出处与不可否认，毫无保密（"私钥加密 = 签名"只对 RSA 成立）。规则：只让一个人读用他的公钥，要人人能验证用我的私钥。合用：Z = E(PUb, E(PRa, X))。
  • 取模：结果在 0 ～ n − 1，−3 mod 7 = 4；乘法、加法随时取模；手算每步写"乘积 → 商 → 余数"。
  • 平方-乘：格式一，列 b1, b2, b4, …，按二进制挑项连乘；格式二，二进制从高位读，每位先平方、是 1 再乘底数。例 887 mod 187 = 11，1123 mod 187 = 88，1327 mod 55 = 7。
  • 模逆：存在 ⇔ gcd(a, n) = 1。试算 b = (1 + kn)/a，k < a；扩展欧几里得表 ri ≡ tia，新 t = 上上 t − 商 × 上 t，到 r = 1 读 t，负则加 n。例 7−1 mod 160 = 23，3−1 mod 40 = 27，13−1 mod 60 = 37。
  • φ(n)：1 ～ n − 1 中与 n 互素的个数；φ(p) = p − 1；φ(pq) = (p − 1)(q − 1)（去掉 p + q − 1 个倍数）。φ(187) = 160，φ(15) = 8。
  • 欧拉定理 aφ(n) ≡ 1 (mod n)，前提 gcd(a, n) = 1；费马小定理 ap−1 ≡ 1 (mod p)。互素时指数可对 φ(n) 取模，用来验算。
  • RSA 密钥生成：选素数 p, q（秘）→ n = pq（公）→ φ(n) = (p − 1)(q − 1)（秘）→ 选 e，gcd(e, φ) = 1（公）→ d = e−1 mod φ(n)（秘）。公钥 {e, n}，私钥 {d, n}。例 {7, 187}、{23, 187}；活动 3：n = 55，φ = 40，d = 27，7 → 13 → 7。实际实现保留 p, q 用中国剩余定理加速。
  • 加解密：C = Me mod n（接收方公钥），M = Cd mod n（接收方私钥），M < n。同一种运算，所以 RSA 也能签名（d）、验签（e）。
  • 正确性：ed = 1 + kφ(n)，gcd(M, n) = 1 时由欧拉定理 Med ≡ M；课件例题 M = 88 与 n 有公因子 11（88160 ≡ 154 ≠ 1），一般情形要对 p、q 分别用费马小定理再用中国剩余定理合成。
  • RSA 安全：分解 n → φ → d；知道 φ 即可分解（p + q = n − φ + 1，解二次方程）。分解困难未被证明（计算安全）。1024 位不够，2048 位最低，3072 位长期；AES-128 ≈ RSA-3072。
  • 教科书 RSA 三问题：确定性（四条指令逐条试加密即可读出，同 ECB 之病，修复 OAEP）；慢（混合加密）；侧信道（计时泄露 d，修复常数时间 + 盲化，别自己写）。
  • 模拟卷 Q2(d)：一句话定义 + 机密性模式图（五个得分点：公钥环、接收方私钥、加密算法、传输密文、明文输出）+ 四步（生成钥匙对、公布公钥并保管私钥、用接收方公钥加密、接收方用私钥解密，只有他能解）。角色前后一致。
  • DH：公开 q 与本原根 α；YA = αXA，YB = αXB；K = YXAB = YXBA = αXAXB mod q。密钥协商，不加密任何东西；XA, XB 不上线路。活动 4：q = 23, α = 5, XA = 6, XB = 15 → YA = 8，YB = 19，K = 2（验算 590mod22 = 52 = 2）。
  • 窃听者看到 q, α, YA, YB，要解离散对数（严格说是 CDH）；小 q 列表即破，2048 位素数无人能解。
  • 中间人：Darth 截下 YA、YB，换成自己的 YD，分别与两边建立不同的密钥（活动 4 参数、XD1 = 3, XD2 = 7：Alice–Darth 12，Darth–Bob 5），解密、阅读、重新加密转发。原因：协议不认证任何人。修复：对交换的值签名，用可信公钥验签 → 公钥归属问题 → L8 PKI。
  • 混合加密：DH 协商或 RSA 传送一把密钥 → 派生对称密钥（KDF）→ AES-GCM 加密全部数据。TLS 1.3 删除了 RSA 密钥传输和静态 DH，基于公钥的密钥交换只剩临时 ECDH，加签名认证（课件"RSA 包 AES 密钥是 TLS 的做法"已过时）。
  • ECC：同样的思想，在曲线上做点加法；128 位安全 ↔ ECC 256 ↔ RSA 3072，256 位安全 ↔ ECC 512 ↔ RSA 15360；短钥匙省算力、带宽、电量。只考概念。能力表：RSA 与 ECC 加解密、签名、密钥交换都能做，DH 只能密钥交换，DSS 只能签名。
  • 量子：Shor 算法破 RSA、DH、ECC；Grover 只把对称密钥强度减半；先收集后解密；NIST 2024 年发布 FIPS 203/204/205。
