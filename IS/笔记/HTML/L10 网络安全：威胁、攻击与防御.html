Lecture 10 — Network Security: Threats, Attacks and Defences

网络安全：威胁、攻击与防御

密码协议默认攻击者待在两个诚实端点之间的网络上；这一讲把攻击者挪到端点、网络基础设施、代码和人身上，逐个看他还能从哪里下手、每一处该用什么挡。路线：三把分析尺子 → 恶意软件 → 网络攻击 → 应用与人 → 防御的放置与分层 → 考点表与场景题。

主线这一讲在做什么

前面几讲的密码学都没被攻破：AES（Advanced Encryption Standard，高级加密标准，L4 讲的分组密码）至今安全，TLS 1.3（Transport Layer Security，传输层安全协议第 1.3 版；浏览器地址栏里的 HTTPS，即 HTTP Secure，就是跑在 TLS 上的网页协议）也经住了考验。可组织照样天天被攻破。课件副标题把这一讲的范围说得很直白：「everything cryptography does not protect you from」——密码学保护不了你的一切。

原因是密码协议有一个默认前提：攻击者待在两个诚实端点之间的网络上。这一讲把攻击者挪到别处，逐一看他还能从哪里下手、每一处该用什么挡：

  1. 站在端点上：恶意软件（第 2 节）；
  2. 攻击网络基础设施本身：冒充地址、劫持会话、投毒查找服务、拒绝服务（第 3 节）；
  3. 绕开网络，攻击代码和人：注入、跨站脚本、社会工程（第 4 节）；
  4. 防御不再是「再加一个算法」，而是放在哪、怎么分层、看不看得见、出事后能不能响应（第 5 节）。

课件的口号是「每个攻击配一个防御，成对地学」。本笔记先在第 1 节立三把分析尺子（违反哪个安全属性、防御降的是发生概率还是损失、密码学管不管用），之后每讲一个攻击当场量一遍，最后在第 6 节汇成课件点名「directly examinable」的十行表。和课件顺序的差别：三把尺子课件到最后的课后题才提出，这里提到开头；四道课后题和课堂活动 4 按题型集中到第 6、7 节（活动 1–3 的解答留在各节末尾）；第 8 节专答模拟卷 Q1(c)。

课件自称「the breadth lecture」：每个话题比密码学那几讲浅，覆盖面大得多，服务于课程级第 4 条学习成果（总结网络安全的主要漏洞、威胁、攻击及缓解办法）。

1密码学守不住的地方

1.1攻击者已经在机器上：上一讲的课后题

L9 实用安全协议的最后一道课后题问：前面所有协议都假设攻击者在两个诚实端点之间的网络上；如果攻击者已经在某台机器上，或者他就是用机器的那个人呢？列出五件我们学过的协议都挡不住的事。课件第 2 页给的就是答案：

场景课件原话为什么密码学帮不上
端点上的恶意软件「Reads the plaintext before it is ever encrypted, and the keystrokes before that.」加密保护的是「路上」的数据；在加密之前就被读走，算法再强也没用
被钓走的凭据「The attacker logs in as a legitimate user. Every check passes because nothing was broken.」认证检查的是「凭据对不对」，凭据本身是真的
恶意或粗心的内部人员「Already inside the perimeter, already authenticated, already authorised.」他本来就在网络边界（perimeter，组织网络与外界的分界）之内，有合法权限
没打补丁的内部服务「Reachable from any machine on the network, and nobody is encrypting an exploit.」漏洞利用（exploit，利用软件缺陷让程序做出设计外行为的输入或代码）走的是正常可达的端口
拒绝服务「No cryptographic operation prevents a flood. Availability is not a property TLS provides.」加密能保证内容，保证不了通道不被塞满

课件的结论：「AES has never been broken. TLS 1.3 has held up. Organisations are compromised every single day — by everything on this list.」

1.2分析每个攻击的三把尺子

每遇到一个攻击都用这三个问题量一遍，考点表（6.2）的各列就是它们。

尺子一：违反了哪个安全属性。 用 L1 信息安全基础的六个安全目标（课堂活动 2 题面原样列出）：

目标一句话含义
机密性（confidentiality）信息不被无权的人读到
完整性（integrity）信息不被未授权地修改
可用性（availability）有权的人需要时用得上
真实性（authenticity）对方确实是他声称的那个人，消息确实来自声称的来源
可追责性（accountability）每个操作都能追到唯一的执行者
不可否认性（non-repudiation）发送方、接收方事后都不能抵赖

前三个合称 CIA 三要素（取三个英文首字母）。一个攻击往往同时伤到几个属性，答题写「主要违反的属性 + 一句为什么」，再补次要的。

尺子二：防御降的是 likelihood 还是 impact。 L1 信息安全基础把风险写成

Risk = P(threat exploits vulnerability) × cost of damage

两个因子各有名字：likelihood（可能性：攻击发生并成功的概率，对应 P）和 impact（影响：攻击成功后造成的损失，对应 cost）。L1 的年化版本 ALE = SLE × ARO（ALE，annualised loss expectancy，年化损失期望；SLE，single loss expectancy，单次损失；ARO，annualised rate of occurrence，年发生次数）里，降 likelihood 的防御压的是 ARO，降 impact 的防御压的是 SLE。下文简写 L＝likelihood、I＝impact。

风险是乘积，所以压哪个因子都能把风险降下来；但两类防御的性质完全不同：降 L 的防御一旦被绕过就不再起作用；降 I 的防御恰恰在前者被绕过、攻击已经得手之后才起作用。具体怎么判断见 6.1。

尺子三：密码学管不管用。 课件几乎每页都在指出「这个防御不是密码学」。要建立的直觉是：密码学只解决「数据在两个可信端点之间传输时被读、被改、被冒充」这一类问题。端点本身、可用性、代码缺陷和人，都要靠别的手段。

2恶意软件

恶意软件（malware，malicious software）的课件定义：「Software written to do something the owner of the machine did not want.」——写出来做机器主人不想让它做的事的软件。

2.1两个独立的问题：怎么传播，做了什么

课件说分类之所以让人糊涂，是因为两个不同的问题常被混在一起：

问题一：它怎么传播（propagation mechanism，传播机制）

传播机制课件原话要点
病毒（virus）「Attaches itself to a host file or program. It spreads only when a user runs that host — it needs human action.」寄生在宿主（host，被它感染的另一个文件或程序）里，宿主被运行时才发作、才传播
蠕虫（worm）「Carries its own propagation code and spreads across a network without any user action at all. This is why worms move so fast.」独立程序，自带传播代码，自己在网络上找下一台机器
特洛伊木马（Trojan）「Does not self-replicate. It is disguised as something the user wanted, and the user installs it themselves.」不自我复制；伪装成有用的东西，由用户亲手装上
路过式下载（drive-by download）「Delivered by simply visiting a compromised web page, exploiting a flaw in the browser or a plug-in.」访问被攻陷的网页，即被利用浏览器或插件的漏洞装上

问题二：它做了什么（payload，载荷：恶意软件到位之后真正执行的那部分功能）

载荷课件原话
勒索软件（ransomware）「Encrypts data and demands payment. Often exfiltrates it first, so paying does not remove the leverage.」
间谍软件 / 键盘记录器（spyware / keylogger）「Records keystrokes, screenshots and credentials, and sends them out.」
僵尸网络客户端（botnet client）「Enrols the machine in a network controlled by an attacker, used for denial of service, spam or mining.」
rootkit（隐藏工具包）「Hides the presence of other malware by subverting the operating system itself, so tools report a clean machine.」
擦除器（wiper）「Destroys data outright. No ransom, no profit motive — the destruction is the objective.」

几个词：外传（exfiltrate，把数据偷偷拷出受害组织）；僵尸网络（botnet，攻击者遥控的大批被感染机器，名字来自 robot + network）；rootkit 的名字来自 Unix 的最高权限账户 root；它改的是操作系统本身，杀毒软件向操作系统询问时拿到的就是假答案。

为什么必须分开问。 课件原话：「Any propagation mechanism can carry any payload.」 两张表可以任意组合，比如装勒索软件的蠕虫「spreads like a worm and does damage like ransomware」。而两半需要不同的应对：

  • 传播靠分段（segmentation，把网络切成互相隔开的小块，见 5.3）和打补丁（patching，安装厂商修复漏洞的更新）遏制；
  • 载荷造成的损失靠备份和最小权限（least privilege，每个用户、每个进程只拿完成任务所需的最少权限，L1 的设计原则之一）遏制。

所以分析任何事故都要两句都问，只问一句就只会想到一半的防御。

真实例子（课件未举，用来记）：2017 年的 WannaCry 是「蠕虫 × 勒索」——利用 Windows 文件共享协议 SMB（Server Message Block）第 1 版的漏洞自动传播，到一台机器就加密文件。同年的 NotPetya 外表是勒索，实际无法解密，是「伪装成勒索的擦除器」。

2.2病毒与蠕虫的区别

模拟卷 Q1(b) 原题。核心区别只有一条，其余是它的推论：

病毒依附于宿主，蠕虫是独立程序。 由此：

  1. 怎么复制：病毒把自己的副本插进别的程序或文件里（修改宿主）；蠕虫复制的是它自己这个完整程序，不需要改别人的代码。
  2. 什么时候发作：病毒寄生在宿主里，只有宿主被运行时它才跟着运行，所以通常要等用户打开文件、运行程序；蠕虫自己就是一个在运行的程序，主动扫描网络、利用服务漏洞钻进下一台机器，不需要用户做任何事。
  3. 传播速度：课件小结第 2 条：「A worm needs no user action. That single property is why worm outbreaks are measured in minutes and virus outbreaks in weeks.」

速度差是怎么来的，算一下就有直觉。2003 年的 Slammer 蠕虫感染数量约每 8.5 秒翻一倍，受害主机至少约 75,000 台。按纯指数增长，要翻倍 log2 75000 ≈ 16.2 次，用时

16.2 × 8.5 s ≈ 138 s ≈ 2.3 min

实测约 10 分钟感染约 90% 的易感主机——比纯指数慢，因为扫描包把带宽自己塞满了。要靠用户打开文件的病毒若每天翻一倍，到 75,000 台要约 16 天。两者相差三到四个数量级（16 天对 2.3 分钟约 104 倍，对实测 10 分钟约 2 × 103 倍），根子就在「要不要等人」。

答法模拟卷 Q1(b) 满分答法（4 分）

What is the difference between a virus and a worm?

  1. 依附方式：A virus attaches itself to a host file or program and replicates by inserting copies of itself into other host code. A worm is a standalone program that carries its own propagation code and does not need to modify other host code to replicate.
  2. 触发条件：A virus runs only when its host is executed, so it normally needs human action (opening a file, running a program). A worm usually needs no user action: it actively scans the network and exploits vulnerable services to reach new machines.
  3. 后果：Worms therefore typically spread far faster — outbreaks often measured in minutes (e.g. Slammer, 2003, about 90% of vulnerable hosts in about ten minutes), viruses in days or weeks.
  4. 防御侧重：Worm propagation is contained by patching and network segmentation; viruses mainly by not running untrusted files and by anti-malware scanning.

前两点各占分，第 1 点是参考答案的口径（「uses other host files or code to replicate」 对 「does not directly modify other host code」），第 2 点是课件的口径（是否需要用户动作），两点都写最稳；第 3、4 点用来补足分值。

勘误两个常见错，以及课件说得太绝对的地方
  • 误：「病毒不能自我复制，蠕虫能。」 正：两者都自我复制，区别在于要不要宿主、要不要用户动作。不自我复制的是特洛伊木马。
  • 课件写病毒 「spreads only when a user runs that host」、蠕虫 「without any user action at all」，这是典型情况，不是定义。病毒的定义只要求宿主被运行，宿主可以由系统自动运行（例如感染引导区、开机自动执行的病毒）；反过来，2000 年的 ILOVEYOU 这类群发邮件型蠕虫就要用户打开附件才传播。「蠕虫以分钟计、病毒以周计」同样是对扫描型蠕虫的经验概括（群发邮件型病毒能在几天内遍及全球），当直觉用，不要当定理写。考场上按「通常需要 / 不需要用户动作」的措辞写即可。

2.3勒索软件：五个阶段，每段配一个防御

课件说勒索软件是「the most damaging category of malware for a decade — and it uses the cryptography from this module against its victim」。课件给了五阶段生命周期，并把四条有效防御各钉在一个阶段上：

  1. 初始访问（initial access）：「Phishing, a stolen credential, or an unpatched internet-facing service.」——快速给对外服务打补丁，直接关掉第三条路。
  2. 驻留与提权（establish and escalate）：「Install persistence, then obtain administrator rights.」 持久化（persistence）指让恶意代码在重启、注销后还能自动回来；提权（privilege escalation）指从普通用户权限升到管理员权限。——最小权限让这一步更难。
  3. 横向移动（lateral movement，从已攻陷的机器扩散到同一内网的其他机器）：「Spread across the flat internal network to reach as many systems as possible.」 平坦网络（flat network）指内网不分区、任何机器都能直接访问任何机器。——分段让它够不到全部，最小权限让它走得更慢。
  4. 外传（exfiltrate）：「Copy the data out BEFORE encrypting it — this is the double extortion step.」 双重勒索（double extortion）：先偷数据，再加密；受害者就算能从备份恢复，攻击者还能威胁公开数据。——课件没给这一阶段的防御；能用的是分段、最小权限（能读到的数据少）和出口流量监控。
  5. 先毁备份，再加密：「Delete or encrypt the backups first, so restoring is not an option, then encrypt everything at once.」 ——离线或不可变、并且做过恢复演练的备份。离线（offline）指平时不连在网络上；不可变（immutable）指写入后在保留期内谁也改不了、删不了，包括管理员；恢复演练（restore test）指定期真的从备份恢复一次，证明它能用。

付钱解决不了问题（课件四条）：数据已被拷走，泄露威胁仍在；攻击者给的解密工具又慢又不全；进来的路没修就还开着；付过钱会被标记为「会付钱的」。

课件底框点明：「Not one of the effective defences is cryptographic — and the attacker is using AES against you, correctly implemented.」 课件还说它们都来自 L1：最小权限是 L1 的设计原则，分段是 L1 的隔离（isolation）原则用在网络上，补丁对应 L1 开场引用的数据——31% 的数据泄露「began with exploitation of a known vulnerability」。课件说「restore-tested backups」也是 L1 的内容，但 L1 课件里只出现过备份方案，并没有「备份必须做恢复测试」这一论点。

勘误课件小结第 3 条把备份说成了唯一答案

小结原话：「Ransomware destroys backups before encrypting. Offline, immutable, restore-tested backups are the only reliable answer.」

这和课件自己的第 4 阶段矛盾：数据在加密前已经外传，备份只能把可用性救回来，对机密性的泄露毫无作用。准确的说法是：备份是「加密那一半」唯一可靠的答案；「外传那一半」要靠分段、最小权限、出口监控和尽早检测。课件同页也列了四条防御，不只备份一条。

2.4为什么恶意软件难检测

第 1 部分封面预告了「The malware lifecycle, and why detection is hard」，正文却没讲为什么难检测。补几条常见原因（课件外）：

  • 多态 / 变形（polymorphic / metamorphic）：每传播一次就改变自己的代码形态，按固定特征匹配的检测（特征检测，见 5.2）就失效了；
  • 加壳（packing）：把真正的代码压缩、加密起来，运行时才解开，静态扫描看到的只是一层壳；
  • rootkit：篡改操作系统本身，让检测工具拿到的是假报告；
  • 无文件（fileless）：只驻留内存或借用系统自带的管理工具，磁盘上没有可扫描的恶意文件；
  • 零日漏洞（zero-day，厂商还不知道、还没有补丁的漏洞）：没人见过，就没有特征。
课堂活动 1 解答：给六个案例分类

题目：每个案例回答两个问题——怎么传播、载荷是什么；有的不止一个正确标签。（第 1 部分封面写「classify eight real cases」，实际只有六个。）

案例怎么传播载荷
a用户打开一个像发票的邮件附件，装上了记录键盘的软件特洛伊木马（伪装成发票，用户自己打开；入口是钓鱼邮件）键盘记录器
b文件共享服务的漏洞让代码 20 分钟内复制到网络上每台机器，没人做任何事蠕虫题面没说，答「未说明」——传播清楚、载荷未知，正是两问要分开的例子

3网络攻击：攻击基础设施本身

第 2 部分的导语：「Attacks on the infrastructure itself, rather than on the data travelling over it.」

3.1先补三样网络常识

课件默认学生懂这些，没讲。

一、两层地址。

  • IP 地址（Internet Protocol address，网际协议地址）：网络层的地址，在网络上标识一台主机，如 203.0.113.20（示意的公网地址；192.168.x.x 这类是只在内网有效的私有地址）。路由器只看数据包的目的 IP 往前转发，不检查源 IP 是不是真的。
  • MAC 地址（media access control address，媒体访问控制地址）：链路层的地址，烧在网卡上的硬件地址，如 aa:aa:aa:aa:aa:01，只在同一个局域网（LAN，local area network，一台交换机或一个 Wi-Fi 下互相直达的那片网络）内有效。软件可以随意改它。
  • 局域网里真正把数据送到哪块网卡，靠的是 MAC 地址，所以主机要先把「对方的 IP」翻译成「对方的 MAC」，这个翻译就是 ARP（见 3.4）。

二、TCP 与 UDP。 传输层的两种协议。TCP（Transmission Control Protocol，传输控制协议）先握手建立连接再传数据：客户端发 SYN（synchronise，请求建立连接），里面带一个初始序号（ISN，initial sequence number，这条连接里字节编号的起点）；服务器回 SYN-ACK（同意，并带上自己的初始序号）；客户端再回 ACK（acknowledge，确认），里面写「服务器的初始序号 + 1」，表示收到了。这叫三次握手。UDP（User Datagram Protocol，用户数据报协议）没有握手，发出去就算，所以伪造源地址的 UDP 包对方照收不误。端口（port）是传输层用来区分同一台主机上不同服务的编号，如 HTTPS 网页默认用 443 端口。

三、会话与 cookie。 HTTP（网页使用的应用层协议）本身无状态：每个请求互不相干，服务器记不住「刚才是谁」。所以登录成功后，服务器发给浏览器一个随机的会话令牌（session token，也叫 session ID），放在 cookie（浏览器替网站保存、并在之后每次访问该网站时自动附上的小段数据）里。之后服务器看到这个令牌，就当作已登录的那个人。这一条同时解释了 3.3 的会话劫持和 4.2 的 CSRF。

3.2IP 欺骗与 MAC 欺骗

课件第 9 页的四行「攻击—后果—防御」表，前两行是冒充地址：

攻击是什么后果防御
IP 欺骗（IP spoofing）「Forge the source address of a packet so it appears to come from somewhere else.」绕过按地址放行的访问规则；隐藏攻击来源；并使反射攻击成为可能——回复发往伪造的地址，不回攻击者（见 3.6）入口 / 出口过滤（ingress / egress filtering）：「reject packets whose source address could not legitimately have come from that direction.」
MAC 欺骗（MAC spoofing）「Change the hardware address of an interface to impersonate another device on the local network.」击破按硬件地址的访问控制——「which is why address filtering on wireless is not a security control」802.1X：「authenticate the device properly rather than trusting an address it chose for itself.」

两条防御的道理：

  • 入口 / 出口过滤：从外面进来（入口）的包若源地址是自己内网的，从内网出去（出口）的包若源地址不是自己内网的，都一定是伪造的，边界路由器直接丢掉——不需要密码学。注意部署位置：受害者在自己边界做入口过滤，只能丢掉「冒充我内网地址」的外来包；反射攻击里被冒充的是受害者自己的地址，要挡住这种伪造包，必须由攻击者所在的网络在出口做源地址校验（业界规范 BCP 38，Best Current Practice 38）。所以这道防御靠各网络普遍部署，受害者无法单方面做到。
  • 802.1X：IEEE（电气电子工程师学会）制定的端口级接入认证标准。设备接上交换机或 Wi-Fi 后，在认证通过之前端口只放行认证报文，认证靠证书或账户口令，而不是设备自报的 MAC 地址。家用路由器的「MAC 白名单」改一下 MAC 就过了。

两者违反的都是真实性：数据包或设备冒充了别人。两条防御都在攻击成功之前起作用，降的是 likelihood。

3.3会话劫持：偷的是已经登录的证明

会话劫持（session hijacking）：「Take over an authenticated session by stealing or predicting the session token.」 偷到或猜到别人的会话令牌，直接接管他已登录的会话。

后果一句话：「The attacker never needs the password. They arrive after authentication has already succeeded, holding the proof of it.」 按 3.1，服务器只认令牌，所以再强的密码也管不了它——它发生在登录之后。

令牌怎么被偷：在没加密的连接上（例如咖啡馆的开放 Wi-Fi 上的 HTTP 页面）直接被嗅探到；被 XSS 脚本读走（4.2）；或者令牌生成得不够随机，被猜出来。

课件的防御四条：

  • 把令牌绑定到连接：「Bind tokens to the connection」——令牌只在发出它的那条连接或那台设备上有效，偷走换个地方用不了；
  • 短生命周期：令牌很快过期，偷到也只能用一小会儿（这一条压的是 impact）；
  • 敏感操作重新认证：改密码、转账之前再要一次密码或第二因素，光有令牌做不了最要紧的事；
  • 始终使用 TLS：「so tokens cannot be captured in transit」——令牌在路上是密文，嗅探不到。配套要给会话 cookie 标 Secure 属性（浏览器只在 TLS 连接上发送它），否则某一次明文 HTTP 请求（例如连接被降级成明文）仍会把它带出去。

违反的主要属性是真实性（攻击者以受害者的身份行事），连带机密性（令牌和账户数据被读）和可追责性（日志把攻击者的操作记在受害者名下）。

3.4ARP 投毒与中间人

中间人攻击（MITM，man in the middle）：「Sit between two parties, relaying and optionally altering traffic.」 攻击者插在通信双方之间，转发流量，想改就改。这正是 L7 公钥密码里 DH 密钥交换（Diffie–Hellman，双方在公开信道上协商出共享密钥的方法）没有认证时会遭遇的攻击，L8 数字签名、证书与 PKI用证书解决了它。课件说在局域网里，中间人位置通常靠 ARP 投毒取得。

ARP（Address Resolution Protocol，地址解析协议）负责局域网里「IP → MAC」的翻译：主机广播「谁有 192.168.1.1？」，持有者回答「192.168.1.1 在 aa:…:01」，主机把答案记进 ARP 缓存。课件的关键一句：「It has no authentication whatsoever: any device can answer any request, or send unsolicited replies that hosts accept.」

课件描述的攻击：「The attacker announces that the router's IP belongs to the attacker's hardware address. Every machine on the segment now sends its outbound traffic to the attacker, who forwards it on.」 受害者网照上、毫无察觉。

防御（课件）：「dynamic ARP inspection on switches, static entries for critical hosts, and segmentation to limit who shares a broadcast domain.」

  • 动态 ARP 检测（DAI，dynamic ARP inspection）：交换机记着「哪个端口上的哪个 MAC 合法地拥有哪个 IP」（这张表来自 DHCP 侦听，DHCP snooping：DHCP 即 Dynamic Host Configuration Protocol，动态主机配置协议，负责给新接入的设备自动分配 IP；交换机旁听这个分配过程，记下「哪个端口、哪个 MAC 拿到了哪个 IP」），收到与之不符的 ARP 报文就丢弃；
  • 静态表项：网关这类关键主机的 IP–MAC 对应关系手工写死，不接受任何 ARP 回复修改；
  • 分段：ARP 只在一个广播域（broadcast domain，广播报文能到达的那片网络）里有效，把网络切小，能投毒的人就少。

再往上一层，中间人本身是唯一一个课件说「IS solved by cryptography」的攻击：「Authenticated key exchange with certificates. This one IS solved by cryptography, provided validation is done properly.」 即使 ARP 被投毒、流量全经过攻击者，只要双方用 TLS 并正确校验证书，攻击者看到的是密文，改了也会被发现，冒充服务器又拿不出有效证书。违反的属性是机密性和完整性（「optionally altering」），攻击者冒充网关还伤了真实性。

勘误课件的两处简化
  • 课件只描述了单向：受害者的出站流量到了攻击者手里。要拿到完整的双向中间人位置（课堂活动 2(b) 说的「relays all traffic」），攻击者通常还要同时欺骗网关，让网关把「受害者 IP」对应到攻击者的 MAC，回程流量也绕过来。
  • 第 9 页底条说「Only the last of these is fixed by cryptography」，即四行里只有中间人靠密码学。但会话劫持那一行的防御里写着「always use TLS」，802.1X 也常用基于证书的认证——密码学在前三行里也是一环。准确的说法是：前三个攻击的根本修复在网络设计和会话管理，密码学只是其中一部分；中间人则直接由密码学解决。

3.5DNS 投毒，以及 TLS 为什么还能兜底

DNS（Domain Name System，域名系统）把名字翻译成 IP 地址，如 www.example.com → 203.0.113.10（示意地址）。解析链是：你的电脑问递归解析器（recursive resolver，通常由运营商或公司提供，替你一路问到底的那台服务器），解析器再去问负责这个域名的权威服务器（authoritative server）；拿到答案后，解析器把它缓存一段时间（这段时间叫 TTL，time to live，生存时间），期间再有人问就直接用缓存回答。

课件：「Traditional DNS is unauthenticated and runs over UDP, so a forged reply that arrives before the genuine one is accepted and cached.」 传统 DNS 不认证、跑在 UDP 上。解析器只核对回复里的两样东西：16 位的事务 ID（每个查询附带的随机编号）和端口号；对得上就收下，谁先到信谁。攻击者抢在真回复之前塞进一个伪造回复，这就是 DNS 缓存投毒（DNS cache poisoning）。

后果是放大的：「Poison a resolver's cache and every user of that resolver is directed to the attacker's server for as long as the entry lives. The user typed the correct name and still arrived at the wrong place.」

防御（课件）：DNSSEC（DNS Security Extensions，DNS 安全扩展）给 DNS 记录加数字签名，解析器验签就能发现伪造；DoT / DoH（DNS over TLS / DNS over HTTPS，把 DNS 查询放进 TLS 或 HTTPS 里传）保护查询在路上不被看、不被改。违反的属性是 DNS 数据的完整性，以及用户到达的服务器的真实性。

ARP 和 DNS 是同一种攻击。 课件的总结：「rather than attacking the target, attack the mechanism that tells you where the target is.」 不攻击目标本身，攻击「告诉你目标在哪」的那个查找机制。两个协议都是为「没人撒谎的合作网络」设计的，都没有认证：「Every layer of a system rests on assumptions made by the layer below, and attackers look there first」——这就是 L1 攻击面（attack surface，系统里攻击者真正够得着、用得上的那些弱点的集合）的思路：attack the assumption, not the target。

TLS 为什么还能兜底。 课件的黄框：「If DNS sends you to the attacker's server, that server cannot present a valid certificate for the name you asked for — so TLS validation fails and the browser warns you. Certificate validation is the backstop for a poisoned lookup.」 查找被投毒，你到了假服务器；但假服务器拿不出你要访问的那个名字的有效证书（证书由 CA（certificate authority，证书颁发机构，替网站担保“这个公钥属于这个名字”的机构）签发，攻击者没有对应的私钥），TLS 校验失败，浏览器报警。限制有两条：「it only holds if the user does not click through the warning, and only for protocols that use TLS at all」。

勘误DoT / DoH 防不了缓存投毒

课件把 DoT / DoH 和 DNSSEC 并列为 DNS 投毒的防御。但课件描述的攻击是「poison a resolver's cache」：投毒发生在递归解析器 ↔ 权威服务器这一段。DoT / DoH 加密的是你的电脑 ↔ 递归解析器这一段，解析器自己的缓存被毒了，它照样把毒答案通过加密通道忠实地发给你。

对缓存投毒真正有效的是 DNSSEC（解析器验签），以及 2008 年以后普遍部署的源端口随机化（查询的端口号也随机选，伪造者要同时猜中事务 ID 和端口）。DoT / DoH 防的是另一种情况：你和解析器之间的本地网络上有人偷看或伪造回复（例如同一个 Wi-Fi 下的攻击者）。

3.6拒绝服务：可用性是容量问题

拒绝服务（DoS，denial of service）：让合法用户用不上服务。课件导语：「The one attack class in this module that no cryptographic mechanism addresses. It targets availability, and availability is a capacity property.」 可用性是容量属性：服务器能处理的请求、链路能承载的带宽都有上限，攻击者只要把它占满。

课件分三类，按「耗尽的是哪种资源」区分：

类别耗尽什么课件原话特点
流量型（volumetric）带宽「Saturate the target's bandwidth with sheer traffic volume.」以 Gbit/s 计；「Nothing on the target can help — the pipe is full before the traffic arrives.」
协议型（protocol）协议实现里的有限表项「Exhaust a finite resource in the protocol implementation, such as the table of half-open connections.」典型是 SYN 洪泛；「Costs the attacker almost nothing.」

SYN 洪泛为什么几乎不花钱。 按 3.1 的三次握手，服务器收到 SYN 后要为这个「握了一半」的连接（半开连接，half-open connection）在表里占一格，回 SYN-ACK，然后等 ACK。攻击者伪造源地址发 SYN，ACK 永远不会来，这一格要等超时才释放。算一个例子（假设服务器未启用 SYN cookies；表大小、超时是假设的典型值，取 Linux 默认的重传设置，不是课件数据）：表有 1024 格；服务器的 SYN-ACK 重传 5 次，间隔从 1 秒起每次翻倍，一格要占 1 + 2 + 4 + 8 + 16 + 32 = 63 秒才放弃。攻击者只要每秒补

个伪造 SYN，就能让表一直是满的，新的合法连接一个也进不来。一个 SYN 包约 60 字节，这只是约 8 kbit/s 的流量——任何一条家用宽带都发得出。

SYN 洪泛算账：多少个伪造 SYN 能塞满半开连接表

默认是笔记里的假设值：表 1024 格，SYN-ACK 重传 5 次、间隔从 1 秒起每次翻倍，SYN 包约 60 字节，未启用 SYN cookies。改任何一格，或改攻击者每秒发多少个，看表占用怎么变；勾上 SYN cookies 看表为什么不再会满。

分布式与放大。 DDoS（distributed denial of service，分布式拒绝服务）用僵尸网络从成千上万个源同时发起，「blocking one address achieves nothing」。放大（amplification）让它更糟：「send a small forged request to a service that replies with a much larger response, addressed to the victim.」 它要和 3.2 的 IP 欺骗配合，又叫反射放大（reflection amplification）：

放大倍数（BAF，bandwidth amplification factor）＝ 反射器响应的 UDP 载荷字节数 ÷ 请求的 UDP 载荷字节数（不算包头）。US-CERT（United States Computer Emergency Readiness Team，美国计算机应急准备小组，现已并入 CISA，美国网络安全与基础设施安全局）的告警 TA14-017A 给的值：DNS 约 28–54 倍，NTP（Network Time Protocol，网络时间协议）约 557 倍，Memcached（一种内存缓存服务）10,000–51,000 倍。设攻击者发出 100 Mbit/s 的伪造请求：

反射器放大倍数受害者收到
DNS28–542.8–5.4 Gbit/s
NTP556.9约 55.7 Gbit/s
Memcached10,000–51,0001,000–5,100 Gbit/s

这是上限量级：倍数按载荷算，而攻击者的 100 Mbit/s 是含包头的线路速率，小请求的包头占比大，实际要打折；受害者收到多少还受反射器数量和它们自身带宽的限制。量级本身足以说明课件那句「A modest attacker generates enormous traffic」。

防御（课件）：「Capacity and distribution — absorb it. Upstream filtering and scrubbing services — stop it before it reaches you. Rate limiting per source. SYN cookies for the protocol case.」 逐条：

  • 容量与分布：带宽、服务器足够多，并分散到多个地点（如 CDN，content delivery network，内容分发网络），洪水被摊薄吸收、服务不中断——按 6.1 的规则，攻击没能让服务不可用，算降 L；吸收不完全、服务只是变慢时，是在减轻损失程度，算降 I；
  • 上游过滤与清洗：在运营商或专业「清洗中心」那里把攻击流量滤掉，只把干净流量送过来——针对流量型；
  • 按源限速：每个来源每秒最多多少请求，针对应用型；
  • SYN cookies：针对协议型（下面的 warning 框里说原理）。

课件的结论：「you cannot encrypt your way out of a capacity problem, and that is why availability sits alongside confidentiality and integrity rather than inside them.」 加密、消息认证码、签名只回答「内容对不对、是谁发的」，回答不了「通道有没有被塞满」。

勘误「没有任何密码学机制能对付 DoS」说得太满

课件同页列的 SYN cookies 恰恰用到了密码学：服务器收到 SYN 后不在表里占格，而是把连接信息（双方地址端口）、时间和服务器自己的秘密密钥一起做带密钥的哈希，编进 SYN-ACK 的初始序号（3.1）里发回去；真客户端回 ACK 时会写上「这个值 + 1」，服务器重算一遍、对得上才建立连接。表项根本不存在，也就无从耗尽。

准确的说法：加密（保密性）解决不了容量问题，流量型 DoS 只能靠容量与流量管理；协议型 DoS 可以借助密码学原语缓解。 考试按课件口径写「availability is a capacity property」即可；若问「为什么」，加上这一层更严谨。

另：课件底框说「Recall Lecture 1, Activity 4, item 5: flooding a portal with two million requests per second」，L1 的课堂活动 4 第 5 项其实是 VPN（virtual private network，虚拟专用网）要十一步操作的那一题，L1 全文没有这道「每秒两百万请求」的题，是交叉引用写错了。

4应用与人：绕过网络

第 3 部分导语：「Two categories that bypass the network entirely: one attacks the code, the other attacks the person.」

4.1注入：数据被当成指令

课件说注入（injection）是「the single most persistent class of application vulnerability」，只有一个原因：「user-supplied data is combined with code, and the interpreter cannot tell which is which.」 用户提供的数据和代码拼在一起，解释器（interpreter，读进一段文本、把它当程序执行的组件，如数据库、操作系统的命令行）分不清哪部分是代码、哪部分是数据。

机理，用课件的例子。 应用把用户名粘进一个字符串，拼成数据库查询。查询语言是 SQL（Structured Query Language，结构化查询语言）：

SELECT * FROM users WHERE name = '<input>'

课件：「The attacker supplies input containing a quote character, which closes the string early. Everything after it is read by the database as part of the query rather than as a value — so the attacker is now writing the query.」 课件没给具体输入，补两个，在一张两列三行的表 users(name, grade) 上用 sqlite 实际跑过：

输入拼接后的查询拼接版结果参数化版结果
bob... WHERE name = 'bob'只返回 bob只返回 bob
x' OR '1'='1... WHERE name = 'x' OR '1'='1'返回整张表空
x' UNION SELECT name, grade FROM users --... WHERE name = 'x' UNION SELECT name, grade FROM users --'返回整张表空

第二行：输入里的第一个 ' 把字符串提前闭合，后面的 OR '1'='1' 成了查询的一部分，条件恒真，所以每一行都满足。第三行：UNION 把另一条查询的结果接上来，-- 是 SQL 的注释符，把模板末尾多出来的那个 ' 注释掉，免得语法报错。UNION 要求左右两条查询的列数相同，所以这一招成立的前提是攻击者猜对了列数（表若是三列，数据库会直接报错，攻击者再改列数重试）；另外 MySQL 要求 -- 后面跟一个空格才算注释。

课件红字：「The database is behaving correctly. It was given a query and it executed it. The fault is entirely in how the query was constructed.」

同样的模式出现在任何「不可信输入到达解释器」的地方：操作系统命令注入、LDAP（Lightweight Directory Access Protocol，轻量目录访问协议，查询组织通讯录、账户目录用的）注入与 XML（Extensible Markup Language，可扩展标记语言，一种结构化数据格式）注入、模板注入、日志注入。

修法：参数化查询（parameterised query）。「The code and the data are sent to the database SEPARATELY, so no input can ever change the structure of the query.」 应用先把带占位符的查询（WHERE name = ?）交给数据库，数据库把它解析成固定的结构；之后输入才作为一个值填进占位符。输入里有多少引号都只是这个值里的字符，结构在它到来之前已经定死了——所以上表参数化版查的是「有没有人名字叫 x' OR '1'='1」，没有，结果为空。课件：「This is a structural fix — it removes the possibility rather than filtering for it.」

SQL 注入演示：同一个输入，拼接与参数化

示例表 users(name, grade) 三行（演示数据）：(alice, A)、(bob, B)、(carol, C)。拼接版把输入粘进 SELECT * FROM users WHERE name = '…' 再交给数据库；页面里的小解释器按 SQLite 的规则执行它。改输入，看哪些字符越过引号变成了查询结构。

为什么过滤输入不是修法。 屏蔽「危险字符」是一张黑名单（denylist，列出禁止的东西、其余放行），黑名单总会漏：「encodings, alternative syntaxes and character sets you did not consider」。输入校验值得做，但代替不了代码与数据分离。

课件把它接回 L1 的故障安全默认（fail-safe defaults：默认拒绝，出错时落在安全的一边）：「Parameterised queries are fail-safe by construction: the insecure outcome becomes impossible rather than merely discouraged. Input filtering is the opposite — it enumerates badness and hopes the list is complete. Given a choice between removing a possibility and forbidding it, always remove it.」

SQL 注入（SQLi）主要违反机密性（整张表被读走），用 UPDATE、DELETE 也能破坏完整性；参数化查询让攻击根本不能成功，降 likelihood。

4.2XSS 与 CSRF：方向相反的两种信任

先补一个课件没讲、但说不清这两个攻击就绕不开的概念：同源策略（same-origin policy）。浏览器规定，一个网站的脚本只能读同一个「源」（协议、域名、端口都相同）的页面内容（cookie 另有一套按域名划定的作用范围规则，效果类似）。它挡住了「evil.com 的脚本去读你在银行网站上的数据」。但它有两个缺口：注入到银行页面里面的脚本，就算同源；它只限制读响应，不限制发请求。XSS 钻第一个缺口，CSRF 钻第二个。

跨站脚本（XSS，cross-site scripting）跨站请求伪造（CSRF，cross-site request forgery）
定义「The attacker gets their script executed in another user's browser, in the context of your site.」「The attacker causes the victim's browser to send a request to your site, using the victim's existing session.」
怎么做存储型（stored）：脚本存进服务器上的评论或个人资料，所有看它的人都中招；反射型（reflected）：脚本藏在 URL（网址）的参数里，被页面原样回显受害者登录着你的网站时访问了攻击者的网页；那个网页触发一个发往你网站的请求，浏览器自动附上会话 cookie
结果脚本带着受害者的会话运行，能读他的数据、以他的身份操作你的网站看到一个已认证、格式正确的请求，照办
防御（表下逐条解释）按输出所在的上下文编码输出；内容安全策略（CSP）；会话 cookie 标 HttpOnly 属性攻击者猜不到的 anti-CSRF 令牌；cookie 的 SameSite 属性；敏感操作重新认证

（XSS 的缩写用 X，是为了不和 CSS——Cascading Style Sheets，层叠样式表，网页的样式语言——撞名。）

课件要求记住的区分：「XSS abuses the trust a USER has in a SITE — your site serves the attacker's script. CSRF abuses the trust a SITE has in a USER'S BROWSER — your site believes a request because it carried a valid session cookie.」

即：XSS 里用户相信页面来自信任的网站，网站送来的脚本就被当成网站自己的执行；CSRF 里网站相信带合法 cookie 的请求是用户本人想发的，可 cookie 是浏览器自动附的，用户根本不知道发了请求。

防御各自对准一个环节：

  • 编码输出：把用户内容里的 <、" 等字符转成「只显示、不执行」的形式再放进页面——和 4.1 的「数据不能变成指令」同一个道理；「按上下文」是因为同一段数据放进 HTML（HyperText Markup Language，网页的标记语言）正文、HTML 属性、JavaScript（浏览器里运行的网页脚本语言）里，要转义的字符不同。
  • 内容安全策略（CSP，Content Security Policy）：网站告诉浏览器「只执行来自这几个来源的脚本」，即使注入了脚本也不执行。
  • HttpOnly：cookie 的一个属性，标上之后页面脚本读不到这个 cookie。它不阻止 XSS 发生，只是让 XSS 偷不走会话令牌，属于止损。
  • anti-CSRF 令牌：每个表单里放一个随机值，提交时必须带回；攻击者的网页读不到它（同源策略挡住了读），伪造的请求就带不上。
  • SameSite：cookie 的一个属性，告诉浏览器「从别的网站发起的请求不要附上这个 cookie」。取 Strict 时一律不附；取 Lax（现代浏览器的默认值）时，用户点链接跳转过去这种顶层 GET 请求仍会附上。所以它切断了 CSRF 的大部分路径，但不是全部，改数据的操作仍应配 anti-CSRF 令牌、且不用 GET 实现。

XSS 主要违反真实性（攻击者以受害者身份操作）与机密性（数据被读）；CSRF 主要违反完整性（以用户名义执行了他不想要的操作）。

XSS 还有第三种

课件只列了存储型和反射型。另有 DOM 型（DOM-based）：脚本根本不经过服务器，而是页面自己的 JavaScript 把 URL 里的内容写进页面结构（DOM，document object model，浏览器内存里的页面结构树）时被执行。防御思路相同：别把数据当代码写进页面。

4.3社会工程：合法的人用合法的凭据

课件导语：「The majority of breaches involve the human element — Lecture 1. Social engineering attacks the person, not the system.」 社会工程（social engineering）：操纵人去做攻击者想要的事，而不是攻破系统。L1 引用的数据是 62% 的数据泄露涉及人为因素。

五种手法：

手法课件原话
钓鱼（phishing）「A mass email inviting the recipient to enter credentials on a convincing but fraudulent page, or to open an attachment.」
鱼叉式钓鱼（spear phishing）「Targeted at one person, using details gathered about them. Far more convincing, and far more successful.」

为什么它能击败技术控制（学习目标第 3 条）。因果链：

  1. 技术控制检查的是「这个凭据对不对、这个请求合不合规」；
  2. 社会工程让合法的人用合法的凭据去做坏事——财务人员亲手付款，用户亲手输入密码、亲手打开附件；
  3. 所以每一道技术检查都会通过，正是 1.1 表里「被钓走的凭据」那一行的情形。

它利用的不是缺陷，而是正常、有用的人类行为（课件 「Why it works」 五条）：权威（上级的要求会被服从）、紧迫（时间压力让人跳过核对）、乐于助人（想帮遇到困难的同事）、熟悉（认识的名字降低警惕）、恐惧（威胁后果换来服从）。

真正有用的防御（课件）：

  • 抗钓鱼的多因素认证（phishing-resistant MFA；MFA，multi-factor authentication，登录要同时出示两类以上凭据，如密码加手机或硬件密钥）：「a stolen password alone becomes useless」；
  • 流程控制：「payment changes verified out of band, by a second person」——带外（out of band）指不走可能被攻击者控制的原渠道，例如收到改账号的邮件，就由第二个人打档案里的电话（不是邮件里给的）核实；
  • 技术过滤：让更少的钓鱼邮件到达任何人；
  • 报告文化：犯了错能安全、快速地报告。

基本没用的防御：「Telling people to be careful. Annual training that people click through. Punishing those who fall for it — which guarantees that the next person to be caught says nothing, and the incident is discovered days later instead of minutes later.」

课件的原则（红字）：「Design the process so a single mistake is survivable.」

勘误「抗钓鱼」指的是什么

课件对抗钓鱼 MFA 只写了「a stolen password alone becomes useless」，但这是任何 MFA 都有的性质，没说出「抗钓鱼」的意思。

普通 MFA（短信或 App 里的六位验证码）挡不住实时中继钓鱼：假网站把你输入的密码和验证码当场转发给真网站，攻击者照样登录。抗钓鱼的 MFA（如基于 FIDO2 / WebAuthn 这类业界无密码认证标准的硬件密钥或通行密钥——passkey，存在手机或电脑里、用指纹或面容解锁的登录密钥）用公钥签名做挑战—响应，并且签名里绑定了浏览器实际访问的域名：你在假域名上登录，认证器签出来的东西对真网站无效。这是 L8 数字签名、证书与 PKI 里签名知识的直接应用。

第 4 部分导语：「Not one more algorithm. Placement, layering, visibility and the ability to respond.」

5.1防火墙：看懂多少流量，以及放在哪

防火墙（firewall）「enforces a policy about which traffic may pass between two networks」——在两个网络之间按策略决定哪些流量放行。各类型的区别在于「how much of the traffic they actually understand」，下表从浅到深：

类型怎么判断优点 / 代价
包过滤（packet filter）逐个包看地址、端口、协议快而简单；不记得之前的包，「cannot tell a reply from an unsolicited packet」
状态检测（stateful inspection）跟踪连接，认得出「内部主动发出的连接的回复」几十年来的标准；仍然看不见连接里面是什么
应用层防火墙 / 代理（application-layer / proxy）理解应用协议（HTTP、SMTP：Simple Mail Transfer Protocol，简单邮件传输协议），检查内容，自己终结连接再代为转发能拦具体动作而不是整个服务；更慢，而且要处理 TLS 才看得见内容
下一代防火墙（NGFW，next-generation firewall）状态检测 ＋ 应用识别 ＋ 用户身份 ＋ 威胁情报如今多数组织部署的；代价是复杂，「misconfiguration is the common failure」

区分前两行的例子：内网电脑访问外网网站，回复包从外面进来。包过滤只看这一个包，要么放行「所有从外面来的、源端口 443（HTTPS 的标准端口）的包」（攻击者也能利用），要么连回复也挡掉；状态检测记得「这台电脑刚发起过这条连接」，只放行它的回复。「要处理 TLS」是因为内容加密了，应用层防火墙得作为中间代理先解开才能检查。

放在哪比用哪种更要紧。 课件：「A perimeter firewall controls what enters and leaves. It does nothing about traffic between two machines inside — which is exactly how incident C in Activity 3 spread. Internal firewalls and segmentation are what limit lateral movement.」

DMZ（demilitarised zone，隔离区，名字借自「非军事区」）：「Public-facing servers sit in a separate segment between two boundaries. They can be reached from the internet; they cannot reach the internal network. If one is compromised, the attacker has gained a foothold in a place deliberately built to be worth little.」

DMZ 的道理：对外服务器最容易被攻破，就把它放在「攻破了也拿不到什么」的地方——假设会被攻破、限制损失，降的是 I。

5.2入侵检测与入侵防御

  • 入侵检测系统（IDS，intrusion detection system）：不串在流量路径上，复制一份流量（或读主机上的行为记录）来看，发现可疑就告警；
  • 入侵防御系统（IPS，intrusion prevention system）：串在流量路径上，发现可疑就拦截。

课件：「The difference is consequential: an IPS that misidentifies legitimate traffic causes an outage.」 IDS 误判只是多一条告警；IPS 误判会把正常业务挡掉，自己造成一次可用性事故。

两种检测方法：

  • 基于特征（signature-based）：「Matches known patterns. Accurate for known attacks, blind to new ones.」（2.4 那些手段正是钻这个空子。）
  • 基于异常（anomaly-based）：「Learns normal behaviour and flags deviation. Can catch novel attacks, and generates far more false positives — which is why alerts get ignored.」 误报（false positive）指把正常行为报成攻击。

误报为什么会多到没人看，课件没解释，算一个数（课件外，数字是假设的）：

告警为什么没人看：基率的算术

设一天有 106 个事件，其中真攻击 10 个（基率，base rate，真攻击在全部事件里占的比例，10−5）。检测器的检出率 99%，误报率只有 1%。

  • 真告警：10 × 0.99 = 9.9 个；
  • 误报：(106 − 10) × 0.01 ≈ 9,999.9 个；
  • 告警里真攻击的比例：9.99.9 + 9999.9 ≈ 0.099%，约每 1,000 条告警里只有 1 条是真的。

误报率降到 0.01%，这个比例也只有约 9%。问题不在检测器「差」，而在真攻击本来就极少：误报率乘的是一个巨大的正常事件数。这叫基率谬误（base-rate fallacy），是所有入侵检测告警疲劳的数学根源（Axelsson，2000），误报率高的异常检测受害最重。课件说的「Alerts tuned enough that people read them」（5.4）指的就是这件事。

告警里有多少是真的：基率计算器

默认是上面折叠块里的数（一天 106 个事件、10 个真攻击、检出率 99%、误报率 1%）。改误报率或真攻击数，看「告警里真攻击的比例」怎么变，下面的点阵按这个比例画出 1000 条告警。

5.3分段与零信任

分段（segmentation）：「Divide the network so that reaching one part does not give access to the rest. Finance separate from research; production separate from test; devices that only need to reach one server able to reach only that server.」 课件的黄字：「It is the single most effective control against lateral movement, and it is Lecture 1's isolation principle applied to a network.」 它直接回应了 2.3 的阶段 3 和事故 C。

微分段（microsegmentation）：「takes it to the level of the individual workload, so that even two servers in the same rack cannot reach each other unless a policy says so.」 粒度细到每一个工作负载（workload，一台服务器、一个虚拟机或容器上跑的一个服务）。

零信任（zero trust）：「Stop treating the internal network as trusted. Every request is authenticated and authorised on its own merits, regardless of where it came from. Position on the network confers nothing.」 三条支柱：

显式验证（verify explicitly）最小权限（least privilege）假设已被攻破（assume breach）
「Authenticate and authorise every request, using identity and device state.」「Grant the minimum access needed, for the shortest time.」「Design as though the attacker is already inside — segment, monitor, limit blast radius.」

爆炸半径（blast radius）：一次攻破能波及的范围。课件把它接回 L1「边界消融」时间轴的最后一格「assume breach」：「Zero trust is that conclusion turned into an architecture. It is not a product you buy — it is a decision to stop granting trust on the basis of network location, and it takes years to implement in an organisation that was not built that way.」 权威标准是 NIST SP 800-207《Zero Trust Architecture》（2020；NIST，National Institute of Standards and Technology，美国国家标准与技术研究院；SP，Special Publication，它的特别出版物系列）。

1.1 里的端点恶意软件、钓到的凭据、内部人员全都「已经在里面」，零信任正是针对这一前提的设计。

5.4日志与事件响应

课件导语：「Prevention fails eventually. What separates a contained incident from a catastrophic one is almost always detection speed and preparation.」

事件响应（incident response）的六个阶段（课件排成 2 行 × 3 列，没画箭头，按阅读顺序走）：

阶段课件原话
准备（prepare）「Plans written, roles assigned, contacts listed, backups tested, and the process rehearsed before it is needed.」
检测（detect）「Logging that is centralised, tamper-resistant and actually monitored. Alerts tuned enough that people read them.」
遏制（contain）「Limit the spread. Isolate affected systems — which requires segmentation to already exist.」
根除（eradicate）「Remove the attacker's access, including persistence they installed and credentials they took.」
恢复（recover）「Restore from known-good backups, verify integrity, and monitor closely for return.」
总结改进（learn）「Establish what actually happened and change something. An incident that produces no change will happen again.」

课件没画箭头；按业界惯例，最后一步的改进反馈给下一轮的准备，六个阶段构成一个循环。这六段与 SANS（美国一家安全培训与研究机构）的 PICERL 模型一一对应，PICERL 是 Preparation、Identification、Containment、Eradication、Recovery、Lessons learned 的首字母（课件的 Detect 对应 Identification，Learn 对应 Lessons learned）。NIST 的事件处理指南旧版 SP 800-61 Rev.2（2012）分四段（准备；检测与分析；遏制、根除与恢复；事后活动）；2025 年的 Rev.3 已取代它，改按 NIST 网络安全框架 CSF 2.0 的六项功能组织。考题问阶段，按课件六段答。

日志为什么是安全控制。 「Logs deliver ACCOUNTABILITY — the Lecture 1 goal that says actions can be traced to an entity. Without them you cannot tell what happened, what was taken, or whether the attacker is still present.」 加粗：「They must be centralised and write-protected — an attacker with administrator rights edits local logs first.」 所以日志要实时送到另一台集中、写保护的服务器。

组织最常跳过的两段：准备——「A response plan nobody has rehearsed is a document, not a capability」，就像没做过恢复测试的备份；以及总结改进——「skipped because the pressure is to return to normal」。

课件底框，也是本节最该记住的一句：「Notice how many phases depend on decisions made long beforehand: containment needs segmentation, recovery needs tested backups, detection needs logging that was switched on and monitored. Incident response is mostly work done before the incident.」

6.1likelihood 还是 impact：判断规则

以攻击成功的那一刻为界：

  • 防御在这一刻之前起作用、让攻击打不成 → 降 likelihood（L）；
  • 防御在这一刻之后起作用、攻击已经得手但损失变小 → 降 impact（I）。

「攻击成功」要按具体攻击来定：勒索软件是「文件被加密」，DoS 是「服务不可用」，注入是「查询被改写」。几个容易判错的：

  • 备份不阻止任何攻击，加密照样发生，它让你能恢复 → I。
  • 分段不阻止第一台机器被攻破，它限制扩散范围 → I（对「攻破某一台特定服务器」这件事而言也降了 L，答题以「限制爆炸半径、降 I」为主）。
  • 最小权限两者都有：让提权更难（L），让失陷账户能碰的东西更少（I）。
  • 检测（IDS、集中日志）不阻止攻击，缩短攻击者在里面待的时间 → I。
  • 短令牌寿命、HttpOnly 不阻止令牌被偷或脚本注入，限制偷到后能做多少 → I。
  • 容量与清洗（DoS）：洪水被吸收或拦在外面、服务没有中断，攻击没有「成功」 → L；吸收不完全、服务只是变慢，是得手之后减轻程度 → I。

两类防御的分工见 1.2；课堂活动 4 问「If a third incident happens anyway, which of your three limits the damage most?」，问的就是降 I 的那一项。

这里的「Lecture 10」是讲者的内部编号，指本讲之后的 capstone 讲（L8 课件的预告页称它「Evaluating and securing a system ... Structured evaluation of unseen systems」）。这一讲在 Moodle 上没有任何课件或资料，本讲之后 Moodle 上直接是区块链部分。能确定的只是题型：给没见过的系统做结构化评估，也就是期末场景题的样子。答题骨架就是 Task 4 的四问，以学校的在线学习平台为例：

  • 资产：学生作业与成绩、个人信息、账户凭据、截止日期前的可用性；
  • 攻击者：想改成绩的学生、窃取凭据的钓鱼团伙、勒索团伙；
  • 最可能的攻击路径：钓鱼拿到教职工凭据 → 登录平台改成绩或导出数据——每道检查都会通过（1.1）；
  • 单项最有效的控制：教职工账户启用抗钓鱼 MFA（降 likelihood）。

8主动攻击的实例：模拟卷 Q1(c)

模拟卷 Q1(c)（7 分）：「Explain active attack with the aid of a diagram. Give some examples of active attacks.」 被动 / 主动攻击的分类和 Darth 示意图在 L1 信息安全基础；这里先勾起要点，重点是每类主动攻击在真实网络里的样子。

8.1从被动到主动：回到 L1 的分类

L1 信息安全基础按 ITU-T X.800（国际电信联盟电信标准化部门 ITU-T 发布的 OSI 安全体系结构建议书；OSI，Open Systems Interconnection，开放系统互连，网络分层的参考模型）把攻击分成两类，攻击者沿用 Stallings 教材的名字 Darth，通信双方是 Alice 和 Bob。被动攻击（passive attack）只旁听——读取消息内容，或者做流量分析（traffic analysis，内容加密了也能看出谁和谁通信、多频繁、多大量），威胁机密性，难发现，策略是预防（加密）。主动攻击（active attack）是 Darth 串进通信路径，修改数据流或制造假数据流（「The message that arrives is not the message that was sent」），分冒充、重放、篡改消息、拒绝服务四类，威胁完整性、真实性和可用性，难以绝对防止，策略是检测并恢复。

8.2四类主动攻击各配本讲的实例

主动攻击（L1 的四类）本讲的实例
冒充（masquerade，假装成另一实体）IP 欺骗、MAC 欺骗（3.2）；DNS 伪造回复冒充权威服务器（3.5）；ARP 投毒冒充网关（3.4）；BEC 冒充院长（4.3）；CSRF 让网站把攻击者造出的请求当成用户本人发的（4.2）
重放（replay，截获合法数据单元、过后重发）截获会话 cookie 后拿来登录（3.3 会话劫持：先被动截获，后主动重发）
篡改消息（modification of messages，改动、延迟或重排一条合法消息）ARP 投毒后的中间人「relaying and optionally altering traffic」（3.4）
拒绝服务（denial of service，阻止设施的正常使用）僵尸网络洪泛、SYN 洪泛、反射放大（3.6）；蠕虫扫描把网络塞满（2.2）

L1 说冒充「usually in combination with one of the others」：ARP 投毒本身是冒充（假装成网关），目的是拿到中间人位置去篡改；会话劫持是重放，效果是冒充受害者。本讲里的被动攻击则是在开放 Wi-Fi 上嗅探未加密的会话 cookie（重放之前的那一步）和键盘记录。

8.3考场答法

答法模拟卷 Q1(c) 满分答法（7 分）

定义（约 2 分）：An active attack involves some modification of the data stream or the creation of a false stream: the attacker (Darth) inserts himself into the communication path between Alice and Bob, so the message that arrives is not the message that was sent. Active attacks threaten integrity, authenticity and availability. Unlike passive attacks they are hard to prevent absolutely, so the goal is to detect them and recover.

图（约 2 分）：画 Alice、Bob 和中间的通信设施（Internet or other communications facility），Darth 串在路径上：Alice → Darth → Bob。旁边并排画被动攻击作对比（Darth 只从线上引一条虚线旁听）。标准画法见 L1 信息安全基础；想多拿分，在箭头旁注明四类攻击各自的动作（见本节四格图）。

例子（约 3 分），四类各一句，再配一个具体实例：

  • Masquerade: one entity pretends to be another — e.g. IP spoofing, or a business email compromise in which an email appears to come from a senior manager.
  • Replay: a valid data unit is captured and retransmitted later — e.g. a stolen session cookie or a captured authentication sequence replayed to gain access.
  • Modification of messages: part of a legitimate message is altered, delayed or reordered — e.g. a man in the middle after ARP poisoning altering traffic he relays.
  • Denial of service: normal use of a facility is prevented — e.g. a botnet flooding a web server, or a SYN flood exhausting the half-open connection table.
勘误参考答案多了一个 repudiation：两本教材分法不同

模拟卷参考答案列的例子是「modification, masquerading, replaying, repudiation, and denial of service」。这套写法来自 Forouzan 的教材，它按受威胁的安全目标归类，把抵赖（repudiation）也算作主动攻击，参考答案照此列出。今年 L1 用 Stallings 的四类，按四类答；抵赖在今年课件里是 STRIDE 威胁模型（L1 讲过，名字取自六类威胁的英文首字母：Spoofing 仿冒、Tampering 篡改、Repudiation 抵赖、Information disclosure 信息泄露、Denial of service 拒绝服务、Elevation of privilege 权限提升）里的 R，由不可否认性对抗；顺带提一句不会扣分。

参考答案里还有一段「authentication sequences can be captured and replayed...」，是 Stallings 对冒充的举例：截获合法的认证过程再重放，让低权限实体冒充高权限实体。

9课件参考文献与出处

课件最后一页的读物：教材 Stallings《Cryptography and Network Security》第 8 版；辅助读物 Rhodes-Ousley《Information Security: The Complete Reference》第 2 版（网络防御、防火墙放置、事件响应的实践章节）；Verizon 每年免费发布的 DBIR（Data Breach Investigations Report，数据泄露调查报告，「Which attacks actually occur, in what proportion」，L1 的数据就来自它）；OWASP Top Ten（OWASP，Open Worldwide Application Security Project，开放全球应用安全项目，发布最常见的十类网页应用漏洞及成熟的防御写法）。布置的延伸学习：读 OWASP Top Ten；浏览当年 DBIR 摘要，记下今年哪些攻击占主导；完成课后题 Task 4。

勘误课件给的教材章号和 OWASP 描述都不准
  • 课件写「Chapter 10 for malicious software; Chapter 11 for intruders and intrusion detection; Chapter 12 for firewalls」。《Cryptography and Network Security》第 8 版的第 10、11、12 章是其他公钥密码体制、密码学哈希函数、消息认证码；防火墙、入侵检测、恶意软件、DDoS 都在第 21 章 Network Endpoint Security。课件的章号其实是 Stallings 另一本书《Network Security Essentials》第 6 版的（第 10 章恶意软件、第 11 章入侵者、第 12 章防火墙）。
  • 课件说 OWASP Top Ten 里「injection, XSS and CSRF are all there」。2021 版起 XSS 已并入 Injection 一类；CSRF 自 2017 版起就不再单列，只作为一个弱点编号被归到访问控制类下面。Injection 也从 2017 版的第 1 位降到 2021 版第 3 位、2025 版第 5 位——说它「most persistent」（最持久）没错，但别写成「最常见」。

本讲速记

  • 主题：密码协议只假设攻击者在两个诚实端点之间；端点上的恶意软件、钓到的凭据、内部人员、没补丁的服务、DoS 都在假设之外。
  • 三把尺子：违反哪个属性（C、I、A、真实性、可追责性、不可否认性）；降 L 还是 I（以攻击成功那一刻为界，之前起作用降 L，之后降 I）；密码学管不管用。
  • 恶意软件两问：怎么传播（病毒、蠕虫、木马、路过式下载）× 做了什么（勒索、间谍 / 键盘记录、僵尸网络、rootkit、擦除器），任意组合；传播靠分段＋补丁，损失靠备份＋最小权限。
  • 病毒 vs 蠕虫：病毒依附宿主、宿主运行才发作、通常要用户动作；蠕虫独立、自带传播代码、不需用户动作，以分钟计。两者都自我复制，不复制的是木马。
  • 勒索五阶段：初始访问 → 驻留提权 → 横向移动 → 外传 → 毁备份再加密；对应补丁、最小权限、分段、离线不可变且演练过的备份（备份救不了外传）。
  • 身份类：IP 欺骗 → 入口 / 出口过滤（防反射靠攻击者一侧出口过滤）；MAC 欺骗 → 802.1X；会话劫持 → TLS＋Secure、令牌绑定、短寿命、重新认证；中间人 → 带证书的认证密钥交换，唯一直接由密码学解决的一项。
  • 查找类：ARP 投毒（ARP 毫无认证）→ 动态 ARP 检测、静态表项、分段；DNS 缓存投毒 → DNSSEC，TLS 证书校验兜底；DoT / DoH 防不了缓存投毒。
  • DoS：流量型（带宽）/ 协议型（SYN 洪泛）/ 应用型（贵请求）；DDoS、反射放大（伪造源 IP）；容量、清洗、限速、SYN cookies。可用性是容量属性；SYN cookies 本身用了带密钥哈希。
  • 注入：数据被解释器当成指令 → 参数化查询（结构性修复）；过滤输入是必漏的黑名单。
  • XSS 滥用用户对网站的信任 → 编码输出、CSP、HttpOnly；CSRF 滥用网站对浏览器的信任 → anti-CSRF 令牌、SameSite、重新认证。
  • 社会工程让合法的人用合法的凭据做坏事；有用：抗钓鱼 MFA、第二人带外核实、技术过滤、报告文化；原则：「Design the process so a single mistake is survivable.」
  • 防火墙：包过滤 → 状态检测 → 应用层代理 → NGFW；放在哪比用哪种更要紧；DMZ 让对外服务器被攻破也不值钱。
  • IDS 告警、IPS 拦截（误判造成中断）；特征检测对新攻击瞎，异常检测误报多（基率谬误）。
  • 分段是对横向移动最有效的单项控制（L1 隔离原则）；零信任：显式验证、最小权限、假设已被攻破。
  • 事件响应六段：准备、检测、遏制、根除、恢复、总结改进；日志集中且写保护；事件响应主要是事前的工作。
  • 考点表（「directly examinable」）见 6.2；主动攻击（Q1(c)）四类冒充、重放、篡改、拒绝服务，各配本讲实例，见第 8 节。
