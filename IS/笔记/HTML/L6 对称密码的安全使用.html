Lecture 6 — Using Symmetric Cryptography

对称密码的安全使用

AES 本身没毛病，系统坏在密码之外的四件事上——多个分组怎样串起来（工作模式），让每次加密不同的那个数从哪来（随机性），怎样发现消息被改（消息认证），密钥怎样生成、保管、更换（密钥管理）。

主线这一讲在做什么

L4 里留下的问题：一次只能加密 128 位的分组密码，怎样加密任意长的消息？这一讲回答它，并推到底：AES 本身没毛病，系统坏在密码之外的四件事上——多个分组怎样串起来（工作模式），让每次加密不同的那个数从哪来（随机性），怎样发现消息被改（消息认证），密钥怎样生成、保管、更换（密钥管理）。

主线按"一个漏洞逼出下一个机制"排：

  1. 最直接的 ECB（electronic codebook，电子密码本模式）每块独立加密，相同明文块得到相同密文块 → 加密必须随机化，于是有 CBC（cipher block chaining，密码分组链接）和 CTR（counter，计数器模式）；
  2. 三种模式只管"看不见"，不管"改不了" → 需要消息认证码（message authentication code，MAC：只有持密钥者算得出的校验值）；简单的 CBC-MAC 有缺陷，修补后是 CMAC（cipher-based MAC）；
  3. 保密和认证一步做完 → 认证加密（authenticated encryption），默认 GCM（Galois/Counter Mode，伽罗瓦/计数器模式）；到此才凑齐为场景选模式的依据；
  4. 每种模式都要一个新鲜的数 → 随机数从哪来，"看起来随机"为什么不够；
  5. 密钥也是随机数，且最常泄露 → 密钥层级、寿命与轮换；最后剩一个对称密码解决不了的问题，交给下一讲。

课件按"模式 → 随机性 → 完整性 → 密钥管理"讲。本笔记把四模式对照表和选模式活动挪到认证加密之后（第 8 节），因为表里最要紧的"能否发现篡改"要到那时才讲得清；把随机性挪到密钥管理之前，因为密钥本身就是随机数。课件只提问题、没给做法的填充、CMAC、GCM 标签都补上了。

1问题：分组之外的一切

1.1密码没坏，坏在怎么用

课件从 L4 的课后作业第 4 题开场：用 ECB（electronic codebook，电子密码本模式）把企鹅图切成 128 位的块、每块用同一把密钥独立加密，企鹅的轮廓依然清楚。课件的判词："AES is not broken here. AES is working perfectly." 出问题的是"每块独立、同一把密钥"这个用法。

由此引出整讲的论点（课件原话）："A block cipher encrypts exactly one block. Everything about how you handle more than one block — how you chain them, how you generate the numbers that keep them distinct, how you detect tampering, how you manage the keys — sits outside the cipher. And that is where systems fail."

四个 how 依次对应本笔记的第 2–4 节（工作模式）、第 9 节（随机数）、第 5–7 节（消息认证与认证加密）、第 10 节（密钥管理）。课件红条："Four lectures building ciphers. One lecture on using them. In practice this is where almost every real failure happens."

分组密码（block cipher）一次处理一个定长分组（block），AES 的分组是 128 位即 16 字节（L4）——"That is the entire specification." 把它变成能保护一条真实消息的过程，叫工作模式（mode of operation）：规定怎样把分组密码反复用在任意长度的数据上。

1.2工作模式要回答的四个问题

课件列了四个问题，每种模式回答得不同，安全性就天差地别：

  1. 消息比一个分组长。 5 MB 的文件约 312,500 个分组，加密完第 1 块，第 2 块怎么办？
  2. 消息长度不是分组的整数倍。 要补齐，接收方还要能准确去掉，见 1.3。
  3. 同一条消息可能发两次。 同样的明文若总得到同样的密文，窃听者就知道你重复了——"sometimes that is the whole secret"。
  4. 出错与随机访问。 一个密文位坏了，要丢掉多少明文？能不能不解前面 899,999 块就直接解第 900,000 块？

1.3填充：补多少、怎样无歧义地去掉

填充（padding）是在消息末尾补字节，凑成分组的整数倍；课件只提了问题。最常用的是 PKCS#7 填充（PKCS 是 Public-Key Cryptography Standards，RSA Security 公司的一组标准）：

还差 k 个字节凑满一块，就补 k 个字节，每个字节的值都是 k；如果长度恰好已经是整数倍，也要再补一整块（16 个值为 10 的字节，十六进制 10 即十进制 16）。

去填充时只看最后一个字节，值是几就去掉几个。已对齐也补一整块是为了无歧义：否则以字节 01 结尾的消息，分不清这个 01 是数据还是填充。

例：100 = 6 × 16 + 4，还差 12 个，补 12 个 0C，共 112 字节；112 字节已对齐，再补 16 个 10，共 128 字节。

勘误课件第 5 页的填充字节数算错了

课件原话："A 100-byte message needs 28 bytes of padding to reach 128 bytes."

误：补 28 字节到 128 字节。

正：分组是 128 位 = 16 字节，只需补 12 字节到 112 字节。课件把 128 位当成了 128 字节；补到 128 多补了一整块，没有哪个标准方案这样补。

只有 ECB 和 CBC 需要填充；CTR 和 GCM 不需要（4.3）。

2ECB：最直接的做法

2.1每块独立用同一把密钥加密

把明文切成分组 P1, P2, …，每块用同一把密钥 K 独立加密再拼起来。记 E(K, · )、D(K, · ) 为分组密码的加密与解密：

Ci = E(K, Pi),  Pi = D(K, Ci)

2.2确定性：重复原样漏进密文

密钥固定时，分组密码是 128 位到 128 位的一个固定的一一映射（L3），同一输入永远得到同一输出。ECB 不给每块加任何别的东西，所以是确定性的（deterministic）：同一密钥下同样的明文永远得到同样的密文——"every time, everywhere, forever"。

于是明文里"哪里和哪里相同"原样留在密文里。课件列的 ECB 泄露：

  • 明文里哪些分组彼此相同；
  • 这条消息是不是和以前发过的某条一样；
  • 足够的结构，能还原出一张图片、数据库的一列、一张有重复字段的表单；
  • 而且分组可以被重排、复制或删除而不被发现，因为没有任何东西把它们按顺序绑在一起（这一条属于"被篡改"，5.1 展开）。

这和 L2 的单表代换是同一个病：一一对应的代换，单位是一个字母还是 128 位都一样，重复原样传给密文，可以按"哪个密文块最多"做频率分析。企鹅图的大片同色区域就是大量相同的明文分组。课件建议自己用 ECB 加密一张图看看。

2.3唯一可以接受的场合

课件："Only when the message is a single block, and that block is itself random or unique — encrypting one key under another, for example." 只有一块且本身随机，就没有重复可漏。其余情况："For anything longer than one block, the answer is no. Treat ECB as a mode you must be able to recognise and reject."

补充用密钥加密密钥的标准做法不是 ECB

课件举的"用一把密钥加密另一把密钥"，实际标准是 AES 密钥包装（AES Key Wrap）：除了保密，它还能发现被包装的密钥是否被改过，ECB 做不到——这才是不用 ECB 的真正理由。（AES-256 的密钥是两个分组，严格说超出了课件"single block"的字面条件，但两个独立的随机块用 ECB 加密也泄露不了什么，相同的概率是 2−128。）

2.4总原则：加密必须随机化

课件把 ECB 的失败提炼成一条总原则："Encryption should be RANDOMISED. Encrypting the same plaintext twice should produce two different ciphertexts, and an observer should not be able to tell that the two messages were the same."

从攻击者看：他怀疑密文 C 的明文是"YES"或"NO"。加密若是确定性的，而他能让系统加密自选的明文（选择明文攻击，chosen-plaintext attack），把"YES"加密一次、和 C 一比就知道答案，不用碰密钥。每次加密都掺进一个新值，这条路才堵死。

课件："Every mode after ECB achieves this by injecting a fresh, unique value into each encryption." CBC 掺进的是初始化向量（IV，见 3.1），CTR、GCM 掺进的是一次性数（nonce，见 4.1），两者要求不同。

3CBC：把块串起来

3.1每块先异或上一块密文

CBC（cipher block chaining，密码分组链接模式）：每个明文块在加密之前，先和上一个密文块逐位异或（XOR，两位相同得 0、不同得 1，记作 ⊕，定义见 L2）；第一块没有"上一块"，就和一个初始化向量（initialisation vector，IV）异或。IV 是一个与分组等长、随消息一起发送的起始值。

Ci = E(K, Pi ⊕ Ci−1),  C0 = IV

解密：D(K, Ci) 得到加密时送进去的 Pi ⊕ Ci−1，再异或一次 Ci−1 就去掉它（x ⊕ a ⊕ a = x）：

Pi = D(K, Ci) ⊕ Ci−1

相同的明文块不再得到相同的密文块。 设 P1 = P3，送进分组密码的是 P1 ⊕ IV 和 P3 ⊕ C2，只有 C2 = IV 时才相等，对 AES 概率约 2−128。"The penguin disappears."

每个密文块依赖之前的全部明文块：C2 由 P2 和 C1 决定，也就间接由 P1 决定，依此类推。6.4 会用到这一点。

3.2IV：公开，但必须不可预测

课件："Random, unpredictable, different for every message. It is not secret — it is sent in the clear alongside the ciphertext." 接收方解第一块要用它，所以明文发送；它的作用靠每条不同、事先猜不到。

IV 重复。 同一密钥、同一 IV 下，两条消息前几块明文相同，前几块密文也相同，直到第一个不同的块为止。课件说这"reveals whether two messages start with the same block"，准确说泄露的是相同前缀有多长。

IV 可预测，就能做选择明文猜测。攻击者截获 C1 = E(K, P1 ⊕ IV1)，想验证 P1 是否等于猜测 G；若他能预知下一个 IV2 并让系统加密他提交的明文，就提交

P′ = G ⊕ IV1 ⊕ IV2

系统算出 E(K, P′ ⊕ IV2) = E(K, G ⊕ IV1)，等于 C1 当且仅当 G = P1。明文取值不多时（PIN 码、是/否字段）很快就能试出来。2011 年的 BEAST 攻击（Browser Exploit Against SSL/TLS）就这样打 TLS 1.0：它拿上一条记录的末块当下一条的 IV。（TLS 即 Transport Layer Security，传输层安全协议，HTTPS 的底层；SSL 是它的前身。）

所以 CBC 的 IV 要不可预测，不只是不重复：明文和 IV 在进入分组密码之前异或在一起，预知 IV 就能操纵分组密码的输入。

3.3并行与错误传播

加密只能顺序做，解密可以并行：加密第 i 块要先有 Ci−1；解密时密文都在手，每块各算各的。随机访问也只在解密方向：解第 i 块只需 Ci、Ci−1。

错误传播到下一块为止。 设 Ci 坏了一位，变成 Ci′：

  • 第 i 块：D(K, Ci′) 的输入变了一位，雪崩效应让输出约一半的位改变，整块乱掉；
  • 第 i + 1 块：Pi+1′ = D(K, Ci+1) ⊕ Ci′，只有 Ci′ 多翻了一位，所以 Pi+1 恰好同一位置翻一位；
  • 第 i + 2 块起只用到 Ci+1 和 Ci+2，完好如初。

实测（AES-128-CBC，翻 C2 第 3 字节最高位）：四块分别变了 0、70、1、0 位。

课件："CBC was the default mode for decades and is still very widely deployed. It is adequate for confidentiality — and, as Part 3 shows, it provides no integrity at all." 传输出错时"只翻同一位"是好事，攻击者故意翻位时就成了篡改工具（5.1）。

分组 4 位。默认是课堂活动 1 的线性密码 E(x) = x ⊕ K；切到 S 盒版就是上面说的非线性 E(x) = S[x ⊕ K]。橙红色的格是与别的块相同的密文；最后一列是 CBC 相邻密文的异或。

4CTR：把分组密码变成流密码

4.1加密计数器，再与明文异或

CTR（counter mode，计数器模式）换了一个思路："Do not encrypt the plaintext at all. Encrypt a counter, and XOR the result with the plaintext."

  • 一次性数（nonce，number used once）：每条消息选一个在这把密钥下从不重复的值；
  • 计数器：块号 i = 1, 2, 3, …；
  • 把两者拼在一起（‖ 表示把两段位串首尾相接，如 96 位 nonce 接 32 位块号，正好 128 位）当作分组密码的输入，输出叫密钥流（keystream）块 Si，再与明文块异或。
Si = E(K, nonce ‖ i),  Ci = Pi ⊕ Si,  Pi = Ci ⊕ Si

这正是 L3 的流密码：密钥流与明文逐位异或。L3 对比两类密码时说"放进合适的工作模式，分组密码就能当流密码用"，指的就是 CTR。

加解密是同一个运算："The block cipher is never run backwards. Decryption uses the ENCRYPTION function." 这也是 L4 说 AES 有意为加密优化的理由之一：CTR、GCM 两个方向都只用加密函数。

4.2nonce 绝不能重复

课件："Reuse it with the same key and you have reused a keystream — the two-time pad failure […]. It is fatal."

两条消息用同一密钥、同一 nonce，密钥流 S 相同，两段密文一异或：

C ⊕ C′ = (P ⊕ S) ⊕ (P′ ⊕ S) = P ⊕ P′

密钥流被消掉，剩下两段明文的异或——L3 讲评过的两次一密（two-time pad），猜中一条的一段，另一条同一位置就读出来。

对比 CBC，CTR 的 nonce 只要不重复，不要求不可预测，可以就是一个计数器。原因：CBC 里明文与 IV 在进入分组密码之前混在一起，预知 IV 就能操纵输入；CTR 里进入分组密码的只有 nonce ‖ i，预知它影响不了什么，只要不重复，每个 Si 都是新的。

课件那句"nonce / IV 存在的唯一目的，是保证同一把密钥下的密钥流永不重复"（L3 1.1 转述过）对 CTR、GCM 成立；CBC 根本没有密钥流，它的 IV 要的是不可预测（3.2）。

4.3CTR 的五个特性

课件列了五条：

特性原因与用处
完全可并行每个密钥流块只依赖计数器，可同时、按任意顺序算。"This is why CTR dominates high-throughput links."
随机访问解第 900,000 块，就加密计数器 900,000
不需要填充密钥流截到消息长度，100 字节消息得 100 字节密文
密钥流可预先算好只取决于密钥和计数器，数据没到就能先算
不传播错误，也没有完整性密文翻一位，明文恰好在同一位置翻一位。"Convenient on a noisy link, and catastrophic when the attacker is choosing which bit."

最后一行是 CTR 几乎从不单独使用的原因，5.1 展开。

勘误课件第 9 页：磁盘加密的标准不是 CTR

课件说随机访问 "Essential for disk and database encryption"。

误：磁盘加密就用 CTR。

正：扇区会被原地重写。若 nonce 由扇区号决定，改写前后两版用同一段密钥流，就是 4.2 的 nonce 重用——新旧两份镜像一异或，得到两版明文的异或。实际标准是 XTS-AES（XEX-based tweaked-codebook mode with ciphertext stealing）：扇区号作"微调值"（tweak）参与每块加密，不产生可重用的密钥流，密文与扇区等长；L4 列的 BitLocker、FileVault 用的就是它。代价：对同一扇区同一位置是确定性的，比较改写前后能看出哪几个 16 字节块变了；也不提供完整性。

5加密不等于完整性

到这里三种模式都只保护机密性（confidentiality）："A cipher guarantees that an attacker cannot READ your message. It says nothing whatsoever about whether they can CHANGE it." 防止消息被改而不被发现是 CIA 三要素里的完整性（integrity），要单独的机制。

5.1三种模式下怎样不用密钥改密文

CTR（及任何"密文 = 明文 ⊕ 密钥流"的模式）：想改哪一位就改哪一位。 攻击者把 C 换成 C′ = C ⊕ Δ（Δ 是想让明文发生的变化），接收方照常解密：

C′ ⊕ S = (P ⊕ S ⊕ Δ) ⊕ S = P ⊕ Δ

S 抵消了，攻击者不需要 S 或 K，只需知道明文要怎么变。

CBC：毁掉一块，精确控制下一块。 攻击者把 Ci 换成 Ci ⊕ Δ，就是 3.3 的错误传播，只是翻哪几位由他决定：

Pi+1′ = D(K, Ci+1) ⊕ (Ci ⊕ Δ) = Pi+1 ⊕ Δ

第 i + 1 块精确改变，第 i 块变成乱码。课件："Controlled tampering is still possible." 第一块还能改得更干净：改 IV。P1′ = D(K, C1) ⊕ (IV ⊕ Δ) = P1 ⊕ Δ，没有任何一块被弄乱（课件没提）。例如把 IV 的第 9 个字节异或 09，PAY BOB 0100 GBP 就解成 PAY BOB 9100 GBP。

ECB：块可以重排、复制、删除。 每块独立加解密，没有任何东西把它们按顺序绑住。例如 PAY BOB 0100 GBP 和 PAY EVE 9999 GBP 两块的 ECB 密文对调位置，接收方解出的就是对调后的两条指令——正是 L1 篡改定义里的"重新排序"。

课件："And in every case the receiver decrypts happily and acts on the result." 任何一串比特都能解出某个明文，有没有被改过，解密算法不知道也不负责。

篡改实验台：不碰密钥改密文，接收方会怎样

真实的 AES-128，密钥、IV、nonce 每次随机生成。选一种模式、一种篡改，看接收方解出什么。消息不足一块的部分补空格，只为对齐演示。

5.2课堂活动 4：不用密钥把 0100 改成 9100

题面：一条支付指令用 CTR 模式发送，"Ciphertext = plaintext ⊕ keystream, byte by byte."

表中第二行是明文的 ASCII 码（American Standard Code for Information Interchange，美国信息交换标准代码：每个字符对应一个字节），都写成十六进制；␣ 表示空格，ASCII 20。

位置123456789101112
明文PAY␣BOB␣0100
ASCII50415920424F422030313030
密文CC6F2884499C1A46A72E7AD2

"You are the attacker. You can see and modify the ciphertext. You do NOT have the key or the keystream." (a) 要把 0100 改成 9100，该改哪个密文字节？(b) 算出把 '0' 变成 '9' 的掩码并作用上去；(c) 一句话解释为什么不需要密钥流。

解答

(a) "PAY BOB " 占 8 个字节，金额的第一个 '0' 是第 9 个字节，对应密文 A7，只改它。

(b) 掩码 = 旧明文字节 ⊕ 新明文字节 = 30 ⊕ 39 = 09（0011 0000 ⊕ 0011 1001 = 0000 1001）。新密文字节 = A7 ⊕ 09 = AE（1010 0111 ⊕ 0000 1001 = 1010 1110）。篡改后的密文：CC 6F 28 84 49 9C 1A 46 AE 2E 7A D2。

(c) C ⊕ m = (P ⊕ S) ⊕ m = (P ⊕ m) ⊕ S，接收方异或密钥流后得到 P ⊕ m = 30 ⊕ 09 = 39，即 '9'。英文一句："Because C ⊕ mask = (P ⊕ mask) ⊕ S, the receiver's XOR with the keystream yields P ⊕ mask — the keystream cancels, so the attacker needs only the plaintext they want to change, not the key."

由题面可以反推密钥流 S = P ⊕ C = 9C 2E 71 A4 0B D3 58 66 97 1F 4A E2，篡改后的密文异或它得 PAY BOB 9100；但攻击者自始至终不需要知道 S。

课堂活动 4 演算：想让接收方读到什么

密文用的是题面那 12 个字节。改下面这一栏（必须 12 个字符），页面算出每个要改的字节的掩码和新密文字节，再替接收方解密。

前提：攻击者要知道明文格式（金额在第几字节、原值是什么）；支付报文、协议头的格式往往公开。课件红条："The receiver will decrypt your modified ciphertext successfully and act on it."

5.3课后作业 1：在 CBC 里篡改

题面："In CBC, an attacker who flips a bit in ciphertext block Ci changes the plaintext of block i + 1 in a predictable way. Work out exactly which plaintext bits change, and what happens to block i itself. Two or three sentences."

解答

设攻击者把 Ci 的第 j 位翻转，即 Ci′ = Ci ⊕ Δ，Δ 只有第 j 位为 1。由 Pi+1 = D(K, Ci+1) ⊕ Ci，第 i + 1 块变成 Pi+1 ⊕ Δ：恰好第 j 位翻转，其余不变，攻击者想翻哪几位就翻哪几位。第 i 块是 D(K, Ci ⊕ Δ)，分组密码的雪崩效应使它约一半的位改变，整块变成攻击者也无法预料的乱码；第 i + 2 块起不受影响。

乱掉的那一块会不会引起接收方怀疑，取决于应用是否检查格式；攻击第 1 块时改 IV，连这块乱码都没有。

6消息认证码

6.1MAC：只有持密钥者算得出的标签

消息认证码（message authentication code，MAC）是用消息和共享密钥算出的一小段值，叫标签（tag）：

tag = MAC(K, message)

发送方连同消息一起发出；接收方用同一密钥重算、比较，不一致就丢弃。

伪造不了的原因（课件）："Computing the tag requires the key. Change one bit of the message and the correct tag changes unpredictably."

MAC 提供两样东西：完整性（途中没被改）和数据源认证（data origin authentication，课件说 authenticity：消息来自持有密钥的一方，不是冒充者）。

6.2MAC 必须满足的三条性质

课件列了三条（对应 Stallings 12.3 节），每条堵一种伪造：

  1. "Given a message and its tag, it must be infeasible to find a different message with the same tag." 否则截获一条合法消息，就能换成自己的消息、沿用原标签。
  2. "Tags must be uniformly distributed — guessing one should cost 2n−1 attempts for an n-bit tag." 随机猜一次中的概率是 2−n，不重复地逐个试平均要 2n−1 次：n = 32 约 2.1 × 109 次，n = 128 约 1.7 × 1038 次。
  3. "The tag must depend equally on every part of the message, not just the end." 比如只用最后几块算标签，前面就能随意改。

6.3MAC 不是签名，也不保密

课件把这两点标成 "Two things students get wrong about MACs"：

一、MAC 不是签名。 "Both parties share the same key, so either could have produced the tag. A MAC proves the message came from someone holding the key — it cannot prove which one, so it gives you integrity and authenticity but not non-repudiation." 不可否认性（non-repudiation，L1 4.2 定义过）指发送方事后无法抵赖。密钥 Alice、Bob 都有，Bob 出示一条带合法标签的消息，Alice 可以说"是 Bob 自己算的"，第三方无法分辨；要不可否认，得用只有一方持有私钥的数字签名，见 L8 数字签名、证书与 PKI。

二、MAC 不隐藏任何东西。 消息仍是明文；要保密还得加密，认证加密一步做完（第 7 节）。

勘误课件第 20 页"MAC 只提供完整性"这半句不准确

课件同一个框里先说 MAC "gives you integrity and authenticity but not non-repudiation"，紧接着又说 "It provides integrity only."

误：MAC 只提供完整性。

正：MAC 提供完整性和数据源认证，不提供保密性和不可否认性。后半句想说"不提供保密"，字面上把认证也丢了；以课件结尾的总结 "A MAC gives integrity and authenticity, but not non-repudiation" 为准。

对照 L1 的四种主动攻击：篡改和外人的冒充，MAC 都能发现；否认，MAC 防不了；重放（把截获的合法消息原样再发一次）的标签依然合法，MAC 单独也防不了，要在消息里加序号或时间戳（课件外）。

6.4课件的 CMAC 其实是 CBC-MAC

课件给的构造："Run the message through AES in CBC mode and keep only the final block as the tag. Because CBC chains, that last block depends on every bit of the message." 并说它 "Standardised as NIST SP 800-38B. It needs no primitive beyond the block cipher you already have — which is why it suits constrained devices."

勘误课件第 20 页把 CBC-MAC 当成了 CMAC

误：CMAC 就是"CBC 加密、只留最后一块"。

正：那是 CBC-MAC，变长消息下可被伪造；CMAC = CBC-MAC + 最后一块异或一个子密钥，见 6.5。考试若问 CMAC 怎么构造，按 6.5 写，并点明它修补的是 CBC-MAC 的变长伪造；以老师口径为准。

这描述的是 CBC-MAC（Stallings 12.6 节叫 DAA，Data Authentication Algorithm）：IV 固定为全 0，做 CBC 加密，只留最后一块作标签。思路是对的：CBC 的最后一块依赖全部明文块（3.1），满足性质 3。

IV 必须固定：若 IV 随消息发送、可以随便选，攻击者把 IV 和 M1 的同一位同时翻转，M1 ⊕ IV 不变，标签也不变，就伪造了一条第一块不同的消息。

6.5CBC-MAC 的拼接伪造与 CMAC 的修补

CBC-MAC 对变长消息不安全。 已知单块消息 M 的标签 T = E(K, M)，两块消息 M ‖ (M ⊕ T) 的标签还是 T：

  1. 第一块：E(K, M) = T；
  2. 第二块送进 E 的是"上一块输出 ⊕ 本块"：T ⊕ (M ⊕ T) = M；
  3. 输出 E(K, M) = T。

标签就是链条的中间值，攻击者可以从它接着往下链，再用一个选好的块把链条拉回已知状态（实际数值见本讲复习卡代表题 3）。CBC-MAC 只在所有消息长度固定时安全。

CMAC（cipher-based MAC，基于分组密码的 MAC，NIST SP 800-38B / RFC 4493；RFC 是 Request for Comments，互联网标准文档系列）的修补在最后一块上：

  1. 先导出两个子密钥（subkey）：L = E(K, 0128)，K1 = 2 · L，K2 = 2 · K1。"乘 2"在有 2128 个元素的有限域 GF(2¹²⁸) 里做，和 L4 的 GF(2⁸) 乘 2 一样：左移一位，移出的最高位是 1 就再异或一个常数，常数从 1B 换成 87（最低字节）。
  2. 前面各块照常做 CBC（IV 为 0）。
  3. 最后一块满 16 字节，先异或 K1 再进 E；不满，先补一个 1 再补 0 到满块，异或 K2。两个子密钥让"恰好满块"和"补过位"的消息不会撞成同一个标签。

拼接伪造为什么失效：标签 T′ = E(K, M ⊕ K1) 不再是链条中间值 E(K, M)，攻击者拿 T′ 构造的 M ‖ (M ⊕ T′)，CMAC 是他算不出的另一个值（已核对）。

拼接伪造：CBC-MAC 上成立，CMAC 上失效

同一把 AES-128 密钥、同一条单块消息 M，分别按 CBC-MAC 和 CMAC 算标签，再照 M ‖ (M ⊕ T) 拼一条两块的消息去骗接收方。默认密钥是 RFC 4493 测试用的那一把。

课件说 CMAC "suits constrained devices"：设备上已有 AES，不需要别的部件。实际更常用的是基于哈希函数（hash，把任意长数据压成定长"指纹"的函数）的 HMAC（hash-based MAC，Stallings 12.5 节），课件没提。

7认证加密

7.1先加密后认证，还是先认证后加密

课件："You almost always need confidentiality AND integrity. Combining them yourself is easy to get wrong, so modern practice uses a mode that does both in one operation." 同时提供两者的叫认证加密（authenticated encryption，AE）。自己用"加密 + MAC"拼，顺序是关键：

先加密后认证（Encrypt-then-MAC）先认证后加密（MAC-then-encrypt）
做法先加密明文，再对密文算 MAC先对明文算 MAC，再把明文和标签一起加密
接收方先验标签，通过了才解密必须先解密，才能验标签
课件的结论"The right answer. Invalid messages are rejected before the decryption code ever runs.""Riskier. The decryption path processes attacker-controlled data before it has been authenticated, which is how padding-oracle attacks became possible."

填充预言机攻击（padding oracle attack，Vaudenay 2002）是先认证后加密出事的经典例子：

  1. CBC 需要填充（1.3），接收方解密后先检查填充格式；
  2. 检查填充发生在验标签之前；"填充错"和"标签错"的反应若不同（报错不同或耗时不同），每次请求就泄露一位："改过的密文，填充对不对"——接收方成了预言机（oracle：只回答是或否、从不说谎的黑盒）；
  3. 由 5.1，攻击者把 Ci−1 的末字节异或一个值 δ，Pi 的末字节 p 就变成 p ⊕ δ。他把 δ 从 00 试到 FF，直到接收方说"填充正确"，即 p ⊕ δ = 01，于是 p = δ ⊕ 01（偶尔倒数第二字节恰好是 02，末字节 02 也算合法，改一下倒数第二字节再试一次就能排除）。下一个字节把目标换成 02 02，依此类推，不需要密钥就能解出整条消息。

填充预言机：只靠「填充对不对」解出一整块

接收方用 AES-128-CBC 解密，先检查 PKCS#7 填充，只回答对或不对。攻击者把前一块的第 j 个字节异或 δ，从 00 试到 FF，直到接收方说「填充正确」。每点一次按钮解出一个字节；密钥和 IV 在点「重新加密」时随机生成。

先加密后认证下，改过的密文过不了标签检查，走不到检查填充那一步。用它还要守两条（课件外）：MAC 覆盖 IV 或 nonce；加密和 MAC 用独立的密钥。

补充还有第三种组合

课件只对比了两种。Stallings 12.7 节还列了"加密与认证并行"（Encrypt-and-MAC：对明文算 MAC、明文另行加密，一起发送）。若 MAC 只覆盖明文，同样的明文得到同样的标签，泄露"两条消息是否相同"；SSH（Secure Shell，远程登录协议）用的就是这种组合，靠在 MAC 输入里加包序号避开了这一点。一般而言它仍不如先加密后认证稳妥。

7.2GCM：CTR 加一个在有限域里算的标签

GCM（Galois/Counter Mode，伽罗瓦/计数器模式；伽罗瓦域即有限域）是今天最主要的认证加密模式。课件："CTR mode for confidentiality, plus an authentication tag computed over the ciphertext in a finite field. One pass over the data, fully parallelisable, hardware accelerated on modern processors, and it can also authenticate associated data."

关联数据（associated data / additional authenticated data，AAD）是必须可见、但不许被改的部分，如网络包头：路由器要读，不能加密；改了必须被发现，所以进标签。能认证关联数据的认证加密叫 AEAD（authenticated encryption with associated data）。

课件预告"We meet how the tag works in Part 3"，但 Part 3 只有"computed over the ciphertext in a finite field"半句。标签的算法（NIST SP 800-38D）补在这里，7.3 的伪造要用到：

  1. 加密部分就是 CTR。 96 位的 IV（即 nonce，要求不重复）拼出初始计数块 J0 = IV ‖ 031 ‖ 1；第 j 块明文用 E(K, J0 + j) 加密。
  2. 认证部分叫 GHASH。 先算哈希子密钥 H = E(K, 0128)，只取决于密钥、与 nonce 无关。要认证的块依次是关联数据 A、密文块 C1, C2, …、记录 A 和 C 长度的块 L；从 X0 = 0 开始，每块 B 做 X ← (X ⊕ B) · H。"·"是 GF(2¹²⁸) 里的乘法（与 L4 的 GF(2⁸) 同类；GCM 的位序和 CMAC 相反，不能套 6.5 的左移规则，这里只需知道它对异或可分配）。展开来，GHASH 是以 H 为未知数的多项式。
  3. 标签 T = GHASHH(A, C) ⊕ E(K, J0)，E(K, J0) 是每条消息不同的掩码。

单块密文、无关联数据时：X1 = C · H，X2 = (X1 ⊕ L) · H = C · H2 ⊕ L · H，再异或掩码：

T = C · H2 ⊕ L · H ⊕ E(K, J0)

课件说的优点在图上都看得出：

  • "computed over the ciphertext"：GHASH 的输入是密文，是先加密后认证的结构，接收方先验标签再解密；
  • 一遍、可并行：CTR 各块独立；GHASH 的多项式可以先算好 H, H2, H3, … 再并行求值；
  • 硬件加速：AES 有 AES-NI 指令（L4），GF(2¹²⁸) 乘法有处理器的"无进位乘法"指令；
  • "It is the default cipher suite in TLS, and it is what you should reach for." TLS 1.3 必须实现 AES-128-GCM；没有 AES 硬件加速的设备用 ChaCha20-Poly1305（ChaCha20 流密码加 Poly1305 认证码组成的 AEAD），纯软件也快。

L4 讲过 WPA2 的 CCMP 内部是 CCM 模式（Counter with CBC-MAC：CTR 加密 + CBC-MAC 认证），正好由本讲的两个部件组成；它要对数据走两遍、不能一遍并行，所以 TLS 默认选 GCM。

7.3GCM 的 nonce 重用：机密性和完整性一起丢

课件的警告："GCM is built on CTR, so a repeated nonce under the same key is catastrophic — it destroys confidentiality AND lets an attacker forge tags. Nonce management is not optional." 课后作业 2 要求把两个后果都说出来。

课后作业 2 解答：同一密钥下 nonce 用了两次

题面："Explain what an attacker learns if the same nonce is used twice with the same key in GCM. Give both consequences — there is one for confidentiality and one for forgery."

后果一：机密性。 同一 nonce ⇒ 同一 J0 ⇒ 同一串 CTR 密钥流，于是 C1 ⊕ C2 = P1 ⊕ P2，回到 两次一密：知道或猜到一条明文，另一条直接读出。

后果二：伪造。 两条消息的掩码 E(K, J0) 相同。以等长单块、无关联数据为例，两个标签异或，掩码和长度项都抵消：

T1 ⊕ T2 = (C1 ⊕ C2) · H2

式中只有 H 未知，其余攻击者都看得见。在 GF(2¹²⁸) 里除以 C1 ⊕ C2 得 H2，再开平方得 H（GF(2¹²⁸) 里每个元素恰有一个平方根；多块时是关于 H 的高次多项式方程，可能有几个候选根，逐个试）。有了 H，由 E(K, J0) = T1 ⊕ C1 · H2 ⊕ L · H 得到这个 nonce 的掩码，此后能为这个 nonce 下的任意密文算出合法标签——配合后果一，改了明文再补上正确标签，接收方验证通过。H 与 nonce 无关，一旦泄露，这把密钥下见过的任何合法消息都能如法炮制。这叫 Joux 的"forbidden attack"（2006）；2016 年有研究者在真实的 HTTPS 服务器上发现了 nonce 重用。

这一伪造已复现：同一 nonce 加密两条消息，解出 H，把 transfer 0100 to 改成 transfer 9100 to 并算出新标签，标准库的 GCM 解密接受了它。

GCM 的 nonce 重用：解出 H，替改过的密文算出合法标签

两条单块消息用同一把密钥、同一个 nonce 加密。攻击者只看得到两组 (C, T)，并知道第一条的内容；页面按上面的推导一步步算，最后把伪造的密文和标签交给标准的 GCM 解密去验。

GCM 的 IV 可以用计数器确定性地生成（TLS 1.3 就这样做），也可以随机生成。随机生成时 96 位也会偶然相撞，所以 NIST 规定随机 IV 时每把密钥最多加密 232 条消息，理由见 10.2 的生日界。

9.3两项要求：统计上随机，且不可预测

要求一：统计上随机。 序列要"看起来随机"，检验两条：

  • 均匀性（uniformity）："zeros and ones appear about equally often, in every part of the sequence"——不只是总数各半，每一段也要各半；
  • 独立性（independence）："no subsequence can be inferred from any other"——看到一段，推不出另一段。

NIST SP 800-22 列了 15 项统计检验来测这些。

要求二：不可预测。 "Given any number of previous outputs, an adversary must not be able to predict the next one — or reconstruct the earlier ones."

  • 前向不可预测（forward unpredictability）：看到前面的输出，猜不出下一位；
  • 后向不可预测（backward unpredictability）：看到后面的输出，推不出前面的输出或种子。

课件："This is the requirement that statistical tests cannot check." 统计检验只看输出长什么样，而一个知道公式就能算出全部输出的序列，样子可以非常随机。

补充后向不可预测的定义，教材与课件略有出入

课件："seeing later output must not reveal earlier output, or the seed." Stallings 8.1 节："It should also not be feasible to determine the seed from knowledge of any generated values."——重点在由输出反推种子（种子一旦推出，前后输出都能算）。默写定义按 Stallings 写，再补一句课件的说法。

反例：线性同余发生器。 线性同余发生器（linear congruential generator，LCG）是最常见的教科书 PRNG：

Xn+1 = (a · Xn + c) mod m

m 是模数、a 乘数、c 增量、X0 种子。参数选得好，统计性质很好；但它是线性的，几个连续输出就能解出参数，前后所有输出随之可算。

手算例：m = 31，攻击者不知道 a、c 和种子，只看到三个连续输出 X1 = 0、X2 = 7、X3 = 22。

  1. 两个相邻的式子相减，消去 c：X3 − X2 = a (X2 − X1) (mod 31)，即 15 = 7a (mod 31)。
  2. 求 7 的模 31 逆元（与 7 相乘、模 31 余 1 的数，下一讲 RSA 会大量用到）：7 × 9 = 63 = 2 × 31 + 1，所以 7−1 = 9。于是 a = 15 × 9 = 135 ≡ 11 (mod 31)。
  3. 代回第一个式子：c = X2 − aX1 = 7 − 11 × 0 = 7。
  4. 预测下一个：X4 = (11 × 22 + 7) mod 31 = 249 mod 31 = 1。往回推种子：X0 = (X1 − c) · a−1 = (0 − 7) × 17 ≡ 5 (mod 31)（11 × 17 = 187 = 6 × 31 + 1，所以 11−1 = 17）。

核对：a = 11、c = 7、X0 = 5 生成的序列正是 0、7、22、1、18、19、30、27…。模数是素数（如 231 − 1）时解法完全一样；m = 232 时差值是偶数就没有逆元，要多看几个输出排除多余的解；m 未知时还要先解出 m。结论不变：几个输出就够。课件说这个 LCG 能通过全部 15 项检验，那要看参数：满周期（a、c 都为奇数）的模 232 LCG 最低位严格 0、1 交替，c 为偶数时最低位干脆是常数，直接拿全部比特用都过不了检验——但这不影响要说的道理：统计性质好不等于不可预测。

从三个连续输出解出 LCG

已知模数 m 和三个连续输出，按上面四步解 a、c，预测下一个、倒推种子。也可以让页面随机造一个 LCG 来试。

种子和算法一样要紧。 "A cryptographically strong PRNG seeded from the system clock offers no security at all — the attacker also knows roughly what time it was." 攻击者只需把那个时间附近的几百万个值试一遍。

该用什么。 "A cryptographically secure PRNG, seeded from the operating system's entropy pool. Never a general-purpose random() function from a programming language's standard library — those are built for simulations, not secrecy." 即密码学安全伪随机数发生器（cryptographically secure PRNG，CSPRNG）。具体（课件外）：Linux 的 getrandom() 或 /dev/urandom、Python 的 secrets；Python 的 random 是梅森旋转算法（Mersenne Twister），看 624 个连续的 32 位输出就能还原全部状态。

10密钥管理

课件第四部分的标语："The cipher is solved. The keys are not."

10.1密钥层级

"Real systems do not use one key for everything. Keys are arranged in layers, each protecting the layer below, so that a compromise at one level does not expose everything."

层范围做什么
主密钥（master key）长期、高价值、很少直接用常放在专用硬件里不出来；只保护别的密钥
密钥加密密钥（key-encrypting key，KEK）保护传输和存储中的密钥分发或存储会话密钥时把它"包"起来；定期更换
会话密钥（session key）一个连接、一次通话每次会话新生成，用完即弃，不写盘
数据密钥（data key）一个文件、一条记录、一条消息按对象派生，直接加密数据；生成和丢弃都便宜

"专用硬件"指硬件安全模块（hardware security module，HSM）：防拆设备，密钥在里面生成和使用，从不出现在外面。会话密钥保护传输中的一段通信，数据密钥保护存储中的一个对象；"按对象派生"用的就是 9.2 的 PRF，这种用途叫密钥派生函数（key derivation function，KDF）。

课件："Fewer uses higher up. The master key might be used a handful of times a year; a data key once." 用得越少，保护的数据越少，泄露机会也越少。

分层的理由（课件）："That is Lecture 1's isolation principle applied to keys: contain the blast when one is lost." 即 L1 设计原则里的隔离（isolation）：丢一把数据密钥只暴露一个文件，丢一把会话密钥只暴露一次会话。

云服务的信封加密（envelope encryption，课件外）就是这个层级：每个文件用新生成的数据密钥加密，数据密钥再用 KEK 加密后和文件存在一起；KEK 留在密钥管理服务（key management service，KMS）里。读文件时先请 KMS 解开数据密钥。

10.2密钥为什么要过期

密钥轮换（key rotation）就是定期换成新密钥、旧密钥退役；一把密钥允许使用的时长叫它的密钥寿命（cryptoperiod）。课件给了四条理由：

  1. 限制损失。 "Rotation caps the blast radius in time." 用得越久保护的数据越多，一次泄露代价越大；爆炸半径（blast radius）即一次泄露波及的范围。
  2. 限制攻击者手上的材料。 "Cryptanalysis and birthday-bound effects both improve with more ciphertext under one key. With a 128-bit block, encrypting beyond roughly 264 blocks under one key starts to leak."
  3. 密钥会慢慢漏出去。 备份、日志、崩溃转储、离职员工、配置错误的存储——"Over a long enough period, the probability a key has escaped somewhere approaches one."
  4. 因为总有一天要紧急换。 "An organisation that has never rotated a key cannot rotate one under pressure." 课件说这是 L1 的教训（L1 笔记里最接近的是设计原则里"没被检验过"那一行）："an untested control is not a control. A rotation procedure nobody has ever run is a plan, not a capability."

第 2 条里的生日界（birthday bound）：q 个随机的 n 位值，两两配对约有 q2/2 对，每对相同的概率是 2−n，所以相同的对数的期望是 λ = q(q − 1)/2n+1。L4 1.1 用过这个界：64 位分组 q = 232 时期望约 1/2，至少一次重复的概率约 39%。从期望到概率的那一步是：逐个放入这 q 个值，第 i + 1 个和前 i 个都不同的概率是 1 − i/2n，所以一个都不撞的概率

q−1∏i=1(1 − i2n) ≈ q−1∏i=1e−i/2n = e−q−1∑i=1i/2n = e−q(q−1)/2n+1

（用的是 x 很小时 1 − x ≈ e−x），取补集：

p ≈ 1 − e−q(q−1)/2n+1 = 1 − e−λ

q 很小时 p ≈ λ，随 q 的平方增长；λ = 1/2 时 p ≈ 0.39。对工作模式的意义：在 CBC 里，两个密文块 Ci = Cj 意味着送进分组密码的输入相同，即 Pi ⊕ Ci−1 = Pj ⊕ Cj−1，于是 Pi ⊕ Pj = Ci−1 ⊕ Cj−1——两块明文的异或直接从密文里读出来。几个点：

勘误课件第 24 页：2⁶⁴ 块不是"开始泄露"的点

课件："encrypting beyond roughly 264 blocks under one key starts to leak."

误：264 块以内安全，超过才开始泄露。

正：泄露概率随 q2 平滑上升，没有"开始"的门槛；264 块时碰撞概率已约 0.39，是"很可能已泄露"的点，实际限额远低于它（如上表最后一行）。264 个 AES 块是 256 EiB，现实中碰不到，对 AES 真正起作用的是 nonce 与使用次数的上限；64 位分组则 32 GiB 就到 0.39，2016 年的 Sweet32 攻击就靠这一点攻击了用三重 DES 的 HTTPS。定性结论（数据越多泄露越多，所以要轮换）没错。

课件："Not one of these is a cryptographic failure. Every one of them is routine."

途径怎样泄露
写死在源代码里"A key committed to a repository is a key published to everyone who ever clones it — and it stays in the history after you delete it."
放在配置文件里被复制到测试环境、未加密备份，能读部署的人都能读
进了日志和崩溃转储打印请求对象的调试输出把里面一切都打出来；崩溃转储含进程内存
放在环境变量里同用户的进程都看得见，监控代理常整包采集
用不足的熵生成"A device that generates its key before it has gathered any entropy produces the same key as every other device of that model." 2012 年的研究扫到大量嵌入式设备共用密钥，正因开机时熵没攒够
过了用处还留着"The key that encrypted the archive nobody has opened since 2019, still valid, still on the file server."

课件："AES has never been broken. Keys are lost every single day. When you evaluate a system, look here before you look at the algorithm." 评估题照这个顺序答：先查密钥放哪、怎么生成、多久换，再谈算法。

10.4对称密码解决不了的问题

课件最后一页回顾贯穿前几讲的假设："Every lecture so far has assumed that the two parties already share a secret key."

  • 对称密码模型需要"a secure channel for the key K"，当时指出了这个循环，就放下了；
  • 一次一密不可破，但要求先送达一把和消息一样长的密钥——问题被挪了地方，没有解决；
  • DES 和 AES 都把密钥当作输入，对它从哪来只字未提；
  • 今天的密钥层级用密钥保护密钥，但最顶上那把密钥仍要以某种方式送到双方手里。

结论："Two strangers who have never met cannot establish a shared secret using symmetric cryptography alone. That is not a gap in our coverage — it is a genuine limitation." 下一讲 L7 公钥密码 就是答案。

课后作业 4 正是为这一讲热身："Two people who have never met want to agree a shared secret key while an attacker watches every message they exchange. Sketch how you think this could possibly work, or argue that it cannot. Do not look it up." 课件强调这题没有错误答案，先自己想再看下一讲。

一种思路（下一讲的内容）

可以做到，靠"单向"的运算：容易算、却很难倒推。双方各自选一个秘密数，只公开一个由它算出的值，再各自把"自己的秘密"和"对方公开的值"组合，得到同一个结果；窃听者看到两个公开值，却算不出这个结果。Diffie–Hellman 密钥交换就是这样：公开一个大素数 q 和它的一个本原根 α；Alice 选私钥 XA、发出公钥 YA = αXA mod q，Bob 选私钥 XB、发出 YB = αXB mod q；双方都能算出 K = αXAXB mod q（Alice 算 YXAB，Bob 算 YXBA），而窃听者要从 YA 求出 XA（离散对数问题），没有已知的快速算法。

题面说攻击者"watches"，只是看。若攻击者能改消息、冒充双方（中间人），单靠这个方案就不够了，还需要认证，这又通向签名与证书。详见 L7 公钥密码、L8 数字签名、证书与 PKI。

11收尾：六条规则与综合题

11.1六条规则

课件的总结规则（括号里是本笔记的出处）：

  1. Never use ECB——多于一个随机分组的数据都不用；加密必须随机化（2.4）。
  2. Use authenticated encryption——默认 GCM；选不带认证的模式要说得出理由（8.1）。
  3. Never reuse a nonce under one key——在 CTR 或 GCM 里这是致命的（4.2、7.3）。
  4. Use the operating system's generator——不用语言的普通 random 函数，不拿时钟当种子（9.3）。
  5. Encryption is not integrity——消息可能被改，就要 MAC 或认证加密（第 5 节）。
  6. Manage the keys——层级、寿命、轮换，绝不进版本库；"This is where systems actually fail."（第 10 节）
勘误课件第 27 页：规则 3 对 CTR 说过了头

课件规则 3 的原话："In CTR or GCM this destroys confidentiality and integrity together."

误：CTR 重用 nonce 会同时毁掉机密性和完整性。

正：CTR 本来就没有完整性，重用 nonce 毁掉的是它的机密性；"两样一起毁"只对 GCM 成立——机密性因密钥流重复而丢，完整性因 H 和掩码被解出而丢（7.3）。

11.2课后作业 3：评估一个设计

题面："A team encrypts customer records with AES-256 in CBC mode, using a fixed IV of all zeros 'so decryption is simpler', and stores the key in the application config file. List every problem you can see, in order of severity."

这道题综合全讲，正是"评估一个系统"的题型。

解答（按严重程度排序）
  1. 密钥放在应用的配置文件里（最严重）。配置文件会被复制到测试环境、未加密备份，能读部署目录的人都能读（10.3）；拿到它就能解开全部记录、任意伪造，AES-256 毫无意义。改法：密钥放进 KMS 或 HSM，用 KEK 包装数据密钥（10.1）。
  2. 没有完整性。 CBC 不发现篡改（5.1）：记录里的位可被有控制地翻转、块可被重排；系统若对填充错误反应不同，还会遭受填充预言机攻击（7.1）。改法：用 GCM。
  3. IV 固定为全 0。 CBC 退化成确定性加密：开头若干块相同的记录，密文开头也相同，泄露"哪些记录开头一样"（同姓名、同地址前缀）；固定 IV 也是可预测的，允许选择明文猜测（3.2）。改法：每条记录随机 IV，与密文一起存。
  4. 一把密钥加密所有记录，没有层级、没有轮换。 一旦泄露，所有记录、所有时间段全部暴露（10.2 的理由 1、3、4）。
  5. "so decryption is simpler" 这个理由本身是错的。 IV 不保密，和密文一起存即可，每条记录多 16 字节，解密并不更复杂。
  6. AES-256 本身不是问题——这一点要明确写出来：密码是整个系统里最强的一环。

第 1、2 条的先后可以讨论：攻击者读不到配置文件、只能改数据库时，第 2 条更现实。写清排序依据即可。

本讲速记

  • 论点："A block cipher encrypts one block. The mode of operation decides what an attacker learns from everything else." 串块、随机数、防篡改、密钥管理都在密码之外，系统就坏在这里；ECB 企鹅里 AES 完美无缺。
  • 模式要回答四个问题：长消息、不满一块（填充）、同一消息发两次、出错与随机访问。
  • PKCS#7：差 k 字节补 k 个值为 k 的字节，已对齐也补一整块。100 字节 → 补 12 个 0C → 112 字节（课件"补 28 到 128"错）。
  • ECB：Ci = E(K, Pi)，确定性，相同明文块 → 相同密文块，可被重排删除；只有单个随机块可用。原则：加密必须随机化。
  • CBC：Ci = E(K, Pi ⊕ Ci−1)，C0 = IV；Pi = D(K, Ci) ⊕ Ci−1。IV 公开但不可预测；重复泄露相同前缀，可预测允许选择明文猜测。加密串行、解密可并行；坏一块 → 本块乱码 + 下一块同位翻转。
  • 活动 1：ECB 1001 0101 1001 1111；CBC 1100 1001 0000 1111；线性玩具密码下 Ci ⊕ Ci−1 就是 ECB 密文。
  • CTR：Ci = Pi ⊕ E(K, nonce ‖ i)，只用 E；nonce 只要不重复，重复即两次一密 C ⊕ C′ = P ⊕ P′。可并行、随机访问、无需填充、可预计算、无完整性。磁盘用 XTS（CTR 原地重写会重用 nonce）。
  • 篡改：CTR 中 C ⊕ Δ → P ⊕ Δ；CBC 改 Ci → Pi+1 ⊕ Δ、Pi 乱码，改 IV 精确改 P1；ECB 可重排。活动 4：A7 ⊕ 09 = AE，0100 → 9100。
  • MAC：三性质（找不到同标签消息；均匀，猜中约 2n−1 次；依赖每一部分）。给完整性 + 数据源认证，不给保密、不给不可否认。
  • 课件的"CMAC"实为 CBC-MAC，可被 M ‖ (M ⊕ T) 伪造。CMAC：L = E(K, 0128)，K1 = 2L，K2 = 2K1，最后一块满 ⊕K1、补位 ⊕K2。
  • 先加密后认证正确；先认证后加密导致填充预言机攻击。
  • GCM = CTR + GHASH：T = GHASHH(A, C) ⊕ E(K, J0)，H = E(K, 0128)；认证关联数据，一遍可并行，TLS 默认。nonce 重用丢机密性，并由 T1 ⊕ T2 = (C1 ⊕ C2)H2 解出 H、伪造标签。CCM = CTR + CBC-MAC（WPA2）。
  • 对照表最后一行（发现篡改）只有 GCM 是"是"。场景题：磁盘 → 随机访问；网银 → GCM；小取值的列 → 必须随机化；固件 → 完整性，最好用签名。
  • 随机数：TRNG 给 PRNG 播种，PRF 派生多个值。要求统计随机（均匀、独立）与不可预测（前向、后向），统计检验查不了不可预测性；LCG 三个输出就能解出参数。用操作系统的 CSPRNG。
  • 密钥层级：主密钥 → KEK → 会话密钥 → 数据密钥，越往上用得越少，即隔离原则。
  • 密钥过期四理由：限制损失、限制攻击材料（生日界 p ≈ 1 − e−q2/2n+1，q = 2n/2 时约 0.39）、密钥会慢慢泄露、轮换须事先演练。
  • 密钥泄露六途径：源代码、配置文件、日志与转储、环境变量、熵不足、过期不删。评估系统先看密钥。
