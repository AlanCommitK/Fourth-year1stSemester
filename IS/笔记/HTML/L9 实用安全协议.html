Lecture 9 — Security Protocols in Practice

实用安全协议

零件全都正确，拼出来的协议为什么还会坏？路线：敌手模型与四个问题 → 新鲜性与重放 → 反射攻击 → Needham–Schroeder 与 Denning–Sacco → Kerberos → TLS 1.3 → IPsec → 网络准入控制与 EAP → 无线安全 → 协议管不到的地方。

主线这一讲在做什么

前几讲造好了零件：认证加密、消息认证码、Diffie–Hellman 密钥交换、数字签名与证书。这一讲不引入新零件，只问：零件全都正确，拼出来的协议为什么还会坏？ 课件的回答是"A protocol is an arrangement, not a collection"。主线：

  1. 先立规矩：攻击者控制网络但破不了密码，协议要回答四个问题，其中最容易被忘的是新鲜性（第 1、2 节）；
  2. 用这套眼光读认证协议：挑战–应答与反射攻击、Needham–Schroeder 与 Denning–Sacco 攻击、它的后代 Kerberos（第 3–5 节）；
  3. 读 TLS 1.3：每个零件都学过，新的是把证书上的身份绑到这一次密钥交换上的那一步；IPsec 是同一套零件在网络层的排法（第 6、7 节）；
  4. 退到更前面一道关：设备连网之前，准入控制与无线安全决定放不放它进来（第 8、9 节）。

1协议是部件的排列

1.1安全协议是什么

课件的定义："A security protocol is a defined sequence of messages between parties, designed to achieve a stated goal in the presence of an adversary who controls the network." 安全协议（security protocol）就是一串事先定死的消息（谁发、发什么、收到后查什么），为一个明确目标服务，并且要在控制网络的敌手（adversary，即攻击者）在场时仍然达成目标。

课件称本讲是综合讲："Nothing here is a new primitive … What is new is how they are ASSEMBLED — and the fact that correct components can be assembled into a broken protocol." 原语（primitive）指分组密码、消息认证码、密钥交换、签名这些最基本的密码学部件。

1.2标准敌手模型

对"攻击者能做什么"的明确假设叫敌手模型（adversary model）。课件用的标准模型，正式名称是 Dolev–Yao 模型（Dolev–Yao model，1983）：

攻击者能做的攻击者做不到的
读到每一条消息破解底层密码学
随意删除、延迟、重排消息猜出密钥，伪造消息认证码或签名
注入自己构造的消息没有密钥就读出被正确加密的内容
把见过的任何消息在任何时候重发
同时开多个会话，用一个攻击另一个

故意假设密码学完美，是为了把问题分开："We assume the primitives are perfect and ask whether the protocol is still secure. If it is not, the flaw is in the arrangement." 本讲每个攻击都属于这一类：没有密钥被猜出，没有算法被破解。

1.3每个协议都要回答的四个问题

问题属性
Who am I talking to?认证（authentication）：对方确实是他声称的人
Is this message fresh?新鲜性（freshness）：消息是此刻为这次通信产生的，不是录下来的旧消息
Has it been altered?完整性（integrity）：途中没被改
Can anyone else read it?机密性（confidentiality）：只有预定的接收方能读

完整性和机密性来自 CIA 三要素。课件说最容易被忘的是新鲜性："Freshness is a property of a message IN TIME — and no amount of encryption tells you whether what you are reading was sent just now or captured last year." 前三个属性看一条消息本身就能检查，新鲜性要看消息和时间的关系（第 2 节）。

长期密钥（long-term key）用几个月到几年，如用户与服务器预先共享的密钥、证书对应的私钥，泄露影响大，所以要少用；会话密钥（session key）为一次通信临时生成、用完即丢，泄露只赔掉这一次。本讲多数协议的目的，就是用长期密钥安全地建立一把新的会话密钥。

读每条消息问四件事，这也是答题的标准写法：谁发给谁；发了什么；用什么密钥保护（谁能读、谁能造）；防什么攻击（删掉这条或某个字段，攻击者能干成什么）。攻击者统一叫 Darth，与教材和 L1 一致。

2新鲜性与重放攻击

2.1重放：不需要任何密码分析的攻击

重放攻击（replay attack）：截获一条合法的、正确加密、正确认证的消息，过后原样再发一次。"Every check passes, because the message is genuine. It is simply not current."

消息 ① 是 Alice 发给服务器的 "Alice", MAC(K, "transfer £100 to Bob")，K 是两者共享的密钥，服务器验证通过就转账。第二天 Darth 把同一串字节发一遍，MAC 依然有效——它不是伪造的，是抄的。服务器分不出两条，再转 £100，Darth 想发几次就发几次。

课件列的四类场景重放后果
支付指令每重放一次就再转一次钱
认证交换录下一次登录应答，以后拿来冒充用户，不需要口令
门禁与车辆遥控录下的开锁信号能再开门。滚动码（rolling code：每按一次发一个新码，接收端只认没用过的码）就是防这个的
会话建立重放旧的密钥协商消息，迫使对方重用一把攻击者已知的旧密钥（4.2 的伏笔）

重放是主动攻击（active attack）：攻击者往网络里发东西、改变系统行为，而不只是旁听。按 L1 5.2，主动攻击有冒充、重放、篡改、拒绝服务四类，受威胁的是完整性和可用性，冒充首先破坏真实性。重放常和冒充连用：录下别人的认证过程再重放，就是在冒充那个人——这正是模拟卷 Q1(c) 参考答案的例子。

2.2加密和 MAC 为什么挡不住重放

"Both are properties of the message content, and the content is unchanged — that is the whole point of a replay." 加密保证没人读得懂，重放不需要读懂；MAC 保证内容没被改，重放一个字节都没改。要挡住重放，消息里必须有每次都不同、接收方又能检查的东西："a nonce it issued, a timestamp it can bound, or a counter it is tracking"。

2.3三种新鲜性机制与怎样选

  • nonce：验证方先生成一个新随机值发过去，要求回应里包含它。回应带着它，就一定是收到之后才做出来的。
  • 时间戳：发送方写入当前时间，接收方拒收超出可接受窗口（window，如"与本地时钟差不过 5 分钟"）的消息。
  • 序列号（sequence number）：双方给消息计数，见过的或顺序不对的编号拒收。
nonce时间戳序列号
好处不需要共享时钟；不可预测，没法预先算好应答不多一个往返，单条消息就能用便宜；还能发现删除和重排
代价多一个往返（round trip：消息发过去、等回复回来的一个来回）要时钟同步，这本身是基础设施问题和攻击面；接受窗口就是重放窗口双方整个会话都要保存状态，状态不跨会话
适合的信道双向、能多付一个往返、不信任时钟（TLS，即第 6 节的传输层安全协议）消息必须单独成立、有同步时钟（第 5 节 Kerberos 认证系统的票据）已建立的会话内部，或单向多消息

课件口诀（结尾七条之三）："nonce if you can challenge, timestamp if you have clocks, counter otherwise."

表里的攻击面（attack surface）见 L1 6.2：时钟同步服务也成了攻击者够得着的部件。"窗口就是重放窗口"指：接受 5 分钟以内的消息，那么 5 分钟里截获的消息照样能重放，而且能重放多次。要关窗，接收方还得记住窗口内见过的消息、拒收重复的，这种记录叫重放缓存（replay cache）；时间戳让缓存只需保存 5 分钟。

易错nonce 的本义只要求不重复

课件把"Unpredictable, so it cannot be pre-computed"写成 nonce 的一般优点。nonce 的定义只要求同一把密钥下不重复（L6 对称密码的安全使用 讲 CTR 计数器模式时说过）；要求攻击者猜不到的只是挑战–应答里的挑战，否则攻击者可以抢先冒充验证方，向合法用户索取未来挑战的应答。L6 讲 GCM（带认证的计数器模式）时也说，它的 IV（初始化向量）可以确定性生成（TLS 1.3 就是），也可以随机生成。

课件此处举序列号的例子是"the CTR-mode counter from Lecture 5 doing double duty"。若把它理解成 CTR 计数器块里的分组计数，那是一条消息内部的编号；讲者的意思应是"每条消息的 nonce 用计数器生成，顺带当序列号用"，TLS 1.3 的记录序号就是这样（6.6）。

2.4序列号的滑动窗口

单向、多消息、会乱序到达的信道（传感器读数、走不同路径的 IP 包），不能要求编号严格加 1，否则一个迟到的包会让后面的全被拒。滑动窗口（sliding window）：接收方记住见过的最大编号 top，以及最近 W 个编号里哪些已收过。收到编号 s：

情况处理
s > top接受，令 top := s，窗口右移
top − W < s ≤ top，没见过接受（乱序但新）
top − W < s ≤ top，见过重放，拒收
s ≤ top − W太旧，拒收；也可能是迟到太久的合法包，这是代价

例：W = 8，依次到达 1, 2, 4, 3, 9, 5, 9, 1, 12, 4, 6，被拒的是第二个 9（重放）、9 之后的 1 和 12 之后的 4（太旧），其余接受。第 7 节的 IPsec（网络层的安全协议）就这么做，其 ESP 标准 RFC 4303 规定窗口至少 32、默认 64（7.2）。课件说这就是活动 1 协议 C 该选的机制。

滑动窗口重放检测

接收方只记两样东西：见过的最大编号 top，以及窗口里哪些编号收过。改窗口大小或到达序列，点任意一格看那一刻的窗口（实心 = 收过，框线 = 当前这个编号）。

2.5课堂活动 1：四个协议的重放缺陷

题目（第 8 页）：各判断能否被重放；能的话加 nonce、时间戳还是序列号，为什么。

  • A 门锁：遥控器发 E(K, "unlock")，解密正确就开门。单向，无回传信道。
  • B 登录：服务器发随机值 R，客户端回 MAC(K, R)。双向，无共享时钟。
  • C 传感器：每分钟发 "sensor7", temp, MAC(K, temp)，可能乱序到达。单向，消息很多。
  • D 支付接口："pay £100 to Bob", timestamp, MAC(K, message ‖ timestamp)，服务器接受五分钟以内的请求。单向，时钟已同步。追问：D 够不够？攻击者还能做什么？
课堂活动 1 解答
会被重放吗攻击者能做什么加什么，为什么
A 门锁会录下一次密文原样重发就能开门，密文每次都一样序列号（滚动码）。无回传信道，锁没法先发挑战；遥控器的时钟成本高、会漂移；计数器只要各存一个整数
B 登录不会被简单重放（R 真随机、不复用）旧应答只回答旧的 R。剩下的不是重放问题：只有单向认证；挡不住实时中继已经用了 nonce，正是双向、无时钟时的选择
C 传感器会重放旧读数，如着火时重放"温度正常"；而且 MAC 不覆盖 "sensor7"，别的传感器的读数可被改标成它序列号加滑动窗口（2.4），MAC 覆盖身份和编号：MAC(K, "sensor7" ‖ seq ‖ temp)
D 支付五分钟内会截获后五分钟内可原样重发任意多次，每次都付 £100加唯一请求编号与服务器端重放缓存：时间戳让缓存只存五分钟，缓存把窗口关上；或改用每客户端递增的序列号

D 说明时间戳只给重放划了范围，没有关掉它（结尾七条之五）。

课后作业 Task 1 解答：用滚动码修复门锁
  1. 遥控器 → 锁：IDfob, c, MAC(K, "unlock" ‖ IDfob ‖ c)，发出后 c 加 1，写入断电不丢的存储。
  2. 锁检查 clast < c ≤ clast+W 且 MAC 正确 → 开锁，令 clast := c。

遥控器存 K 和 c；锁存每个遥控器的 K、clast 和前瞻窗口 W（如 256）。失步（在锁收不到的地方误按）时：落差在 W 内，锁直接跳到新值，中间的码作废；超出 W，进入重同步，如要求连续两个相邻的有效码，或重新配对。滚动码只防重放用过的码，挡不住"先干扰并截留一个没用过的码、日后再用"（RollJam 类攻击）；有回传信道时应改用挑战–应答。

3挑战–应答与反射攻击

3.1单向认证与直观的双向扩展

问题（第 10 页）："Alice must prove she holds a secret, without revealing it, over a channel an attacker is recording." 挑战–应答（challenge–response），双方共享 K：

  1. B → A: Nb —— 明文。Bob 每次新出一个 nonce，录下的旧应答"回答的是 Bob 再也不会问的问题"，所以防重放；
  2. A → B: MAC(K, Nb) —— 没有 K 算不出，Bob 由此知道对方此刻持有 K；K 本身从不上网。

这是单向认证（one-way authentication）："Bob now knows Alice is present. Alice knows nothing about Bob." 直观的双向认证（mutual authentication）是让 Alice 也出一道题：

  1. B → A: Nb
  2. A → B: MAC(K, Nb), Na
  3. B → A: MAC(K, Na)

每条消息都正确，问题出在两个方向用了完全相同的构造 MAC(K, 挑战)。

3.2反射攻击：同时开两个会话

反射攻击（reflection attack）：把对方发出的挑战，在另一个会话里原样"反射"回给对方，让对方替你算出应答。按课件画出的角色（Bob 先出挑战），Darth 冒充 Bob：

会话 1 里 Darth 随便发一个 X，Alice 回 MAC(K, X) 和挑战 Na；Darth 另开会话 2，把 Na 当挑战发给 Alice，Alice 回 MAC(K, Na)；Darth 拿它交回会话 1，Alice 认定对方是 Bob。课件："every message is correctly formed and every MAC verifies … they use the protocol against itself by running two sessions at once."

勘误课件的文字版攻击 Bob，需要一个没写出的前提

课件说攻击者"ask Bob to answer the very challenge they were asked — then relay his answer back"。按图上的顺序 Bob 只在第 3 条回答挑战、而且要先验证第 2 条，所以这只有在 Bob 在别的会话里也当应答方（角色对称、谁都能发起）时才成立。只用图上的角色，能直接成立的是上面攻击 Alice 的版本；修复相同。

3.3修复：让两个方向不一样

"make the two directions different — include the sender's identity, or use separate keys."

  • 把身份写进 MAC：Alice 回 MAC(K, Nb ‖ "Alice")，Bob 回 MAC(K, Na ‖ "Bob")。会话 2 里 Alice 算出的带 "Alice"，会话 1 要的带 "Bob"，反射来的值对不上。
  • 两个方向用不同密钥 KAB ≠ KBA：Alice 算出的东西永远不会被她自己接受。

TLS 1.3 两样都用：两个方向的签名带不同的上下文串，流量密钥也分方向。背后的原则是：消息里写明谁发的、发给谁、是哪一步，不让接收方从上下文推断。

反射攻击，修与不修

MAC 用 HMAC-SHA256 取前 8 位十六进制（演示用）。三种协议：原样的双向挑战–应答、把发送者身份写进 MAC、两个方向用不同密钥。看 Darth 反射回来的值能不能被 Alice 接受。

4Needham–Schroeder 对称密钥协议

4.1五条消息逐条读

挑战–应答假设双方已有共享密钥。1000 个用户两两共享要 1000 × 999/2 = 499 500 把；改为每人只和一个可信的密钥分发中心（key distribution centre，KDC）共享一把，只要 1000 把，两人要通信时由 KDC 现场生成会话密钥。Needham–Schroeder 对称密钥协议（1978）就做这件事，课件说它是 Kerberos 的祖先。Ka、Kb 是 Alice、Bob 各自与 KDC 的长期密钥，Ks 是新会话密钥，f 是对 nonce 的某个公开变换（如 N2+1）。

  • ① A → KDC：IDA, IDB, N1，明文。N1 由 Alice 记住，回复里出现同一个 N1，才说明回复针对这次请求。
  • ② KDC → A：E(Ka, [Ks, IDB, N1, E(Kb, [Ks, IDA])])。外层 Ka：只有 Alice 能拿到 Ks，也证明消息来自 KDC。N1 防攻击者重放旧的 ②、塞给 Alice 旧密钥。IDB 防攻击者在 ① 里把 IDB 换成自己——那样 KDC 发的是"Alice 与 Darth"的密钥。内层 E(Kb, …) 是封给 Bob 的票，Alice 读不了也改不了。
  • ③ A → B：E(Kb, [Ks, IDA])。只有 Bob 能解开，知道这把钥匙用于和 Alice 通信、确实出自 KDC。但里面没有任何 Bob 能检验新鲜性的东西：能确定"KDC 某时发的"，确定不了"这一次发的"。
  • ④ B → A：E(Ks, N2)，Bob 出挑战。
  • ⑤ A → B：E(Ks, f(N2))。只有持有 Ks 的人算得出；用 f 变换，是因为原样送回 E(Ks, N2) 的话，任何人把 ④ 弹回去就能通过。
勘误课件第 11 页的四处说法不准
  • "N₂ assures Bob that Alice is present now"：N2 只证明此刻对面有人持有 Ks，证明不了是 Alice，更证明不了 Ks 是新的。这是给活动 2 埋的伏笔，背下来会答错。
  • "Every message is encrypted under a key only its intended reader holds"：① 是明文。
  • "widely deployed"：广泛部署的是后代 Kerberos。
  • "believed correct for seventeen years"：见 4.4。

4.2Denning–Sacco 攻击

活动 2 的情境（第 12 页）：Darth "has somehow recovered an OLD session key Kₛ from a session that finished long ago"，还录下了那次的 ③；长期密钥仍保密，KDC 诚实，密码学没被破。会话密钥用得多、存放的地方多（内存、日志），比长期密钥容易泄露，这个假设并不苛刻。

课堂活动 2 规范答法

(a) Bob 收到重放的消息 3 会怎样？ 用 Kb 解开，得到 Ks 与 IDA，认为 KDC 为他和 Alice 发了会话密钥，于是发出消息 4。因为消息 3 含会话密钥和身份，却不含任何证明它是新的东西：既无时间戳，也无 Bob 自己的 nonce。

(b) Darth 能完成 4、5 吗？ 能。两条只要求持有 Ks，Darth 正好持有旧 Ks：解出 N2′，算 f(N2′) 再加密回去。N2 只证明有人知道 Ks。

(c) Bob 相信什么、实际是什么？ Bob 相信刚和 Alice 建立了一把只有两人知道的新密钥、Alice 此刻在线；实际上密钥是旧的且已泄露，对方是 Darth，此后 Bob 用 Ks 加密的一切 Darth 都能读、也能冒充 Alice 回复。

(d) 缺什么、怎么修？ 缺新鲜性（消息 3 对 Bob 的新鲜性）。修复：让 Bob 的票里带上他能检验新鲜性的东西——KDC 写入的时间戳（4.3），或者 Bob 事先给出、经 KDC 封进票里的一个值。

失败全在排法：消息 ② 对 Alice 有新鲜性保证（N1），消息 ③ 对 Bob 没有。

4.3修复：把时间戳封进票里

Denning–Sacco 的修复（Stallings 第 8 版 §16.2），KDC 在两份密文里都放进时间戳 T：

  1. A → KDC: IDA ‖ IDB
  2. KDC → A: E(Ka, [Ks ‖ IDB ‖ T ‖ E(Kb, [Ks ‖ IDA ‖ T])])
  3. A → B: E(Kb, [Ks ‖ IDA ‖ T])
  4. B → A: E(Ks, N2)
  5. A → B: E(Ks, f(N2))

（教材在第 4、5 条把 Bob 的挑战写作 N1，这里保留原协议的名字 N2。原协议 ① 的 N1 被拿掉了，Alice 的新鲜性改由 T 提供。）

要点是 T 在 Kb 封装的票里面：放在外面攻击者可以改成当前时间；放在里面他没有 Kb 改不了，旧票带着旧时间。Alice 和 Bob 各自检查

|Clock−T| < Δt1+Δt2

Clock 是本地时钟，Δt1 是 KDC 时钟与本地时钟的正常偏差，Δt2 是网络时延：消息上的时间与现在相差不超过"钟差加路上的时间"才算新。例：Δt1 = 30 s、Δt2 = 5 s，容差 35 s，几年前的旧票必然被拒。代价是各方要时钟同步。

另一种修法不靠全网时钟（Neuman–Stubblebine 1993）：Bob 先把自己给出的一个值 Tb 用 Kb 封好交给 KDC，KDC 解开后把 Tb 抄进新票 E(Kb, [IDA ‖ Ks ‖ Tb])。Bob 在票里看到自己刚给出的 Tb，就知道票和其中的 Ks 是这之后才做出来的；Tb 只由 Bob 自己的时钟检查。协议里 Alice 另用 Ks 加密 Bob 的 nonce 交回，那只是密钥确认，挡不住持有旧 Ks 的人——挡住旧票的是 Tb。

4.4十七年说的是公钥版

勘误"seventeen years" 是另一个协议的故事

课件四处（第 9、11、12、26 页）说 Needham–Schroeder 的缺陷十七年才被发现，可第 11 页自己写着 "Published in 1978" 和 "In 1981 Denning and Sacco found a flaw"：对称版只有 3 年。17 年属于同一篇 1978 年论文里的公钥版：1995 年 Lowe 用模型检测（model checking：让程序穷举协议所有可能的消息交错、自动找攻击）发现了它的中间人攻击，1978 + 17 = 1995。考试若问年数，写清版本。

Needham–Schroeder 公钥版与 Lowe 攻击（课件外）

核心三条：A → B: E(PKB, [Na, IDA])；B → A: E(PKA, [Na, Nb])；A → B: E(PKB, Nb)，E(PKB, · ) 是用 Bob 公钥加密（L7 公钥密码）。Lowe 攻击：合法用户 Darth 在 Alice 主动找他时，把她的第一条消息重新加密给 Bob、把 Bob 的回复原样转给 Alice，骗 Alice 替他解出 Nb，于是 Bob 以为在和 Alice 通信。修复：第二条加 IDB。和 3.3 同一原则：消息里写明是谁发的。

课件由此得出的教训（七条之四）："Suspect any protocol whose security rests on careful reading."

5Kerberos

5.1两处改动与两个新概念

Kerberos 是 MIT（Massachusetts Institute of Technology，麻省理工学院）开发的认证系统，今天用在 Windows 域（由中央服务器统一管理账号的一组 Windows 计算机）和许多 Unix 网络里。课件："It takes the Needham–Schroeder structure, adds timestamps, and separates the KDC into two services." 两个服务是：

  • 认证服务器（authentication server，AS）：登录时核验用户，发给他一张票据授予票据（ticket-granting ticket，TGT）；
  • 票据授予服务器（ticket-granting server，TGS）：凭 TGT 签发访问具体服务的服务票据（service ticket）。

票据（ticket）是 Needham–Schroeder 里"封给 Bob 的包"的升级版：用某个服务器的长期密钥加密，装着会话密钥、用户身份和有效期，用户只能转交。认证符（authenticator）是出示票据时附带的一小段数据，用票里的会话密钥加密，含用户身份和当前时间戳，证明出示者此刻持有那把会话密钥。

5.2六条消息

课件第 13 页只画了简化的前四条，没写密钥。下面是 Stallings 的第 4 版完整六条：

第 5 版（RFC 4120）把三对交换叫 AS、TGS、AP 交换，（AP 指 application，即应用服务器），并在前两个请求里另加了 nonce，所以并非只靠时间戳。

5.3为什么把 KDC 拆成两个

"The Authentication Server sees the password-derived key once, at login. After that the client uses the ticket-granting ticket, so the long-term key is not needed again all day." 由口令派生的 Kc 只在 ② 用一次，之后凭 TGT 换各种服务票，不必再输口令，长期密钥暴露的时间也缩短了。这就是单点登录（single sign-on，SSO），也是 L6 对称密码的安全使用 的密钥层级（用少数高价值长期密钥保护一批短命的低层密钥）用在认证上。

课件"What Kerberos gets right"另两条：服务离线验票，V 用自己的 Kv 就能验，不必每次问 KDC；票会过期，被偷的票有用的时间很短。

5.4时间戳到底挡住了什么

易错挡住 Denning–Sacco 的是票里的时间戳，不是认证符里的

课件说"Timestamps in the authenticator close the Denning–Sacco replay"。Denning–Sacco 的攻击者持有旧会话密钥：拿到旧 Kc, v 和旧 Ticketv 的 Darth 自己就能造一个带当前时间的认证符（第 4 版还要冒用 ADC 那个地址）。挡住他的是票里用 Kv 封装的 TS4 和 Lifetime4，他改不了，过期的票被拒——与 4.3 把 T 封进票里同理。

两种时间戳各管一种攻击：票里的签发时间和有效期限制旧会话密钥能用多久；认证符里的时间戳加服务器的重放缓存，对付不知道会话密钥的人重放截获的认证符。即便如此，旧密钥在票的有效期内（Windows 域默认 10 小时）仍可用，只是限了时：七条之五 "A timestamp bounds a replay window; it does not close it."

5.5Kerberos 的假设与代价

  1. 时钟必须同步："Skew beyond the window breaks logins; a manipulated clock widens the replay window." RFC 4120 的典型容差是 5 分钟。
  2. KDC 是全盘失败的单点："compromise it and every identity in the domain is forged."例如 TGS 的长期密钥被偷，就能给任何用户伪造 TGT（俗称"黄金票据"）。
  3. 长期密钥由口令派生，弱口令可离线猜：拿到一条 ②，就能在自己电脑上逐个猜口令、算 Kc、试解密，KDC 毫无察觉。这叫离线字典攻击（offline dictionary attack：拿着截获的数据，在本地用一本常见口令"字典"逐个试）。
勘误"The password never crosses the network, in any form" 说过头了

口令本身不上网，但口令派生密钥加密的数据会上网：② 就是 E(Kc, …)；第 5 版的预认证（pre-authentication：客户端先发一个 E(Kc, 时间戳) 证明自己知道口令，AS 才回 ②）也是。所以同一页才说"weak passwords remain guessable offline"。

课后 Task 2 问的就是第 1 条代价背后的取舍。

课后作业 Task 2 解答：依赖时间戳的两个代价
  1. 时钟不同步，合法登录失败（偏差超过典型的 5 分钟）。应对：域内分层时间同步，成员机跟随域控制器，监控漂移；时间源本身也要认证，防止被篡改来撑大窗口。
  2. 窗口就是重放窗口，窗口内截获的认证符可能被重用。应对：服务器维护重放缓存（RFC 4120 要求，除非应用自己另有抗重放手段），配合短票据寿命，必要时做双向认证（⑥）。

6TLS 1.3

TLS（Transport Layer Security，传输层安全协议）是浏览器地址栏挂锁背后的协议；网址以 https 开头时，HTTPS（HTTP Secure，在 TLS 连接里跑网页协议 HTTP，HyperText Transfer Protocol）底下就是它。本节讲 2018 年定稿的 1.3 版。

6.1起点：证书原样转发的中间人

上一讲的课后作业问：证书只证明服务器持有某把私钥，浏览器怎样从"这真是 bank.com"走到"我们共享这次会话的密钥"？课件第 2 页说几乎人人都答出了三步：

  1. 认证服务器：校验证书链与名字（L8 数字签名、证书与 PKI 的检查清单）；
  2. 协商新秘密：跑一次 Diffie–Hellman 密钥交换（DH，L7 公钥密码）；
  3. 切换到对称密码：用这个秘密驱动 AES-GCM（L6 对称密码的安全使用）加密数据，因为公钥运算太慢。

几乎人人漏掉的第四步："Binding the two halves together." 服务器必须证明，它跑的这次密钥交换和证书属于同一个主人，否则 L7 的中间人攻击就会回来。L7 用小数字完整演示过 DH 的中间人；TLS 场景多出的只有一点：Darth 把 bank 的真证书原样转发。沿用 L7 的记号（Y = αX mod q，Darth 自选 XD1、XD2）：

  1. 客户端 → Darth：YA；
  2. Darth → bank：YD1；
  3. bank → Darth：YB 与 bank 的证书；
  4. Darth → 客户端：bank 的证书（原样）与 YD2。

证书的链、名字、有效期全对，客户端"认证了 bank"，密钥却和 Darth 共享，bank 那边同样。证书只证明 bank 持有私钥，没有任何东西证明 YD2 是 bank 发的。修复："the server SIGNS the key exchange values with the private key its certificate certifies"：Darth 没有 bank 的私钥，伪造不出覆盖 YD2 的签名。TLS 1.3 里这一步叫 CertificateVerify（6.4）。

6.3握手：课件版与完整版

为什么只要一个往返。 课件："The client sends its DH share in the first message, guessing which group the server will pick." 组（group）指 DH 运算所在的数学结构，如某条椭圆曲线，双方必须用同一个。客户端直接猜一个组并附上 DH 公开值，猜对时服务器在第二条回自己的值，双方立刻算出密钥，之后一切加密。TLS 1.2 的客户端要等服务器选好参数、发来 DH 值后才发自己的，所以要两个往返。猜错时服务器回 HelloRetryRequest（重试请求，指明它要的组），退化为两个往返。课件说"keys are ready after message 2"，此时就绪的是只加密握手后半段的握手流量密钥（handshake traffic secret）；加密应用数据的应用流量密钥（application traffic secret）要到服务器 Finished 之后才派生。

RFC 8446 §2 的完整握手：

图里的几个概念：transcript（握手记录）是到目前为止收发过的全部握手消息按序拼在一起，对它做的哈希相当于整段对话的指纹，任何一条被改一个字节都会变；HMAC（hash-based MAC）是用哈希函数构造的消息认证码；HKDF（HMAC-based key derivation function，基于 HMAC 的密钥派生函数）由一个共享秘密加一段标签派生出新密钥，标签不同密钥就互不相关，TLS 用它派生出各方向、各阶段的全部密钥。

和课件版比，完整版多出五样：

  1. 双方的 random（各 32 字节随机数）——它就是第 2 节说"TLS uses them"的 nonce，保证每次握手的 transcript 与密钥都不同，旧握手重放没用；
  2. ServerHello 里的 supported_versions，版本靠它协商，6.4 的降级防护要用到；
  3. EncryptedExtensions（服务器装其余协商结果的消息）才是第一条加密消息；
  4. 要求客户端证书时的 CertificateRequest，以及客户端的 Certificate 与 CertificateVerify；
  5. 两个方向各用一把密钥，与 3.3 对付反射的做法一致。

勘误"TLS 1.3 contains no primitive you have not met" 只在概念上成立

七条之六这样说。MAC、密钥派生、认证加密的概念都见过，但 Finished 用的 HMAC、整个密钥派生用的 HKDF，本课程都没讲过（L6 只讲了 CMAC）。第 14 页"Everything from Lectures 2 to 7 appears inside it"也是修辞：古典密码和 DES 在 TLS 1.3 里不出现。答活动 3 的 e 写"MAC（L6）"即可。

6.4CertificateVerify 绑定身份，Finished 确认密钥

课件右下框："Message 4 is the binding … That is what ties the identity in the certificate to the key exchange actually performed — and it is what defeats the man in the middle."

为什么是它。 服务器用证书私钥对到 Certificate 为止的 transcript 签名，签名数据前面还带一个上下文串 "TLS 1.3, server CertificateVerify"。这段 transcript 里有客户端实际收到的 DH 值。回到 6.1：真 bank 签的是它看到的 transcript（里面是 YD1，random 也对不上），Darth 没有私钥，造不出覆盖 YD2 的签名，客户端验签失败。

证书与签名的分工。 证书说"这把公钥属于 bank.com"，由 CA（certificate authority，证书颁发机构）担保；CertificateVerify 说"这次握手确实是这把私钥的主人做的"。这就是 L8 数字签名、证书与 PKI 八项检查的最后一项"持有私钥"：证书是公开的，谁都能原样复制，前七项检查全过；只有当场用私钥签名，才证明对面是证书的主人。

Finished 替代不了它。 Finished 是用这次 DH 派生的密钥对 transcript 算的 HMAC，作用是密钥确认（key confirmation：证明对方算出了同样的密钥、看到了同样的握手）。在中间人攻击里 Darth 本人就是客户端这次 DH 的对端，算得出合法的 Finished。所以活动 3 的追问"删掉哪一条整个协议就垮"，答案是 CertificateVerify。

删掉哪一条，中间人就复活

沿用 L7 活动 4 的 DH 参数，Darth 自选 XD1、XD2（6.1 的四步）。选一种情形，看客户端的三项检查各自怎样。transcript 只示意三条消息，摘要与 Finished 用 SHA-256 / HMAC 现算。

勘误降级防护不只靠 Finished

课件第 16 页说"Messages 5 and 6 protect against downgrade: each side MACs the whole transcript"。降级攻击（downgrade attack）是篡改协商，让双方同意更弱的算法或旧版本。只靠 Finished 不够：它的密钥派生自这次协商出的 DH 秘密，若攻击者能把双方降到一个他破得了的弱组，就算得出 Finished。以证书认证的完整握手为例，TLS 1.3 的防护有四层：

  1. CertificateVerify 用长期私钥签名，覆盖 ClientHello 里的完整提议，被删改会被发现；
  2. Finished 再确认一遍 transcript；
  3. 服务器若被迫协商到旧版本，会在 ServerHello.random 末尾写一个固定的"降级哨兵"，支持 1.3 的客户端看到就中止（前提是被降到的旧版本连接用临时 DH；用 RSA 密钥传输时没有这层保护）；
  4. 弱选项被整个删除："You cannot be downgraded to something that no longer exists."

课件只说了最弱的第 2 层。

6.5前向保密

前向保密（forward secrecy）：长期私钥日后泄露，过去录下的会话仍解不开。

旧版 TLS 的 RSA 密钥传输（RSA key transport）没有前向保密：客户端生成一个秘密值，用服务器证书里的 RSA 公钥加密发过去，双方由它和两边的随机数算出会话密钥。录下握手的人日后不论靠入侵、法院命令还是等待（"by breach, by court order, or by patience"）拿到私钥，就能解出那个秘密值，随机数本来就是明文，过去所有会话都被解密。课件说加密的是"the session key"，准确地说是 48 字节的预主密钥（pre-master secret），会话密钥再由它派生（与 L7 一致）。

临时 DH（ephemeral Diffie–Hellman）有前向保密：DH 私有值每次握手新生成、用完即删；长期私钥只用来签名，从不参与算共享秘密。日后偷到私钥，能冒充服务器做将来的握手，却算不出过去的共享秘密。TLS 1.3 删掉了 RSA 传输。

勘误TLS 1.3 并不是每个会话都有前向保密

课件第 15 页说"every session now uses an ephemeral Diffie–Hellman exchange"，说过头了。TLS 1.3 支持会话恢复（session resumption）：完整握手后服务器发给客户端一张恢复票据，双方得到一个预共享密钥（pre-shared key，PSK），下次直接用它建立密钥、省掉证书和签名。若只用 PSK、不再做 DH（psk_ke 模式），就没有前向保密：谁日后拿到 PSK 或服务器加密票据的密钥，就能解开这些会话。RFC 8446 §1.2（RFC 9846 §1.3）的准确说法是"all public-key based key exchange mechanisms now provide forward secrecy"。

0-RTT：为省一个往返放弃新鲜性（课件外）

持有 PSK 的客户端可以在第一条消息里就附带应用数据，不等任何往返，叫 0-RTT（zero round-trip time）早期数据。这些数据发在服务器回复之前，里面不可能有服务器的新 nonce：录下来再发一次，服务器会再执行一次（RFC 8446 §8："TLS does not provide inherent replay protections for 0-RTT data"），若内容是"pay £100 to Bob"就是活动 1 的协议 D。它相对 PSK 也没有前向保密。所以只能放幂等（idempotent：执行一次与多次效果相同，如读网页）的请求，服务器还可让每张票据只用一次（又是重放缓存）。

6.6记录层：序列号身兼两职

握手后，应用数据切成一条条记录（record），每条用认证加密保护；GCM 的 nonce 在同一把密钥下重复，机密性和完整性一起崩溃（L6）。TLS 1.3 的做法：

nonce = IV ⊕ 64 位记录序号

IV（initialisation vector，初始化向量）在这里是与每一级流量密钥一起由 HKDF 派生的 12 字节值，同一把密钥下不变；记录序号在每把新密钥下从 0 开始、每条加 1，左补 0 到 12 字节再异或。序号递增，nonce 就不重复；序号不许回绕，实际上认证加密（AEAD，L6）的用量上限（AES-GCM 约 224.5 条满长记录）远早于 264 就逼着换密钥。

身兼两职：序号不在记录里传输，双方各自数。中间的记录被删、重排或重放，接收方算出的 nonce 对不上，认证标签校验失败，连接报错（截掉末尾几条靠的是关闭告警 close_notify）。一个计数器既保证 nonce 唯一，又检查新鲜性。

不传输的序号怎样发现删除、重排和重放

发送方按 0、1、2… 给记录编号，用 nonce = IV ⊕ 序号加密；编号本身不发出去。接收方自己数，用自己数出的序号算 nonce 去验标签（标签用 HMAC 演示）。

7IPsec 与 VPN

7.1在网络层保护每一个包

"TLS protects one connection between two applications. IPsec protects traffic at the network layer, so every packet between two points is covered regardless of which application sent it." IP（Internet Protocol，互联网协议）层负责把数据包从一台主机送到另一台，所有应用的数据最终都装在 IP 包里。IPsec（IP security）在这一层加密和认证每个包，应用程序不用改。典型用途是 VPN（virtual private network，虚拟专用网）：在公共互联网上搭一条加密隧道，让两个分支的内网（站点到站点），或出差员工和公司内网（远程接入），像接在同一个私有网络里。

课件底部："IPsec negotiates keys with Diffie–Hellman, authenticates with certificates or shared secrets, encrypts with AES, and protects against replay with sequence numbers in a sliding window … Different layer, different requirement, same toolbox."

协商密钥的 IKEv2（课件外）

课件没提协议名字：做这件事的是 IKEv2（Internet Key Exchange version 2，RFC 7296），最少两对消息。IKE_SA_INIT（明文）交换算法提议、DH 公开值和双方 nonce，由此派生出包括加密、完整性、认证在内的一组密钥；IKE_AUTH（在派生出的密钥保护下）交换身份和证书，AUTH 字段对"自己的第一条消息 ‖ 对方的 nonce ‖ 用认证密钥对自己身份算的 MAC"签名。签名把身份绑到这次 DH 上（相当于 CertificateVerify），MAC 过的身份把身份绑到这次派生的密钥上（相当于 Finished）。这种"签名绑身份、MAC 确认密钥"的结构叫 SIGMA，TLS 1.3 与 IKEv2 都属于它。

7.2AH 与 ESP

AH（Authentication Header，认证头）ESP（Encapsulating Security Payload，封装安全载荷）
提供完整性与来源认证，覆盖部分 IP 头加密，加完整性与认证
机密性完全没有有（加密可选，实际几乎总是开启）
现状很少用实际部署用的就是它

AH 少用，一是 ESP 本身也给完整性；二是 AH 保护 IP 头里的地址，一经过 NAT（network address translation，网络地址转换：家用路由器把内网地址换成公网地址）就因地址被改而校验失败。

ESP 头里有 SPI（security parameter index，安全参数索引），告诉接收方用哪个安全关联（security association，SA：两端之间单方向的一份约定，规定算法、密钥和当前序列号，一对通信每个方向一个）；还有每包加 1 的序列号，接收方用 2.4 的滑动窗口查重放。包尾的 ICV（integrity check value，完整性校验值）相当于 MAC。

7.3传输模式与隧道模式

  • 传输模式（transport mode）：只保护载荷，原 IP 头可见；用于主机到主机，网关只能用它保护自己收发的包。
  • 隧道模式（tunnel mode）：整个原始包连同 IP 头加密，再套一个新 IP 头。新 IP 头写两端网关地址，必须是明文，否则路由器没法转发。典型用于网关到网关（站点到站点 VPN），隐藏了内部地址。远程接入 VPN 是主机到网关，也用隧道模式，所以课件写的"Gateway to gateway"只是典型用法。

8网络准入控制

课件第 19 页："Before a device can use the network at all, something has to decide whether to let it on."

8.1NAC：既认证用户，也检查设备

网络准入控制（network access control，NAC）是管理谁、用什么设备能接入网络哪一部分的统称："NAC authenticates the user, and also evaluates the DEVICE — its patch level, its antimalware state, its configuration — before granting access." 对设备安全状况的检查叫姿态评估（posture assessment）。

两个目的缺一不可：认证回答"你是谁"，姿态评估回答"你安全到可以放进来吗"。"A legitimate user on an infected laptop is exactly the case NAC exists to catch — and no amount of cryptography addresses it." 口令和证书都对，任何认证协议都会放行，只有姿态评估能拦住。姿态是设备自己报告的，被攻破的设备可能撒谎，所以它不能单独依赖，网络分段是另一道防线。

8.2三个组件与 802.1X 的三个角色

IEEE 802.1X 是 IEEE（Institute of Electrical and Electronics Engineers，电气电子工程师学会）制定的基于端口的接入控制标准（同系列的 802.11 是 Wi-Fi）。课件说它的三个角色就是"the NAC triple again, at the link layer"：

NAC 组件802.1X 角色是什么
接入请求者（access requestor，AR）请求者（supplicant）想接入的设备：笔记本、手机、打印机、物联网设备
网络接入服务器（network access server，NAS）认证者（authenticator）执行点：控制端口的交换机或无线接入点，执行策略服务器的决定

802.1X 在链路层（link layer：同一局域网内相邻设备之间传数据帧的那一层，比 IP 低一层）设卡："Until a device authenticates, the switch port or wireless association carries nothing but authentication traffic. The device is physically connected and functionally outside the network." 设备连 IP 地址都拿不到。

VLAN 分配放进某个虚拟局域网（virtual LAN，VLAN：在同一套交换机上从逻辑上划出、彼此隔离的网段）：完全访问、访客或隔离
防火墙规则在执行点按设备放行或拒绝流量
DHCP 管理用分配 IP 地址的方式控制访问。DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）给新设备自动分配地址；单用很弱，攻击者可以手动给自己设一个地址

8.4EAP：是框架，不是认证方法

EAP（Extensible Authentication Protocol，可扩展认证协议，RFC 3748）"is NOT an authentication method. It is a generic transport for authentication exchanges — a container into which many different methods can be plugged." EAP 只规定信封：Request、Response、Success、Failure 四种报文怎么往返；里面用证书、口令还是 SIM 卡，由别的规范定义。认证者不需要懂里面的方法："It relays EAP messages between supplicant and authentication server and enforces the final verdict."

为什么这样设计：公司笔记本、访客手机、工厂传感器、带 SIM 卡的设备需要的凭证完全不同，EAP 只定义信封、让每个部署自己选方法，加新方法不用改任何交换机或接入点。课件的类比："the same design instinct as modes of operation in Lecture 5: separate the framework from the choice that varies."——和 L6 的工作模式一样，把框架与会变的选择分开。

9.1三代方案

方案年份构成课件评价

勘误WPA3 并没有取代四次握手

课件第 22 页说 WPA3 "Replaces the handshake with a password-authenticated key exchange"。WPA3 个人模式的 SAE 取代的是"由口令直接算出 PMK"这一步（9.4）；SAE 产出 PMK 之后，仍然照常跑同一个四次握手派生会话密钥。照课件去理解，会推出"KRACK 与 WPA3 无关"之类的错误结论——KRACK 打的是四次握手的实现，修复靠打补丁，与代际无关。

9.2WEP：好部件被用坏的标本

WEP 每个包的 RC4（流密码，用密钥流与明文异或）密钥 = 24 位 IV（初始化向量，每包一个，明文附在包头）拼上 40 或 104 位的共享密钥 K，全网共用同一把 K。

IV 太短，密钥流必然重复。 同一个 IV 意味着同一条密钥流，两段密文异或就消掉密钥流，剩下两段明文的异或——即 密钥重用（两次一密）。多快重复：沿用 L6 生日界的记号，q 个随机的 n 位值至少撞一次的概率

p ≈ 1 − e−q(q − 1)/2n + 1

（推导见 L6 对称密码的安全使用：逐个放入，用 1 − x ≈ e−x 把"一个都不撞"的连乘化成指数。）令 p = 1/2，取 q(q − 1) ≈ q2，得 q ≈ √2n + 1ln 2。n = 24 时约 4823 个包有一半把握撞上；按 11 Mb/s 标称速率、每包 1500 字节满载估算约 916.7 包/秒，约 5.3 秒。若 IV 从 0 顺序递增，单个发送方要用完整个空间才重复：224/916.7 ≈ 18 302 s，约 5.08 小时，这就是课件"repeats within hours"的来历。但多台设备共用 K、又各自上电从 0 计数时，小 IV 跨设备几乎立刻就撞。

IV 多快重复

按上面的近似式算「一半把握撞上」要多少个包、满载要多久，并和「顺序递增用完整个空间」比较。曲线是 p 随包数的变化。

勘误WEP 的失败不只是"IV 太短"，RC4 也谈不上"a sound cipher"

课件说"a protocol failing because of how a sound cipher was used — the IV was simply too short"，又说"Keys are recoverable in minutes with passive capture"。完整的失败链：

  1. IV 碰撞 → 密钥流重用，可解密流量，但不能恢复 K；
  2. 几分钟恢复 K 靠的是另一个弱点：每包密钥是"公开 IV 拼固定 K"，形成一批只差已知部分的相关密钥，RC4 用密钥初始化内部状态的那一步（密钥编排）有缺陷，FMS（2001）和 PTW（2007，约 4 万个包）攻击据此直接算出 K，与 IV 是否重复无关；
  3. 完整性校验用 CRC-32（循环冗余校验，一种不含密钥的检错码），它对异或是仿射的（线性再加一个常数），攻击者不用密钥就能精确改密文并同步修正校验值；
  4. 没有任何重放保护；
  5. 全网一把静态密钥，一人知道就等于所有人知道。

RC4 本身的密钥流也有偏差，IETF 已禁止 TLS 使用它。

9.3WPA2：四次握手与离线字典攻击

WPA2 基于 IEEE 802.11i-2004，数据加密用 AES-CCMP（Counter Mode with CBC-MAC Protocol，计数器模式加 CBC-MAC 协议）：AES 以 CTR 模式加密，CBC-MAC 管完整性，两者都在 L6 讲过。

密钥层级：

  • PMK（pairwise master key，成对主密钥）：客户端与接入点共有的顶层秘密。个人模式下 PMK = PBKDF2(口令, SSID, 4096 轮)：SSID（service set identifier）是网络名；PBKDF2（password-based key derivation function 2，基于口令的密钥派生函数）把口令和盐（salt：与口令一起输入的公开值，让同一口令在不同网络里算出不同结果，预先算好的口令表就用不上）反复做 4096 轮 HMAC，故意让每算一次都慢一点。口令不变，PMK 就永远不变。企业模式的 PMK 来自 802.1X/EAP。
  • PTK（pairwise transient key，成对临时密钥）：每次关联新算，PTK = PRF(PMK, 两端 MAC 地址, ANonce, SNonce)，PRF（pseudorandom function，伪随机函数）在这里是基于 HMAC 的密钥派生函数；MAC 地址（media access control address：网卡的硬件地址）与消息认证码只是缩写相同。PTK 切出 KCK（key confirmation key，密钥确认密钥，给握手消息算完整性码）、KEK（key encryption key，加密下发的组密钥）和 TK（temporal key，临时密钥，CCMP 加密数据用）。

握手在客户端 STA（station，站点）与 AP（access point，接入点）之间进行，握手消息上的认证码 802.11 标准叫 MIC（message integrity code，消息完整性码）：

  • ① AP → STA：ANonce，明文。AP 一侧的新鲜性：PMK 多年不变，PTK 也每次都新。
  • ② STA → AP：SNonce、能力列表、MIC。STA 一侧的新鲜性；MIC 用 KCK 算，证明 STA 知道 PMK（不知道 PMK 算不出 KCK）。
  • ③ AP → STA：ANonce、能力列表、加密的组密钥、MIC。证明 AP 也知道 PMK，双向认证完成；STA 把能力列表与 AP 广播里的对比，不一致说明有人想降级。
  • ④ STA → AP：确认、MIC。双方安装 TK。

离线字典攻击（课件"an attacker can capture it and mount an offline dictionary attack against a weak passphrase"）：录下 ① ②，就有了两个 nonce、两个 MAC 地址和 ② 的 MIC。对每个候选口令算 PMK → PTK → KCK → MIC，与录到的比，相同即猜中。全程不和网络交互，不会被察觉、不受限速，PBKDF2 的 4096 轮只是拖慢。有的 AP 在 ① 里还附带一个由 PMK 算出的标识 PMKID（PMK identifier），攻击者连客户端都不用等。

另外两个弱点：PTK 只由 PMK 与明文的 nonce、MAC 地址决定，个人模式下知道口令的人录到别人的握手就能解密别人的流量，没有前向保密。KRACK（key reinstallation attack，密钥重装攻击，2017）：攻击者截住客户端的 ④，AP 以为 ③ 丢了而重传，攻击者把重传的 ③ 转给客户端；有缺陷的客户端每收到一次 ③ 就把同一个 PTK 重装一次，同时把数据帧的包编号（即 CCMP 的 nonce）和接收重放计数器重置，同一把密钥下 nonce 重复，密钥流重复。这是第 2 节的新鲜性教训在无线协议里的真实案例，修复是补丁：装过的密钥不再重装。

9.4WPA3 与 SAE

WPA3 个人模式用 SAE（Simultaneous Authentication of Equals，对等实体同时认证，基于名为 Dragonfly 的密钥交换）取代"口令直接算 PMK"。SAE 是一种口令认证密钥交换（password-authenticated key exchange，PAKE）：用口令认证双方、同时协商出强密钥，被动截获的数据不足以检验任何口令猜测。

双方由口令算出一个"口令元素"，各选一个新的随机秘密与之结合成类似 DH 的值互换，再互相确认。交换的值掺着从不发送的随机秘密，旁观者拿一个候选口令没法验证；要验证只能亲自和网络跑一次交换："each guess requires a fresh interaction with the network, so guessing becomes detectable and rate-limited." PMK 来自这次新选的随机秘密，日后口令泄露也算不出过去的 PMK，这是前向保密。SAE 产出 PMK 之后，照常做四次握手。

"Offline dictionary attacks no longer work"是协议层面的结论：2019 年公布的 Dragonblood 攻击表明，早期实现由口令算口令元素时的耗时会随口令变化，可据此离线缩小口令范围；兼容老设备的过渡模式还能被降级回 WPA2。

10协议管不到的地方

10.1在防火墙后面就安全吗

课后 Task 3："A company deploys TLS 1.3 correctly on its public website, and runs its internal services over plain HTTP because "they are behind the firewall". Every laptop is on one flat network with valid domain credentials. Identify the assumption being made and explain why it fails."

课后作业 Task 3 解答

假设：网络边界就是信任边界，防火墙里面的人和设备都可信。

为什么不成立：扁平网里任何一台被入侵或心怀恶意的设备都能嗅探明文 HTTP，或伪造地址应答把自己插进别人的通信路径，拿到会话 cookie（网站用来记住登录状态的小段数据，拿到它就等于登录）和口令，这些流量根本不经过防火墙；域凭证只回答"你是谁"，不回答设备是否安全，也不限制它能访问多远（8.1）；外部网站的 TLS 只保护外部那一段。这就是 L1 6.1 的"边界是怎样消失的"。

应对：内部服务也上 TLS，网络分段，NAC 姿态评估——不因为在内网就默认信任的零信任（zero trust）思路。

10.2攻击者就在机器上

课后 Task 4（课件说它是下一讲的开场）："What if the attacker is already ON one of the machines — or is the person using it? List five things that could go wrong that no protocol we have studied would prevent." 本讲所有协议都在 标准模型下设计：攻击者在网络上，两端诚实。端点本身失陷，协议再完美也无能为力。

课后作业 Task 4 解答
  1. 恶意软件在加密前读明文、在输入时偷口令（"Malware on your laptop reads the plaintext first"）；
  2. 钓鱼与社会工程：用户亲手交出凭证，协议忠实地认证了攻击者；
  3. 内部人员滥用合法权限；
  4. 应用层漏洞：SQL 注入（SQL 是数据库查询语言；把数据库命令混进输入让服务器执行）、跨站脚本（把恶意脚本注入网页让别人的浏览器执行）、缓冲区溢出、权限提升——TLS 只保证字节完好送达，不管内容是否恶意；
  5. 软件供应链（从开发、依赖库到分发更新的整条链条）被投毒、勒索软件、本机私钥或票据被盗，以及拒绝服务。

这些是 L10 网络安全：威胁、攻击与防御 的主题。

11七条结论

课件第 26 页的"Seven things to leave with"：

  1. 协议是排列，不是部件的堆砌；部件全对，协议仍可能坏。（1.1、3.2）
  2. 新鲜性是独立的属性：加密说明没人读过，MAC 说明没人改过，都说不出消息何时发出。（2.2）
  3. 按信道选机制：能挑战用 nonce，有时钟用时间戳，否则用计数器。（2.3）
  4. 课件说 Needham–Schroeder 的缺陷十七年才被发现（对称版实为 3 年，17 年是公钥版）；安全性只靠仔细阅读的协议都值得怀疑。（4.4）
  5. 时间戳给重放划了窗口，没有关上它；Kerberos 天生带着这个弱点。（5.4）
  6. TLS 1.3 里没有没见过的原语（就概念而言）；CertificateVerify 是把身份绑到密钥交换上的那条消息。（6.4）
  7. 认证回答"谁"，不回答设备是否安全，也不限制一次失陷能波及多远。（8.1、9.6）

本讲速记

  • 协议 = 敌手在场时的消息排列；Dolev–Yao：网络归攻击者，密码完美。四问：认证、新鲜性、完整性、机密性。
  • 重放：原样重发合法消息，加密和 MAC 都挡不住。nonce（能挑战）/ 时间戳（有时钟，窗口即重放窗口，靠重放缓存关窗）/ 序列号（会话内，乱序用滑动窗口）。
  • 反射：两个方向构造相同 → 另开会话让对方替你应答；修复：写身份或分方向密钥。
  • Needham–Schroeder：消息 ③ 对 Bob 无新鲜性 → Denning–Sacco 用旧 Ks 重放；修复：时间戳封在 Kb 票里，或 Bob 给出的值 Tb 经 KDC 抄进票里。17 年是公钥版。
  • Kerberos：加时间戳、AS 与 TGS 分开；单点登录；挡旧会话密钥的是票里的时间戳；代价：时钟同步、KDC 单点、口令可离线猜。
  • TLS：三步加绑定；CertificateVerify = L8 第 8 项"持有私钥"，删掉它中间人复活，Finished 救不了。一个往返（客户端猜组）。前向保密靠临时 DH，纯 PSK 没有。记录 nonce = IV ⊕ 序号。失败在协商、校验、实现；1.3 靠删功能。
  • IPsec：AH 不加密、ESP 加密；传输模式主机到主机，隧道模式隐藏内部地址；与 TLS 同一套零件。
  • NAC：认证加姿态评估；AR/NAS/PS = 请求者/认证者/认证服务器；EAP 是框架。
  • WEP：IV 碰撞 + RC4 相关密钥 + 线性 CRC + 无重放保护。WPA2：录下握手即可离线字典攻击，KRACK。WPA3：SAE 取代口令算 PMK，四次握手仍在。
  • 协议只防网络上的攻击者，端点问题归 L10。
